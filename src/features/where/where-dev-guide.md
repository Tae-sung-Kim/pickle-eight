# A안

# 🗺️ "오늘 어디 가지?" - 맞춤형 지역 나들이 & 여행 추천 서비스 기획서

## 1. 프로젝트 개요

* **서비스명**: (가칭) 오늘 어디 가지? (Where To Go Today)
* **주요 기술 스택**: Next.js, React, TypeScript, Tailwind CSS
* **서비스 컨셉**: 갈 곳을 고민하는 사용자들에게 현재 위치 또는 원하는 지역(시/군/구) 기준 **축제, 볼거리, 놀거리, 먹거리, 숙박 시설** 정보를 맞춤 제공하는 지역 기반 여행 정보 플래폼
* **핵심 타깃**: 데이트 코스를 찾는 연인, 아이와 함께 주말 나들이를 계획하는 가족, 혼자 여행객 등

---

## 2. 주요 기능 및 요구사항 (Functional Requirements)

### 2.1. 위치 및 지역 선택기 (Location & Region Filter)

* **현재 위치 기반 거리 계산**:
  * 위치 동의 시, 사용자 위치에서 대상 장소까지의 직선 거리/예상 이동 거리(km) 계산 및 리스트 표출.
  * *비회원/위치 미동의 시에도 서비스 이용 가능.*
* **지역 직접 선택 (SelectBox)**:
  * 1단계: 광역시/도 선택 (예: 서울특별시, 경기도, 강원도 등)
  * 2단계: 시/군/구 선택 (예: 강릉시, 해운대구, 가평군 등)

### 2.2. 맞춤형 필터 및 추천 로직 (Smart Recommendation)

1. **동행자/대상별 맞춤 추천 (Target Group)**:
   * **가족 / 아이와 함께**: 키즈카페, 체험 농장, 수목원, 박물관, 유모차 대여 가능 장소
   * **연인 (데이트)**: 감성 카페, 야경 명소, 공원, 미술관, 일몰 포인트
   * **친구 / 모임**: 액티비티, 테마파크, 캠핑/글램핑, 맛집 투어
   * **나홀로**: 힐링 산책로, 템플스테이, 독립서점, 독립 숙소
2. **계절별 추천 (Seasonal Highlights)**:
   * **봄**: 벚꽃 명소, 꽃 축제, 피크닉 장소
   * **여름**: 계곡, 해수욕장, 워터파크, 실내 인프라
   * **가을**: 단풍 명소, 억새길, 걷기 좋은 길
   * **겨울**: 눈썰매장, 빛 축제, 온천, 실내 전시
3. **편의시설 유무 확인 (Parking & Restroom)**:
   * 주차 가능 여부 및 주차 요금 정보
   * 주변 공용주차장 / 개방화장실 위치 연동 정보 표출

### 2.3. 상세 정보 노출 (Place Details)

장소 카드 및 상세 페이지에서 아래 정보들을 일목요연하게 표출:
* **기본 정보**: 장소명, 주소, 대표 전화번호
* **운영 정보**: 운영/관람 시간, 휴무일
* **비용 정보**: 입장료/관람료, 예상 1인 비용 (유/무료 구분 표시)
* **상세 설명**: 한 줄 요약 및 주요 특징 설명
* **주요 편의시설**: 주차장 보유 여부, 장애인/유모차 편의시설, 개방 화장실 유무

## 3. 지도 노출에 관한 검토 (Map API Necessity Analysis)

### ❓ 지도가 꼭 필요한가요?
> **결론: "선택적 도입 (리스트 View + 미니 지도/모달 형태 추천)"**

* **점심 메뉴 vs 여행/나들이의 차이점**:
  * 점심 식당은 '가깝다'는 것과 '메뉴 이름'이 가장 중요하므로 **리스트만으로 충분**합니다.
  * 하지만 나들이/여행은 **동선 계획(주변에 다른 놀거리가 같이 있는지, 주차장과의 거리 등)**이 중요하기 때문에 **지도가 주는 경험(UX) 가치가 매우 높습니다.**
* **권장 구현 방식**:
  * **메인 화면**: 기본은 **리스트 형태**로 노출하여 가볍고 빠르게 로딩.
  * **상세 보기 화면**: 장소의 위치와 주변 주차장/화장실 위치를 한눈에 볼 수 있는 **작은 지도(Mini Map) 카드 노출**.
  * 카카오/네이버 지도 SDK 웹 라이브러리는 일일 무료 쿼터가 수만~수십만 건이므로 비용 부담 없이 사용 가능합니다.

## 5. UI/UX 화면 구성안

1. **상단 필터 바**:
   * `[위치: 내 주변 10km]` or `[지역 선택: 강원도 > 강릉시]`
   * `[동행: 👶 아이와 함께]` `[계절: 🍁 가을 추천]` `[카테고리: 🎡 놀거리/축제]`
2. **리스트 카테고리 카드**:
   * 이미지, 장소명, 예상 거리 (예: `현재 위치에서 12km`)
   * 입장료/비용 정보 (예: `무료` / `성인 10,000원`)
   * 편의시설 태그 (예: `🅿️ 주차 가능`, `🚻 화장실`, `👶 유모차 OK`)
3. **상세 모달 / 페이지**:
   * 운용 시간, 팁, 대략적인 1인 예상 비용 (입장료 + 먹거리 대략 추정치)
   * 네이버/카카오 지도 앱 연결 버튼 (길찾기 딥링크)
   * 미니 지도 View (선택 사항)

# B안
# 지역 기반 나들이·여행 추천 서비스 기획 및 요구사항 정리

## 1. 서비스 개요

### 1.1 서비스 목적

항상 어디를 갈지 고민하는 사람들을 위해 지역별 축제, 관광지,
체험·놀거리, 먹거리, 숙박 및 편의시설 정보를 모아 추천하는 서비스다.

사용자가 현재 위치 또는 직접 선택한 지역을 기준으로 갈 만한 장소를
탐색하고, 누구와 함께 가는지, 계절, 인원, 예산 등을 고려해 적합한 나들이
코스를 찾을 수 있도록 돕는다.

단순한 장소 목록이 아니라 **누구와, 언제, 어디로, 얼마의 비용으로 갈 수
있는지**를 한 번에 파악할 수 있도록 하는 것이 핵심이다.

### 1.2 핵심 가치

-   갈 곳을 정하지 못한 사용자가 쉽게 목적지를 찾는다.
-   현재 위치 또는 선택한 지역을 기준으로 장소를 탐색한다.
-   축제, 관광지, 체험, 놀거리, 먹거리, 숙박 정보를 제공한다.
-   가족·연인·아이 동반 등 동행 유형에 맞춰 추천한다.
-   계절과 방문 시기에 맞는 장소를 추천한다.
-   예상 비용과 이동 거리를 제공해 방문 결정을 돕는다.
-   주차장, 화장실 등 실제 방문에 필요한 편의정보를 제공한다.
-   공공데이터를 우선 활용하고 부족한 정보는 적합한 외부 데이터로
    보완한다.

------------------------------------------------------------------------

## 2. 주요 사용자 및 이용 상황

### 2.1 주요 사용자 유형

-   가족과 주말 나들이를 계획하는 사람
-   아이와 함께 갈 장소를 찾는 부모
-   연인과 데이트 장소를 찾는 사람
-   친구·지인과 놀거리나 여행지를 찾는 사람
-   혼자 가볍게 여행하거나 산책할 장소를 찾는 사람
-   여행 중 주변 관광지와 먹거리를 찾는 사람

### 2.2 대표 이용 상황

-   이번 주말에 아이와 갈 곳을 찾고 싶다.
-   비가 오거나 날씨가 더울 때 갈 만한 실내 장소가 필요하다.
-   현재 위치에서 자동차로 1시간 이내에 갈 곳을 찾고 싶다.
-   특정 시·군·구의 축제나 관광지를 알고 싶다.
-   가족 4명이 당일치기로 다녀올 만한 장소와 예상 비용을 알고 싶다.
-   관광지 주변에서 식사할 곳과 주차장을 함께 확인하고 싶다.
-   여행지에서 숙박할 곳과 주변 볼거리를 찾고 싶다.

## 3. 지역 및 위치 기반 탐색

### 3.1 현재 위치 기반 탐색

사용자가 위치정보 제공에 동의하면 현재 위치를 기준으로 목적지까지의
대략적인 거리와 예상 이동시간을 제공한다.

요구사항:

-   브라우저 Geolocation API로 현재 위치를 가져온다.
-   위치정보 사용 전에 사용자 동의를 받는다.
-   현재 위치를 서버 DB에 저장하지 않는 것을 기본 원칙으로 한다.
-   현재 위치를 기준으로 지역 또는 장소를 검색한다.
-   검색 반경이나 예상 이동 범위를 선택할 수 있도록 검토한다.
-   위치정보를 허용하지 않으면 지역 직접 선택 기능을 이용할 수 있도록
    한다.

거리 및 이동시간 표시 예시:

-   약 5km
-   자동차 약 20분
-   대중교통 약 35분

단, 직선거리와 실제 도로 이동거리를 구분한다. 도로 이동거리나 이동시간은
경로·교통 데이터가 있을 때만 제공하고, 단순 좌표 계산값을 실제
이동시간처럼 표시하지 않는다.

### 3.2 지역 직접 선택

현재 위치와 관계없이 사용자가 원하는 지역을 선택할 수 있도록 한다.

지역 선택 구조 예시:

-   시·도
-   시·군·구
-   필요할 경우 읍·면·동

예시:

-   경기도 → 가평군
-   경기도 → 양평군
-   강원특별자치도 → 춘천시
-   충청남도 → 태안군
-   전북특별자치도 → 전주시

요구사항:

-   시·도 선택에 따라 시·군·구 목록을 갱신한다.
-   지역 선택만으로도 해당 지역의 축제·관광지·놀거리 등을 검색할 수
    있다.
-   현재 위치와 선택 지역을 함께 사용하는 탐색도 지원할 수 있다.
-   지역 데이터는 행정구역 코드 등 일관된 기준으로 관리한다.

### 3.3 탐색 범위

초기에는 다음과 같은 조건을 검토한다.

-   선택 지역 전체
-   현재 위치 주변
-   자동차 이동시간 기준
-   특정 거리 이내
-   당일치기 가능 범위

## 4. 장소 및 콘텐츠 정보

### 4.1 제공할 장소 유형

  분류          세부 정보 예시
  ------------- --------------------------------------------
  축제·행사     지역 축제, 계절 축제, 문화 행사, 공연
  관광·볼거리   관광 명소, 자연 경관, 박물관, 전시관
  놀거리·체험   테마파크, 키즈카페, 체험장, 레저, 액티비티
  자연·야외     공원, 수목원, 캠핑장, 계곡, 해변, 산책로
  먹거리        지역 맛집, 전통시장, 특산물, 음식거리
  숙박          호텔, 펜션, 캠핑장, 야영장, 관광 숙박시설
  편의시설      주차장, 화장실, 수유실, 관광안내소 등

장소 유형은 처음부터 지나치게 세분화하지 않고, 데이터 확보 가능성과
사용자 검색 수요를 고려해 확장한다.

### 4.2 장소 상세 정보

각 장소의 상세 화면에서 다음 정보를 제공한다.

  항목            설명
  --------------- --------------------------------
  장소명          관광지·시설·행사 이름
  대표 이미지     장소를 파악할 수 있는 사진
  주소            도로명 주소 및 지번 주소
  전화번호        문의 가능한 연락처
  운영시간        요일별 운영시간 및 휴무일
  이용료          무료·유료 여부와 요금
  간단한 설명     장소의 특징 및 주요 볼거리
  소요시간        예상 관람·체험 시간
  추천 대상       가족, 연인, 아이 동반 등
  이용 조건       예약 필요 여부, 연령 제한 등
  공식 홈페이지   운영기관 또는 장소 공식 사이트
  데이터 기준일   정보의 최종 확인·갱신 시점

정보가 없거나 확인되지 않은 항목은 임의로 채우지 않고 '정보 확인 필요'
또는 미제공으로 표시한다.

### 4.3 축제·행사 정보

축제와 행사는 날짜가 중요하므로 별도의 정보 항목을 관리한다.

-   행사명
-   개최 지역
-   행사 시작일 및 종료일
-   운영시간
-   행사 장소
-   입장료 또는 체험비
-   행사 설명
-   공식 홈페이지
-   문의 전화
-   현재 진행 중인지 여부
-   정보 갱신일

종료된 행사가 현재 진행 중인 것처럼 노출되지 않도록 행사 기간과 데이터
갱신 상태를 확인한다.

## 5. 누구와 함께 가는지에 따른 추천

### 5.1 동행 유형 선택

사용자가 누구와 함께 방문하는지 선택할 수 있도록 한다.

초기 분류:

-   혼자
-   연인
-   친구
-   가족
-   아이와 함께
-   부모님과 함께
-   단체

### 5.2 인원 및 연령 조건

동행 유형뿐 아니라 실제 인원과 아이의 연령대가 추천에 영향을 줄 수 있다.

선택 가능한 조건 예시:

-   성인 인원
-   어린이 인원
-   영유아 동반 여부
-   아이 연령대
-   부모님 동반 여부

개인정보를 과도하게 수집하지 않고 추천에 필요한 범위에서만 입력받는다.

### 5.3 동행 유형별 추천 예시

  동행 유형     추천 장소·활동
  ------------- -------------------------------------------
  연인          야경, 카페거리, 전시, 드라이브, 감성 숙소
  가족          동물원, 수목원, 자연휴양림, 체험마을
  아이 동반     키즈 체험, 과학관, 동물 체험, 놀이터
  부모님 동반   전통시장, 자연 경관, 온천, 편안한 관광지
  친구          레저, 액티비티, 맛집, 축제
  혼자          산책로, 박물관, 카페, 조용한 관광지

이 표는 추천 규칙의 출발점이며, 실제 장소 데이터의 이용 조건과 적합성을
확인해 적용한다.

### 5.4 인원에 따른 먹거리·놀거리 추천

-   인원수에 적합한 식당 및 메뉴 추천
-   가족 단위 식사가 가능한 장소
-   단체 예약이 가능한 체험·관광시설
-   아이 동반 가능 여부
-   연령·신장 제한 등 이용 조건
-   인원별 입장료 및 체험비 계산

## 7. 주차장 및 편의시설 정보

### 7.1 제공을 검토할 편의시설

-   주차장
-   공중화장실
-   장애인 화장실 및 접근성 정보
-   수유실
-   유아 휴게 공간
-   관광안내소
-   전기차 충전소
-   대중교통 접근 정보
-   휠체어 접근 가능 여부
-   반려동물 동반 가능 여부

### 7.2 장소와 편의시설의 관계

장소 자체의 편의시설인지, 주변에 별도로 존재하는 시설인지 구분한다.

예시:

-   장소 내부 주차장
-   장소에서 300m 떨어진 공영주차장
-   장소 내부 화장실
-   인근 공중화장실

거리와 위치가 확인되지 않은 편의시설을 해당 장소의 시설인 것처럼
표시하지 않는다.

### 7.3 주차 정보

가능한 경우 다음 정보를 제공한다.

-   주차장 이름
-   주소 및 위치
-   장소와의 거리
-   주차 가능 대수
-   요금
-   운영시간
-   운영 여부 및 데이터 갱신 시점

실시간 주차 가능 여부는 실시간 데이터 제공처가 있는 경우에만 제공한다.

## 8. 예상 비용 안내

### 8.1 기능 목적

사용자가 방문 전에 대략적인 예산을 파악할 수 있도록 예상 비용을
제공한다.

### 8.2 비용 항목

  항목     예시
  -------- ---------------------------------
  입장료   관광지·전시관·테마파크 입장료
  체험비   만들기, 체험 프로그램, 액티비티
  식비     인원수에 따른 예상 식사 비용
  주차비   주차 요금
  교통비   대중교통 또는 차량 이동 비용
  숙박비   숙박시설의 1박 기준 요금

### 8.3 인원별 비용 계산

예시 조건:

-   성인 2명
-   어린이 1명
-   당일치기
-   식사 1회
-   유료 관광지 1곳

예상 비용은 다음처럼 분리해서 표시한다.

-   입장료: 성인·어린이 요금 합계
-   체험비: 선택한 체험의 인원별 요금
-   식비: 참고 가격 또는 사용자 설정 예산
-   주차비: 확인 가능한 경우
-   교통비: 경로 및 요금 데이터가 있는 경우
-   총 예상 비용: 확보된 항목의 합계

### 8.4 비용 표시 원칙

-   실제 요금과 추정 비용을 구분한다.
-   무료 장소는 무료라고 표시하되 주차비 등 추가 비용 가능성을 안내한다.
-   가격이 확인되지 않으면 임의의 금액을 표시하지 않는다.
-   비용 기준일을 표시한다.
-   숙박비와 식비는 날짜·인원·업체에 따라 변동될 수 있음을 안내한다.

## 9. 지도 노출 여부 및 위치 표현

### 9.1 검토 결론

초기 MVP에서는 지도 화면을 필수로 만들지 않는다. 다만 나들이·여행
서비스는 장소의 지리적 관계와 이동 동선이 중요하기 때문에, 점심 추천
서비스보다 지도 기능의 필요성이 높다.

따라서 다음과 같은 단계적 접근을 권장한다.

### 9.2 1차: 리스트 중심

-   장소명
-   주소
-   현재 위치 또는 선택 지역으로부터의 거리
-   예상 이동시간(근거 데이터가 있을 때)
-   외부 지도 길찾기 링크

이 단계에서는 지도 SDK 없이도 서비스를 제공할 수 있다.

### 9.3 2차: 선택적 지도 제공

사용자가 지도 보기 기능을 선택할 때만 지도를 표시하는 방안을 검토한다.

가능한 선택지:

-   지도 SDK를 사용하는 방식
-   비용 및 상업적 이용 조건이 적합한 오픈소스 지도 구성
-   외부 지도 서비스 링크로 이동하는 방식

지도 도입 시 확인할 항목:

-   지도 표시 비용 및 무료 제공 범위
-   상업적 서비스 이용 조건
-   지도 타일·API 호출 제한
-   장소 마커 및 경로 표시 가능 여부
-   모바일 사용성
-   데이터 출처 및 라이선스

### 9.4 지도 없이 제공할 수 있는 정보

-   장소 주소
-   대략적인 직선거리
-   외부 지도 길찾기
-   장소와 주변 편의시설의 거리
-   선택 지역 내 장소 리스트

실제 도로 이동거리와 이동시간은 지도 화면을 표시하지 않더라도 경로 탐색
데이터가 필요할 수 있다.

-   원천 장소 ID
-   데이터 갱신일

원천 데이터의 이용 조건에 따라 저장·캐싱·재노출이 허용되는 범위만 내부
DB에 보관한다.

## 11. 추천 알고리즘

### 11.1 초기 추천 방식

초기에는 규칙 기반 추천을 사용한다.

추천 조건:

-   지역
-   거리 또는 이동시간
-   동행 유형
-   인원 및 연령 조건
-   계절 및 방문 날짜
-   장소 유형
-   예산
-   운영 여부

추천 처리 예시:

1.  사용자가 현재 위치 또는 지역을 선택한다.
2.  동행 유형과 인원수를 선택한다.
3.  방문 날짜 또는 계절을 선택한다.
4.  예산과 선호 활동을 선택한다.
5.  조건에 맞는 장소를 조회한다.
6.  이용 가능 여부와 데이터 최신성을 확인한다.
7.  적합한 장소를 우선순위에 따라 노출한다.

### 11.2 추천 결과 예시

입력 조건:

-   지역: 경기도 가평군
-   동행: 가족
-   인원: 성인 2명, 어린이 1명
-   방문 시기: 가을
-   예산: 10만 원 내외
-   방문 형태: 당일치기

추천 결과 구성:

-   가족이 함께 즐길 수 있는 관광지
-   아이 체험이 가능한 장소
-   주변 식당
-   주차장 및 화장실
-   장소별 입장료
-   예상 식비
-   이동거리와 예상 이동시간
-   총 예상 비용

### 11.3 향후 확장

-   사용자 선호 기반 추천
-   방문하거나 저장한 장소 기록
-   이미 방문한 장소 제외
-   장소 간 이동 동선을 고려한 코스 추천
-   날씨 변화에 따른 대체 장소 추천
-   사용자 평가 및 만족도 반영

AI는 초기 필수 요소가 아니다. 데이터가 충분히 확보된 이후 자연어
검색이나 추천 설명 생성 등에 도입한다.

## 18. 개발 착수 전 우선순위

이 서비스는 기능 자체보다 지역별 공공데이터의 품질과 범위가 중요하다.

따라서 다음 순서로 검증하는 것을 권장한다.

1.  한국관광공사 관광정보 API에서 관광지·축제·음식점·숙박 데이터 확인
2.  공공데이터포털에서 주차장·화장실 데이터 확인
3.  경기도 등 특정 지역을 선정해 실제 데이터 조회
4.  장소명·주소·좌표·운영시간·입장료의 제공 여부 확인
5.  데이터 중복과 갱신 주기 확인
6.  지역 선택 및 리스트 화면으로 작은 PoC 구현
7.  실제 데이터 품질을 바탕으로 MVP 범위 확정

**핵심 원칙:** 처음부터 전국의 모든 정보를 제공하려고 하지 않는다. 한두
개 지역의 관광·축제·편의시설 데이터를 먼저 연결해 실제로 쓸 만한 추천이
가능한지 확인한 다음 전국으로 확장한다.

**최종 지향점:** 사용자가 지역, 동행자, 날짜, 예산을 선택하면 갈 만한
장소와 주변 먹거리·놀거리·편의시설, 예상 비용까지 한 번에 확인할 수 있는
지역 기반 나들이 추천 서비스.
