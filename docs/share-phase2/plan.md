## 목표

### 공유 카드 내용 (2차 대상)

| 기능 | 카드에 넣는 내용 | 넣지 않는 것 |
|---|---|---|
| 오늘의 운세 (`/fortune/today`) | 기능명, 한 줄 요약, 행운 요소(숫자·색 등), 고지 한 줄, 기능 주소 | 생년월일, 입력한 이름, 해석 전문 |
| 띠별 운세 (`/fortune/tti`) | 띠 이름, 한 줄 요약, 행운 요소, 고지 한 줄, 기능 주소 | 생년, 해석 전문 |
| 별자리 운세 (`/fortune/star-sign`) | 별자리 이름, 한 줄 요약, 행운 요소, 고지 한 줄, 기능 주소 | 태어난 날짜와 시각, 해석 전문 |
| 로또 생성기 (`/lotto/generator`) | 생성된 번호, 사행성 고지 문구, 기능 주소 | 생성 조건 값(필터, 가중치 설정 값) |

- 카드 레이아웃은 1차와 같다고 가정한다(540x675 기준, 같은 자리에 기능명·결과·주소·고지). 행운 요소 자리가 1차 레이아웃에 없으면 열린 질문 2번에서 다룬다.
- 카드에 날짜는 넣지 않는다(1차 열린 질문 3과 같은 기준).

## 유저 스토리

- US-1: 운세를 본 사용자로서 오늘의 운세나 띠·별자리 운세를 친구에게 카드 이미지로 보내고 싶다. 같이 보는 재미를 나누기 위해서다.
- US-2: 로또 번호를 뽑은 사용자로서 생성된 번호를 카드 이미지로 저장하거나 보내고 싶다. 같이 고르는 재미를 나누기 위해서다.
- US-3: 사이트 운영자로서 운세와 로또 카드에 생년월일, 이름, 당첨 연상 문구가 실리지 않기를 원한다. 개인정보와 사행성 위험을 늘리지 않기 위해서다.

## 완료 조건 (AC)

태그는 검증 층이다. `[E2E]`는 화면 흐름 단위로 묶었고, 자동 spec은 대표 흐름만 만든다. 실기기 항목은 수동이며 `qa-report.md`에 따로 기록한다.

- AC-1 [E2E] (오늘의 운세, PC 흐름): 결과가 나오면 "링크 복사", "이미지 저장", "이미지 복사"(지원할 때만) 버튼이 보이고, 결과 전에는 보이지 않는다. "이미지 저장"을 누르면 공유 카드 PNG가 내려받아지고 파일 크기가 0이 아니다. 320px 너비에서 가로 스크롤이 생기지 않는다.
- AC-2 [E2E] (띠별 운세와 별자리 운세, 모바일 공유창 흐름. 모바일 판정과 공유 기능을 모의): 각 페이지에서 결과가 나온 뒤 공유 버튼이 1개 보인다. 누르면 공유창이 열리고 카드 PNG와 기능 주소가 같이 전달된다. 공유창을 닫으면 오류 안내가 뜨지 않는다.
- AC-3 [E2E] (이미지 만들기 실패, 운세 화면 한 곳 기준): 이미지 만들기가 실패하면 1차와 같은 실패 안내가 뜨고, 링크 공유 경로가 그대로 동작한다. 빈 파일이 내려받아지거나 공유창에 넘어가지 않는다.
- AC-4 [E2E] (로또 생성기, 번호 생성 뒤 공유 흐름. 1차 AC-5 회귀를 포함): 번호를 생성하면 공유 버튼이 보이고, 이미지 저장으로 카드 PNG가 내려받아진다. 모바일 판정 환경에서는 공유창에 카드 PNG가 넘어간다. 버튼을 빠르게 두 번 눌러도 한 번만 실행된다. 1차 AC-5(기존 로또 공유 동작 유지)를 이 흐름에 포함한다.
- AC-5 [단위] (운세 카드 문구 규칙): 운세 카드에 들어가는 문구는 "공유 카드 내용" 표의 해당 행 항목, 기능 주소, 고지 한 줄뿐이다. 생년월일, 입력한 이름은 어떤 카드에도 들어가지 않는다. 띠·별자리 이름과 행운 요소 값은 들어갈 수 있다. 카드 문구는 기능별 금지어 검사를 통과한다.
- AC-6 [단위] (로또 카드 문구 규칙): 로또 카드의 고지 문구는 문구 상수에서 가져온다. 카드 문구에 당첨 보장, 필승, 확률 상승 등 사행성 연상 표현이 없다는 것을 금지어 검사로 확인한다. 생성 조건 값은 카드에 들어가지 않는다.
- AC-7 [정적] (적용 범위): 2차 대상(`/fortune/today`, `/fortune/tti`, `/fortune/star-sign`, `/lotto/generator`)에만 공통 공유 버튼이 추가됐다. 타로 페이지, 사주, 꿈 해몽, 로또 기록·채점·분석·시뮬레이터, 나의 번호에는 공유 버튼이 없다. 1차 대상 화면의 공유 동작은 바뀌지 않는다.
- AC-8 [정적] (검색·미리보기 값 유지): 2차 대상 페이지의 `title`, `description`, OG 제목이 바뀌지 않는다. 메타데이터는 `buildMetadata()`를 그대로 쓴다. 로또 OG 기본 문구가 운세 페이지 미리보기에 나오지 않는다. 새 라우트와 sitemap 항목이 생기지 않는다.
- AC-9 [정적] (문구 모음과 캡처 제외): 운세·로또 카드의 고지 문구와 공유 문구가 문구 상수 파일에 모여 있고 copy-rule 검사 대상에 들어 있다. 카드 DOM 안의 버튼, 입력란, 광고, 동의 배너에는 캡처 제외 표시가 붙어 있다.
- AC-10 [정적] (라이선스 문서): 새 라이브러리나 글꼴을 넣지 않았다면 `DEPENDENCY_LICENSES.md`와 `THIRD_PARTY_NOTICES.md`는 바뀌지 않는다. 넣었다면 두 파일이 같이 갱신돼 있다.
- AC-11 [E2E] (수동, 실기기 — 자동 spec 아님): 1차 AC-6 대상 기기(iPhone Safari, Android Chrome, 인앱 브라우저)에서 운세 카드 이미지와 로또 카드 이미지를 첫 시도부터 공유해 본다. 이미지가 빈 상태로 나오지 않는다. 대상 기기 목록은 1차 열린 질문 7번을 따른다.

## 예외·빈 상태

- 결과가 없는 상태: 공유 버튼을 보이지 않게 한다(1차와 같다).
- 운세 결과에 위기 안내나 죽음 관련 풀이가 붙는 경우: 공유 버튼을 숨긴다(열린 질문 4번, 1차 열린 질문 17번과 같은 기준).
- 로또 번호를 아직 생성하지 않은 상태: 공유 버튼이 보이지 않는다.
- 이미지 만들기 실패, 공유창 취소, 인앱 브라우저 안내: 1차 규칙과 같다.
- 띠·별자리 이름이 긴 경우(예: 긴 이름): 카드에서 잘리지 않게 한다. 줄임 기준은 설계.
- 행운 요소 값이 없는 결과(데이터 누락): 행운 요소 줄을 빼고 나머지 항목으로 카드를 만든다. 빈 칸을 그리지 않는다.
- 320px 너비: 공유 버튼과 안내 문구가 가로 스크롤을 만들지 않는다.

## 검색 노출

- 키워드:
  - 운세: "오늘의 운세", "띠별 운세", "별자리 운세"(기존 검색어 유지. 검색량 조회 결과는 각 기능 plan을 따른다).

- 페이지가 답할 질문:
  - 오늘의 운세: 오늘 운세를 어떻게 보면 되는지, 행운 요소는 무엇을 뜻하는지.
  - 띠별 운세: 내 띠의 오늘 흐름을 어디서 보는지.
  - 별자리 운세: 내 별자리의 오늘 흐름을 어디서 보는지.
  - 로또 생성기: 번호를 어떤 조건으로 뽑을 수 있고, 이 도구가 당첨을 보장하지 않는다는 점.

- 공유 링크 미리보기: 공유 주소는 각 페이지의 canonical 주소다. OG 제목·설명·이미지가 기능에 맞게 나오는지 확인한다(AC-8). 기능별 고정 OG 이미지는 1차 열린 질문 8번을 따른다.

## 법적·정책 요구사항

- 개인정보 수집:
  - 운세 3종은 생년월일을 입력받을 수 있다(오늘의 운세 입력 방식은 열린 질문 7번에서 확인). 카드에는 생년월일과 입력 이름을 넣지 않으므로 공유 기능이 새로 수집하는 정보는 없다.
  - 띠·별자리 이름은 생년월일에서 나온 파생값이다. 1차 궁합과 같은 법률 확인 대상이다(열린 질문 3번).
  - 로또 생성기는 개인정보를 입력받지 않는다.
  - 공유는 브라우저 안에서 이미지와 주소를 만들고 서버로 결과를 보내지 않는다(1차 기준).
  - 공유 기록은 만들지 않는다.
- 고지 문구:
  - 운세 카드 하단 고지 한 줄(초안): "재미로 보는 참고용 결과예요. 실제 결과를 보장하지 않아요."(열린 질문 4번, 법률 확인 필요)
  - 변경 메모(2026-11-26, 사용자 승인): 초안의 "보장하지 않아요"는 문구 규칙(보장 금지어) 위반이라 "재미로 보는 참고용 결과입니다. 실제 상황과 다를 수 있습니다."로 바꿨다. 구현과 단위 테스트는 이 문구를 따른다.
  - 로또 카드 하단 고지 한 줄(초안): "재미로 고른 번호예요. 당첨을 보장하지 않아요."(열린 질문 5번, 법률 확인 필요. `COMPLIANCE.md`의 로또 준수 사항과 맞춘다.)
  - 두 문구 확정은 PM 승인으로 한다. 법률 확인 전에는 초안을 쓴다.
  - 공유 버튼이 보이는 화면의 기존 고지(약관, 방침 링크, 위기 안내, 로또 연령·책임 고지)는 그대로 둔다.
- 상업적 이용 주의:
  - 카드에 광고 요소, 광고 링크, 상업 문구를 넣지 않는다(1차 기준).
  - 로또 번호 이미지 공유는 사행성 해석과 당첨 연상을 법률 확인한 뒤 옮긴다(1차 열린 질문 16번). 사용자는 카드 고지 포함으로 진행하기로 확정했으나, 공유 기능 출시 전 법률 확인이 끝나야 한다.
  - 운세 카드에 쓰는 행운 요소와 한 줄 요약의 출처가 AI 생성 문구이면 문구 권리를 확인한다(열린 질문 1번).
  - 새 글꼴, 로고, 이미지를 넣지 않는 것을 기본으로 한다. 넣으면 1차 기준(라이선스, `THIRD_PARTY_NOTICES.md`)을 따른다.
  - 타로 카드 그림은 권리 확인 전까지 2차에서도 쓰지 않는다(제외 범위).

## 열린 질문

사용자 확인이 필요한 것은 1, 2, 3, 5번이다. 나머지는 권장안으로 진행해도 되는지 확인한다.

1. (운세 한 줄 요약 출처) 한 줄 요약을 기존 결과 데이터의 짧은 문장에서 가져올지, 공유용으로 새 요약 문구를 만들지. 권장: 기존 결과 데이터에 이미 있는 문장만 쓴다. 새 문구를 만들면 문구 검수와 권리 확인이 필요하다.
2. (행운 요소 자리) 행운 요소(숫자·색 등)가 결과 데이터에 실제로 있는지, 항목이 몇 개인지. 1차 카드 레이아웃에 행운 요소 자리가 없으면 새 레이아웃이 필요하다. 권장: 데이터가 있으면 1차 레이아웃의 하단 한 줄에 칩으로 넣고, 새 레이아웃은 설계 단계에서 확정한다. 사용자 확인 필요.
3. (띠·별자리 이름과 법률) 띠별·별자리 운세 카드의 띠·별자리 이름은 생년월일에서 자동 판정된 값인지, 사용자가 고른 값인지. 궁합과 같은 파생값 위험이 있으므로 법률 확인을 받는다. 권장: 이름만 넣는 것을 유지하고, 1차 열린 질문 1과 함께 확인한다. 사용자 확인 필요.
4. (운세 고지와 위기 신호) 운세 카드 고지 초안을 승인받는다. 위기 안내나 죽음 관련 풀이가 붙는 결과는 공유 버튼을 숨긴다(1차 열린 질문 17과 같은 기준). 권장: 그대로 진행.
5. (로또 고지 문구와 법률) 로또 카드 고지 초안을 승인받고, 사행성과 당첨 연상에 대한 법률 확인을 공유 출시 전에 끝낸다. 사용자 확정은 카드에 고지를 넣는 것까지다. 권장: 초안 승인 후 법률 확인 결과가 나올 때까지 출시를 보류하지 않되, 확인 결과에 따라 고지 문구를 바꾼다. 사용자 확인 필요.
6. (로또 기존 버튼 교체) 로또 생성기의 기존 공유 버튼 문구와 위치를 새 공통 버튼으로 바꿀지. 권장: 같은 자리에 공통 버튼으로 교체하고, 기존 이미지 공유 결과와 저장 파일명 규칙은 AC-4로 확인한다.
7. (오늘의 운세 입력 방식) 오늘의 운세가 생년월일 입력을 받는지, 띠·별자리 선택만으로 결과가 나오는지. 입력을 받으면 카드에 입력값이 들어가지 않도록 AC-5로 막는다. 권장: 입력값은 카드에 넣지 않는다. 확인 필요.
8. (실기기 대상) 2차 페이지의 실기기 목록과 버전을 1차 열린 질문 7번과 같게 할지. 권장: 같게 한다. 버전 번호는 QA 시작 전에 PM이 정한다.
9. (2차 카드 크기) 운세 카드도 1차 카드 기준 크기(540x675, PNG 2배)를 쓸지. 권장: 같은 크기를 쓴다. 다르면 설계 단계에서 상수를 나눈다.
