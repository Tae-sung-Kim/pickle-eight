# 텍스트 접기 5단계 기획서 (text-slim stage 5)

작성일: 2026-11-27
근거: `docs/text-audit/audit-round2.md` 4장(후보 1~10), 5장(상위 10개). 1~4단계 기획과 `docs/text-slim/status.md`(구현 완료). 공통 컴포넌트 `src/components/common/collapsible.component.tsx`(제목은 보이고 본문만 접는 `<details>`, `note`로 한 줄 요약 지원, 서버 컴포넌트).

## 목표

기본 화면에서 설명 본문(이용 방법, 띠·별자리 찾기 안내, 궁합 "~이란"과 등급 규칙, 손 없는 날 규칙 설명과 연도 달력, 뽑기 설명 문단, 사주 계산 기준)을 접어 입력과 결과가 먼저 보이게 한다. 이번 단계는 문구를 하나도 지우지 않는다. 접힌 본문은 서버 HTML과 구조화 데이터에 그대로 남는다.

## 확정된 사용자 결정

- 이번 단계는 접기만 한다. 문구 삭제는 없다.
- 접는다: 오늘의 운세 설명 3섹션, 띠별 운세 설명 3섹션, 별자리 운세 설명 3섹션, 사주 계산 기준, 띠 궁합과 별자리 궁합의 "~이란" 설명과 등급 규칙(표 포함), 손 없는 날 허브·연도 화면의 규칙 설명, 손 없는 날 연도 화면의 "달력으로 보기", 운빨 뽑기 도구 3화면의 긴 설명 문단.
- 사주 계산 기준은 입력 단계의 링크가 있으므로, 링크가 있는 부분은 접힌 블록 밖에 두고 가이드 본문만 접는다. 펼침 연결 방식은 열린 질문 1.
- 손 없는 날 음력 출처 한 줄 "음력 표는 한국천문연구원 음양력 정보를 바탕으로 합니다."는 접힌 블록 밖에 남긴다.
- 접지 않는다: 상시 고지(h1 아래), 입력칸 근처 비전송·만 14세 안내, 이용 안내의 책임·만 14세 항목, 이용 동의 화면, 결과 하단 고지, 상담전화 5곳, 운세 허브 "믿을 만한가요?" FAQ, 로또 화면 전부, 손 없는 날 월별 목록, 손 없는 날 하단 안내·출처.

## 범위

- 포함: 아래 기능 목록 F-1~F-9.
- 제외:
  - 문구 삭제와 문구 수정. 줄 위치 이동(음력 출처 한 줄 분리)만 허용한다.
  - 사주 "이용 방법"(약 222자). 사용자 결정 목록에 없다.
  - 사주 외 계산 기준 4화면(띠, 별자리, 오늘, 궁합 4화면의 "계산 기준" 약 146~149자). 사용자 결정 목록에 없으므로 이번 단계에서 접지 않는다. 필요하면 다음 단계 후보.
  - 운빨 뽑기 허브(`/lucky-draw`)의 설명 문단(183자). 사용자 결정이 "도구 3화면"이다.
  - 상시 고지, 입력 안내, 이용 안내, 이용 동의 화면, 결과 하단 고지, 상담전화, 로또 6개 화면, 손 없는 날 월별 목록.
  - 접기 컴포넌트 자체 변경. 1단계 AC-7(누름 영역 44px, 포커스, 움직임 끄기)은 그대로 적용된다.
  - 광고 슬롯 위치와 개수, 메타데이터, 구조화 데이터, 사이트맵.
  - 새 기능, 새 저장 항목, 새 외부 자원.

## 유저 스토리

- US-1: 운세 이용자로서, 입력칸과 결과 버튼을 먼저 보고 싶다. 왜냐하면 설명 본문이 입력 위에 긴 스크롤을 만들기 때문이다.
- US-2: 사주 이용자로서, 계산 기준이 궁금할 때 입력 단계의 링크를 누르면 본문이 바로 열리기를 원한다. 왜냐하면 기준을 찾으려고 다시 펼칠 필요가 없어야 하기 때문이다.
- US-3: 손 없는 날 이용자로서, 날짜 목록과 달력 중 필요한 것을 고르고 싶다. 왜냐하면 규칙 설명과 달력이 같은 화면에서 먼저 보일 필요가 없기 때문이다.

## 완료 조건 (AC)

QA가 이 목록으로 테스트를 만든다. 접기 컴포넌트의 열림·닫힘 동작은 1·2단계 E2E에서 이미 검사했으므로, 이번 단계의 E2E는 화면별 제목과 새로 생긴 흐름(사주 링크)만 확인한다.

- AC-1 [E2E]: 데스크톱에서 `/fortune/tti`를 열면 "내 띠 찾는 방법", "입력해서 내 띠 찾기", "설날 기준과 다를 수 있는 이유"가 제목 줄로 보이고 본문은 닫혀 있다. 제목을 누르면 본문이 보이고 다시 누르면 닫힌다. 같은 화면의 상시 면책, 입력 안내, 계산 기준은 접히지 않고 보인다. 대표 화면 한 곳만 E2E로 검사하고, 나머지 화면은 AC-6으로 본다.
- AC-2 [E2E]: `/fortune/saju`에서 동의한 뒤 입력 단계의 "계산 기준 보기" 링크를 누르면, 닫혀 있던 "계산 기준" 본문이 열리고 "계산 기준" 제목으로 이동한다. 링크 자체는 접히지 않는다. 열린 질문 1이 승인되어야 이 AC를 확정한다.
- AC-3 [E2E]: `/fortune/compatibility/tti`에서 "띠 궁합이란"과 "등급 규칙"이 제목 줄로 보이고 닫혀 있다. "등급 규칙"을 누르면 설명 문단과 등급 표가 보인다. 상단 면책과 입력 안내는 접히지 않는다.
- AC-4 [E2E]: `/no-son-days/2027`에서 "달력으로 보기"가 닫혀 있고, 누르면 달력이 보인다. 1~12월 제목과 날짜 목록은 접히지 않고 보인다. "음력 표는 한국천문연구원 음양력 정보를 바탕으로 합니다."는 접힌 블록 밖에 보인다. 허브 `/no-son-days`에서 "손 없는 날, 이렇게 계산합니다"가 닫혀 있다.
- AC-5 [E2E]: JS를 끈 상태에서 `/fortune/saju`와 `/no-son-days/2027`을 열면, 접힌 계산 기준 문장과 접힌 달력 본문이 서버 HTML에 있다(`toBeAttached`로 확인, 펼친 상태와 같은 텍스트).
- AC-6 [정적]: F-1~F-9는 모두 기존 `CollapsibleComponent`를 쓴다. 각 접힌 제목 줄은 위 화면별 표의 제목과 같고, 기존 상수나 기존 제목 문자열만 쓴다. 새로 만든 문장은 없다(F-9 제목은 열린 질문 3 결정 뒤). 사주 계산 기준을 공통 컴포넌트에서 접을 때 사주 외 4화면(`/fortune/today`, `/fortune/tti`, `/fortune/star-sign`, `/fortune/compatibility/*`)의 계산 기준은 접히지 않는다.
- AC-7 [정적]: 문구 diff가 없다. 접히는 블록과 남는 블록의 문장 원문이 변경 전과 같다. 허용되는 변화는 음력 출처 문장을 같은 상수 문단에서 떼어 블록 밖 한 줄로 두는 것뿐이다. 접지 않는 블록(상시 면책, 입력 안내, 이용 안내의 책임·만 14세 항목, 이용 동의, 결과 하단 면책, 상담전화 5곳, 손 없는 날 월별 목록과 하단 출처)의 문구와 위치가 바뀌지 않는다. 광고 슬롯 위치와 개수가 바뀌지 않고, 접힌 블록 안에 광고가 없다.
- AC-8 [단위]: `unit/fortune/*`, `unit/no-son-days/*`, `unit/lucky-draw/*`의 기존 문구 검사 테스트가 변경 후에도 통과한다.
- AC-9 [정적]: `npm run typecheck`와 `npm run lint`가 통과한다.

## 예외·빈 상태

- 펼침 상태는 저장하지 않는다. 새로고침하면 닫힌 상태로 돌아간다.
- JS를 끈 상태에서 접힌 블록은 `<details>`로 펼칠 수 있다. 사주 링크(F-4)는 JS 패널 안에 있으므로 JS를 끈 상태에서는 나타나지 않는다. 링크는 JS 동작에 기대고, 본문은 HTML에 있다(AC-5).
- 사주 링크가 여러 번 눌려도 본문은 열린 상태로 남는다. 닫는 동작은 제목 줄을 눌러서만 한다.

- 접힌 블록 안에 내부 링크가 있으면 펼친다. 현재 확인된 내부 링크는 사주 "계산 기준 보기"(F-4) 하나다. 손 없는 날 "이번 달 손 없는 날 달력 보기" 링크는 달력 블록 밖에 있다.
- 접힌 블록 안에 광고나 결과 영역을 넣지 않는다.
- 브라우저 찾기(Ctrl+F)로 접힌 텍스트를 찾을 때 자동 펼침은 1단계 열린 질문 9와 같이 이번에 정하지 않는다.
