# 3단계 기획서: 로또 6개 화면 문구 정리

작성일: 2026-11-27
대상 화면: 번호 생성기(`/lotto/generator`), 회차별(`/lotto/history`), 채점기(`/lotto/check`), 나의 번호(`/lotto/my-numbers`), 분석(`/lotto/analysis`), 시뮬레이터(`/lotto/simulator`)
입력: `docs/text-audit/audit.md` 3.20·3.21장, 4장 "로또 6개" 행, 7장 후보 9. `docs/lotto-notice/plan.md`. `COMPLIANCE.md` 2장·3장·11장. `docs/text-slim/plan.md`, `plan-stage2.md`(1·2단계 완료).

## 승인 요청

사용자 승인이 필요한 항목을 먼저 적는다. 승인 전에는 개발을 시작하지 않는다.

1. 삭제·변경 원문 8개(화면 문장 4개, 헤더 설명 1개, 하단 고지 3항을 한 항목으로 합침)와 신규 문구 1개를 승인한다. 전체 목록은 "삭제·변경 문구 목록"에 있다.
2. 승인 필수 A: 화면 설명 3곳(생성기, 분석, 시뮬레이터)에서 "당첨을 보장하지 않습니다"를 지운다. `docs/lotto-notice/plan.md`가 이 세 화면의 문구 변경을 범위 밖으로 정했으므로, 그 결정을 바꾸는 승인이다. 상단 노출이 줄어든다(열린 질문 Q1).
3. 승인 필수 B: 하단 고지를 6항에서 4항으로 줄인다. `docs/lotto-notice/plan.md`의 "푸터에 있는 기존 고지 다섯 항목은 그대로 둔다"를 바꾸는 승인이다.
4. 확인 요청: "당첨 보장 없음"을 법적 필수로 본다. 이 기획서는 사용자 방침대로 필수로 취급해 유지한다. 다만 `COMPLIANCE.md`에는 이 문장을 직접 요구하는 조항이 없고, `docs/lotto-notice/plan.md` Q5(법적 필수인지 내부 정책인지)는 아직 열려 있다.
5. 설계(architect)와 UI/UX(ui-ux-designer) 단계는 생략한다. 문구만 바뀌며 화면 구조·로직·디자인은 바뀌지 않는다. 이 생략도 사용자 승인이 필요하다.

법적 필수 문구는 하나도 삭제하지 않는다. 단, "당첨 보장 없음" 문장의 화면 상단 노출은 승인 A에 따라 줄어든다. 자세한 대조는 "법적·정책 요구사항"에 있다.

## 목표

로또 6개 화면에서 같은 고지가 여러 번 나오는 문장을 줄이되, 법적 필수 고지(만 19세, 비제휴, 당첨 보장 없음·참고용, 성인 확인 팝업, 경고 알림)는 원문 그대로 남겨 이용자가 화면을 읽는 부담을 줄인다.

## 범위

- 포함:
  - 로또 공통 레이아웃의 헤더 설명(`src/app/lotto/layout.tsx:17`).
  - 하단 고지 6항 중 3항을 한 항목으로 합치는 작업(`src/features/lotto/shared/components/footer-notice.component.tsx`).
  - 6개 화면의 화면 설명 문장 3곳(생성기, 분석, 시뮬레이터)과 생성기 고급 옵션 소개 문장 1곳.
- 제외:
  - 메타데이터(title, description, keywords, OG, canonical)와 JSON-LD FAQ. `docs/lotto-notice/plan.md`의 제외 항목을 그대로 따른다.
  - 경고 알림(`warning-alert.component.tsx`)과 성인 확인 팝업(`age-gate-dialog.component.tsx`)의 문구. 법적 필수이므로 바꾸지 않는다.
  - 기능 라벨, 버튼, 빈 상태, 검증 메시지. 기능 문구이므로 바꾸지 않는다.
  - 공유 카드 문구(`src/features/lotto/constants/lotto-share.constant.ts`)와 API 문서 문구. 6개 화면 밖이다.
  - 페이지 구조(h1 개수), 푸터 디자인, 광고 배치, 로직, 법률 검토 자체.
  - `/lotto` 허브와 `/lotto/[draw]`는 레이아웃 공통 블록만 영향을 받으며 별도 문구 작업은 없다.

## 유저 스토리

- US-1: 로또 이용자로서, 화면마다 같은 경고를 반복해서 읽지 않고 싶다. 왜냐하면 번호 생성, 채점, 분석 결과를 볼 때 필요한 정보가 먼저 보이기를 원하기 때문이다. 다만 만 19세 제한과 "당첨을 보장하지 않습니다"는 어느 화면에서든 계속 확인할 수 있어야 한다.

## 법적·검색 관찰 (이번 범위 밖)

- FAQPage JSON-LD (M-1~M-4): 생성기, 분석, 시뮬레이터, 나의 번호의 페이지 소스에 FAQPage 구조화 데이터가 있다. audit 3.20에 따르면 화면에 보이는 FAQ는 없다. 검색 엔진은 보이지 않는 내용을 구조화 데이터로 두는 것을 권장하지 않는다. 이번에 이 점을 직접 검증하지 않았다.
- 화면 설명에서 "당첨을 보장하지 않습니다"를 지우면, JSON-LD 답변에는 그 문장이 그대로 남는다. 화면과 구조화 데이터의 차이가 조금 커진다. 이 항목은 이번 범위 밖이며 따로 다룬다.

## 열린 질문

- Q1 (승인 A): 화면 설명 3곳(생성기, 분석, 시뮬레이터)에서 "당첨을 보장하지 않습니다"를 지우는 것을 승인하는가. 지우면 하단에만 남고 상단 노출이 줄어든다. 상단 노출이 필요하면 D-5~D-7은 취소한다. lotto-notice Q3과 함께 결정한다.
