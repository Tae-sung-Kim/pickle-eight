# 운세 문구 작성·검수 이력

이 문서는 운세 문구 풀(개인 일운, 공통, 띠, 별자리)의 작성자, 작성일, 검수 상태를 기록한다. 형식은 `docs/tarot/copy-log.md`를 따른다. 작성 이력은 문구 데이터에 넣지 않고 이 문서에만 둔다.

## AI 생성 지침 (plan "콘텐츠 제작 원칙")

1. 카드 의미·십신 관계·오행 상생상극·절기처럼 이론 수준의 아이디어만 바탕으로 처음부터 새로 쓴다.
2. 작성 중에는 타 사이트·책·앱·언론사 운세의 풀이 문장을 보지 않고, 웹에서 풀이 문장을 찾아 참조하지 않으며, 그런 문장을 AI 입력으로 붙여 넣지 않는다.
3. 번역, 어순 변경, 일부 단어 교체로 만든 문장을 쓰지 않는다. 개발 가이드의 예시 문장(6.1의 분위기 예시, 9.3의 요약 문장)도 그대로 쓰지 않는다.
4. 정해진 구조(조건별 묶음, 점수 구간, 변형 수)대로 쓰고, 문장 끝이 반복되지 않게 변주한다.
5. 합니다체와 "금지 표현 목록", "문구 안전 원칙", "용어 사용 규칙: 사주"를 따른다. 건강·재물·애정 문구의 제한을 따른다.
6. 묶음마다 작성 주체(AI), 작성일을 기록한다.

## 톤 (C-1 초안 기준, U-2 검수에서 확정)

- 합니다체. 문장 끝은 "~일 수 있습니다", "~해 보시기 바랍니다", "~해 보는 것도 방법입니다", "~하는 편이 좋겠습니다", "~도움이 됩니다", "~입니다"를 섞어 변주한다. 해요체와 "게 됩니다" 계열은 쓰지 않는다.
- 항목 본문은 두 문장이다. 앞 문장은 그날의 흐름, 뒤 문장은 행동 제안이다. 낮은 구간도 행동 제안(휴식, 정리, 확인, 미루기)으로 끝낸다.
- 재물은 지출 점검·기록·정리만 쓴다. 투자, 주식, 코인, 복권, 도박, 대출, 부동산을 쓰지 않는다.
- 건강은 휴식, 수면, 식사 시간, 가벼운 움직임 같은 생활 리듬만 쓴다. 병명, 증상, 약을 쓰지 않는다.
- 공통 풀(요약·조언·주의)은 한 문장이다. 방식 A·B가 같이 쓰므로 띠·별자리·개인 특성을 넣지 않는다.
- 띠 풀은 쥐의 이미지(재치, 눈치, 부지런함, 꼼꼼함)를, 별자리 풀은 양자리의 이미지(추진력, 솔직함, 의욕, 성급함)를 성향 수준으로만 쓴다. 한 문장으로 성격을 단정하지 않는다.
- "사주"라는 단어를 방식 A 풀에 쓰지 않는다.
- 검수 중 바뀐 톤은 이 절에 날짜와 함께 덧붙인다.

## 웹 검색 샘플 확인 기록

C-4에서 완성된 문구의 대표 문장을 웹 검색해 같은 문구가 있는지 확인한다(researcher). 샘플 규모는 묶음(개인·띠·별자리)별 20문장 이상, 공통 풀 10문장 이상, 고지·FAQ·가이드 10문장 이상이다(U-4 제안값). 같거나 거의 같은 문장이 나오면 C-5(frontend-dev)가 새로 쓰고 아래 표의 해당 칸에 "수정함"으로 남긴다. 전수 검사가 아니며 한계를 확인 범위에 적는다.

C-1 시점과 C-3c 시점에는 확인하지 않았다. 작성 중에는 웹 검색 도구와 외부 문장 참조를 쓰지 않았다. C-4는 2026-11-06에 researcher가 수행했다. 이 점검에서는 일치가 나와도 문구 파일을 고치지 않고 기록만 했다. 수정은 C-5에서 한다.

### 방법

- 문장 전체 또는 특징적인 어구(약 15~25자)를 큰따옴표로 감싸 검색 도구(WebSearch)로 문장마다 1회 검색했다. 한 문장을 어구 하나로만 검색했다.
- 결과로 나온 페이지의 제목과 요약에서 같거나 거의 같은 문장이 있는지만 판단했다. 외부 사이트의 문장은 이 문서에 옮겨 적지 않았다. 일치가 나온 경우에만 출처 URL과 "일치 있음"을 적었다.
- 판정은 세 가지다.
  - 일치 없음: 같거나 비슷한 문장이 결과에 없다.
  - 일치 없음(일반 어구): 운세·건강·재물 글에서 흔한 어구나 같은 뜻의 설명이 부분적으로 나올 뿐 문장 전체는 같지 않다.
  - 일치 있음: 같거나 거의 같은 문장이 있다. C-5에서 새로 쓴다.
- 판정이 애매한 곳은 해당 페이지를 직접 열어 확인했다. 확인한 곳은 세 군데이다. C03(한국경제 기사), 운세 고지문 계열 N01·N02(운세미 이용약관), N12(운세 기사의 행운 숫자 고지)이다. N03(허브 FAQ)은 페이지를 열어 확인하지 않았고 검색 결과의 제목과 요약으로만 판정했다(C-5에서 바로잡음, 2026-11-06).

### 한계 (AC-41)

- 검색 엔진의 따옴표 검색은 정확 일치를 보장하지 않는다. 이번에 쓴 도구는 결과 상위 약 10건의 제목과 요약만 보여 주고 페이지 본문 전체를 읽지 않는다. "일치 없음"은 "없다"가 아니라 "이번 검색에서 찾지 못했다"는 뜻이다. 한 문장당 검색 1회라서 놓친 일치가 있을 수 있다.
- 샘플은 전체의 일부다. 문구 전체 1152문장(풀)과 가이드·FAQ·C-3d 131문장 가운데 98문장(약 8%)을 확인했고, 나머지는 확인하지 않았다. 입력 오류·지원 범위·윤달 안내(C-3d 묶음)는 이번 샘플에 넣지 않았다.
- 뉴스·블로그·SNS 일부, 앱 내부 화면, 책, 로그인이나 유료 뒤에 있는 풀이 문장은 검색에 잡히지 않는다.
- 판정은 사람이 읽고 한 것이 아니라 한 명(researcher)이 검색 결과 요약을 보고 한 것이다. 요약이 틀렸을 수 있어, 일치 가능성이 있다고 느낀 건만 페이지를 직접 확인했다.
- 일반 어구 판정(19건)은 문장 전체가 같지 않다는 뜻이다. 의미가 비슷한 풀이는 사람이 읽어야 걸러진다.
