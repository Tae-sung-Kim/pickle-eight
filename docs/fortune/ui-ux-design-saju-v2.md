### 0.2 사용자 선택이 필요한 항목

| 번호 | 질문 | 추천 | 대안 |
|---|---|---|---|
| UD-1 | 결과가 나올 때 기둥 표 칸에 모션을 넣을지 | 빼는 안: 기둥 표는 움직임 없이 바로 보인다. 움직임은 기존 M1(점수 눈금) 하나만 둔다 | 넣는 안: 연주 → 월주 → 일주 → 시주 칸이 40ms 간격으로 투명도 0 → 1(칸당 150ms, 합 약 270ms, framer-motion). 장점은 "기둥을 하나씩 세운다"는 이 기능의 첫인상을 준다는 것이다. 단점은 바로 아래 M1 눈금과 한 화면에서 경쟁하고, 시간·후보를 바꿀 때마다 반복되며, 기둥 표는 사실 데이터라 연출이 필요 없다는 것이다 |

## 1. 디자인 방향 (변경 없음, 사주의 개성 위치만 정한다)

한 줄 요약: **기존 "하루치 관측 기록지"를 그대로 쓰고, 사주의 개성은 연·월·일·시 기둥 표 한 곳에만 둔다.**

- 이유: 사이트·운세 전체 일관성이 우선이다(design-system). 기둥 표는 이미 승인된 사주 고유 화면이고, 기록지의 "대장 표" 모양과 맞는다.
- 그 밖의 모든 요소(패널, 버튼, 입력, 고지, 결과 기록표, 점수 눈금)는 기존 운세 페이지와 같다.
- 쓰지 않는 것(기존 규칙 유지): 음양 태극, 부적, 금박, 별 가루, 오행 색, 기둥을 세우는 그림. 이유: 점술집 분위기를 피하고, 오행 색은 로또 공 색과 겹친다.
- 십신 이름의 한자는 표시한다(正財 등). 이유: 기둥 표가 한글 + 한자를 함께 보이므로 같은 규칙이어야 한다. `aria-hidden`.

기존 표를 그대로 쓴다. 새 토큰 없음. 사주에서 추가로 쓰는 곳만 적는다.

| 오행 눈금 채운 칸 | `bg-menu-fortune` (card 위 비텍스트 대비 약 5.2:1) | 메뉴 색의 "일러스트" 용도 |

## 3. 타이포그래피·간격

기존 표를 그대로 쓴다. 추가·변경만 적는다.

| 요소 | 값 | 이유 |
|---|---|---|
| 기둥 표 칸 한글 / 한자 | 기존(700 `text-3xl` / 400 `text-xl`) | 변경 없음 |
| 일진 비교 칸 값 | 한글 700 `text-2xl`, 한자 400 `text-lg text-muted-foreground`, `leading-none` | 기둥 표보다 한 단계 작게 해서 표가 위계에서 앞선다 |
| 일진 비교 칸 라벨 | `text-xs text-muted-foreground`(card 위 5.4:1) | 기둥 표 행 머리와 같음 |

| 오행 이름·개수 | 이름 500 `text-sm`, 개수 700 `text-lg tabular-nums` | 개수가 읽는 정보 |

간격: 패널 안 블록 사이 `space-y-8`, 블록 구분은 `border-t border-border pt-8`(기존 폼-결과 구분과 같음). 한자는 시스템 글꼴로 대체되므로 `font-normal`(기존 유지).

## 4. 화면별 레이아웃

사주 페이지 전체 순서는 기존 공통 틀과 같다(h1 → 상시 면책 → 입력 안내 → noscript → [게이트 패널] → 하단 면책·상담전화 → 가이드 → 계산 기준 → FAQ → 이용 안내 → 동의 다시 설정). 사주는 "오늘의 운세 링크"(띠별·별자리용)가 없다. 계산 기준 h2에 `id`(앵커)를 둔다.

### 4.1 입력 단계 1: 생년월일 (step input)

- 패널 h2 "생년월일 입력", 구성은 기존 "입력" 절의 모바일·데스크톱 레이아웃과 같다(달력 → 연·월·일 → 윤달). 버튼은 "생년월일 확인"(`h-11`, 전체 폭은 모바일만).
- 동의 직후 포커스는 이 h2로 간다(기존 키보드 절의 "생년월일과 태어난 시간" → "생년월일 입력").
- 오류(빈 칸, 범위 밖, `out-of-table`)는 기존 날짜 오류 줄을 그대로 쓴다. 이유: 날짜 판정은 사주 전용 규칙이 없다.
- 연령 미달(step age-blocked): 기존 `FortuneAgeBlockedComponent` 그대로. 입력값은 비우고(AC-47) 시간 단계는 나오지 않는다.

### 4.2 입력 단계 2: 태어난 시간 (step time)

```
모바일                                     데스크톱 (md 이상)
┌ 패널 ─────────────────────────┐          ┌ 패널 ─────────────────────────────┐
│ 생년월일 입력 (폼, 값 유지)    │          │ 생년월일 입력 (한 줄 폼, 값 유지)  │
│ [ 생년월일 확인 ] ← outline    │          │ ───────────────────────────────── │
│ ───────────────────────────── │          │ 태어난 시간                  h3   │
│ 태어난 시간                h3 │          │ 양력 1990년 6월 15일 기준         │
│ 양력 1990년 6월 15일 기준      │          │ 시주를 구하려면 …(max-w-[68ch])   │
│ 시주를 구하려면 …              │          │ 시 [ ]  분 [ ]                    │
│ 시 [ ]   분 [ ]                │          │ [ 사주 보기 ] [ 시간 모름 ]       │
│ [      사주 보기      ]        │          │ 계산 기준 보기                    │
│ [      시간 모름      ]        │          └───────────────────────────────────┘
│ 계산 기준 보기                 │
└───────────────────────────────┘
```

- 위치: 날짜 폼 아래에 이어 붙는다(UD-3 안 A). 폼과 값은 남는다. 단계 구분은 `border-t border-border pt-8 mt-8`. 이유: 기존 시각 질문과 같은 방식이라 학습 비용이 없다.
- h3 "태어난 시간"은 `tabIndex={-1}`로 나타나자마자 포커스를 받고 화면 밖이면 스크롤한다(기존 규칙).
- 입력 요약 줄(0.3 요청): 상태의 `solar` 기준. 음력으로 입력했으면 기존 음력 확인 줄(`FortuneLunarConfirmComponent`)이 그 자리를 대신한다.
- 시·분: 기존 `FortuneBirthTimeFormComponent`(`inputMode="numeric"`, 각 `w-16`, 보이는 라벨 "시", "분"). 24시간 형식 안내는 help 문구에 포함.
- 버튼: "사주 보기"(주요), "시간 모름"(outline). 모바일은 전체 폭 두 줄, sm 이상은 한 줄 `gap-3`. 같은 크기, `min-h-11`.
- "계산 기준 보기": 링크 모양, `min-h-11`, 계산 기준 h2 앵커로 이동한다(이동 뒤 해당 h2로 포커스). 이유: 23시대 출생·시주 경계처럼 결과가 만세력마다 다른 사람이 입력 전에 이 서비스의 기준을 볼 수 있어야 한다(AC-56).
- 날짜 칸을 고치고 "생년월일 확인"을 다시 누르면 상태가 새 날짜로 시간 단계에서 다시 시작한다(결과가 있었다면 사라진다). 고치기만 하고 누르지 않으면 요약 줄 덕분에 이전 날짜 기준임이 보인다.
- 시·분 오류(형식·범위)는 입력 보조 아래 한 줄, `text-destructive` + 아이콘 + 글자. 첫 `aria-invalid` 칸으로 포커스.
- 오늘 날짜에 현재보다 늦은 시각은 막지 않는다(S2-9). 막는 안내를 만들지 않는다.

### 4.3 경계일 + 시간 모름 (step choose)

```
┌ 선택 면 ────────────────────────────────┐
│ 양력 2025년 2월 3일 기준                 │
│ 이 날은 입춘이 드는 날이라 태어난 시간을 │ ← FORTUNE_SAJU_BOUNDARY_NOTICE_TEMPLATE
│ 모르면 연주와 월주를 하나로 정할 수 없…  │
│ [ 연주 갑진으로 보기 ][ 연주 을사로 보기 ]│ ← aria-pressed, 같은 크기
└─────────────────────────────────────────┘
```

- 기존 "후보 선택" 규칙 그대로: 같은 크기, 미리 선택·추천·정답 표시 없음, 순서는 절기 전(`charts[0]`) → 절기 후(`charts[1]`).
- 라벨: `boundary.kind`가 `year`(입춘)면 "연주 {간지}로 보기", `month`면 "월주 {간지}로 보기". 두 버튼의 라벨에 간지가 들어 있어 두 경우가 한 화면에 함께 보인다(AC-51, AC-53). 모바일 두 줄 전체 폭, sm 이상 한 줄 `grid-cols-2 gap-3`.
- 안내의 절기 이름·"연주와 월주"/"월주"는 템플릿 값이다.
- 고르면 아래에 결과 블록이 나오고, 버튼은 남아 다른 쪽으로 바꿀 수 있다(바꾸면 결과 블록 값이 바뀐다). 진입 시 포커스는 첫 후보 버튼.
- 이 단계가 나오는 조건: 경계일 + "시간 모름". 시간을 입력한 경계일은 분 단위 비교로 후보 없이 결과가 나온다.

데스크톱 (md 이상)

```
│ 연·월·일·시 기둥                         양력 1990년 6월 15일 기준 │
│ ┌ 기둥 표 (max-w-lg) ────────┐ │ 오행 분포                       │
│ │ 연주 월주 일주 시주        │ │ 목 0 ▭▭▭▭▭▭▭▭                  │
│ │ …                          │ │ 화 3 ▮▮▮▭▭▭▭▭ …                │
│ └────────────────────────────┘ │ 표에 보이는 글자의 …            │
│ 3기둥 안내 / 표준시 안내       │                                  │
│ ───────────────────────────────────────────────────────────────── │
│ 오늘 일진과 내 일간                                                │
│ [오늘 일진 계미 癸未] [내 일간 무 戊] [십신 정재 正財]  (grid-cols-3)│
│ 십신 한 줄 설명                                                    │
```

- 제목 줄: h2 + 입력 요약 줄. md 이상 `md:flex md:items-baseline md:justify-between`(기존 "오늘의 결과" 제목 줄과 같다). 음력 입력이면 요약 줄 대신 음력 확인 줄.
- 블록 상단 2열: `md:grid md:grid-cols-[minmax(0,32rem)_minmax(0,1fr)] md:gap-x-10`. 이유: 폼이 한 열(`max-w-4xl`)이라 기둥 표 옆이 비게 되는 것을 오행 분포로 채운다. 두 열은 같은 데이터(표에 보이는 글자)를 요약하므로 같이 읽는다.
- 기둥 표 규칙은 기존 사주 절을 따른다(`table-fixed`, `caption` sr-only "연·월·일·시 기둥", 열 머리 연주 → 월주 → 일주 → 시주, 일간 `border-2 border-menu-fortune` + "일간" 글자, 한자 `aria-hidden`). 달라지는 점:
  - 모바일 칸 폭이 약 60px(360px 화면, 행 머리 열 `w-12`)이므로 칸 `p-2`, 시간 모름 칸의 글자는 두 줄("시간 / 모름")을 허용한다(`break-keep`). 한자는 모바일에서 한글 아래, sm 이상에서 같은 줄(기존).
  - 표 아래 안내는 해당할 때만, 순서는 (1) 시간 모름이면 `FORTUNE_SAJU_TIME_UNKNOWN_NOTICE`(3기둥 안내), (2) 1948~1961·1987~1988년 + 시간 입력이면 `FORTUNE_DST_NOTICE`. 둘은 동시에 나오지 않는다(시간 모름이면 표준시 안내가 없다, AC-57). `text-sm leading-6 text-muted-foreground`, 표 바로 아래 `mt-3`.
- 오행 분포: `<section aria-labelledby>` + h3 + `<dl>` 5행(목, 화, 토, 금, 수). 행은 `grid grid-cols-[2rem_1.75rem_1fr] items-center gap-x-3 py-1.5`: 이름(`dt`), 개수(`dd`), 눈금(`aria-hidden`).
  - 눈금 칸 수 = 표에 보이는 글자 수(4기둥 8칸, 3기둥 6칸). 칸 `h-3 w-4 rounded-sm`, 칸 사이 `gap-1`. 채운 칸 `bg-menu-fortune`, 빈 칸 `border border-border`. 8칸 폭은 약 156px이라 360px 화면에도 들어간다.
  - 개수 0은 "0"과 빈 칸만. 많고 적음에 평가 말(좋음·부족·과다)을 붙이지 않는다(S2-5, 오행 색 없음 유지).
  - 안내 `FORTUNE_SAJU_ELEMENTS_NOTE`는 눈금 아래 `text-sm leading-6 text-muted-foreground`.
  - 이유(변경): 기존 가로 5칸에 막대 최대 8개는 모바일에서 넘친다. 행으로 두면 눈금 칸 수가 같아 항목끼리 개수를 위아래로 비교하기 쉽고, 점수 눈금과 같은 "눈금자" 언어다.
- 일진 비교(h3 "오늘 일진과 내 일간"): `<dl>`. 값은 기둥 표 칸과 같은 모양.
  - 모바일: 세 행, 행마다 `dt`(라벨) 왼쪽 + `dd`(값) 오른쪽(`flex justify-between border-t border-border py-3`). 칸 상자 없이 기록표 행으로 둔다. 이유: 좁은 폭에서 상자 3개는 값이 줄바꿈된다.
  - md 이상: `grid grid-cols-3 gap-3`, 칸 `rounded-md border p-3 text-center`. 내 일간 칸만 `border-2 border-menu-fortune`.
  - 십신 값: 이름 700 `text-2xl` + 한자 `text-lg text-muted-foreground aria-hidden`. 지지 음양·지지 십신은 표시하지 않는다(AC-55).
  - 오늘 일진 날짜는 이 블록에 따로 적지 않는다. 아래 "오늘의 결과" 제목 줄의 기준 날짜(한국 시간)가 같은 날짜다.
- 십신 한 줄 설명(`FORTUNE_SAJU_TEN_GOD_DESCRIPTIONS`)은 비교 아래 단락. 길흉 단정·불안 표현 없음(문구 담당 규칙).
- 아래 블록 "오늘의 결과"는 기존 명세(기록표, 점수 눈금, 방식 B 안내, 점수 안내, 행운 요소, 로또 고지)를 그대로 쓴다. 사주 결과에는 "다른 기준의 운세" 링크가 없다(S2-7).
- 결과 뒤에도 폼·시간 단계·후보 버튼이 남는다. "시간 모름"으로 본 뒤 시간을 넣고 싶으면 시·분을 채워 "사주 보기"를 다시 누른다(상태 `time` 단계에서 `SUBMIT_TIME`).

## 5. 계산 기준 영역 (서버, `FortuneCalcBasisComponent`)

- h2 "계산 기준" + `id`, 글머리 목록(`list-disc pl-5 space-y-1 text-sm leading-7`), 문장 `max-w-[68ch]`. 기존 계산 기준 모양과 같다.
- 항목 순서(확정, V3.1): 연주·월주 기준 → 일주·시주(23:00~23:59 포함) → 23시대 학설 → 자시 시작 23:00 → 보정 안 함 → 시간 모름 → 학파별 기준 선언 → 지원 범위(마지막, 컴포넌트가 붙임). 이유: 23시대 처리 셋(일주·시주, 학설, 자시 시작)이 붙어 있어야 다른 만세력과 비교하는 사람이 한 곳에서 읽는다.
- 소제목(h3)은 두지 않는다. 이유: 항목이 7개이고 기존 페이지의 계산 기준과 같은 모양을 유지한다. 길어서 읽기 힘들다는 의견이 나오면 3묶음(기둥 나누기 / 23시대 출생 / 입력과 보정)으로 나누는 안을 나중에 올린다.
- 용어: "23:00~23:59"를 먼저 쓰고 "야자시"는 괄호로 한 번만 쓴다. "정자시", "정통", "정확한"은 쓰지 않는다(S2-3). 문장 본문은 C-S3.
- 앵커로 들어온 사용자를 위해 h2에 `scroll-mt-24`(기존 `scroll-mb-48` 규칙과 같은 목적, 고정 헤더에 가리지 않게).
- 상태: 서버 HTML이라 로딩·에러·빈 상태 없음. JS를 꺼도 보인다(AC-56).

## 6. 허브 갱신 (`/fortune`)

기존 허브 절에서 바뀌는 곳만 적는다. 코드(`hub/components/root.component.tsx`)는 바꾸지 않는다(design-saju-v2 V8.1).

```
운세 고르기 (h2)
[★] 오늘의 운세
[발] 띠별 운세
[망] 별자리 운세
[기록] 사주                    ← 새 네 번째 행, 같은 모양
    태어난 연·월·일·시로 기둥을 세우고 오늘의 일진과 비교.
운세 종류와 차이 (h2)           ← 제목 개정(초안)
  단락 1  개수 표현 없이 운세 소개 ("사주" 없음)
  단락 2  방식 구분(사주 괄호 설명 포함, 화이트리스트 문장)
  단락 3~4 기존 그대로
  단락 5  사주 소개(첫 "사주"에 괄호 설명)       ← 새 단락
자주 묻는 질문 (h2) 7쌍
  … 기존 6쌍 …
  7. 사주는 다른 운세와 무엇이 다른가요?       ← 새 질문, 맨 끝
```

- 사주 행: `MenuListComponent` 그대로(아이콘 칸 `bg-secondary text-primary`). 배지·"NEW"·강조 색을 붙이지 않는다. 이유: 네 번째 운세도 같은 도구 목록의 한 줄이고, 눈에 띄게 하는 것은 기존 규칙(메뉴마다 같은 체계)과 어긋난다. `example`은 목록에 나오지 않는다(기존 동작).
- 모바일·데스크톱 모두 한 열 유지(4개여도 2열·카드 격자를 만들지 않는다, 기존 이유 그대로).
- 사주 소개 단락 위치는 방식 구분 단락 바로 뒤. 이유: 방식 A 세 운세와 사주의 차이를 읽고 바로 사주가 무엇인지 이어서 읽는다. 단락 수가 5개가 되어도 하위 제목은 두지 않는다(기존 이유 그대로). 약 600자 이상 조건은 유지.
- FAQ 새 질문은 맨 끝에 둔다. 이유: 기존 질문 번호·순서(JSON-LD 포함)를 바꾸지 않는다.
- 허브 접근성: h2 4개(운세 고르기, 운세 종류와 차이, 자주 묻는 질문, 이용 안내)와 링크 4행. PC 탭 정지는 목록 4행. 대비·모션은 기존 허브 절과 같고 새 모션 없음.
- 오늘의 운세·띠별·별자리 페이지는 바꾸지 않고 사주 링크를 넣지 않는다.

## 8. 인터랙션·애니메이션

넣지 않는 모션(확정, 이유)
- 시간 단계·선택 면·결과 블록의 등장(펼침·슬라이드): 단계가 바뀐 것은 h3 포커스와 스크롤로 알린다. 한 화면에서 M1과 경쟁하는 움직임을 늘리지 않는다.
- 오행 눈금 채우기, 일진 비교 칸 강조, 십신 바뀔 때 효과: 꾸밈뿐이고 사실 데이터다.
- 후보 버튼 선택 효과, 계산 기준 링크의 hover 전환, 허브의 사주 행 새 효과: 기존 규칙과 같이 움직임 없음. 앵커 스크롤은 `prefers-reduced-motion`이면 `behavior: 'auto'`.
- 점수 숫자 세어 올리기: 기존 이유 그대로.

## 9. 접근성

- 명도 대비: 새 글자 색 조합이 없다. 기존 값을 그대로 쓴다(`foreground` 11.8/12.6, `muted-foreground` card 5.4·종이 5.0, `primary` 링크 5.6/6.0, `menu-fortune` 면 5.2). 일진 비교 칸 라벨·한자는 card/종이 위 `muted-foreground`(5.0 이상). 오행 채운 칸 `menu-fortune`은 비텍스트라 3:1 이상이고 개수 숫자가 정보를 전한다.
- 색만으로 알리지 않는다: 내 일간 칸은 테두리 + 라벨 "내 일간", 기둥 표 일간은 "일간" 글자, 오행은 숫자 + 눈금, 후보는 `aria-pressed` + 테두리.
- 키보드 순서(시각 순서 = DOM 순서, CSS `order` 없음):
  1. 양력/음력 → 연도 → 월 → 일 → (윤달) → "생년월일 확인"
  2. 연령 통과: 포커스가 시간 h3로 이동 → 시 → 분 → "사주 보기" → "시간 모름" → "계산 기준 보기"
  3. 경계일 + 시간 모름: 포커스가 첫 후보 버튼 → 둘째 후보 버튼(`role="group" aria-labelledby={경계 안내 id}`)
  4. 결과: 포커스가 결과 h2 "연·월·일·시 기둥"(`tabIndex=-1`) → 이후 탭은 결과 안의 링크·버튼(행운 요소의 로또 링크)
  5. 연령 안내: 그 h2(기존)
- 오류: 날짜·시간 오류는 기존대로 첫 `aria-invalid` 칸으로 포커스, 오류 문구는 `aria-live="polite"`로 한 번 읽힘. 오류 문구에 입력값을 넣지 않는다.
- 라벨: 기둥 표 `caption` "연·월·일·시 기둥", `th scope`, 한자 `aria-hidden`. 오행 `<dl>`의 눈금 `aria-hidden`("화 3"이 읽힘). 일진 비교는 `<dl>`(라벨 `dt`, 값 `dd`), 한자 `aria-hidden`. 입력 요약 줄은 일반 텍스트. 기능 영역 `aria-live="polite"` 하나가 결과가 나오면 결과 공지(`FORTUNE_SAJU_PANEL_TEXTS`)를 한 번 읽는다.
- 터치 영역 44px 이상(버튼, 후보 버튼, 계산 기준 링크 `min-h-11`).
- 확대 200%: 기둥 표는 5열 `table-fixed`가 좁아지면 칸 안 한자가 한글 아래로 내려가고 "시간 모름"이 두 줄이 된다. 일진 비교는 모바일 행 형태라 영향이 없다. 오행 눈금 8칸(약 156px)은 `flex-wrap`을 쓰지 않고 칸 폭을 `w-3`으로 줄이는 한이 있어도 한 줄을 유지한다(칸 수가 개수 의미라서 줄이 갈리면 읽기 어렵다).
- 동작 줄이기: 8장 표대로.

## 10. 문구 처리

- 새로 쓴 화면 문장은 위 초안 몇 개뿐이고 모두 상수로 둔다(0.3). 컴포넌트에 문자열을 하드코딩하지 않는다(V10.1).
- "사주 네 기둥", "사주 4기둥", "정자시", "same-day", "next-day", "정확한", "AI"는 어디에도 쓰지 않았다. 패널 제목은 "연·월·일·시 기둥"(plan 규칙의 후속 표기), h1 "사주"와 설명(괄호 설명 포함)은 기존 승인 문구 그대로.
- 허브 개정 문장(제목, 단락 1·2, 사주 소개, FAQ 7)은 C-S3 작성 + 사용자 승인 후 화이트리스트에 등록한다(V8.2).

## 11. 기존 문서 충돌 정리

- 기존 사주 절의 입력 스케치(한 폼에 시·분·"태어난 시간 모름"·"사주 보기")와 키보드 순서 "일 → (윤달) → 시 → 분 → 태어난 시간 모름 → 사주 보기"는 이 문서 4.1~4.2로 대체한다.
- 기존 컴포넌트 상태 표 "시·분 입력 … 태어난 시간 모름 체크 시 disabled" 행은 사주에 적용하지 않는다(체크박스 없음). 띠·별자리 찾기의 시각 질문은 기존 그대로다.
- 기존 허브 절의 "세 가지 운세의 차이", "6쌍", "운세 그룹 항목 3개", 목록 순서 "오늘의 운세 → 띠별 → 별자리"는 출시 상태에서 6장으로 대체된다. 출시 전(`MENU_LIST`에 사주 없음)에는 기존 허브 절이 그대로 유효하다.
- 기존 키보드 절 "동의 성공 → 첫 h2 '생년월일과 태어난 시간'"은 사주에 한해 "생년월일 입력"으로 바뀐다.
