# 달력·절기 표 검증 기록 (BE-1c)

## 기본 정보

- 조회일: 2026-11-05 (표 생성과 대조 모두 이날 실행)
- 사용한 API (한국천문연구원 KASI, 공공데이터포털 Open API)
  - 절기 표 생성: 특일 정보 `SpcdeInfoService/get24DivisionsInfo`
  - 음력 표 생성: 음양력 정보 `LrsrCldInfoService/getSolCalInfo` (음력 → 양력)
  - 표 대조(생성과 다른 방향): 음양력 정보 `LrsrCldInfoService/getLunCalInfo` (양력 → 음력)
- 인증키는 이 문서와 저장소 어디에도 적지 않는다. 키는 사용자가 PowerShell 세션 환경변수로만 사용했다.
- 실행 스크립트: `scripts/fortune-calendar/generate.mjs`(표 생성), `scripts/fortune-calendar/verify.mjs`(대조). 대조 결과 원본은 `scripts/fortune-calendar/verify-result.json`.

## 양력→음력 무작위 대조 (verify.mjs)

양력 날짜를 표로 음력 변환한 값(음력 연·월·일과 윤달 여부)을 `getLunCalInfo` 응답과 비교했다.

| 항목 | 결과 |
|---|---|
| 표본 수 | 80건 (기준 60건 이상 충족) |
| 일치 | 80건 |
| 불일치 | 0건 |
| 스크립트 내장 알려진 값 불일치 | 0건 |
| API 호출 | 80회 |
| 난수 시드 | 737602826 (같은 시드로 다시 실행 가능) |

표본 구성

- 경계일 6건: 1920-01-01, 1920-02-05, 2000-02-05, 2025-01-29, 2026-02-04, 2028-12-31
- 윤달 구간 지정 표본 7건 (기준 6건 이상 충족): 1922-07-22, 1949-09-16, 1957-10-11, 1968-08-24, 1971-07-13, 1993-05-09, 2023-04-15. 무작위 표본 중 윤달에 해당한 1건을 더하면 윤달 표본은 모두 8건이고 전부 일치했다.
- 무작위 67건: 1920~2028년 사이에서 뽑았다.

각 표본에는 같은 응답의 일진(`lunIljin`)과 세차(`lunSecha`)가 함께 저장되어 있다. 2단계 사주의 일주 검증 자료로 쓴다. 월건(`lunWolgeon`)은 음력월 기준이라 절기 월주와 다를 수 있어 비교에 쓰지 않는다.

## 알려진 값 대조 9건 (표 파일에서 직접 확인)

표 파일을 직접 읽어 확인했다. 절기 값은 `월일 × 10000 + 시분`이다. 음력 표는 `newYear`(음력 1월 1일의 양력 MMDD), `leapMonth`, `monthBits`를 본다.

| 번호 | 기대값 | 표의 값 | 결과 |
|---|---|---|---|
| 1 | 음력 2025-01-01 = 양력 2025-01-29 | 2025년 `newYear` 129 (1월 29일) | 일치 |
| 2 | 음력 2000-01-01 = 양력 2000-02-05 | 2000년 `newYear` 205 (2월 5일) | 일치 |
| 3 | 2025 입춘 02-03 23:10 | 2025년 인덱스 2 = 2032310 | 일치 |
| 4 | 2024 춘분 03-20 12:06 | 2024년 인덱스 5 = 3201206 | 일치 |
| 5 | 2025 춘분 03-20 18:01 | 2025년 인덱스 5 = 3201801 | 일치 |
| 6 | 2026 춘분 03-20 23:46 | 2026년 인덱스 5 = 3202346 | 일치 |
| 7 | 2027 춘분 03-21 05:25 | 2027년 인덱스 5 = 3210525 | 일치 |
| 8 | 1920 입춘 02-05 11:26 | 1920년 인덱스 2 = 2051126 | 일치 |
| 9 | 2026 입춘 02-04 05:02 | 2026년 인덱스 2 = 2040502 | 일치 |

9건 모두 일치, 불일치 0건. 추가로 `kasi-api-check.md`에 적힌 1950 입춘 02-04 18:21도 표에서 2041821로 일치함을 확인했다.

## 윤달 필드 확인

- 윤달이 있는 달을 `getSolCalInfo`로 물으면 평달과 윤달 두 건이 온다. 이를 구분하는 필드는 `lunLeapmonth`이고 값은 "평"과 "윤"이다. design.md 4.1에 적은 필드 이름과 값이 맞다.
- `generate.mjs`는 이 값이 "평"이나 "윤"이 아니면 멈추도록 되어 있고, 이번 생성은 멈추지 않고 끝났다. 따라서 모든 응답에서 이 필드가 기대대로 왔다.
- 무작위 대조에서도 윤달 표본의 표시(예: 1971-05-21 윤)가 API 응답과 표 계산이 모두 일치했다.
- 음력 2023년 윤2월 사례: 표의 2023년 행은 `leapMonth` 2, `newYear` 122(1월 22일), `monthBits` 2774이다. `leapMonth`가 2이므로 윤2월이 있는 해로 기록되어 있다. 양력 2023-04-15는 표와 API 모두 음력 2023-02-25(윤)로 일치했다. 윤달이 있는 달의 `getSolCalInfo` 응답이 2건(평달·윤달)이라는 `kasi-api-check.md`의 사전 확인과도 같다.

## KASI 데이터 특이점

- 1950년 대한: KASI 원본이 `locdate`=19500120, `kst`="2400"으로 온다. 같은 날의 끝 자정을 뜻하므로 다음 날(1월 21일) 00:00으로 정규화했다. 표 값은 1210000이다. 생성된 표 파일에서 1950년 인덱스 1(대한)을 직접 확인했고 1210000이 들어 있다. 같은 해 소한(1060639)과 입춘(2041821)은 정상 범위의 값이다. 정규화 코드는 `scripts/fortune-calendar/calendar-core.mjs`에 있고 정규화가 일어나면 생성 로그에 알린다. 그 밖의 범위 밖 시각은 오류로 멈춘다.
- 절기 응답의 `sunLongitude`는 비어 있어 쓰지 않고 `dateName`으로 인덱스를 정했다. `kst`는 끝 공백이 있어 trim한다(design.md 4.1).
- 시각은 모두 현재 한국 표준시(UTC+9) 기준으로 적혀 있고 1954-03-21~1961-08-09(UTC+8:30)와 서머타임 연도는 보정하지 않는다(plan 보정 4).

## 불일치 처리 규칙

- KASI 값을 정답으로 따른다. 표나 AC 사례와 KASI 값이 다르면 표를 KASI 값으로 맞추고, PM에게 알려 plan의 AC를 고치도록 요청한다.
- 이번 결과는 무작위 대조 불일치 0건, 알려진 값 불일치 0건이므로 처리할 항목이 없다.
- 이 대조는 표본(80건)과 알려진 값 대조이며 전체 표를 전수 검사한 것은 아니다. 표 전체의 구조 검사(연도 연속, 달 길이, 한 해 일수, 절기 간격 등)는 `e2e/fortune-calc.spec.ts`(design.md 17장)에서 한다.
