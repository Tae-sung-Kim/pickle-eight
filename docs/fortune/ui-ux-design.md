## 디자인 방향 (S1 A 확정)

한 줄 요약: **"하루치 관측 기록지"**. 운빨연구소가 매일 적는 관측 기록 한 장이다. 종이 위에 강황(`menu-fortune`) 잉크로 그은 눈금 위에 오늘의 점수를 표시하고, 항목은 기록표처럼 줄을 맞춰 적는다. 점술집, 부적, 금박, 별 가루, 음양 태극 같은 운세 기본값은 쓰지 않는다.

- 이유: 사이트 컨셉("운을 차분하게 관찰하는 연구실")과 점수 30~95라는 기능의 성격이 맞는다. 점수를 "적중률"이 아니라 "서비스 규칙으로 잰 눈금 위치"로 보이게 하면 점수 안내 문구("정확도를 뜻하지 않습니다")와 같은 말을 한다.
- 개성은 **점수 눈금 한 곳**에만 준다. 페이지 틀, 허브 목록, 버튼, 패널, 글자, 고지 상자는 타로·로또와 같은 공용 체계를 그대로 쓴다.
- 동의·이용 불가·연령 안내 화면은 개성을 주는 곳이 아니다. 서류 확인처럼 담담하게 둔다. 이유: 법적 확인 화면에 장식이 붙으면 놀이의 일부처럼 가볍게 읽힌다.
- 허브는 로또 허브와 같은 "도구 목록" 화면이다. 이유: 메뉴마다 다른 사이트처럼 보이면 안 된다(design-system). 눈금 그림은 허브에 넣지 않는다.
- 상담전화는 타로와 같은 기관·번호·설명 문구(D4 공용 상수)를 쓴다. 터치 기기에서는 타로와 같은 전화 링크로, PC에서는 링크 모양 없는 전화번호부 같은 텍스트로 보인다(S9). 상담전화에는 개성을 주지 않는다.

### 공통 규칙

- 왼쪽 정렬 본문. h1과 상시 면책만 가운데 정렬(공용 `TitleWrapperComponent`, 타로 면책 상자와 같음). 이유: 한국어 여러 줄은 가운데 정렬이 읽기 어렵다.
- 대문자 라벨, 제목 위 작은 머리 라벨, 제목 안 한 단어만 색 바꾸기, 링크 뒤 화살표(→), 가운뎃점으로 이은 메타 문자열은 쓰지 않는다.
- 01/02/03 같은 번호 표식을 쓰지 않는다. 동의 항목 3개도 순서가 있는 단계가 아니므로 번호 없이 둔다.
- 그림자를 쓰지 않는다. 면은 `background`(종이) → `card`(밝은 종이) → `muted`(옅은 녹색) 밝기 차이와 `border`로 나눈다.

## 간격·그리드

- 기본 단위 Tailwind 4px 눈금. 새 간격 토큰 없음.
- 본문 폭: 레이아웃 `max-w-7xl` 안에서 `mx-auto max-w-4xl px-4`(타로와 같음). 허브도 같은 폭.

- 기능 영역 패널: `rounded-panel border border-border bg-card p-5 sm:p-8`.
- 패널 안 하위 면(행운 요소, 찾기 면, 시각 질문): `rounded-lg border border-border bg-background p-4`.
- 반경 계층: 칩 `rounded-md`, 버튼·입력·동의 항목 행·하위 면·상시 면책 상자 `rounded-lg`, 패널·결과 하단 안내·이용 안내 상자 `rounded-panel`.

- 기록표 행 사이 `border-t border-border py-5`.
- 터치 영역: 버튼, 칩, 동의 항목 행, 라디오, 링크 모두 44px 이상(`h-11` / `min-h-11`). 인접 대상 사이 4px 이상. 상담전화는 터치 상태에서 링크라 이 규칙을 따른다(항목마다 `min-h-11`). PC 상태는 누르는 대상이 아니라 규칙 대상이 아니지만, 높이를 유지하기 위해 같은 `min-h-11`을 둔다("상담전화 기기별 표시" 절).
- 윤달 체크 줄: 라벨이 체크박스를 감싸 `inline-flex min-h-11 items-center gap-2`(터치 영역 44px). 날짜 칸 줄과 `gap-2`(모바일) 간격.

허브 접근성
- h1 하나(`TitleWrapperComponent`). h2 네 개(운세 고르기, 세 가지 운세의 차이, 자주 묻는 질문, 이용 안내) + 하단 고지 안의 제목 구조는 기능 페이지와 같다.
- 목록은 `MenuListComponent`의 `<ul>`·`<li>`·`<Link>`. 링크 이름은 항목 이름 + 설명(보이는 글자 그대로). `<ul aria-labelledby>`는 공용 컴포넌트에 props가 없으므로 붙이지 않는다. 대신 `<section aria-labelledby>`가 묶음 이름을 준다.
- 아이콘은 공용 컴포넌트에서 `aria-hidden`.
- 포커스: 공용 컴포넌트의 `focus-visible:outline-2 outline-ring`(행 전체 윤곽). 탭 정지는 PC에서 목록 3행, 터치 기기(외부 키보드·스위치 제어)에서 목록 3행 → 상담전화 5곳.
- 대비: 항목 이름 `foreground` 약 11.8:1, 설명 `muted-foreground` 약 5.0:1. hover 면(`secondary/70`) 위 설명은 약 4.4:1로 잠깐 내려가지만 공용 컴포넌트의 기존 값이고 로또 허브와 같다. 운세에서 따로 고치지 않는다(PM 참고 사항).
- 모션: 공용 컴포넌트의 hover `transition-colors`(기존)만 있다. 새 모션 없음.

### 공통 틀 (기능 페이지 네 개)

순서는 design.md 12.2 트리와 같다. **[서버]**는 동의와 관계없이 서버 HTML에 있는 영역, **[게이트]**는 동의 상태에 따라 클라이언트에서 바뀌는 영역이다.

```
[서버] h1 + 설명 (TitleWrapperComponent)
[서버] 상시 면책 상자
[서버] 입력 영역 안내 (개인정보 / 연령·책임)
[서버] <noscript> 안내
┌ [게이트] 기능 영역 패널 (card) ──────────────┐
│ checking  : 스켈레톤                          │
│ required  : 이용 동의 화면                    │
│ declined  : 이용 불가 화면                    │
│ granted   : 입력·선택·결과 (panel)            │
└──────────────────────────────────────────────┘
[서버] 결과 하단 면책 + 상담전화 5곳 (터치 기기 링크 / PC 텍스트)
[서버] 오늘의 운세 링크 (띠별·별자리만, D12)
[서버] 가이드
[서버] 계산 기준
[서버] 자주 묻는 질문
[서버] 이용 안내 (상세 9항)
[게이트] 동의 다시 설정 (granted일 때만)
```

- 시각 구분: 게이트 영역은 card 패널 하나이고, 서버 영역은 종이 바탕 위에 흐르는 글이다(고지 상자 둘만 테두리). 이유: 동의 전후로 바뀌는 곳이 패널 하나뿐이라 동의 화면이 "페이지를 막는 벽"이 아니라 "기능 자리의 한 단계"로 보인다(design.md 13.2).
- `checking` 스켈레톤은 동의 화면과 같은 높이 구성으로 그려 아래 서버 영역이 크게 밀리지 않게 한다.
- 이용 불가 화면과 연령 안내 화면 자체에는 상담전화를 따로 넣지 않는다. 패널 바로 아래의 결과 하단 상자(서버, 항상)가 그대로 보이므로 같은 번호가 한 화면에 두 번 나오지 않게 한다.
- 광고 요소를 추가하지 않는다.

### 이용 동의 화면 `FortuneConsentFormComponent` [게이트, required]

모바일

```

│ 이용 전 확인해 주세요              │ ← h2, tabIndex -1
│ 운세를 이용하시려면 아래 세 가지를 │ ← 안내, muted
│ 직접 확인해 주시기 바랍니다. …     │
│ ┌──────────────────────────────┐   │
│ │ [ ] 만 14세 이상입니다.      │   │ ← 행 전체가 label
│ └──────────────────────────────┘   │
│ ┌──────────────────────────────┐   │
│ │ [ ] 운세는 오락과 참고를 위한 │   │
│ │     것이며, 결과를 바탕으로 … │   │
│ └──────────────────────────────┘   │
│ ┌──────────────────────────────┐   │
│ │ [ ] 입력한 생년월일은 서버로  │   │

│     이용하실 수 있습니다.          │
│ [        동의하고 시작        ]    │ ← primary, 전체 폭
│ [        동의하지 않음        ]    │ ← outline, 같은 높이
│ 동의 여부와 동의한 안내문의 버전,  │ ← 보관 안내, text-xs muted
│ 동의 시각만 이 탭에 저장되며 …     │
└────────────────────────────────────┘
```

데스크톱 (sm 이상): 같은 순서, 버튼 두 개가 한 줄(`sm:flex-row sm:gap-3`).

- 내용 폭 `max-w-2xl`, 왼쪽 정렬.
- 항목 묶음: `<fieldset>` + `<legend className="sr-only">이용 전 확인 항목 세 가지</legend>`, 행 사이 `space-y-2`.
- 항목 행: `<label>`이 체크박스와 문장을 감싼다. `flex min-h-11 cursor-pointer items-start gap-3 rounded-lg border border-border bg-background px-4 py-3 has-[:checked]:border-primary has-[:checked]:bg-primary/5`. 체크박스 `size-5 mt-0.5 shrink-0 accent-primary`. `src/components/ui`에 Checkbox가 없고 새 radix 의존성을 들이지 않기 위해 네이티브 입력을 쓴다.
- 처음 표시와 "돌아가기"로 다시 올 때 세 항목은 모두 해제(AC-68). 폼 state가 화면 전환 때 새로 만들어져 따로 초기화하지 않는다.
- 버튼 줄: 모바일 `flex flex-col gap-2`, sm 이상 `sm:flex-row sm:gap-3`. 두 버튼 `h-11 min-w-40`. 순서 "동의하고 시작" → "동의하지 않음". 같은 크기로 두는 이유: 거절을 작은 글자 링크로 숨기지 않는다.
- **진행 불가 처리 (S4 A 확정)**
  - 세 항목을 모두 고르기 전: "동의하고 시작"은 `aria-disabled="true"` + `opacity-60`이지만 포커스할 수 있고 누를 수 있다. 진행 불가 안내가 버튼 위에 `text-sm text-muted-foreground` + lucide `Info` 16px로 항상 보인다.
  - 이때 누르면(클릭, Enter, Space): 진행하지 않는다. 안내가 `text-destructive` + `AlertCircle`로 바뀌고 `aria-live="polite"` 영역에서 읽힌다. 포커스는 **첫 번째 미선택 체크박스**로 간다.
  - 세 항목을 모두 고르면 안내가 사라지고 `aria-disabled`가 풀린다. 이때 누르면 `grant()`.
  - 한두 항목만 골라도 위와 같이 진행되지 않는다(AC-69).
- 보관 안내: 버튼 아래 `text-xs leading-5 text-muted-foreground`.
- 쿠키 배너와 함께 떠도 패널은 본문 흐름 안에 있어 서로를 가리지 않는다. 버튼·체크박스에 `scroll-mb-48`.

### 스켈레톤 [게이트, checking / panel 지연 로드 중]

- md 이상 `md:flex md:flex-wrap md:items-end md:gap-6`. 좌우 2열을 쓰지 않는 이유: 결과가 길어 폼 옆이 비게 된다. 윤달 안내 줄과 오류 줄은 `md:basis-full`로 한 줄 전체를 쓴다.
- 양력/음력: 네이티브 라디오 두 개를 세그먼트 라벨로 감싼다. `inline-flex rounded-lg border border-input p-0.5`, 라벨 `h-10 min-w-16 rounded-md px-4 text-sm font-medium`, 선택됨 `has-[:checked]:bg-primary has-[:checked]:text-primary-foreground`. 기본값 양력. RadioGroup 의존성을 들이지 않는다. `달력` fieldset에는 이 라디오 두 개만 있다.

##### 연도 범위와 지원 범위 안내 (D14, design.md 4.3, 4.10)

- 입력 가능한 연도: 1920 ~ `min(KST 오늘 연도, FORTUNE_SUPPORTED_MAX_YEAR)`(지금은 2028). 칸 모양(`maxLength=4`, 숫자 키패드)은 그대로다. HTML `min`/`max`는 쓰지 않는다(`type="text"`라 효과가 없고, 범위 안내는 오류 문구가 한다).
- 범위 밖 연도를 넣고 "운세 보기"를 누르면 날짜 묶음 아래 오류 줄에 범위 문장이 나온다(아래 "입력 오류 문구"의 `before-min`/`after-max`). 2028년보다 크면 `after-max`, 오늘 연도보다 크지만 2028 이하이면 `future`를 보인다(design.md 4.3 판정 순서와 같다). 음력 입력은 양력으로 바꾼 날짜로 판정한다.
- 입력칸 옆·아래에 지원 범위를 미리 적은 보조 문구는 **두지 않는다**. 이유: 2029년 이후 출생자는 2042년까지 만 14세 미만이라 정상 이용자가 범위 상한에 걸리는 일이 없고, 하한(1920년)도 드물다. 모두에게 보이는 줄을 늘리기보다 걸린 사람에게만 정확한 범위를 알린다.
- 지원 범위 안내 `FORTUNE_SUPPORTED_RANGE_NOTICE`는 각 기능 페이지의 "계산 기준" 목록에 한 항목으로 둔다(design.md FE-6 calc-basis). 모양은 다른 계산 기준 항목과 같은 글머리(`list-disc` 항목, `text-sm leading-7`). 허브에는 두지 않는다(계산 기준 상세가 없는 화면).
- 띠·별자리 찾기 면, 2단계 사주 입력도 같은 범위와 같은 오류 줄을 쓴다.

##### 윤달 체크 (design.md 4.3, AC-8 수정, AC-85, 위치 L-A 확정)

- 음력을 골랐을 때만 렌더링한다. 양력으로 바꾸면 사라지고 선택이 해제된다.
- 위치: 일 칸 다음. 이유: 활성 여부가 연·월 입력에 달려 있어, 연·월·일을 친 뒤에 도착해야 상태가 맞고 키보드 사용자가 되돌아가지 않는다.
- 모양: `<label className="inline-flex min-h-11 items-center gap-2 text-sm font-medium">` 안 네이티브 체크박스(`size-5 accent-primary`) + "윤달".
- 활성 조건: 연도가 1920~지원 상한 안의 네 자리이고 월이 1~12이면 `getLunarLeapMonth(year)`로 확인한다.
  - 그 달에 윤달이 있음: 체크 활성. 바로 아래에 윤달 안내 한 줄(`FORTUNE_LEAP_MONTH_HINT_TEMPLATE`, `text-sm leading-6 text-muted-foreground`, `id`를 줘서 체크박스 `aria-describedby`로 연결).
  - 그 달에 윤달이 없음: 체크 비활성(네이티브 `disabled`), 선택 해제, 안내 줄 없음.
  - 연도·월이 아직 비었거나 범위 밖: 체크 비활성, 안내 줄 없음.
- 비활성 모양: 네이티브 비활성 체크박스 + 라벨 `text-muted-foreground`, `cursor-not-allowed`. 숨기지 않고 비활성으로 두는 이유: AC-8 수정안이 "선택할 수 없음(비활성)"을 요구하고, 체크 자리가 생겼다 없어졌다 하면 폼이 흔들린다.
- 비활성일 때는 탭 순서에서 빠진다(네이티브 `disabled` 동작). 일 칸 다음 Tab은 "운세 보기"로 간다.
- 안내 줄은 `aria-live`를 쓰지 않는다. 이유: 연도·월을 칠 때마다 읽히면 소란스럽다. 일 칸 다음 Tab으로 체크박스에 도착하면 `aria-describedby`로 함께 읽힌다.
- 연도·월을 바꿔 윤달이 없는 달이 되어 선택이 자동 해제될 때 따로 알리지 않는다. 제출 뒤 음력 확인 줄이 실제로 쓰인 날짜를 보인다.
- 윤달이 없는 달을 알리는 문장("○년 ○월에는 윤달이 없습니다")은 넣지 않았다. design.md 상수 목록에 없기 때문이다. 필요하면 architect에 상수 추가를 요청한다("남은 질문" 참고).
- 폐기안: L-B(달력 줄, 연도 앞에 두는 기존 위치)는 U-12에서 채택하지 않았다(2026-11-05).

### 상담전화 기기별 표시 (S9, 사용자 결정 2026-11-05 수정본, 구현 D15·8.4 안 5)

사용자 결정: 통화 앱이 열리는 동작이 문제가 되는 곳은 PC다. 터치 기기에서는 기존처럼 `tel:` 링크로 눌러 걸 수 있게 두고, PC(마우스·키보드 환경)에서는 링크처럼 보이거나 동작하지 않게 한다. 번호 텍스트는 PC에서도 보이고 복사할 수 있어야 한다.

- 운세에서 상담전화가 나오는 곳은 `FortuneResultNoticeComponent` 하나다(모든 기능 페이지 + 허브). 운세는 자유 입력란이 없어 타로의 위기 안내 패널(입력 감지 시)은 없다(plan 고지 17). 타로는 결과 하단(같은 모양)과 위기 안내 패널(아래 "타로 위기 안내 패널의 PC 상태" 절) 두 곳이다.
- 두 상태의 구분(확정, design.md 8.4): 서버 HTML에 터치용 `<a href="tel:…">`와 PC용 `<span>`을 함께 두고, CSS 미디어 쿼리 `(hover: hover) and (pointer: fine)`이 참이면 **PC 상태**(글자만 보임), 아니면 **터치 상태**(링크만 보임)다. 숨는 쪽은 `display: none`이라 탭 순서·접근성 트리·Ctrl+F·복사 범위에서 빠진다. JS가 없어도 같고, 첫 화면에서 바뀌는 깜빡임이 없다.
- 디자인 쪽 제약(구현이 지켜야 하는 것)
  - 숨김은 `display`로만 한다. `sr-only`, `opacity`, `visibility`, `aria-hidden`으로 숨기지 않는다.
  - `linkClassName`·`textClassName`에는 `display` 관련 클래스를 넣지 않는다(`flex`, `inline-flex`, `block`, `hidden`). 보이는 쪽의 `display` 값은 컴포넌트가 정한다(design.md 8.4). 아래 명세의 `flex`·`inline-flex`는 "보일 때 이 배치"라는 뜻이며, FE-1a가 컴포넌트의 PC 표시 값(`[@media(hover:hover)_and_(pointer:fine)]:flex` 등)과 링크 쪽 기본값으로 옮긴다.
  - 숨은 쪽 요소에 `id`를 주거나 다른 요소가 `aria-labelledby`/`aria-describedby`로 가리키지 않는다.
- 경계 기기
  - 마우스를 연결한 태블릿, 트랙패드를 쓰는 iPad: 주 포인터가 fine이면 PC 상태가 된다. 번호는 보이고 복사할 수 있어 정보는 잃지 않는다.
  - 터치스크린 노트북: 주 포인터(마우스·트랙패드)가 fine이면 PC 상태. 사용자 의도(PC에서 앱이 열리지 않게)와 맞다.
  - 미디어 쿼리를 지원하지 않는 오래된 브라우저: 터치 상태(기본값)로 보인다. 이유: 번호를 잃지 않고, 기존 타로 동작과 같다.
  - 사용 중 입력 장치가 바뀌면(마우스 연결 등) CSS가 바로 다른 상태를 보인다. 높이가 같아 아래 내용이 밀리지 않는다(아래 "높이 유지").

- 타로 `TarotResultNoticeComponent`(S6 A안)와 같은 모양·구조다. sm 이상 터치 기기(태블릿)는 `sm:grid-cols-2`, 109 항목 `sm:col-span-2`.
- 목록 `<ul>`: 모바일 `flex flex-col gap-1`, sm 이상 `sm:grid sm:grid-cols-2 sm:gap-x-6 sm:gap-y-1`. 목록의 `display`는 상태와 관계없이 같다(바뀌는 것은 `<li>` 안의 두 요소뿐).
- 항목: `<li>` 하나 안에 `CrisisPhoneComponent`. 링크(`linkClassName`): `group min-h-11 flex-col justify-center rounded-sm py-1 break-keep` + 보일 때 `flex`. `linkContent`는 두 줄.
  - 첫 줄 `<span className="block">`: 기관명 + 공백 글자 + 번호. `text-primary underline underline-offset-4`, 누름(`active`) 시 `decoration-2`(`group-active:decoration-2`). 109만 `font-semibold`. 번호 `<span className="whitespace-nowrap tabular-nums">`.
  - 둘째 줄 `<span className="block text-muted-foreground">`: 설명(링크 안이지만 밑줄 없음).
- 터치 대상: 항목마다 `min-h-11`(44px), 항목 사이 `gap-1`(4px). WCAG 2.5.8 충족(기존 명세 유지).
- 포커스(외부 키보드·스위치 제어): `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2 focus-visible:ring-offset-background focus-visible:outline-none`.
- 읽기: 링크 이름 = 보이는 글자 "자살예방 상담전화 109 자살 생각과 위기 상황 상담"(`aria-label` 없음, Label in Name 충족). `<ul aria-labelledby={안내 첫 줄 id}>`(안내 첫 줄은 항상 보이는 요소라 참조해도 된다).
- 번호 표기: 보이는 번호는 하이픈 포함("1577-0199"), `href`는 하이픈 없음(`tel:15770199`). 번호는 하나의 텍스트 노드로 두고 숫자·하이픈을 다른 span으로 나누지 않는다. 읽기 방식은 아래 "번호 읽기" 절.
- 복사: 링크라 길게 누르면 브라우저의 링크 메뉴가 뜬다(iOS: 통화·메시지·연락처 추가·복사, Android Chrome: 링크 주소 복사·링크 텍스트 복사). 이 메뉴로 복사할 수 있으므로 따로 복사 장치를 두지 않는다.
- 안내 첫 줄의 `Phone` 아이콘(16px, `aria-hidden`, `mt-1 shrink-0 text-muted-foreground`)은 터치 상태에서만 보인다. 아이콘은 `CrisisPhoneComponent` 밖이라 같은 미디어 조건의 숨김 클래스(`[@media(hover:hover)_and_(pointer:fine)]:hidden`, 리터럴)를 아이콘에 직접 붙인다. 장식 아이콘이라 접근성 트리에는 영향이 없다.

#### PC 상태 (`(hover: hover) and (pointer: fine)`) — 일반 텍스트

```

│ 운세는 오락과 참고를 위한 …                                    │

│ 자살 생각과 위기 상황 상담                                     │
```

- 배치는 터치 상태와 같다(같은 목록, `sm:grid-cols-2`, 109 `sm:col-span-2`, 같은 글자 크기·순서). 바뀌는 것은 모양과 동작뿐이다. 이유: 창 크기나 입력 장치가 바뀌어도 내용 위치가 흔들리지 않는다.
- 글자(`textClassName`): `min-h-11 flex-col justify-center py-1 break-keep` + 보일 때 `flex`. 링크와 같은 상자 크기다(`rounded-sm`는 포커스 링용이라 뺀다). `textContent`는 터치 상태와 같은 두 줄 구조.
  - 첫 줄 `<span className="block text-foreground">`: 기관명 + 공백 글자 + 번호. 밑줄 없음. 109만 `font-semibold`. 번호 `<span className="whitespace-nowrap tabular-nums select-all">`.
  - 둘째 줄 `<span className="block text-muted-foreground">`: 설명(같음).
- 공백은 CSS `gap`이 아니라 실제 공백 글자로 둔다. 이유: 복사하거나 읽을 때 "정신건강위기상담전화1577-0199"처럼 붙지 않게 한다. 첫 줄을 `block` span 하나로 감싸는 이유도 같다(flex 항목 사이의 공백 글자는 사라진다).
- 모양
  - 안내 첫 줄의 `Phone` 아이콘: 보이지 않는다.
  - hover 효과 없음(색·밑줄·배경 변화 없음). 커서는 기본(글자 위에서는 브라우저 기본 텍스트 커서). `cursor-pointer`를 쓰지 않는다.
- 높이 유지: 항목 `min-h-11 py-1`, 목록 `gap-1`/`sm:gap-y-1`을 터치 상태와 똑같이 둔다. 누르는 대상이 아니라 44px 규칙 대상은 아니지만, 상태가 바뀌어도 상자 높이와 아래 내용 위치가 같게 하려고 둔다(design.md 8.4).
- 동작
  - 클릭해도 아무 일도 일어나지 않는다(통화 앱, `tel:` 처리기, 확인 창이 열리지 않는다).
  - 탭 순서에 들어가지 않는다. 포커스 링 없음.
  - 화면 읽기 도구에서 "링크"로 안내되지 않는다. 목록·텍스트로 읽힌다.
- 선택·복사
  - 번호를 드래그하거나 클릭해 선택하고 Ctrl+C로 복사할 수 있어야 한다. 상자·목록·항목에 `select-none`, `pointer-events-none`을 두지 않는다.
  - 번호에 `select-all`을 준다. 한 번 클릭으로 하이픈까지 번호 전체가 선택된다. 이유: 더블클릭은 하이픈에서 끊겨 "1577"만 고를 수 있다. 단점: 번호 일부만 고르기 어렵다(필요가 거의 없다). 기관명은 일반 선택이다. QA가 Chrome·Edge·Safari·Firefox에서 확인한다.
  - 복사 버튼, "복사됨" 토스트는 두지 않는다. 이유: 새 누르는 대상과 클립보드 기능은 이번 결정 범위 밖이다.

#### 링크 동작 표현의 사용 위치

- "전화 연결", "눌러서", "탭하여", "바로 걸기" 같은 표현은 **터치 상태 링크 안에서만** 쓴다. 지금 해당하는 것은 타로 상수 두 개뿐이다: `TAROT_CRISIS_CALL_LABEL`("109 전화 연결", `linkContent`), `TAROT_CRISIS_PHONE_ARIA_LABEL`("자살예방 상담전화 109 전화 연결", `linkAriaLabel`).
- PC 상태 글자(`textContent`)와 두 상태에 함께 보이는 문장(안내 첫 줄, 본문, 묶음 이름, 설명 구절)에는 이런 표현을 쓰지 않는다.
- 운세 화면에는 이 표현이 없다. 안내 문장(plan 고지 17), 기관명 5개, 설명 구절 5개 모두 PC·터치 양쪽에서 맞다.
- 두 상태에 다른 안내 문장을 두지 않는다. "번호를 눌러 전화하세요" 같은 터치 전용 안내를 새로 넣지 않는다(PC에서 틀린 말이 되고, 문구를 두 벌 관리하게 된다).

| 읽기 | 읽기 도구가 하이픈 번호를 한 덩어리로 읽는다. 도구에 따라 "천오백칠십칠 다시 영일구구" 또는 숫자 단위로 읽는다 | 숫자 하나씩 일정하게 읽힌다 |
| 장점 | 보이는 글자 = 읽는 글자 = 링크 이름(터치 상태). 복사할 때 숨은 글자가 섞이지 않는다 | 읽는 방식이 도구와 무관하게 같다 |
| 단점 | 도구에 따라 큰 수로 읽힐 수 있다 | PC에서 복사할 때 `sr-only` 글자가 함께 복사될 수 있다. 터치 상태에서 링크 이름과 보이는 글자가 달라져 Label in Name(2.5.3)이 깨진다 |

- 확정 A안. B안은 복사 요구와 2.5.3에 걸린다.
- 쓰지 않는 방법: PC 상태의 일반 `<span>`에 `aria-label`(역할 없는 요소의 `aria-label`은 무시되거나 금지), `role="text"`(표준 역할이 아님).

##### Q8 대안 (U-13 실기기 확인에서 문제가 나왔을 때만 적용)

U-13에서 `1577-0199`, `1588-9191`이 알아듣기 어렵게 읽히면(큰 수로 읽힘, 하이픈이 "빼기"로 읽힘, 조각남) 아래 순서로 처리한다. 문제가 없으면 아무것도 바꾸지 않는다.

| 문제가 난 환경 | 대안 | 이유 |
|---|---|---|
| VoiceOver(iOS Safari), TalkBack(Android Chrome) = 터치 상태 링크 | 해당 번호의 링크에 `linkAriaLabel`을 준다. 값은 보이는 글자와 같은 순서·같은 단어에서 번호의 하이픈만 공백으로 바꾼 것. 예: "정신건강위기상담전화 1577 0199 우울·불안 등 정신건강 위기 상담" | 읽기 도구는 공백으로 나뉜 네 자리를 두 덩어리로 읽는다. WCAG 2.5.3은 구두점 차이를 같은 이름으로 보므로 보이는 글자와 이름이 맞는다. 보이는 글자·복사 내용은 그대로다. 터치 상태 링크에만 붙어서 PC에는 영향이 없다 |
| NVDA + Chrome = PC 상태 글자 | 바꾸지 않고 "알려진 제한"으로 qa-report에 기록한다. 화면 읽기 사용자는 글자 단위 읽기(NVDA 숫자 키패드 / 화살표)로 번호를 확인할 수 있다 | PC 글자는 역할 없는 `<span>`이라 `aria-label`을 쓸 수 없다. 숨은 읽기 전용 글자(B안)는 복사에 섞여 들어가 복사 요구와 충돌한다 |
| 109, 1388, 1366 | 해당 없음 | 세 자리·네 자리 단일 번호라 하이픈이 없다 |

- 대안을 적용하면 FE-1a 담당이 공용 표시 쪽에서 한 번 고치고(dev-tasks 규칙), 타로 109의 기존 `linkAriaLabel`은 그대로 둔다.
- 하이픈을 다른 글자(줄바꿈 없는 하이픈 U+2011 등)로 바꾸는 방법은 쓰지 않는다. 복사한 번호가 다이얼·검색에서 다른 글자로 인식될 수 있다.

#### 상태·모션

- 두 상태 모두 서버 HTML이라 로딩·오류·빈 상태 없음. JS를 꺼도 같다.
- 모션 없음. 상태 전환(입력 장치 변경)도 즉시 바뀐다. 터치 상태의 밑줄 두께 변화는 즉시 바뀐다. 이유: 위기 안내에 움직임을 붙이지 않는다는 타로 원칙과 같다.

### 오늘의 운세 링크 `FortuneTodayLinkComponent` [서버, 띠별·별자리만] (D12, 신규)

위치: `/fortune/tti`, `/fortune/star-sign`에서 결과 하단 면책 + 상담전화 상자 **바로 아래, 가이드 위**. 게이트 패널 밖이라 동의 전에도 보이고 JS를 끈 서버 HTML에도 있다(design.md 7.5).

모바일

```
┌ 결과 하단 면책 + 상담전화 ─────────┐
└────────────────────────────────────┘
생년월일을 기준으로 한 개인 운세는    ← 안내 한 줄, text-sm muted
따로 볼 수 있습니다.
생년월일로 보는 오늘의 운세           ← 링크, text-primary underline
```

데스크톱 (sm 이상): 안내와 링크를 한 줄로(`sm:flex sm:flex-wrap sm:items-baseline sm:gap-x-2`).

```
생년월일을 기준으로 한 개인 운세는 따로 볼 수 있습니다.  생년월일로 보는 오늘의 운세
```

- 구조: `<p className="text-sm leading-6 text-muted-foreground break-keep">` 안내 + `<Link href={FORTUNE_ROUTES.today}>` 링크. 상자·테두리 없음. 이유: 바로 위가 테두리 상자(결과 하단 안내)라 상자를 겹치면 고지처럼 보인다. 내비게이션이므로 종이 위 글로 둔다.
- 링크: `inline-flex min-h-11 items-center text-base font-medium text-primary underline underline-offset-4 hover:decoration-2 break-keep` + 포커스 `focus-visible:ring-2 ring-ring ring-offset-2 ring-offset-background rounded-sm`. 오늘의 운세 결과의 "다른 기준의 운세" 링크와 같은 모양. 혼자 있으므로 글자를 한 단계 크게(`text-base font-medium`) 둔다.
- 라벨: "생년월일로 보는 오늘의 운세"(design.md 7.5 확정 라벨, plan 화면 표기 규칙의 허용 이름). 아이콘·화살표·쿼리·해시 없음.
- 간격: 위 상자와 `mt-4`, 아래 가이드와는 섹션 간격(`space-y-10`).
- 안내 한 줄을 두는 이유: 라벨만 있으면 "띠 운세와 무엇이 다른지"가 링크 앞에서 보이지 않는다. 기준 차이 안내(AC-19)는 동의 후 패널 안에만 있어 동의 전에는 보이지 않는다.
- 한 페이지에 오늘의 운세 링크는 이것 하나다(패널 안 기준 차이 안내에는 넣지 않음).
- 접근성: 링크 이름은 보이는 라벨 그대로(`aria-label` 없음). 안내 문장은 링크 바로 앞 같은 문단이라 문맥으로 읽힌다(WCAG 2.4.4). 탭 순서는 PC에서 패널 다음 첫 정지, 터치 기기에서는 상담전화 5곳 다음.
- 상태: 서버 링크라 로딩·오류·빈 상태 없음. hover는 밑줄 두께만 즉시 바뀐다.

### 가이드·계산 기준·FAQ·이용 안내 [서버]

- 가이드: h2 + 단락 `max-w-[68ch] text-sm leading-7 sm:text-base`.
  - 띠 가이드의 12띠와 출생 연도 대응: `<table>`(띠 이름 / 최근 출생 연도 예 / 입춘 기준 안내), `text-sm`.
  - 별자리 가이드의 날짜표: 같은 형식 + "해마다 하루 정도 달라질 수 있습니다"(AC-26).
  - 방식 A 페이지의 가이드·FAQ에서 "사주"를 쓰는 경우는 plan "용어 사용 규칙: 사주"의 방식 구분 설명 문장에 한하고, 첫 언급에 괄호 설명을 붙인다(콘텐츠 작성자 전달).
- 계산 기준: h2 "계산 기준" + 글머리 목록(`list-disc pl-5 space-y-1 text-sm leading-7`). 지원 범위 안내(`FORTUNE_SUPPORTED_RANGE_NOTICE`)는 이 목록의 마지막 항목이다. 이유: 범위는 계산 자료의 한계라 계산 기준의 일부로 읽히는 것이 맞다.
- FAQ: 펼친 목록(h2 + h3 + p). 아코디언 없음(서버 HTML과 JSON-LD가 같다, AC-64).
- 이용 안내: 타로 `TarotDetailNoticeComponent`와 같은 형식, 9항 글머리.

### 메뉴 (`MENU_LIST` 운세 그룹) (승인됨 2026-11-05)

| 항목 | 아이콘 (lucide) | 설명 | 예시 |
|---|---|---|---|
| 오늘의 운세 | `Star` (유지) | 생년월일로 오늘의 총운과 행운 포인트를 확인. (유지) | 예: 출근 전에 오늘의 총운과 재물·애정 운세 확인 |
| 띠별 운세 | `PawPrint` | 12띠의 오늘 운세와 입춘 기준 내 띠 찾기. | 예: 1~2월생이 입춘·설날 기준 띠를 함께 확인 |
| 별자리 운세 | `Telescope` | 12별자리의 오늘 운세와 경계일 시각까지 반영한 내 별자리 찾기. | 예: 3월 20일생이 태어난 시각으로 별자리 확인 |

- 세 항목 `colorClass: 'text-menu-fortune'`. 그룹 `href`는 `/fortune`(design.md 13.1, 허브).
- 설명은 허브 목록 행의 둘째 줄로도 쓰인다(`MenuListComponent`). 허브용 별도 설명을 두지 않는다. 이유: 같은 기능을 메뉴와 허브에서 다른 말로 부르지 않는다.
- 아이콘 이유: `PawPrint`는 특정 동물 하나를 고르지 않고 열두 동물을 떠올리게 한다. `Telescope`는 "관찰하는 연구소"와 별자리를 잇는다. `MENU_ICONS`에 없으면 추가한다(lucide-react 기존 의존성).

- M2 목록 항목 펼치기·접기 움직임(사용자 결정: 뺌): M1과 한 화면에서 경쟁하고, 스크롤 이동과 겹쳐 흔들려 보인다. 즉시 펼치고 포커스·스크롤로 위치를 알린다.

- 점수 숫자 세어 올리기: 기다리게 만들고, 화면 읽기 도구가 여러 번 읽을 수 있다.
- 섹션·카드 등장 효과, 운세 컨트롤 hover 전환, 행운 숫자 반짝임, 별·구름 장식, 허브 목록의 새 효과: 꾸밈뿐이다.
- 후보 버튼 선택 효과, 오늘의 운세 링크, 상담전화(두 상태 모두, 타로 위기 패널 109 PC 글자 포함), 윤달 체크·안내 줄 등장: 움직임 없음. 윤달 안내는 입력 중에 생겼다 사라지므로 움직이면 산만하다.

- 허브: PC는 목록 3행이 탭 정지의 전부다. 터치 기기(외부 키보드)는 목록 3행 → 상담전화 5곳.
- 이용 동의 화면: 체크박스 1 → 2 → 3(Space) → "동의하고 시작" → "동의하지 않음".
  - 세 항목 전에 "동의하고 시작"을 누르면 진행하지 않고 안내가 읽히며 첫 미선택 체크박스로 포커스(S4 A).
  - 성공 → 기능 영역 첫 h2("생년월일 입력" / "띠 고르기" / "별자리 고르기" / "생년월일과 태어난 시간")로 포커스.

### 라벨·읽기

- 동의 화면: `<section aria-labelledby>`. 체크박스는 `<label>`이 감싸 문장 전체가 이름. "동의하고 시작"에 세 항목 전까지 `aria-describedby={진행 불가 안내 id}`. 안내는 `aria-live="polite"`.
- 이용 불가·연령 안내: `<section aria-labelledby>`. `alertdialog`, `role="alert"`를 쓰지 않는다(화면을 가리지 않는 본문 블록).
- 입력: `<fieldset><legend>달력</legend>`(양력/음력만), `<fieldset><legend>생년월일</legend>` + 보이는 `<Label htmlFor>` "연도", "월", "일" + 윤달 체크(L-A), `<fieldset><legend>태어난 시각</legend>` + "시", "분". 보조 문구 `aria-describedby`. `autoComplete="off"`.
- 윤달 체크박스: `생년월일` fieldset 안에 있어 화면 읽기 도구는 "생년월일, 윤달, 체크 상자"로 읽는다. 보이는 라벨 "윤달"이 이름. 윤달 안내 줄이 있으면 `aria-describedby`로 연결. 안내 줄이 없을 때는 `aria-describedby`를 붙이지 않는다(없는 id를 가리키지 않게).
- 점수: "72점" 글자가 이름. 눈금 `aria-hidden`.
- 결과 공지: 기능 영역에 `aria-live="polite"` 하나. 결과가 나오면 한 번 읽는다(문구 절).
- 칩: `<button aria-pressed>`, 묶음 `role="group" aria-labelledby`. 별자리 칩 이름은 날짜까지 포함(보이는 글자 = 이름).
- 후보 버튼: `aria-pressed`, 묶음 `role="group" aria-labelledby={안내 문장 id}`.
- 목록: `<ul>` + `<li>` + h3. 펼친 항목은 h3 옆 `sr-only` "(선택한 띠)" / "(선택한 별자리)".
- 사주 표: `<table>` + `caption`("연·월·일·시 기둥") + `th scope`. 한자 `aria-hidden`.
- 허브: `<section aria-labelledby>`로 목록 묶음 이름. 링크 이름은 공용 컴포넌트의 이름 + 설명.
- 오늘의 운세 링크: 보이는 라벨이 이름. 앞 문장이 같은 문단 문맥.
- 상담전화: 두 상태 모두 `<ul aria-labelledby={안내 첫 줄 id}>`로 "목록, 항목 5개"와 묶음 이름이 읽힌다. 터치 상태는 항목마다 "링크, 기관명 번호 설명", PC 상태는 "기관명 번호 설명" 텍스트(링크로 안내되지 않음). 번호는 하나의 텍스트 노드, aria 없음(번호 읽기 A안, Q8 대안은 문제가 나올 때만). 한 시점에 두 상태 중 하나만 접근성 트리에 있다(`display: none`, design.md 8.4).
- (타로) 위기 패널 109: 터치 상태 링크 이름은 기존 `TAROT_CRISIS_PHONE_ARIA_LABEL`. PC 상태는 "자살예방 상담전화 109" 텍스트이며 `aria-label`이 없다. "전화 연결"은 PC에서 보이지도 읽히지도 않는다.
- 아이콘·오행 막대는 `aria-hidden`.
- 터치 영역 44px 이상(누르는 대상만, 터치 상태 상담전화·윤달 체크 라벨 포함). 확대 200%에서 한 줄 폼은 `flex-wrap`(윤달 체크는 일 칸 뒤에서 다음 줄로 내려간다), 기록표 2열은 md 아래에서 한 열, 사주 표는 한자가 한글 아래로 내려간다. 상담전화 sm 2열은 확대 시 기관명이 줄바꿈되고 번호는 `whitespace-nowrap`이라 갈리지 않는다. 타로 위기 패널 109 PC 글자는 확대 시 이름과 "109"가 두 줄로 갈릴 수 있고(`min-h-11`이라 늘어난다), 번호 자체는 갈리지 않는다.
