# 다음 기능 (리서치 → 기획 순서로 진행)

1. 홈 재구성: 홈을 로또 중심에서 오늘의 운과 선택을 가볍게 즐기는 도구 모음으로 바꾼다.
   - 기획서 작성 완료, 사용자 승인 대기 (`docs/home-reposition/plan.md`, `status.md`).
   - 메뉴 구성·순서 점검(그룹 순서, 하위 항목 순서, 이름 톤, 홈 설명 문구, 모바일 접힘, 허브 순서)도 같은 기획서에 들어 있다.
   - 열린 질문 16개에 답해야 설계로 넘어간다. 핵심은 사이트 이름(`NEXT_PUBLIC_SITE_NAME`) 확인, 서치 콘솔의 `/` 검색어와 `/lotto/*` 유입 확인, 메뉴 순서(권장: 운세 → 뭐 먹지 → 타로 → 운빨 뽑기 → 꿈 해몽 → 로또), 당첨 번호 배너 위치(권장: `/lotto` 안), 히어로 문구 3안 중 선택이다.
   - 메뉴 순서(`MENU_LIST`)는 홈뿐 아니라 PC·모바일 헤더와 사이트맵에도 쓰인다.
2. 궁합 테스트: 이름, 띠, 별자리
3. 손 없는 날·길일 달력.
4. 로또 QR 코드: 입력 없이 사진으로 바로 접속할 수 있게 한다.
5. 뭐먹지에 더 많은 메뉴를 추가하기.
6. 뭐 먹지 동네 이름 입력으로 지도 검색: 기획서 작성 중, 설계부터는 이어서 진행한다 (`docs/meal-location/plan.md`, 조사 `docs/research/meal-location.md`).
   - 처음에는 "내 위치 공유로 주변 검색"을 원했으나, 카카오·네이버·구글 웹 검색 URL이 좌표 기준 주변 검색을 공식 지원하지 않아 B안(동네 이름 입력)으로 정했다(2026-11-24).
   - 위치 권한은 쓰지 않는다. 나중에 지도 서비스가 웹 URL 좌표 검색을 지원하면 좌표 방식을 다시 검토한다.
7. 다국어 지원 검토: 일단 영어만. 리서치부터 시작한다.
   - 어떤 메뉴가 영어 사용자에게 의미가 있는지 나눈다. 한국 전용(로또, 사주, 한국식 메뉴, 카카오·네이버 지도)과 그대로 쓸 수 있는 것(운빨 뽑기, 타로 등)을 구분한다.
   - 주소 구조(`/en` 하위 경로 등), `hreflang`·sitemap·메타데이터, 라이브러리 선택(Next.js App Router i18n, 예: `next-intl`)과 새 라이브러리 라이선스 문서 갱신 여부를 조사한다.
   - 약관·방침·법적 고지(영어판), 광고(AdFit은 국내 중심이라 영어 방문자용 광고 정책), 번역 품질과 문구 검수 방식, 서비스 문구 금지어 검사(`copy-rule`)의 영어판 필요 여부를 확인한다.
8. 그 밖에 이 사이트에 맞는 메뉴를 계속 추가한다.
9. 거의 모든 기능에 카카오 공유 버튼 기능 추가

# 나중에 확인할 일

1. README 정리: 기능을 추가할 때마다 계속 갱신한다.
2. SEO 확인: 구글, 네이버 URL 관리. 점심 공개 후 sitemap 등록을 다시 본다.
3. 전체적인 문구 정리.
4. 타로, 운세: 개발 완료 후 전체적으로 검증이 필요하다.
5. 루트 404 화면(`src/app/not-found.tsx`)에 꿈 해몽 허브 링크 추가 검토. 사이트 전체 화면이라 사용자 승인이 필요하다.
6. 루트 `src/app/loading.tsx` 스트리밍 영향 점검 (전 페이지 영향, 별도 작업으로 로또 포함 검토 필요)
   - JS를 끄면 본문이 `hidden` 영역에 남아 보이지 않는다. 서버 HTML에는 본문이 있다(2026-11-05 알려진 한계 수용, `docs/tarot/status.md`).
   - 없는 주소(404)에서 로드 직후 h1이 잠깐 2개로 잡혔다가 1개로 돌아온다(모바일에서 간헐적, 운영 빌드 확인).
7. 기존 e2e 중복 정리: QA 범위 규칙은 2026-11-24에 `CLAUDE.md`, `.claude/agents/qa.md`, `.claude/agents/planner.md`에 반영했다. 운빨 뽑기 e2e는 새 규칙으로 정리했다(33개에서 21개).
   - 아직 정리하지 않은 큰 spec: `e2e/fortune.spec.ts`(671줄), `e2e/tarot.spec.ts`(400줄), `e2e/meal.spec.ts`(319줄), `e2e/lotto.spec.ts`.
   - 같은 화면을 여러 테스트가 반복해서 여는 곳, 공통 검사(h1, 메타, 320px)가 페이지마다 반복되는 곳을 흐름 단위로 합친다.
   - 점심 e2e가 전체 병렬 실행에서만 가끔 실패했다(qa 실행에서 한 번, 단독 실행과 이후 전체 실행은 통과). 다시 나오면 원인을 확인한다.
   - `docs/_templates/plan.md`의 AC 표에는 검증 층 태그(`[E2E]`, `[단위]`, `[정적]`) 열이 아직 없다. 넣을지 정한다(규칙 문서라 승인 필요).
8. API 요청 제한 보강: 트래픽이 늘거나 CSV 내보내기 남용이 보이면 검토한다.
   - 지금은 서버 메모리(Map)로 세서 Vercel 인스턴스끼리 공유되지 않는다 (`src/app/api/lotto/draws/route.ts`, `export/route.ts`).
   - 순서: Vercel Firewall rate limit 규칙(코드 변경 없음, 요금제 확인) → 안 되면 Upstash Redis + `@upstash/ratelimit`.
9. 전체적인 불필요한 파일 및 코드 확인
   - 메뉴 룰렛(`meal`)과 운빨 뽑기에서 거의 복사된 공용 후보: 스크린리더 알림(`status`), `noscript-notice`, `disclaimer-notice`를 `src/components/common/`의 컴포넌트로 합친다.
   - 두 copy-rule의 공통 금지어(단정·최상급 표현)를 공용 기본 목록으로 뺀다.
   - 난수는 합치지 않는다. 운빨 뽑기는 `Math.random` 대체가 없어야 해서(`COMPLIANCE.md`) `src/lib/random.ts`와 따로 둔 것이다. 합치려면 `lib/`에 대체 없는 함수를 새로 만들어야 한다.
   - `docs/lucky-draw/qa-report.md` 등에 남은 옛 실패 기록과 임시 문구를 정리한다.
10. 돌림판 결과 가리기의 한계: 칸 글자는 숨기지만 칸 경계선과 바늘 위치로 칸을 셀 수 있다. FAQ에 한계를 적었다. 더 막으려면 설계부터 다시 봐야 한다.
