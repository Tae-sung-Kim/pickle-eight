# 다음 기능 (리서치 → 기획 순서로 진행)

1. 운빨 뽑기 도구: 사다리, 돌림판, 제비뽑기. 점심 룰렛의 공용 돌림판 컴포넌트(`src/components/common/roulette.component.tsx`)를 재사용한다.
2. 궁합 테스트: 이름, 띠, 별자리. 카카오 공유 버튼 포함.
3. 손 없는 날·길일 달력.
4. QR 코드: 입력 없이 사진으로 바로 접속할 수 있게 한다.
5. 메뉴 룰렛에 끼니 구분 추가: 점심 / 저녁 / 술안주. 지금은 점심(`/lunch/today`)만 있다.
   - 방향 후보: 한 화면에서 끼니를 고르는 방식, 또는 끼니별 페이지. 메뉴 이름과 URL(`/lunch/...`)을 바꿀지는 기획 때 정한다.
   - 메뉴 데이터: 저녁·술안주용 메뉴 목록을 따로 쓴다. 점심 메뉴 48개를 그대로 재사용할 수 있는지 먼저 본다.
   - 점심운 문구는 끼니마다 따로 쓴다. 술안주는 음주 관련이라 문구·법적 고지(미성년자, 음주 권유로 읽히지 않게)를 기획 단계에서 따로 검토한다. AdFit 심사도 다시 확인한다.
   - 기존 약관 9장·방침 6장·`COMPLIANCE.md` 점심 항목에 반영이 필요하다.
   - 순서: 기획(리서치 필요 여부 판단) → 설계 → UI/UX → 개발 → QA. 점심 안정화 후 진행.
   - 메뉴 이름: 끼니가 늘면 "점심"보다 "메뉴 추천" 같은 넓은 이름이 맞다. 이름과 URL(`/lunch`)을 바꿀지 기획 때 정한다. URL을 바꾸면 기존 `/lunch/today`에서 리다이렉트가 필요하다.
6. 그 밖에 이 사이트에 맞는 메뉴를 계속 추가한다.

# 나중에 확인할 일

1. README 정리: 기능을 추가할 때마다 계속 갱신한다.
2. 홈 정리: 진행 중.
3. SEO 확인: 구글, 네이버 URL 관리. 점심 공개 후 sitemap 등록을 다시 본다.
4. 전체적인 문구 정리.
5. 타로, 운세: 개발 완료 후 전체적으로 검증이 필요하다.
6. 루트 404 화면(`src/app/not-found.tsx`)에 꿈 해몽 허브 링크 추가 검토. 사이트 전체 화면이라 사용자 승인이 필요하다.
7. 루트 `src/app/loading.tsx` 스트리밍 영향 점검 (전 페이지 영향, 별도 작업으로 로또 포함 검토 필요)
   - JS를 끄면 본문이 `hidden` 영역에 남아 보이지 않는다. 서버 HTML에는 본문이 있다(2026-11-05 알려진 한계 수용, `docs/tarot/status.md`).
   - 없는 주소(404)에서 로드 직후 h1이 잠깐 2개로 잡혔다가 1개로 돌아온다(모바일에서 간헐적, 운영 빌드 확인).
8. QA·e2e 범위 규칙 정리: 작은 수정(문구, 버튼 글자)에도 스펙 전체 실행과 보고서 작성이 길어진다.
   - 점심 지도 버튼 라벨 수정 때 qa가 스펙 수정, 전체 재실행, AC-4 반복, 스크린샷, 보고서를 모두 했다.
   - 작업 크기별 기준을 `CLAUDE.md`와 `.claude/agents/qa.md`에 정한다. 예: 문구·상수만 바꾸면 영향받는 AC만 실행, 반복 실행(`--repeat-each`)은 불안정 테스트에만, 보고서는 실패·변경 사유만.
   - 다른 AC 중복 검사(같은 문구를 여러 스펙에서 보는 것)도 줄일 수 있는지 `e2e/lunch.spec.ts`부터 점검한다.
   - 규칙 문서와 agent 지침은 사용자 승인 없이 바꾸지 않는다.
9. API 요청 제한 보강: 트래픽이 늘거나 CSV 내보내기 남용이 보이면 검토한다.
   - 지금은 서버 메모리(Map)로 세서 Vercel 인스턴스끼리 공유되지 않는다 (`src/app/api/lotto/draws/route.ts`, `export/route.ts`).
   - 순서: Vercel Firewall rate limit 규칙(코드 변경 없음, 요금제 확인) → 안 되면 Upstash Redis + `@upstash/ratelimit`.
