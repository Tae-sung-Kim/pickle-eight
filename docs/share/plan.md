## 목표

결과를 본 사용자가 한 번의 버튼으로 결과 카드 이미지나 기능 링크를 친구에게 보내고, 공유할 수 없는 환경에서도 다음 행동을 알 수 있게 한다. 공유 이미지에는 개인 식별값(생년월일, 질문, 상대방 정보, 동네 이름)이 들어가지 않는다.

## 범위

- 포함:
  - 결과 화면의 공통 공유 버튼(모바일: OS 공유창 버튼 1개, PC: 링크 복사·이미지 저장·이미지 복사 버튼 3개).
  - 화면 전체가 아니라 기능별 공유 카드 영역만 PNG로 만들어 공유하거나 저장하는 기능(기존 `use-capture` 흐름 기반). 카드는 공유용 레이아웃으로 따로 그린다(열린 질문 21).
  - 기능 소개 주소(링크) 공유.
  - 공유 실패, 공유창 취소, 인앱 브라우저(카카오톡 Android 포함)에서의 안내 화면.
  - 공유 카드 문구 규칙(고지 문구 포함, 개인 식별값 제외).
  - 1차 대상 기능 적용(뭐 먹지, 운빨 뽑기 3종, 궁합)과 2차 대상 기능 적용(운세·띠·별자리, 타로, 로또 생성기).
- 제외:
  - 카카오 JS SDK, 카카오 앱 키, 카카오 도메인 등록.
  - 결과 전용 링크(상대가 같은 결과를 여는 링크)와 결과 값의 서버 저장.
  - 서버 렌더 이미지(`/api/og-image` 기반 결과 이미지) 생성. 리서치 안 C는 보류한다.
  - 화면 전체 캡처.
  - 공유 이벤트 분석 기록(열린 질문 12번에서 결정 전까지 기록하지 않음).
  - 사주, 꿈 해몽, 로또 기록·채점·분석·시뮬레이터: 공유 범위에서 뺀다(아래 "제외 이유" 참고).
  - 새 페이지, 새 라우트, sitemap 변경.
  - 이미지에 광고 요소 넣기.

#### 선택 이유

- 바이럴 수요: 친구와 같이 보는 결과(뭐 먹지, 운빨 뽑기, 궁합, 운세, 타로)는 공유 욕구가 크다. 1차에 넣은 이유다.
- 개인정보 위험: 사주(생년월일시), 궁합 상대방 정보, 사다리 이름 입력은 위험이 있다. 사주는 제외하고, 궁합은 생년월일과 상대방 정보를 빼는 조건으로, 사다리는 미리보기 확인 조건으로 넣는다.
- 결과 단독 의미: 꿈 해몽은 내 결과가 없고, 로또 기록·분석·시뮬레이터는 표와 통계가 중심이라 카드 한 장으로 뜻이 전달되지 않는다. 채점기와 나의 번호는 입력 번호가 필요하다.

### 공유 카드 내용 (기능별)

- 공유 이미지는 결과 화면 전체가 아니다. 기능마다 아래 표의 항목만 담은 공유 카드 한 장이다.
- 모든 카드는 맨 아래에 기능 주소와 고지 한 줄을 넣는다.
- 생년월일, 질문, 상대방 정보, 동네 이름은 어떤 카드에도 넣지 않는다.
- 사용자가 쓴 이름 목록(사다리 참가자, 돌림판 후보)은 "넣는 내용"에 적힌 경우에만 넣는다. 넣을 때는 공유 직전 카드 미리보기를 거쳐야 한다(열린 질문 22).

### 기존 훅 한계와 요구사항 반영

`use-capture.hook.ts`의 현재 동작을 기준으로 적는다. 구현 방식은 설계 담당이 정한다.

| 현재 한계 | 요구사항 |
|---|---|
| 실패 시 아무 안내가 없고 `console.error`만 남긴다 | 실패하면 사용자에게 한글 안내를 보여 준다. 안내 문구는 문구 상수 한 곳에 모은다. 오류 기록 방식은 설계에서 정한다. |
| 공유창을 닫으면(취소) 예외가 날 수 있다 | 사용자가 취소한 것은 오류로 보지 않고 안내를 띄우지 않는다. 기기마다 예외 이름이 다를 수 있으므로 확인 필요. |
| 공유 가능 여부를 확인하지 않고 파일 공유를 시도한다 | 파일 공유가 안 되면 링크 공유로 낮추고, 링크 공유도 안 되면 PC 경로(복사·저장)로 간다. |
| 인앱 브라우저(카카오톡 Android) 대응이 없다 | 공유창과 클립보드가 둘 다 막히는 환경을 감지하거나 실패 후 따로 처리해, 안내 화면에서 주소를 보여 주고 길게 눌러 복사하도록 안내한다. 외부 브라우저 강제 실행은 하지 않는다. |
| iOS에서 첫 호출이 빈 이미지로 나올 수 있다(리서치 이슈 #488, #292) | 빈 이미지는 공유하거나 저장하지 않는다. 첫 시도에서도 정상 이미지가 나와야 하며, 실기기 확인을 필수 항목으로 둔다. |
| 이미지 생성 전에 사용자 클릭이 끝나고, 공유창은 클릭 직후에만 열린다 | 클릭과 공유창 호출 사이가 길어지지 않아야 한다. 미리 만들어 둘지 클릭 뒤에 만들지는 열린 질문 14번. |
| 중복 클릭 시 같은 작업이 여러 번 실행된다 | 이미지 만들기 중에는 버튼이 로딩 상태가 되어 중복 실행되지 않는다. |
| 공유 버튼 문구와 아이콘에 고정된 제목·본문(`공유 이미지`, 빈 본문)이 있다 | 공유 제목과 본문은 기능별로 주고, 주소는 한 번만 넣는다(iOS 공유창이 문서 제목과 주소를 자동으로 붙이므로 중복 방지). |
| 캡처 대상 안의 버튼, 입력란, 광고, 동의 배너가 이미지에 섞일 수 있다 | 현재 훅은 `data-capture="ignore"`와 `pe-no-capture` 클래스로 뺀다. 공유 카드도 같은 표시로 버튼, 입력란, 광고, 동의 배너를 제외한다(AC-16). |

## 유저 스토리

- US-1: 모바일 사용자로서 오늘 뭐 먹지 결과 카드를 메신저 앱으로 친구에게 보내고 싶다. 같이 고르는 재미를 나누고 싶기 때문이다.
- US-2: PC 사용자로서 결과 링크를 복사하거나 카드 이미지를 저장·복사하고 싶다. 메신저 PC 앱이나 문서에 붙여 넣기 위해서다.
- US-3: 인앱 브라우저(카카오톡 등)에서 들어온 사용자로서 공유가 안 될 때 무엇을 해야 하는지 알고 싶다. 막다른 화면에서 멈추지 않기 위해서다.
- US-4: 사이트 운영자로서 공유 이미지와 링크에 생년월일, 입력 질문 같은 개인 정보가 실리지 않기를 원한다. 개인정보 처리 부담을 늘리지 않기 위해서다.

## 완료 조건 (AC)

QA가 이 목록으로 테스트를 만든다. 태그는 검증 층이다. `[E2E]`는 브라우저 흐름 한 화면 단위로 묶었다. `[E2E]` 중 실기기 항목은 자동 spec 대상이 아니라 수동 확인이며 `qa-report.md`에 따로 기록한다.

- AC-1 [E2E] (뭐 먹지, PC 흐름. 마우스 기기로 판정된 환경): 메뉴 결과가 나오기 전에는 공유 버튼이 보이지 않는다. 결과가 나오면 "링크 복사", "이미지 저장", "이미지 복사" 세 버튼이 메뉴 없이 바로 보이고, 320px 너비에서 가로 스크롤이 생기지 않는다. "링크 복사"를 누르면 "링크를 복사했어요" 안내가 뜬다. "이미지 저장"을 누르면 공유 카드 PNG 파일이 내려받아지고, 파일 크기가 0이 아니다. "이미지 복사"를 누르면 "이미지를 복사했어요" 안내가 뜬다. 이미지 복사 버튼은 지원하지 않는 환경에서는 보이지 않는다(AC-8).
- AC-2 [E2E] (뭐 먹지, 공유창 흐름. 모바일 판정 환경과 공유 기능을 모의): 결과가 나온 뒤 공유 버튼이 1개 보인다. 누르면 공유창이 열리고, 공유 카드 PNG 파일과 기능 주소가 같이 전달된다. 사용자가 공유창을 닫으면 오류 안내는 뜨지 않는다. 버튼을 빠르게 두 번 누르면 공유창 호출이 한 번만 일어난다.
- AC-3 [E2E] (이미지 만들기 실패, 실패를 모의): 이미지 만들기가 실패하면 "이미지를 만들지 못했어요. 링크로 공유해 주세요"(초안) 안내가 뜬다. 같은 화면에서 링크 공유가 그대로 동작한다(PC는 링크 복사와 이미지 저장 버튼이 그대로 동작한다). 빈 파일이 내려받아지거나 공유창에 넘어가지 않는다.
- AC-4 [E2E] (인앱 안드로이드 안내 화면, 카카오톡 사용자 에이전트와 공유·클립보드 차단을 모의): 공유 버튼을 누르면 "이 브라우저에서는 공유할 수 없어요"(초안) 안내 화면이 뜬다. 기능 주소가 화면에 보이고, 길게 눌러 복사하라는 안내가 같이 나온다. 외부 브라우저 강제 실행 시도는 없고, 안내 화면에서 결과 화면으로 돌아갈 수 있다.
- AC-5 [E2E] (로또 번호 생성기 회귀, 2차 전까지): 번호를 생성하면 기존 공유 버튼이 그대로 보이고, 이미지 공유와 저장이 전과 같이 동작한다. 공통 훅이 바뀌어도 로또 화면의 동작이 달라지지 않는다.
- AC-6 [E2E] (수동, 실기기 — 자동 spec 아님): iPhone Safari와 Android Chrome에서 각각 공유 카드 이미지 공유를 첫 시도부터 해 본다. 이미지가 빈 상태로 나오지 않는다. 카카오톡 Android 인앱, 네이버 앱, 인스타그램 인앱에서 AC-4 안내 화면이 뜨는지, 또는 공유가 되는지 기록한다. 대상 기기 목록은 열린 질문 7번.
- AC-7 [단위] (공유 카드 문구 규칙): 카드에 들어가는 문구는 "공유 카드 내용" 절의 해당 기능 행에 적힌 항목, 기능 주소, 고지 한 줄뿐이다. 생년월일, 질문, 상대방 정보, 동네 이름은 어떤 카드에도 들어가지 않는다. 사용자가 쓴 이름 목록은 해당 행에 "넣는 내용"으로 적힌 경우에만, 공유 직전 미리보기를 거친 뒤에만 들어간다(열린 질문 22). 고지 한 줄은 기능별 상수에서 가져오고, 카드 문구는 기능별 금지어 검사를 통과한다.
- AC-8 [단위] (공유 경로 분기 규칙): 입력은 기기 종류(모바일, PC 마우스 기기), 파일 공유 가능 여부, 이미지 복사 지원 여부, 카카오톡 Android 인앱 여부다. 결과는 다음과 같다.
  - 모바일, 파일 공유 가능: 공유 버튼 1개. 공유창에 카드 PNG와 기능 주소를 넘긴다.
  - 모바일, 파일 공유 불가: 공유 버튼 1개. 공유창에 기능 주소만 넘긴다. 파일은 넘기지 않는다.
  - 카카오톡 Android 인앱: 공유 버튼을 누르면 안내 화면(AC-4). 공유창은 열지 않는다.
  - PC(마우스 기기): 버튼 3개(링크 복사, 이미지 저장, 이미지 복사). 이미지 복사는 지원할 때만 보이고, 지원하지 않으면 버튼 2개다.
  - 판정이 실패하면 PC 경로(지원되는 버튼만)로 간다.
- AC-9 [단위] (공유 링크 주소 규칙): 공유 주소는 기능 소개 페이지의 canonical 주소와 같고, 쿼리 문자열과 입력값이 붙지 않는다. 주소는 `/`로 시작한다.
- AC-10 [정적] (적용 범위): 1차 대상 페이지(`/meal`, `/lucky-draw/ladder`, `/lucky-draw/roulette`, `/lucky-draw/lots`, `/fortune/compatibility`) 외의 결과 화면에는 공통 공유 버튼이 붙지 않는다. 사주, 꿈 해몽, 로또 기록·채점·분석·시뮬레이터, 나의 번호에는 공유 버튼이 없다. 로또 생성기는 2차 전까지 기존 버튼만 유지한다(열린 질문 16번).
- AC-11 [정적] (검색·미리보기 값 유지): 공유 기능을 넣은 뒤에도 대상 페이지의 `title`, `description`, OG 제목이 바뀌지 않는다. 새 라우트와 sitemap 항목이 생기지 않는다. 메타데이터는 `buildMetadata()`를 그대로 쓴다.
- AC-12 [정적] (문구 모음): 공유 버튼 문구, 안내 문구, 이미지 고지 문구가 문구 상수 파일 한 곳에 모여 있고, 기능별 copy-rule 검사 대상에 들어 있다.
- AC-13 [정적] (라이선스 문서): 새 라이브러리, 글꼴, 이미지를 넣었다면 `DEPENDENCY_LICENSES.md`와 `THIRD_PARTY_NOTICES.md`가 같이 갱신돼 있다. 넣지 않았다면 두 파일은 바뀌지 않는다.
- AC-14 [E2E] (카드 영역만 캡처, 레이아웃 불변. 뭐 먹지와 돌림판 결과 화면): "이미지 저장"을 누르면 내려받은 PNG의 가로·세로가 공유 카드의 기준 크기(설계 문서 값)와 같고, 화면 뷰포트 크기와는 다르다. 이미지 저장 뒤에도 결과 문장과 버튼의 위치가 바뀌지 않고, 320px에서 가로 스크롤이 없다.
- AC-15 [정적] (캡처 대상): 이미지 만들기는 공유 카드 요소 하나만 대상으로 한다. 페이지 전체, 결과 화면 루트, 버튼 영역을 대상으로 하지 않는다. 카드 기준 크기와 카드 레이아웃 값은 상수 한 곳에 있다.
- AC-16 [정적] (캡처 제외 표시): 카드 DOM 안에 버튼, 입력란, 광고, 동의 배너가 있으면 `data-capture="ignore"` 또는 `pe-no-capture` 표시가 붙어 이미지에서 빠진다. 1차 대상 화면 모두 해당한다.
- AC-17 [E2E] (이름 카드 미리보기, Q22): 사다리 참가자·돌림판 후보처럼 이름이 실리는 카드는 공유를 누르면 카드 이미지 미리보기가 먼저 뜬다. 이름은 기본으로 가려져 있고 해제할 수 있다. "이 내용으로 공유"를 누르기 전에는 파일이 내려받아지거나 공유창이 열리지 않는다. 취소하면 닫히고 포커스가 처음 누른 버튼으로 돌아간다. (상세 `docs/share/design.md` 6장)

## 예외·빈 상태

- 결과가 아직 없는 상태: 공유 버튼을 보이지 않게 하거나 비활성화하고, 이유를 짧게 알린다(설계 선택).
- 이미지 만들기 중: 버튼이 로딩 상태가 되고 중복 클릭이 무시된다.
- 이미지 만들기 실패(글꼴 로딩 실패, 메모리 부족, 빈 결과): 안내 후 링크 공유 경로를 연다. 빈 파일을 넘기지 않는다.
- 웹 글꼴이 아직 로드되지 않은 상태에서 만든 이미지: 한글이 기본 글꼴로 깨지지 않도록 글꼴 로딩이 끝난 뒤에 만든다.
- 공유창 취소: 오류 안내 없음.
- 공유 API 호출은 되지만 예외가 남(기기 문제): 안내 후 PC 경로(복사·저장)로 낮춘다.
- 이미지 복사를 지원하지 않는 PC: 이미지 복사 버튼만 숨기고, 나머지 두 버튼은 그대로 보인다. 버튼이 사라져도 화면이 흔들리면 안 된다.
- 공유 카드 미리보기: 이름 목록을 넣는 카드(사다리, 돌림판)는 공유 전에 카드 내용을 볼 수 있어야 한다(열린 질문 22).
- 클립보드 쓰기 권한 거부, 인앱 브라우저: 주소를 화면에 보이게 하고 길게 눌러 복사하라고 안내한다.
- 카카오톡 Android 인앱: 공유창과 클립보드 모두 막힐 수 있다. AC-4 안내 화면을 쓴다.
- 카카오톡 iOS 인앱, 네이버 앱, 인스타그램 인앱: 동작 근거가 부족하다. 실기기 결과가 나오기 전까지는 공유를 시도하고, 실패하면 AC-4와 같은 안내 화면을 쓴다(확인 필요).
- 다크 모드: 카드 배경과 글자 색이 기기 테마에 따라 바뀌면 글자가 안 보일 수 있다. 카드 배경을 고정할지 열린 질문 15번.
- 긴 결과 문장이나 긴 목록(사다리 참가자가 많음, 돌림판 후보가 많음): 카드에서 잘리거나 넘치지 않게 줄여서 보여 준다. 줄임 기준은 설계.
- 320px 너비: 공유 버튼, 메뉴, 안내 문구가 가로 스크롤을 만들지 않는다.
- 안내 화면에서 뒤로 가기: 결과 화면이 그대로 남아 있어야 한다.
- 로또 생성기: 공통 훅 변경으로 기존 이미지 공유가 깨지지 않는다(AC-5).
- 공유 카드에 들어갈 기능명과 결과 문장이 금지어에 걸리는 경우: 공유 버튼은 보이되 카드 문구를 기본 문구로 바꾼다. 문구 상수 설계는 설계 담당.

## 검색 노출

- 키워드:
  - 공유 기능 자체를 검색어로 노리지 않는다. 공유는 기존 페이지로 들어오는 유입 경로다.
  - 1차 대상 기능의 기존 검색어를 그대로 둔다: "오늘 뭐 먹지", "점심 메뉴 추천"(뭐 먹지 페이지), "사다리 타기", "돌림판", "제비뽑기"(운빨 뽑기 페이지), "띠 궁합", "별자리 궁합", "궁합 테스트"(궁합 페이지, `docs/TODO.md` 7번). 검색량 조회 결과는 각 기능 plan을 따른다.
  - "카카오톡 공유" 같은 검색어는 사용자 의도가 불분명해 키워드로 넣지 않는다(열린 질문 5번).
- 페이지가 답할 질문:
  - 뭐 먹지 페이지: 오늘 점심이나 저녁 메뉴를 어떻게 고르면 되는지, 이 도구가 무엇인지.
  - 운빨 뽑기 페이지: 사다리, 돌림판, 제비뽑기 중 무엇을 어떤 상황에 쓰는지.
  - 궁합 페이지: 띠나 별자리로 궁합을 어떻게 보는지, 무엇을 참고용으로 읽으면 되는지.
  - 공유 버튼은 본문 설명을 바꾸지 않는다. 공유로 들어온 방문자가 같은 질문에 바로 답을 얻는 것이 목표다.
- 공유 링크 미리보기: 공유되는 주소는 기능 소개 페이지다. 그 페이지의 OG 제목, 설명, 이미지가 기능에 맞게 나오는지 확인한다(AC-11). `/api/og-image`의 기본 문구는 로또용이므로 로또 문구가 다른 기능 미리보기에 나오지 않는지 본다. 기능별 고정 OG 이미지는 열린 질문 8번.

## 법적·정책 요구사항

- 개인정보 수집:
  - 뭐 먹지는 입력값을 받지 않는다. 운빨 뽑기 사다리와 돌림판은 사용자가 쓴 이름이나 항목을 카드에 넣을 수 있다(열린 질문 22). 궁합은 생년월일과 상대방 정보를 입력받지만 카드에는 띠·별자리 이름과 등급만 넣는다(열린 질문 1).
  - 공유 기능은 브라우저 안에서 이미지와 주소를 만들고, 서비스 서버로 결과를 보내지 않는다(리서치 4.6 기준, 설계에서 확인).
  - 공유 기록(클릭 수 등)은 1차에서 만들지 않는다(열린 질문 12번). 만들면 방침 1장과 6장 갱신이 필요하다.
  - 2차 운세·띠·별자리도 생년 정보는 카드에 넣지 않는 것을 기본으로 한다. 그러면 공유 기능이 새로 수집하는 정보는 없다.
  - 결과 전용 링크를 만들면(열린 질문 2번, 기본값은 만들지 않음) 결과 값의 보관, 보관 기간, 방침 갱신이 필요하다. 법률 확인 필요.
  - 사다리·돌림판의 이름 목록은 아동 이름이 들어갈 수 있다. `docs/TODO.md`의 운빨 뽑기 위험 수용 기록(아동 이름 입력)과 연결되므로, 미리보기를 넣을지 법률과 함께 확인한다(열린 질문 22).
- 고지 문구:
  - 카드 하단 고지 한 줄(1차 초안):
    - 뭐 먹지: "재미로 고른 메뉴예요. 개인 정보는 담기지 않아요."
    - 운빨 뽑기: "재미와 참고를 위한 무작위 결과예요. 금전이나 승부와 관계없어요."
    - 궁합: "재미로 보는 참고용 결과예요. 실제 관계를 판단하지 않아요."
  - 세 문구는 초안이다. 법률 확인 필요이며, 문구 확정은 PM 승인으로 한다. 운빨 뽑기와 궁합 고지는 `COMPLIANCE.md`의 오락 목적 표기 형식을 따른다.
  - 2차 해석 기능(운세, 타로)은 "오락·참고용" 고지를 카드에도 넣는다(열린 질문 4번). 위기 안내 문구는 카드에 넣지 않는다(열린 질문 17번).
  - 공유 버튼이 보이는 화면의 기존 고지(약관, 방침 링크, 위기 안내)는 그대로 둔다.
- 상업적 이용 주의:
  - 공유 카드에 광고 요소, 광고 링크, 상업 문구를 넣지 않는 것을 기본으로 한다. 광고 플랫폼의 공유 이미지 정책은 이번 조사에서 확인하지 못했다. 확인 필요(열린 질문 13번).
  - 카드 글자에 쓰는 글꼴은 라이선스를 확인해야 한다. 이번 조사에서 프로젝트 현행 웹 글꼴의 라이선스는 확인하지 않았다. 확인 필요. 새 글꼴을 넣으면 OFL 등 조건(라이선스 문구 동봉, 이름 규칙)을 맞추고 `THIRD_PARTY_NOTICES.md`를 갱신한다. 서브셋(글자만 추린 파일)은 법률 확인 필요.
  - 카드 로고를 쓰면 로고의 저작권과 상표를 확인한다(열린 질문 21).
  - 타로 카드 그림은 권리 확인 전까지 2차에서도 쓰지 않는다(열린 질문 23).
  - 이모지는 1차에서 넣지 않는다(열린 질문 10번). 넣으면 Twemoji(CC BY 4.0) 표기가 필요하다.
  - 메신저 이름과 로고(카카오톡 등)를 버튼이나 아이콘에 쓰면 상표 확인이 필요하다(열린 질문 5번).
  - 운빨 뽑기 결과를 이미지로 퍼뜨리는 것이 사행성 해석에 영향을 주는지는 기존 위험 수용 범위를 넘는다. 법률 확인 필요(열린 질문 18번).
  - 로또 번호 이미지 공유는 2차 전에 사행성과 당첨 연상 고지를 확인한다(열린 질문 16번).
  - 라이브러리: `html-to-image`(MIT)와 `downloadjs`(MIT)는 `DEPENDENCY_LICENSES.md`에 이미 있다. 새 라이브러리가 필요 없으면 변경 없음.

## 열린 질문

각 질문 뒤에 권장안을 적었다. 번호 1~13은 `docs/research/share.md` 열린 질문(R1~R13)과 맞춘다. 14번 이후는 새 질문이다. 사용자 확인이 필요한 것은 1, 7, 14, 16, 21, 22, 23번이다. 11번은 사용자 결정(2026-11-24)으로 반영했다.

1. (R1) 1차 대상 범위와 궁합 포함. PM 권장안: 1차는 뭐 먹지, 운빨 뽑기 3종(사다리, 돌림판, 제비뽑기), 궁합. 2차는 운세·띠·별자리, 타로, 로또 생성기. 제외는 사주, 꿈 해몽, 로또 기록·채점·분석·시뮬레이터. 궁합은 생년월일과 상대방 정보를 카드에서 뺀다. 궁합은 `docs/TODO.md`의 궁합 위험 수용(2026-11-24: 상대방 정보 입력, 개인정보보호법 제22조의2, 표시광고법, AI 문구 권리) 범위를 넘는 새 위험이 있는지 법률 확인이 필요하다. 특히 띠·별자리 이름과 등급이 생년월일 파생값이라는 점을 본다. 사용자 승인 필요.
2. (R2) 결과 전용 링크를 만들까. 권장: 만들지 않는다. 결과 값을 URL이나 서버에 넣지 않는다.
3. (R3) 공유 카드에 무엇을 넣을까. 권장: 기능별 "공유 카드 내용" 절의 항목, 기능 주소, 고지 한 줄. 날짜는 넣지 않는다(결과가 무작위라 날짜 의미가 약하고, 오래된 이미지로 오해될 수 있음).
4. (R4) 카드에 오락·참고 고지를 넣을까. 권장: 넣는다. 1차 문구는 "고지 문구" 절의 초안. 법률 확인 필요.
5. (R5) 버튼 문구에 "카카오톡"을 쓸까. 권장: "공유하기"로 쓴다. 공유창에서 앱을 고르는 방식이라 이름이 없어도 된다. 안내 문구에서 카카오톡을 언급하는 경우에만 상표 확인을 한다.
6. (R6) 카카오톡 Android 인앱 안내 화면 문구. 권장: "이 브라우저에서는 공유할 수 없어요. 아래 주소를 길게 눌러 복사한 뒤 다른 앱에서 붙여 넣어 주세요."(초안). 외부 브라우저 강제 실행은 하지 않는다. 강제 실행 방법은 이번 조사에서 확인하지 못했다.
7. (R7) 실기기 대상 목록. 권장: iPhone Safari(최신 iOS 1개와 한 버전 전), Android Chrome(최신 1개), 카카오톡 Android와 iOS 인앱, 네이버 앱, 인스타그램 인앱. 버전 번호는 QA 시작 전에 PM이 정한다. 인스타그램과 네이버 앱은 근거가 없어 실기기 결과로 판단한다.
8. (R8) `/api/og-image`를 계속 쓸지, 기능별 고정 이미지로 바꿀지. 권장: 1차에서는 기존 페이지 OG 값만 점검한다(AC-11). 기능별 고정 이미지는 2차 전에 정한다. 공유 카드에는 서버 OG 경로를 쓰지 않는다(클라이언트 캡처 방식).
9. (R9) 한글 글꼴. 권장: 클라이언트 캡처 방식에서는 `next/og`의 500KB 한도가 적용되지 않는다. 그래서 웹에서 쓰는 글꼴을 그대로 쓰고, 캡처 전에 글꼴 로딩이 끝났는지 확인한다. 카드 전용 글꼴 파일을 따로 만들면 OFL 서브셋 규칙을 확인한다. 법률 확인 필요.
10. (R10) 이모지. 권장: 1차는 넣지 않는다.
11. (R11) PC 이미지 복사 버튼. 사용자 결정(2026-11-24): PC는 링크 복사, 이미지 저장, 이미지 복사 세 버튼을 둔다. 이미지 복사는 기기가 지원할 때만 보인다(AC-8). 지원 판정 방식과 실패 안내는 설계에서 정하고, 실기기 PC 브라우저에서 확인한다.
12. (R12) 공유 버튼 클릭 기록. 권장: 1차에서는 기록하지 않는다. 기록하면 방침 갱신 후 시작한다.
13. (R13) 광고와 공유 카드. 권장: 공유 카드에는 광고 요소를 넣지 않는다. 공유 화면의 광고 배치는 기존 정책을 따른다. 광고 플랫폼 정책 확인 필요.
14. (신규) 이미지 준비 시점. iOS는 공유창을 사용자 클릭 직후에만 열 수 있다는 점을 고려해야 한다. 질문: 결과가 나온 뒤 미리 이미지를 만들어 두고 클릭 시 바로 공유할지, 클릭 뒤에 만들지. 권장: 결과가 나오면 미리 만들어 두고(실패하면 다시 시도 버튼), 클릭 시에는 공유창만 연다. 미리 만든 이미지가 오래되면 다시 만든다. 실기기에서 어느 쪽이 빈 이미지 없이 되는지 확인 후 확정. 사용자 확인 필요.
15. (신규) 카드 배경. 질문: 카드 배경을 기기 테마에 맞출지, 항상 같은 색으로 할지. 권장: 항상 같은 밝은 배경과 어두운 글자로 고정한다. 이미지가 어디서 보여도 글자가 보이게 하기 위해서다.
16. (신규) 로또 생성기 기존 공유 버튼. 질문: 2차에서 새 카드 형식으로 옮길지, 1차 동안 그대로 둘지. 권장: 1차 동안 그대로 두고 훅 변경으로 깨지지 않는지만 본다(AC-5). 2차에서 새 형식으로 옮기되, 번호 이미지 공유의 사행성 해석과 당첨 연상 고지를 법률 확인한 뒤 옮긴다. 사용자 확인 필요.
17. (신규) 위기 안내가 있는 결과(타로, 운세 일부)의 공유. 질문: 위기 안내 문구나 죽음 관련 풀이를 카드에 넣을지, 그런 결과는 공유 버튼을 숨길지. 권장: 위기 안내 문구는 카드에 넣지 않고, 위기 신호가 있는 결과는 공유 버튼을 숨긴다. 2차에서 기능별로 확정.
18. (신규) 운빨 뽑기 결과 카드와 사행성. 질문: 돌림판과 제비뽑기 결과를 카드로 공유해도 되는지, 고지 한 줄로 충분한지. 권장: 1차는 고지 한 줄로 진행하고 법률 확인을 받는다. 문제가 되면 카드 공유만 뺀다. `docs/TODO.md`의 운빨 뽑기 위험 수용 기록(2026-11-23)에 이 항목을 추가한다.
19. (신규) 공유 시 같이 보내는 텍스트. 질문: 공유창에 넘길 본문 문구와 주소를 어떻게 줄지. 권장: 본문은 기능명과 짧은 한 줄만 두고, 주소는 한 번만 넣는다. iOS가 문서 제목과 주소를 자동으로 붙이므로 중복 여부는 실기기에서 확인한다.
20. (신규) 입력 중 상태. 질문: 뭐 먹지 동네 이름 입력란이 있는 화면에서 입력 중인 값이 카드나 링크에 들어가지 않게 막을지. 권장: 카드와 링크에는 입력값을 넣지 않으므로 AC-7, AC-9로 막는다. 추가 확인 없음. 참고용.
21. (신규, 사용자 추가 요구) 공유 카드를 화면 그대로 캡처할지, 공유용 고정 폭 레이아웃을 따로 그릴지. 권장: 따로 만든다. 화면 그대로 찍으면 버튼, 입력란, 헤더가 들어가고 화면 폭에 따라 크기가 흔들린다. 따로 만든 카드는 기능명, 결과, 기능 주소, 고지 문구를 항상 같은 자리에 둘 수 있다. 단점은 디자인과 구현이 한 벌 더 든다는 것이다. 카드는 화면 밖이나 숨김 영역에서 그리고, 공유 직전에 그 영역만 캡처한다(AC-14, AC-15). 카드 로고는 기존 사이트 로고를 쓸지 정해야 하며, 로고의 저작권과 상표는 확인이 필요하다. 사용자 확인 필요.
22. (신규, PM 추가 요구) 이름 입력을 카드에 넣는 경우 공유 직전 미리보기. 대상은 사다리 참가자 목록, 돌림판 후보 목록(PM 1차 안에서 포함). 질문: 공유를 누르면 카드 이미지를 미리 한 번 보여 주고 "이 내용으로 공유" 버튼을 누르게 할지. 권장: 넣는다. 미리보기는 이름이 실린 카드에만 적용하고, 미리보기에서 이름이 보이면 해당 항목을 빼거나 가린 뒤 다시 만들 수 있게 한다. 미리보기만으로는 아동 이름 위험을 충분히 막지 못할 수 있으므로 기본 가림(예: 두 번째 글자 이후 가림)을 같이 검토한다. 미리보기 채택 시 AC를 추가한다(확인 1회: 미리보기 뜸, 승인 전에는 파일이 내려받아지거나 공유창이 열리지 않음). 사용자 확인 필요.
