# 공유 UI/UX 디자인 명세

입력: `docs/share/plan.md`(승인), `docs/share/design.md`(승인, D-1~D-8 확정, AC-17 이름 카드 미리보기 추가), 결과 화면 맥락은 `docs/menu-meals/ui-ux-design.md`(결과 카드·지도 링크·고지 자리), `docs/lucky-draw/ui-ux-design.md`(사다리·돌림판·제비뽑기 결과 영역), `docs/compatibility/ui-ux-design.md`(궁합 결과 패널)의 결과 화면 절만 읽었다.
규칙: `docs/conventions/design-system.md`, `code-style.md`의 "먼저 재사용할 기존 코드".
작성일: 2026-11-24. 상태: 작성 완료, 승인 대기. 코드는 쓰지 않았다.

## 디자인 방향

한 줄 요약: 화면의 공유 영역은 결과 아래에 조용히 붙는 보조 버튼 줄이고, 공유되는 카드 이미지는 "피클 병에 붙인 종이 라벨"처럼 보이는 밝은 종이 한 장이다.

- 이유: 사이트 컨셉이 "피클 병 속 연구실"(종이 위 잉크)이라, 이미지가 메신저에 단독으로 떠도 출처가 라벨 한 장으로 알아보이게 한다. 사이트 로고 이미지를 쓰지 않으므로 이 틀이 브랜드 역할을 대신한다.
- 화면 쪽 공유 영역은 개성을 주지 않는다. 결과가 주인공이고, 공유는 모든 기능에서 똑같은 모양이어야 학습 비용이 없다. 이 기능의 개성은 **카드 이미지(기능명 이름표 + 기능별 본문 연출)** 한 곳에만 둔다.
- 템플릿스러운 기본값(그라데이션 배경, 큰 숫자와 작은 라벨, 카드마다 같은 그림자)은 쓰지 않는다. 카드는 면을 나누지 않고 선과 글자 크기 차이로 위계를 만든다.

## 색상

화면(웹 UI)은 기존 토큰만 쓴다. 카드(이미지)는 design.md 2.8이 정한 카드 전용 고정 토큰만 쓴다. 카드는 `.dark`와 무관하게 항상 같은 색이다(Q15).

### 화면 UI

| 용도 | 토큰 | 이유 |
|---|---|---|
| 공유 버튼(보조 동작) | `variant="outline"` 기본 색(`border`, `foreground`, `card` 면) | 결과 화면의 주요 버튼(돌리기, 시작 등)은 메뉴 색이 이미 쓰고 있다. 공유는 보조 동작이라 같은 위계로 경쟁하지 않는다 |
| 버튼 포커스 링 | `ring`(primary) | 규칙: 포커스는 메뉴와 상관없이 primary |
| 로딩 스피너, 아이콘 | `muted-foreground` | 로딩은 눈에 띄지 않게. 글자(preparingLabel)가 같이 있다 |
| 준비 실패·복사 실패 안내 | `text-destructive` + `CircleAlert` | 운빨 뽑기 명세의 입력 오류 방식과 같다 |
| 인라인 안내(인앱, 클립보드) | 면 `card`, 테두리 `border`, `rounded-panel`, 아이콘 `Info`는 `muted-foreground` | 오류가 아니라 "이렇게 하세요" 안내라 경고색을 쓰지 않는다 |
| 주소 상자 | 면 `background`, 테두리 `border`, `rounded-md`, `font-mono` | 주소는 코드 성격의 글자이고, 길게 눌러 선택하는 대상이라 면으로 구분한다 |
| 미리보기 확인 버튼 | 기본 `primary` 버튼 | Dialog는 모든 기능 공통이라 메뉴 색을 쓰지 않는다. 확인 한 개만 채운 버튼이다 |
| 미리보기 이미지 틀 | `border`, `rounded-md`, 면 `muted/40` | 카드 밝은 배경이 Dialog 면(`popover`)과 같은 색이라 경계가 필요하다 |

### 카드 (이미지) 고정 토큰

design.md가 이름만 정한 7개 토큰의 값을 확정한다. `globals.css`의 `:root`에 넣고 `.dark`에서는 덮어쓰지 않는다. Tailwind 색으로 쓰려면 `menu-*`와 같은 방식으로 `@theme`에 `--color-share-card-*`로 등록한다.

| 토큰 | 값 | 용도 | 대비 (종이 `#eef0e6` 기준, 계산값) |
|---|---|---|---|
| `--share-card-bg` | `#eef0e6` | 카드 바탕 | — |
| `--share-card-fg` | `#1b3328` | 본문 글자 | 약 11:1 |
| `--share-card-muted` | `#5a6a5f` | 보조 글자(고지, 사이트 이름) | 약 5.0:1 |
| `--share-card-border` | `#b9c3a8` | 라벨 테두리, 구분선 | 장식이라 대비 요구 없음. 메신저 압축에도 보이게 사이트 `border`(`#d3d9c4`)보다 진하게 잡았다 |
| `--share-card-accent-meal` | `#a5481f` | 뭐 먹지 이름표 | 종이 위 글자 약 5.1:1 |
| `--share-card-accent-lucky` | `#4b4690` | 운빨 뽑기 이름표 | 약 7.1:1 |
| `--share-card-accent-fortune` | `#8a6110` | 궁합 이름표 | 약 4.8:1 |

- 값은 기존 `background`, `foreground`, `muted-foreground`, `menu-meal`, `menu-lucky`, `menu-fortune`와 같다. 새 색을 만들지 않고 "고정 복사본"을 만든 것이다. 이유: 다크 모드를 나중에 켜도 이미지는 바뀌면 안 되고(Q15), 원본 토큰은 `.dark`에서 바뀐다.
- 새 토큰은 위 7개뿐이고 모두 design.md가 이미 승인한 이름이다. 값 승인만 받는다.
- **강조색 사용 규칙(대비)**: 강조색 글자는 맨 종이 바탕 위에서만 쓴다. 강조색 10% 옅은 면(`accent/10`) 위의 글자는 항상 `--share-card-fg`를 쓴다. 이유: 계산해 보면 옅은 면 위 강조색 글자는 뭐 먹지 약 4.5:1(경계), 궁합 약 4.2:1(부족)이다.
- 강조색 면적: 이름표(작은 면)와 기능별 연출 한 곳의 선·글자. 큰 면을 칠하지 않는다(design-system "큰 면적 금지").
- 카드에는 `dark:` 변형, hex 직접 값, Tailwind 기본 팔레트를 쓰지 않는다.

폰트는 Pretendard Variable 하나뿐이다. 카드에도 `font-mono`를 쓰지 않는다(Fira Mono를 임베드하면 캡처 준비가 느려지고 D-5 글꼴 임베드 대상이 늘어난다). 카드 숫자는 `tabular-nums`.

| 요소 | 크기 | 굵기 | 줄 간격 |
|---|---|---|---|
| 공유 버튼 글자 | 14px (`text-sm`) | 500 | 20px, 줄바꿈 허용(`min-h-11`, `py-2`) |
| 인라인 안내 제목 | 16px | 600 | 24px |

| 오류 안내, 옵션 설명 | 14px | 400 | 20px |
| Dialog 제목 | 18px | 600 | 28px |

### 카드 (CSS px 기준. PNG는 2배 = 1080×1350)

메신저에서 카드는 폭 약 300px로 줄어 보인다(축소 비율 약 0.55). 그래서 가장 작은 글자도 16px(화면에서 약 9px)로 하고, 읽어야 하는 글자는 20px 이상으로 한다.

| 요소 | 크기 | 굵기 | 줄 간격 | 색 |
|---|---|---|---|---|
| 기능명 이름표 | 20px | 700 | 1 (높이 36px 고정) | 종이색 글자 on 강조색 면 |
| 사이트 이름 | 16px | 600 | 1 | `muted` |
| 결과 핵심(뭐 먹지 메뉴, 돌림판 결과) | 72 → 30px 단계(기능별 표) | 700 | 1.15 | `fg` |
| 보조 결과(사다리·제비뽑기 줄, 궁합 이름) | 20~44px 단계 | 600~700 | 1.2 | `fg` / 강조색(맨 종이 위만) |
| 본문 문장(궁합 요약) | 22px(길면 20px) | 400 | 1.55 | `fg` |
| 주소 | 16px | 600 | 22px | `fg` |
| 고지 한 줄 | 16px | 400 | 22px, 최대 2줄 | `muted` |

- 모든 카드 글자는 `word-break: keep-all`(한국어 어절 단위 줄바꿈)이고, 긴 영문·숫자 덩어리만 `overflow-wrap: anywhere`로 끊는다. 이유: 한국어를 글자 단위로 끊으면 단어가 쪼개져 읽기 어렵다.
- 대문자 라벨, 점으로 이은 메타 문장, 화살표 장식을 쓰지 않는다.

## 간격·그리드

화면: 공유 영역과 위 요소 사이 16px(`mt-4`), 버튼 사이 8px(`gap-2`), 버튼 높이 최소 44px, 영역 최대 폭 448px(`max-w-md`), 왼쪽 정렬. 폭이 넓은 화면에서 버튼이 길게 늘어나지 않게 하고, 결과 카드와 같은 왼쪽 선을 따른다.

카드(CSS px, 4px 단위): 아래 값은 `share.constant.ts`가 아니라 카드 틀 컴포넌트의 레이아웃 값이다. 단 크기 540×675는 AC-15 대로 `SHARE_CARD_SIZE` 한 곳에서만 온다.

| 영역 | 값 |
|---|---|
| 카드 | 540×675, 바탕 `bg` |
| 바깥 여백 | 20 |
| 라벨(안쪽 틀) | 500×635, 테두리 2px `border`, 반경 14(`rounded-panel`) |
| 라벨 안쪽 여백 | 28 → 내용 폭 440, 내용 높이 575 |
| 머리 | 높이 36, 아래 간격 20 |
| 본문 | 높이 약 410 (남는 높이를 모두 차지, 가운데 정렬 기본) |
| 꼬리 | 위 간격 20, 구분선 1px `border`, 위 14, 주소 22, 간격 4, 고지 최대 2줄 44 → 약 86 |

- 본문 높이는 꼬리 고지가 1줄이어도 2줄 높이를 항상 예약한다. 이유: 기능마다 카드 아래쪽이 같은 자리에 있어야 한다(plan 열린 질문 21의 "항상 같은 자리").

## 화면별 레이아웃

### 1. 공유 영역 (`SharePanelComponent`) 위치와 모양

구조: `role="group"`, 이름 "결과 공유"(sr-only 라벨, `aria-label`). 결과가 있을 때만 그린다(design.md: `cardKey` null이면 없음).

모바일 (공유창 모드, 버튼 1개)
```
 ┌ 결과 영역 ──────────────────────┐
 └─────────────────────────────────┘
 ┌─────────────────────────────────┐ ← outline, 폭 100%(최대 448), 높이 44
 │  ⇪  공유하기                    │    아이콘 Share2 16px
 └─────────────────────────────────┘
```

PC (마우스 기기, 버튼 3개) — 영역 폭이 352px(22rem) 이상이면 한 줄, 미만이면 세로
```
 ┌─────────┐┌─────────┐┌─────────┐
 │ 링크 복사 ││ 이미지 저장 ││ 이미지 복사 │   각 버튼 flex-1, 높이 44
 └─────────┘└─────────┘└─────────┘
 (320px 화면)
 ┌─────────────────────────────┐
 │ 링크 복사                    │
 ├─────────────────────────────┤  세로 쌓임, 간격 8
 │ 이미지 저장                  │
 ├─────────────────────────────┤
 │ 이미지 복사                  │  (미지원이면 이 버튼만 빠진다)
 └─────────────────────────────┘
```

- 아이콘(lucide, 16px, `aria-hidden`): 공유하기 `Share2`, 링크 복사 `Link2`, 이미지 저장 `Download`, 이미지 복사 `Copy`. 새 아이콘 세트 없음. 메신저 로고 없음(Q5).
- 한 줄/세로 전환 기준은 화면 폭이 아니라 **영역 폭**이다(컨테이너 쿼리 `@container`, `@[22rem]:flex-row`). 이유: 뭐 먹지 데스크톱 결과 열(약 400px)과 궁합 패널(최대 4xl)처럼 열 폭이 제각각이라, 화면 폭 기준으로는 열 안에서 줄바꿈이 어긋난다.
- 이미지 복사가 지원되지 않아 버튼이 2개가 돼도 버튼이 `flex-1`이라 남는 폭을 나눠 가진다. 영역 높이는 변하지 않는다(plan "화면이 흔들리면 안 된다").
- `unknown` 모드(마운트 직전): 같은 위치에 높이 44px 빈 자리만 둔다. 이유: 흔들림 방지. 결과는 마운트 이후에 나오므로 실제로는 거의 안 보인다.
- 모바일에서 공유창 없이 PC 경로로 낮아지면(`shareFailed`) 버튼이 1개에서 3개로 바뀐다. 이때 눌렀던 버튼이 사라지므로 **포커스를 새 첫 버튼("링크 복사")으로 옮긴다**. 이유: 포커스가 사라지면 키보드·스크린리더 사용자가 위치를 잃는다.

#### 준비 중·실패 표시 (이미지가 필요한 버튼만)

- 준비 중: 이미지를 쓰는 버튼(모바일 "공유하기" 파일 경로, PC "이미지 저장", "이미지 복사")은 `aria-disabled="true"`, 아이콘이 `Loader2`(회전)로 바뀌고 글자는 그대로다. 글자를 바꾸지 않는다. 이유: 결과가 나온 직후 약 0.4~2초 동안만 보이는 상태라, 글자가 "공유하기" → "이미지 만드는 중" → "공유하기"로 바뀌면 깜빡임으로 읽힌다. 보조 기기에는 `aria-describedby`로 sr-only "이미지 만드는 중"을 연결한다. "링크 복사"는 이미지가 필요 없으므로 준비 중에도 정상이다.
- 준비 실패: 버튼 줄 아래에 인라인 오류 한 줄(`CircleAlert` + "이미지를 만들지 못했어요. 링크로 공유해 주세요")과 보조 버튼 "이미지 다시 만들기"(outline, 높이 44, 작은 크기 아님). `role="alert"`로 한 번 읽힌다. 링크 공유(모바일은 링크만 공유, PC는 링크 복사)와 PC "이미지 저장"은 그대로 동작한다(AC-3).
- 빈 이미지, 재시도 소진도 같은 실패 표시를 쓴다. 빈 파일은 내보내지 않는다.

#### 인라인 안내 (`ShareGuideComponent`) — 카카오 Android 인앱, 클립보드 거부 (D-4 A안)

```
 ┌ border, card 면, rounded-panel, p-4 ─────────┐
 │ ⓘ 이 브라우저에서는 공유할 수 없어요       │ ← 제목 16/600 (제목 태그 아님)
 │ 아래 주소를 길게 눌러 복사한 뒤 다른 앱에서 │ ← 본문 14/24
 │ 붙여 넣어 주세요.                            │
 │ ┌ 주소 상자 (font-mono, select-all) ────┐  │ ← 높이 ≥44, 줄바꿈 허용
 │ │ pickle-eight.vercel.app/meal           │  │
 │ └────────────────────────────────────────┘  │
 │ [ 결과로 돌아가기 ]                          │ ← outline, 모바일 폭 100%
 └──────────────────────────────────────────────┘
```

- 인앱(`in-app`): 안내가 공유 버튼 자리를 **대신한다**. 공유 버튼은 어차피 동작하지 않기 때문이다. "결과로 돌아가기"를 누르면 공유 버튼이 되돌아오고 포커스는 그 버튼으로 간다.
- 클립보드 거부(`clipboard`, PC): 버튼 3개는 **그대로 두고 그 아래에 안내를 붙인다**. 이유: "이미지 저장"은 클립보드 없이도 되므로 지우면 안 된다. 제목·본문은 `guideClipboardTitle/Body`, 같은 모양.
- 주소: 선택 가능한 일반 텍스트(`select-all`, 한 번 눌러도 전체 선택)이고 입력란이 아니다. `tabIndex=0`과 `aria-label` "공유 주소"로 키보드 사용자도 포커스해서 선택할 수 있다. 줄바꿈은 `break-all`이라 320px에서 가로 스크롤이 없다.
- 안내가 열리면 포커스가 안내의 제목 줄(`tabIndex=-1`)로 이동하고 화면이 안내가 보이는 곳까지 스크롤된다(`block: nearest`). Esc로도 닫을 수 있다.
- 외부 앱 열기, 강제 이동 버튼은 없다. 뒤로 가기는 history를 건드리지 않으므로 결과 화면이 그대로 남는다.

### 2. 기능별 배치

공통 규칙: 공유 영역은 **결과를 읽는 순서의 끝, 그 기능의 하단 고지 앞**에 둔다. DOM 순서 = 시각 순서 = 탭 순서. 카드 호스트(화면 밖)는 DOM 어디에 있어도 보이지도 포커스되지도 않는다(`inert`, `aria-hidden`).

| 기능 | 위치 | 나타나는 때 | 비고 |
|---|---|---|---|
| 뭐 먹지 `/meal` | 결과 카드(지도 링크 3개까지 포함)의 바로 아래, "무작위·보상 없음" 고지 앞. 데스크톱은 오른쪽 결과 열 안 | 룰렛이 멈추고 결과가 나온 뒤 | 끼니를 바꾸면 결과가 지워지므로 공유 영역도 함께 사라진다. 지도 링크 → 공유 → 고지 순서 |
| 사다리 `/lucky-draw/ladder` | "전체 결과" 목록(과 "결과 보기" 버튼) 아래, 결과 하단 고지 앞 | 보이는 결과가 1개 이상일 때 | 결과 가리기는 "결과 보기" 뒤에, 한 명씩 열기는 첫 확인 뒤에 나타난다. 이름을 하나 더 확인하면 카드 내용이 바뀌어 버튼이 잠깐 준비 중이 된다 |
| 돌림판 `/lucky-draw/roulette` | 결과 영역 바로 아래(모바일은 "남은 항목" 위, 데스크톱은 오른쪽 열 맨 아래) | 결과가 공개된 뒤(`done`이고 공개) | 결과 가리기에서는 "결과 보기"를 누르기 전에는 없다 |
| 제비뽑기 `/lucky-draw/lots` | **카드 격자 아래**, 결과 하단 고지 앞 | 열린 카드가 1장 이상일 때 | 격자 위나 도구 막대에 두면 첫 카드를 여는 순간 격자가 아래로 밀려 다음에 누를 카드 위치가 움직인다. 격자 아래는 누르는 중에 위쪽 요소가 안 움직인다 |

- 궁합만 공유 영역 바로 아래에 개인정보 안내 한 줄(14px, `muted-foreground`, 앞 아이콘 `EyeOff`, 합니다체)을 둔다: "공유 이미지에는 생년월일과 입력한 정보가 담기지 않습니다." 이유: 궁합은 생년월일과 상대방 정보를 입력받는 유일한 1차 기능이라 누르기 전에 불안을 줄여야 한다. 새 문구라 궁합 copy-rule 검사 대상에 넣어야 한다(열린 질문 P-1).
- 뭐 먹지에는 이 안내가 필요 없다(입력값이 없고 카드 고지에 같은 뜻이 있다). 사다리·돌림판은 미리보기 Dialog가 그 역할을 한다.

### 3. 이름 카드 미리보기 (`SharePreviewDialogComponent`, 사다리·돌림판, AC-17)

shadcn `Dialog`를 쓴다. 이미지가 나가는 동작(모바일 파일 공유, PC 이미지 저장·이미지 복사)을 눌렀을 때만 열린다. 링크만 나가는 동작은 열리지 않는다.

모바일 (320px, Dialog 폭 288)
```
┌ Dialog (max-h = 100dvh - 2rem, 안쪽 세로 스크롤) ┐
│ 공유할 이미지 미리보기                    [×]    │ ← 제목 18/600
│ 이미지에 들어갈 이름을 확인해 주세요. 필요하면  │ ← 설명 14/muted
│ 가리거나 뺄 수 있어요.                           │
│ ┌ 이미지 틀 (4:5, 폭 100%, 높이 최대 45dvh) ─┐ │
│ │      (실제로 나갈 PNG)                      │ │
│ └─────────────────────────────────────────────┘ │
│ 이름 가리기                           [ 스위치 ]│ ← 줄 높이 ≥44, 라벨 전체 클릭
│ 첫 글자만 남기고 가려요.                         │
│ 후보 목록 넣기 (돌림판만)             [ 스위치 ]│
│ 끄면 결과만 이미지에 들어가요.                   │
│ (가림을 끄면) ⓘ 가리지 않으면 입력한 이름이 …   │
├──────────────────────────────────────────────────┤ ← 하단 고정(스크롤 밖)
│ [ 취소 ]                                         │ ← 폭 288에서는 세로
```

데스크톱 (640px 이상, Dialog 최대 폭 672px)
```
│ 공유할 이미지 미리보기                       [×] │
│ 이미지에 들어갈 이름을 확인해 주세요. …           │
│ ┌ 이미지(폭 280) ┐   이름 가리기        [스위치] │
│ │               │   첫 글자만 남기고 가려요.      │
│ │               │   후보 목록 넣기     [스위치] │
│ └───────────────┘   끄면 결과만 …                │
│                                  [취소][이 내용으로 공유]│
```

- 이미지 틀은 `<img>`(object URL)이고 카드 비율 4:5를 항상 유지한다. 높이를 `45dvh`로 제한하고 폭은 비율대로 줄인다. 이유: 320×568 화면에서 이미지가 화면을 다 먹으면 옵션과 버튼을 못 본다. 이미지 확대 기능은 넣지 않는다.
- 확인 버튼 글자는 연 동작에 따라 "이 내용으로 공유"(모바일), "이 내용으로 저장", "이 내용으로 복사"(PC). 뜻은 한 가지(지금 보이는 그대로 내보낸다)이고 동작 이름만 다르다.
- 기본값(D-3 A): 이름 가리기 켬, 돌림판 후보 목록 넣기 켬. 이름 가리기를 끄면 스위치 아래에 안내 한 줄(`Info`): "가리지 않으면 입력한 이름이 이미지에 그대로 들어가요." 이유: 약관 문단의 "다른 사람 이름은 동의를 받는다"를 버튼을 누르는 자리에서 한 번 더 알린다. 경고색은 쓰지 않는다.
- 옵션을 바꾸면 이미지가 다시 만들어지는 동안(약 0.4~2초): 기존 이미지를 `opacity-60`으로 두고 가운데에 `Loader2`와 "이미지 만드는 중"(보이는 글자), 확인 버튼은 `aria-disabled`. 이미지가 바뀌는 순간 즉시 교체한다(페이드 없음). 이유: 이미지가 사라졌다 나타나면 틀 높이가 흔들린다.
- 실패 시: 이미지 틀 안에 `CircleAlert` + 실패 문구 + "이미지 다시 만들기", 확인 버튼 `aria-disabled`. 취소는 항상 가능하다.
- 확인: 그 클릭 안에서 동작을 실행하고 Dialog를 닫는다(design.md 6장). 취소, Esc, 바깥 클릭, ×는 모두 취소이며 아무것도 내려받지 않고 공유창도 열지 않는다.
- 포커스: 열면 첫 번째 스위치("이름 가리기")로 간다. 확인 버튼이 아니다. 이유: Enter를 한 번 눌러 바로 공유되는 사고를 막고, 검토가 목적이다. 제목과 설명은 Dialog 이름과 설명으로 연결돼 열릴 때 읽힌다. Tab 순서: 스위치들 → (실패 시 "이미지 다시 만들기") → 취소 → 확인 → × 닫기. 닫으면 포커스는 Dialog를 연 버튼(공유하기, 이미지 저장, 이미지 복사)으로 돌아간다. 트리거 없는 제어형 Dialog이므로 직접 되돌려야 한다.
- × 닫기는 shadcn 기본을 쓴다(`src/components/ui/`는 고치지 않는다). 터치 크기가 작아도 "취소"가 44px 경로로 같은 일을 한다.

#### 궁합 (이름표 `accent-fortune`, "띠 궁합" / "별자리 궁합")

- 화면의 "대조 줄"(두 이름, 선, 두 점)을 그대로 옮겼다. 사이트에서 이미 보는 모양이라 받는 사람도 같은 기능으로 알아본다.
- 등급은 이름표와 같은 강조색을 쓰지만 면을 채우지 않고 선과 글자만 쓴다. 이유: 이름표(작은 채움)와 등급(큰 채움)이 둘 다 채워지면 강조가 두 곳으로 갈라진다. 등급 글자는 맨 종이 위 강조색(약 4.8:1)이고 34px 굵은 글자라 AA를 넘는다.
- 별자리 궁합은 이름이 4자(예: "처녀자리")여도 칸 폭에 들어간다(40px × 4자 = 160 이하이므로 이름 글자 크기를 40px로 한 단계 낮춘다. 띠는 44px).
- 요약 글자는 90자를 넘으면 20px로 줄이고 5줄에서 말줄임. 점수, 퍼센트, 하트, 막대, 관계 이름, 원소는 쓰지 않는다. 날짜도 쓰지 않는다.

### 5. 320px

- 공유 버튼: 영역 폭 288px이라 PC 3버튼은 세로로 쌓이고(높이 약 148px) 모바일 1버튼은 폭 100%. 가로 스크롤 없음(AC-1, AC-14).
- 버튼 글자는 줄바꿈을 허용하고(`min-h-11`, `h-auto`), 200% 글자 확대에서도 잘리지 않는다.
- 인라인 안내: 주소 상자는 `break-all`로 줄바꿈하고 "결과로 돌아가기"는 폭 100%.
- 미리보기 Dialog: 폭 288. 설명 아래 이미지 틀은 높이 최대 45dvh라 320×568에서 약 255px 높이(폭 204px). 옵션과 버튼은 Dialog 안쪽 스크롤로 닿는다. 하단 버튼 줄은 스크롤 밖에 고정이라 항상 보인다.
- 토스트(`sonner`)는 기존 설정을 따른다. 문구가 긴 `shareFailed`는 최대 3줄이 된다.
- 카드 호스트는 화면 왼쪽 밖(`-left-[10000px]`)이라 어떤 폭에서도 가로 스크롤을 만들지 않는다.

## 접근성

- 명도 대비
  - 화면 UI: 기존 토큰 조합만 쓴다(`foreground`/`muted-foreground`/`destructive` on `background`·`card`). 새 조합 없음.
  - 카드: 위 색상 표의 계산값 모두 4.5:1 이상(고지 `muted` 약 5.0, 강황 이름표 약 4.8). 옅은 면 위에서는 항상 `fg`를 쓴다는 규칙으로 나머지를 막는다. 가장 작은 카드 글자는 16px.
  - 색에만 의존하지 않는다: 카드에서 결과 구분은 글자 굵기, 선, 위치로도 전해진다(돌림판의 결과 태그는 상단 박스에 같은 글자가 이미 크게 있다).
- 키보드 이동
  - 공유 영역 탭 순서는 결과 읽기 순서(지도 링크 → 공유 버튼들 → 하단 고지) 그대로다.
  - 버튼은 Enter·Space. 미리보기 Dialog는 포커스를 가두고(shadcn), Esc로 취소한다. 안내는 Esc로 닫힌다.
  - 열렸다 닫힐 때 포커스 이동: 인앱 안내가 열리면 안내 제목으로, 닫히면 공유 버튼으로. 모바일에서 3버튼 모드로 낮아지면 "링크 복사"로. Dialog가 닫히면 연 버튼으로.
  - 모든 클릭 대상은 높이·폭 44px 이상(버튼, 스위치 줄, 주소 상자, 취소·확인). × 닫기만 shadcn 기본 크기이고 취소 버튼이 대신한다.
- 라벨과 알림(aria-live)
  - 공유 영역 `role="group"` + 이름 "결과 공유". 아이콘은 `aria-hidden`. 버튼 접근 이름은 보이는 글자 그대로(AC-1의 "링크 복사" 등. WCAG 2.5.3).
  - 복사·저장 결과는 `sonner`가 `aria-live="polite"`로 읽는다. 별도 live 영역을 더하지 않는다(이중 낭독 방지).
  - 이미지 준비 실패는 인라인 오류에 `role="alert"`로 한 번 읽힌다. 준비 중 상태는 읽지 않는다(결과마다 반복되기 때문). 단 미리보기 안에서는 다시 만들기 시작에 "이미지 만드는 중", 끝에 "이미지를 준비했어요"를 sr-only `role="status"`로 알린다.
  - 인라인 안내는 오류가 아니므로 `role="alert"`를 쓰지 않는다. 포커스 이동이 알림 역할을 한다.
  - 미리보기 Dialog의 제목·설명이 Dialog의 이름·설명이다. 이미지 `alt`는 `previewImageAlt`이고 카드에 들어가는 글자는 sr-only 목록으로 같이 제공한다(열린 질문 P-3).
  - 카드 호스트는 `aria-hidden`, `inert`라 스크린리더에 중복으로 읽히지 않는다.
- 터치: 모바일 버튼 1개는 폭 100%라 한 손 엄지로 닿는다. 닫기·확인 사이 간격 8px 이상.
- 글자 확대 200%: 버튼 글자 줄바꿈, 인라인 안내 폭 100%, Dialog 안쪽 스크롤.

## 열린 질문 / 시안 선택 요청

사용자가 고른다. 각 항목에 권장안을 적었다. 선택 전까지 구현은 권장안으로 가정한다.

### S-1. 카드 틀 모양

- A (권장) "병 라벨": 종이 바탕 + 2px 라벨 테두리(반경 14) + 기능색 이름표 + 기능별 연출 한 곳. 장점: 사이트 컨셉과 이어지고 로고 없이 출처가 보인다. 이름표 색으로 기능이 구분된다. 단점: 틀이 있어 본문 높이가 약 410px로 줄어 사다리 10명, 돌림판 후보 20개처럼 많을 때 글자가 작아진다.
- B "민짜": 테두리 없이 종이 바탕에 기능명을 큰 글자로, 본문은 전체 높이 사용. 장점: 본문 높이가 약 460px로 넉넉하다. 단점: 다른 서비스 이미지와 구분이 약하고 출처가 주소 글자뿐이다.

### S-2. 공유 영역 모양

- A (권장) 결과 아래 텍스트 있는 outline 버튼. 장점: 뜻이 바로 읽히고(AC-1이 버튼 이름을 확인) 44px 이상 터치 대상이 쉽다. 단점: 결과 아래 세로 공간을 약 44~148px 쓴다.
- B 결과 카드 오른쪽 위 아이콘 버튼 하나(PC는 메뉴로 3개). 장점: 공간 절약. 단점: 아이콘만 있으면 못 찾고, plan의 "메뉴 없이 바로 보이는 3버튼"(AC-1)과 어긋난다. 비추천.

### S-3. 카드 로고

- A (권장) 사용하지 않음. `SITE_NAME` 글자만. 장점: 권리 확인 불필요, `<img>` 금지 규칙 유지, 캡처 실패 원인 하나 제거. 단점: 브랜드 이미지가 글자로만 전달된다.
- B 기존 사이트 로고 이미지를 이름표 옆에 넣음. 장점: 인지도. 단점: 저작권·상표 확인(Q21), `<img>` 규칙과 CORS, 라이선스 문서 갱신 가능성. 쓰려면 별도 승인.

### M-1. 인라인 안내가 열릴 때 모션 (애매함)

- 넣는 안: 안내 상자가 150ms 페이드인(`tw-animate-css`, `animate-in fade-in-0`, 동작 줄이기이면 즉시 표시). 장점: 버튼 자리에서 갑자기 다른 내용이 생기는 변화가 부드럽다. 단점: design-system 모션 표의 "오버레이"가 아닌 인라인 요소라 표에 직접 해당하지 않고, 등장 효과 금지 정신에 가깝다.
- 빼는 안(권장): 즉시 표시. 포커스 이동과 상자 테두리로 변화를 알린다. 장점: 규칙과 맞고 구현이 가장 단순하다. 단점: 변화가 갑작스러울 수 있다.

### M-2. 복사·저장 성공을 버튼에도 표시할지 (애매함)

- 빼는 안(권장): 토스트만. 장점: 상태가 단순하고 sonner 하나로 읽힘이 통일된다. 단점: PC에서 토스트 위치가 멀면 놓칠 수 있다.
