## 디자인 방향

한 줄 요약: "연구 노트에 끼워 둔 표본 카드". 종이 위에 비트(`menu-tarot`) 잉크 한 색으로 찍은 기하 도해 카드이며, 점술집이 아니라 차분한 관찰 노트의 톤이다.

- 이유: 사이트 컨셉(피클 병 속 연구실, 카지노·점술집 분위기 금지)을 지키면서 타로의 개성을 줄 수 있다. 보라·별 가루·금박 같은 흔한 타로 기본값을 쓰지 않는다.
- 개성은 **카드 그림 체계 한 곳**에만 준다. 사람 모양이나 장면 없이 선과 도형으로 그린 도해, 그리고 마이너 카드의 "눈금자" 표식이 이 기능만의 기억에 남는 요소다. 페이지 레이아웃, 버튼, 패널, 글자는 로또 화면과 같은 공용 체계를 그대로 쓴다.
- 핵심 모션은 하나만 둔다. 카드를 뽑았을 때 그 자리에서 뒤집히는 연출이다(design-system "기능의 핵심 연출" 예시와 같다).
- 상담전화 안내는 개성을 주는 곳이 아니다. 전화번호부처럼 담담하고 읽기 쉽게 둔다. 이유: 위기 안내에 장식이 붙으면 진지함이 떨어진다.

## 타이포그래피

폰트는 Pretendard Variable 하나만 쓴다(새 웹폰트 없음). 숫자 표시도 Pretendard를 쓰고 `font-mono`는 쓰지 않는다. 이유: 카드 번호는 데이터 라벨이 아니라 그림의 일부이고, 고정폭 글꼴은 이 화면에서 "템플릿 느낌"만 더한다. 전화번호도 같은 이유로 Pretendard를 쓴다.

## 간격·그리드

- 기본 단위는 Tailwind 4px 눈금이다. 새 간격 토큰은 없다.
- 페이지 본문 폭: 레이아웃 `max-w-7xl` 안에서 타로 본문은 `mx-auto max-w-4xl px-4`로 좁힌다. 이유: 카드 1~3장과 짧은 문장이 주인공이라 넓은 폭은 시선을 흩뜨린다.
- 섹션 사이: `space-y-10`(로또 생성기와 같음). 섹션 안: `space-y-4`.
- 뽑기 영역(무대 패널): `rounded-panel border border-border bg-card p-5 sm:p-8`. 그 안의 카드 무대: `rounded-panel bg-muted/60 p-6`.
- 반경 계층: 칩·키워드 `rounded-md`, 버튼·입력 `rounded-lg`, 패널·무대 `rounded-panel`. 카드 SVG 모서리는 viewBox 기준 rx 10(240px 폭에서 약 12px)으로 패널과 비슷하게 둔다. 텍스트 링크의 포커스 링 모서리는 `rounded-sm`.
- 그림자: 쓰지 않는다. 카드와 무대는 밝기 차이(`card` 위 `muted`)로만 구분한다. 이유: 모든 카드에 같은 회색 그림자를 까는 기본값을 피하고 "종이 위 종이" 느낌을 유지한다.
- 터치 영역: 버튼과 전화 링크는 모두 높이 44px 이상(`h-11` 또는 `min-h-11`). 링크끼리 세로 간격은 4px 이상 둔다.
- 카드 크기(폭 기준, 비율 200:340 고정, `aspect-[200/340]`)

| 위치 | 모바일 (<640px) | 태블릿 (sm) | 데스크톱 (md 이상) |
|---|---|---|---|
| 오늘의 타로 무대 | 160px | 200px | 240px |
| 3장 타로 무대 (한 줄 3장) | 각 `calc((100% - 24px) / 3)`, 최대 104px | 각 140px | 각 180px |
| 가이드 그림(정/역방향 예시, 배치도) | 88px | 104px | 104px |

## 화면별 레이아웃

### 공통 머리 영역 (두 페이지)

순서는 design.md 12.2 트리 그대로이며 모두 서버 HTML이다.

1. `TitleWrapperComponent` (h1 + description)
   - 오늘의 타로 description: "카드 한 장으로 오늘의 흐름과 생각해 볼 점을 살펴봅니다."
   - 3장 타로 description: "카드 세 장으로 지난 흐름과 지금, 앞으로의 흐름을 정리해 봅니다."
2. `TarotDisclaimerNoticeComponent`: `mx-auto max-w-2xl rounded-lg border border-border bg-card px-4 py-3 text-center text-sm leading-6 text-muted-foreground`. 아이콘 없음. 문구는 사용자 지정 문구 그대로("본 타로 서비스는 오락 및 엔터테인먼트 목적으로 제공되며, 전문적인 법률·의학·재정적 조언을 대신할 수 없습니다."). 이유: 테두리 상자로 설명문과 구분해 "보이는 고지"로 만들되, 색은 보조 글자라 화면을 누르지 않는다. 접기·툴팁 없음.
3. (오늘의 타로만) `TarotDailyStorageNoticeComponent`: 무대 패널 바로 위, 왼쪽 정렬 `text-xs text-muted-foreground`, 앞에 lucide `Smartphone` 아이콘 14px(`aria-hidden`). 문구 "오늘의 카드는 이 기기에 저장됩니다(한국 시간 자정 기준). 다른 기기에서는 다른 카드가 나올 수 있습니다."
4. `TarotNoscriptNoticeComponent`: 무대 패널 바로 위. `<noscript>` 안 `rounded-lg border border-border bg-card p-4 text-sm text-foreground`. 문구 "카드 뽑기에는 JavaScript가 필요합니다. 브라우저 설정에서 JavaScript를 켜 주시기 바랍니다."
5. 뽑기 영역(클라이언트 root), 그 아래 `TarotResultNoticeComponent`, 가이드, FAQ, 상세 안내.

광고: 타로 화면에 광고 요소를 추가하지 않는다. 루트 상단 AdFit 슬롯만 있으며, 무대 패널과 결과 사이에 어떤 슬롯도 두지 않는다.

- 그리드: `md:grid md:grid-cols-[minmax(0,5fr)_minmax(0,7fr)] md:gap-8 md:items-start`. 왼쪽은 카드 무대, 오른쪽은 상태에 따라 "옵션·질문·버튼" 또는 "결과 읽기"로 바뀐다. 이유: 카드는 같은 자리에서 뒤집히고, 바뀌는 것은 오른쪽 글만이라 무엇이 바뀌었는지 한눈에 보인다.

- 모바일에서 "카드 뽑기"는 전체 폭(`w-full`), 데스크톱은 내용 폭(`min-w-40`).

- 죽음 카드 보충 문구는 왼쪽 선 하나로 "덧붙인 설명"임을 표시한다. 상자를 새로 만들지 않는 이유: 결과 블록 안 위계가 세 단계를 넘지 않게 한다.

### 3장 타로 (`/tarot/three-card`)

모바일

```

│ ┌ 카드 무대 ─────────────────────┐ │
│ │  과거      현재      미래      │ │ ← 위치 이름(보이는 라벨)
│ │ [카드]    [카드]    [카드]     │ │ ← 각 최대 104px, gap-3
│ │ (역방향)  (역방향)  (역방향)   │ │

│ 분야  [연애·인간관계][직업·학업]   │

(revealed일 때 무대 패널 안, 카드 무대 아래)

정방향                                 ← 방향 (이름과 다른 줄)
[키워드] [키워드] [키워드]
```

- 모바일은 카드 세 장을 한 줄로 두고(배치 전체를 한눈에 보여 줌), 읽기 글은 그 아래에 과거 → 현재 → 미래 순서로 쌓는다. 읽기 블록에는 카드 그림을 다시 넣지 않는다. 이유: 104px 카드를 글 옆에 반복하면 화면이 길어지고, 그림은 위 무대에서 이미 보인다.
- 데스크톱(md 이상): 3열 그리드 `md:grid-cols-3 md:gap-6`. 각 열이 [위치 이름 → 카드 180px → 역방향 글자 → 위치 안내 → 카드 이름 → 방향 → 키워드 → 요약]을 세로로 갖는다. 이유: 데스크톱 폭에서는 카드와 그 해석을 같은 열에 붙이는 편이 대응 관계가 분명하다.
- idle 상태의 옵션·칩·질문·버튼은 데스크톱에서도 카드 무대 아래 한 열(`max-w-xl mx-auto`)로 둔다. 이유: 세 장이 가로를 다 쓰므로 오늘의 타로처럼 좌우 2열로 나누면 카드가 작아진다.
- 위치 이름은 순서가 있는 내용(과거→현재→미래)이지만 이름 자체가 순서를 말하므로 01/02/03 번호를 붙이지 않는다.
- 위치 이름은 idle부터 각 카드 뒷면 위에 보인다(AC-9). 위치 안내 한 줄은 결과에서 보인다. 위치 안내 예시(최종 문구는 콘텐츠 단계에서 확정): 과거 "지금 상황에 영향을 준 지난 흐름을 돌아보는 자리입니다." / 현재 "지금 마주한 상황과 마음을 살펴보는 자리입니다." / 미래 "이대로 흘러갈 때 나타날 수 있는 흐름을 참고하는 자리입니다."
- 분야 칩: 단일 선택 토글 버튼 4개, `rounded-md border px-3 py-1.5 text-sm`. 누르면 해당 분야의 첫 예시가 입력칸에 채워지고, 같은 칩을 다시 누르면 다음 예시로 넘어간다(마지막 다음은 처음). 이미 적은 질문은 예시로 바뀐다. 이유: 동작 규칙이 하나라 예측하기 쉽고, 입력칸이 바로 아래 보여 바뀐 내용을 바로 확인할 수 있다.
- 칩 아래 안내(AC-11): "분야는 질문 예시를 채우는 용도이며, 해석 문구는 분야와 관계없이 같습니다."
- 재뽑기 안내(AC-13): "같은 질문으로 반복해서 뽑기보다 한 번의 결과를 차분히 돌아보시기 바랍니다." "세 장 뽑기" 버튼 아래와 "다시 뽑기" 버튼 아래에 항상 표시한다(정적 문구라 새 상태가 필요 없다).
- "다시 뽑기": 화면을 `idle`로 되돌린다. 카드는 뒷면으로 즉시 바뀌고(연출 없음), 옵션·칩·질문은 그대로 남아 고칠 수 있다. 포커스는 "세 장 뽑기" 버튼으로 옮긴다. 이유: 바로 다시 세 장을 펼치면 같은 질문 반복을 부추기므로 한 단계 쉬어 가게 한다.

### 위기 안내 패널 (`TarotCrisisNoticeComponent`, 두 페이지 공용)

S5 권장안(A안) 기준이다. B안은 아래 "S5" 참고.

- 위치: `crisis` 상태에서 옵션·질문 영역 자리(오늘의 타로 데스크톱은 오른쪽 열, 그 외는 카드 무대 아래). 카드는 뒷면인 채로 둔다.
- 모양: `rounded-panel bg-jar p-5 sm:p-6 text-jar-foreground space-y-4`, 아이콘 없음.
- 노출 번호: 109, 1577-0199, 1588-9191 세 개만. 이유(사용자 결정): 위기 순간에는 고를 것이 적어야 한다. 청소년·여성 대상 번호는 결과 하단 상시 안내에서 보인다.
- 내용 순서(화면 순서 = DOM 순서 = 탭 순서)
  1. 제목(h2, `text-lg font-semibold`, `tabIndex=-1`): "카드를 보기 전에 전해 드릴 안내가 있습니다" (변경 없음)
  2. 본문(`max-w-[68ch] text-sm leading-7 sm:text-base`): "마음이 많이 힘드시다면 혼자 견디지 마시고 아래 상담전화에서 이야기를 나눠 보시기 바랍니다. 세 곳 모두 24시간 운영합니다."
  3. 전화 묶음
     - 주 버튼 `<a href="tel:109">` "109 전화 연결": `inline-flex h-11 w-full sm:w-auto items-center justify-center rounded-lg bg-jar-foreground px-6 font-semibold text-jar hover:bg-jar-foreground/90` (기존과 같음)
     - 묶음 이름(`p`, `text-sm font-medium text-jar-muted`): "다른 상담전화"
     - 목록 `<ul>`(`flex flex-col gap-1`) 안에 링크 2개. 각 링크 `inline-flex min-h-11 items-center gap-2 rounded-sm text-base font-medium text-jar-foreground underline underline-offset-4 hover:decoration-2 break-keep`

       - "한국생명의전화 1588-9191" (`tel:15889191`)
       - 번호 부분은 `<span className="font-semibold whitespace-nowrap">`
       - 설명 구절은 넣지 않는다. 이유: 위기 순간에는 읽을 글을 줄이고, 기관 이름만으로 무엇인지 알 수 있다. 설명은 결과 하단 상시 안내에 있다.

  - 전화 링크 셋과 "계속 보기" 사이에 구획선 하나를 둬서 "전화하기"와 "결과 보기"가 서로 다른 갈래임을 보여 준다.

- 시각 순서와 DOM 순서를 같게 둔다. CSS `order`로 바꾸지 않는다. 이유: 탭 순서가 109 → 1577-0199 → 1588-9191 → 계속 보기로 보이는 순서와 일치해야 한다(WCAG 2.4.3).
- "계속 보기"를 누르면 그 자리에서 카드가 뒤집히고 결과가 나온다. 다른 확인 단계는 없다(결과를 막지 않음, AC-29).
- 전화 링크를 눌러도 패널은 그대로 남는다(자동으로 닫거나 결과로 넘어가지 않는다). 이유: 통화 앱에서 돌아왔을 때 같은 자리에서 다시 고를 수 있어야 한다. 포커스도 누른 링크에 그대로 둔다.
- 이유: 경고색 대신 사이트에서 가장 무게 있는 `jar` 면을 써서 진지하게 멈추게 하되 놀라게 하지 않는다. 109를 앞에 두되 "계속 보기"도 같은 크기로 둬서 강요하지 않는다.

### 결과 하단 면책 + 상담전화 (`TarotResultNoticeComponent`, 서버, 항상)

S6 권장안(A안) 기준이다.

- 뽑기 영역 바로 아래, `rounded-panel border border-border bg-background p-4 sm:p-5 text-sm leading-6 space-y-3`.
  - 이유: 지금의 `bg-muted` 위 `text-muted-foreground`는 약 4.2:1로 AA(4.5:1)에 못 미친다. 종이 바탕(`background`) + 테두리로 바꾸면 보조 글자 약 5.0:1, 링크(`primary`) 약 5.6:1이 된다. 바탕을 종이 그대로 두면 바로 위 무대 패널(`card`)보다 한 단계 낮은 면이 되어 결과보다 앞서 보이지 않는다.
- 첫 단락(`text-muted-foreground break-keep`): "타로는 오락과 자기 성찰을 위한 콘텐츠이며, 결과는 미래를 예측하거나 보장하지 않습니다. 건강·법률·투자 등 중요한 결정은 전문가와 상담하시기 바랍니다." (변경 없음)
- 상담전화 묶음(`border-t border-border pt-3 space-y-2`)
  - 안내 첫 줄(`p`, `flex items-start gap-2 text-foreground break-keep`, lucide `Phone` 16px `aria-hidden` `mt-1 shrink-0 text-muted-foreground`): "마음이 많이 힘드시다면 혼자 견디지 마시고 아래 상담전화에서 이야기를 나눠 보시기 바랍니다. 모두 24시간 운영합니다." 이 줄에 `id`를 주고 목록의 `aria-labelledby`로 쓴다.
  - 목록 `<ul>`: 모바일 `flex flex-col gap-1`, sm 이상 `sm:grid sm:grid-cols-2 sm:gap-x-6 sm:gap-y-1`. 109 항목만 `sm:col-span-2`.
  - 각 항목 `<li>` 안에 링크 하나. 링크가 두 줄(이름·번호 줄 + 설명 줄)을 감싼다: `<a href="tel:…" className="group flex min-h-11 flex-col justify-center rounded-sm py-1 break-keep">`
    - 첫 줄 `<span>`: `text-primary underline underline-offset-4 group-hover:decoration-2`. 기관 이름 + 공백 + 번호(`whitespace-nowrap`). 109 항목만 `font-semibold`, 나머지는 `font-normal`.
    - 둘째 줄 `<span className="block text-muted-foreground">`: 설명 구절. 밑줄 없음.
  - 순서: 109 → 1577-0199 → 1588-9191 → 1388 → 1366. sm 이상 2열에서도 행 우선 배치라 DOM 순서와 읽는 순서가 같다.
- 109를 한 단계 진하게 하는 방법: 굵기(`font-semibold`)와 자리(목록 맨 앞, sm 이상에서는 혼자 한 줄 전체)만 쓴다. 색을 따로 쓰지 않는다. 이유: 다른 색을 쓰면 경고처럼 보이고, 결과보다 시선을 끈다.
- 뽑기 전에도 보이는 위치다. 결과가 나오면 자연히 "결과 바로 아래"가 된다.

### 상담전화 문구

서비스 문구는 합니다체다. 기관 이름과 번호는 고유 명칭이라 그대로 쓰고, 설명은 상담 분야를 명사구 한 구절로 쓴다. 효과나 결과를 약속하는 표현("도와 드립니다", "해결해 드립니다")은 쓰지 않는다.

| 순서 | 라벨(기관 이름 + 번호) | `href` | 설명 구절 (결과 하단에만) | 위기 패널 | 결과 하단 |
|---|---|---|---|---|---|
| 1 | 자살예방 상담전화 109 | `tel:109` | 자살 생각과 위기 상황 상담 | 주 버튼("109 전화 연결") | 굵게, 맨 앞 |
| 2 | 정신건강위기상담전화 1577-0199 | `tel:15770199` | 우울·불안 등 정신건강 위기 상담 | 밑줄 링크 | 보통 |
| 3 | 한국생명의전화 1588-9191 | `tel:15889191` | 삶의 고민과 마음의 어려움 상담 | 밑줄 링크 | 보통 |
| 4 | 청소년전화 1388 | `tel:1388` | 청소년의 고민과 위기 상담 | 없음 | 보통 |
| 5 | 여성긴급전화 1366 | `tel:1366` | 가정폭력·성폭력 등 폭력 피해 상담 | 없음 | 보통 |

- `href`는 숫자만 쓴다(하이픈 없음). 이유: 일부 단말의 전화 앱이 하이픈을 다르게 처리한다. 화면에는 하이픈을 넣은 번호를 보인다.
- "24시간"은 항목마다 반복하지 않고 안내 첫 줄에 한 번만 쓴다("세 곳 모두 24시간 운영합니다." / "모두 24시간 운영합니다."). 이유: 같은 단어 다섯 번은 읽을 거리만 늘린다. 출시 전 재확인에서 어느 한 곳이라도 운영 시간이 다르면, 이 문장을 빼고 해당 항목 설명 뒤에 운영 시간을 붙인다.
- 위기 패널 본문, 결과 하단 안내 첫 줄은 기존 `TAROT_CRISIS_LINE_TEXT`("… 자살예방 상담전화 109(24시간)에서 …")를 나눠 대체한다. 두 문장의 끝이 다르므로(세 곳 / 모두) 상수를 둘로 나눈다.
- 설명 구절과 새 안내 문장은 고지 문구라 사용자 승인이 필요하다(`tarot-notice.constant.ts` 머리 주석 규칙).

## 카드 SVG 시각 명세

### 공통 원칙

- 자체 제작. 사람·동물 모양, 장면, 풍경을 그리지 않고 선·원·다각형·호만 쓴다. 이유: 특정 덱 구도와 겹칠 여지를 없애고, "연구 노트의 도해" 컨셉과 맞는다.
- 금지(외부 덱 도안 연상 방지): 장미·백합 뒷면, 두 기둥 사이 인물, 절벽 끝 인물과 개, 사자 입을 여는 인물, 거꾸로 매달린 인물, 해골 기사, 무너지는 탑에서 떨어지는 인물, 큰 별 1개와 작은 별 7개, 탑·늑대·개·가재가 있는 달, 화환과 네 모서리의 네 생물, 머리 위 무한대 기호, 오각별(펜타그램), 얼굴이 있는 해·달.
- 한 색: 잉크는 `currentColor`(부모 `text-menu-tarot`), 바탕은 `var(--card)`. 보조선은 같은 잉크에 `opacity` 0.35~0.45. 채움은 작은 점과 강조 도형 하나에만 쓴다.
- 선: 주 선 `stroke-width` 3, 보조선 1.5, `stroke-linecap="round"`, `stroke-linejoin="round"`.
- viewBox `0 0 200 340` 안의 배치(모든 앞면 공통, `TarotCardFrameComponent`)
  - 바깥 테두리: x 6, y 6, 너비 188, 높이 328, rx 10, 선 2
  - 안쪽 선: 바깥에서 8 안쪽, 선 1.5, opacity 0.4
  - 번호 자리: 가운데, 기준선 y 44
  - 상징 영역: 140 × 140 정사각형, 중심 (100, 172)
  - 이름 자리: 가운데, 기준선 y 308. 긴 이름("펜타클 나이트")도 들어가도록 7자 이상이면 `textLength`로 최대 150에 맞춘다
  - 번호 자리와 상징 영역 사이, 상징 영역과 이름 사이에 짧은 가로선(길이 24, opacity 0.4) 하나씩. 연구 노트의 구획선 역할
- 역방향: SVG를 감싼 요소에 `rotate-180`. 번호와 이름도 함께 뒤집힌다(카드 전체가 뒤집힌 것이 타로의 역방향이므로). 방향 정보는 카드 밖 "역방향" 글자가 맡는다.

"생각"은 상징이 담는 뜻, "도형"은 그리는 모양이다. 0번의 "열린 점선 길"과 21번의 "닫힌 점선 원"이 짝을 이뤄 메이저 전체가 하나의 여정처럼 읽히게 한다.

### 마이너 56장

- 수트 아이콘(`TarotSuitIconComponent`, 상징 영역 가운데 약 72 × 72)
  - 완드: 세로 막대 하나, 위쪽에 짧은 곁가지 두 개와 마디 표시 두 개
  - 컵: 반원 그릇 + 짧은 목 + 납작한 받침
  - 소드: 가늘고 긴 마름모 날 + 짧은 가로 손잡이 + 끝의 작은 원
  - 펜타클: 이중 원(동전) + 가운데 채운 점. 별 모양을 넣지 않는다(오각별 금지)
- 숫자 카드(에이스~10): 번호 자리에 "A", "2"~"10". 상징 영역 왼쪽 안쪽(x 28)에 세로 **눈금자**: 가는 눈금 10개(간격 12), 그중 아래에서부터 rank개를 길고 진하게(opacity 1), 나머지는 짧고 옅게(0.35). 수트 아이콘은 가운데 하나만 둔다. 이유: 숫자를 아이콘 여러 개로 늘어놓는 카드놀이식 배치 대신 "측정·관찰" 컨셉으로 수를 보여 주는, 이 기능만의 표식이다.
- 코트 카드(`TarotCourtMarkComponent`): 번호 자리에 높이가 다른 세로 막대 묶음(페이지 1개, 나이트 2개, 퀸 3개, 킹 4개, 막대 폭 3, 간격 5, 높이 10에서 16까지 차례로 커짐). 눈금자 자리에는 같은 막대 수를 크게 반복한다. 수트 아이콘은 이중 테두리 원 안에 둔다. 이니셜(P/N/Q/K)은 쓰지 않는다. 이유: 영문 이니셜은 한글 이름 체계와 섞여 혼란스럽고, 막대 수는 아래 한글 이름과 함께 보면 바로 읽힌다.
  - 메모: design.md 4.1의 코트 표식도 이 명세(막대만, 이니셜 없음)를 따라가도록 design 쪽에서 맞춘다.

### 뒷면 (`TarotCardBackComponent`)

뒷면 바탕은 S1 확정에 따라 A안 종이 바탕(`var(--card)`)이다.

- 도안: 바깥 테두리(앞면과 같음), 안쪽에 45도 마름모 격자(간격 20, 선 1, opacity 0.35), 가운데 "봉인": 동심원 2개(r 26, r 18) + 가운데 채운 점, 봉인 둘레 격자는 비운다. 위아래 대칭이라 뒤집어도 같다.
- 장미·백합·별자리·눈 모양을 쓰지 않는다.

넣지 않는 모션(이유)
- 역방향 카드의 추가 회전: 뒤집기가 끝나면 이미 반전된 상태로 놓인다. 두 번째 움직임은 같은 정보를 반복한다.
- 결과 글의 등장 효과(fade-up 등): 카드 뒤집기와 경쟁한다. 글은 공개 시작과 함께 바로 렌더링한다.
- 이미 뽑은 날 재방문 시 뒤집기: 사용자 행동이 없었으므로 앞면을 바로 보여 준다.
- "다시 뽑기" 시 앞면→뒷면 되뒤집기: 되돌리는 동작은 알릴 내용이 적다. 즉시 뒷면으로 바꾼다.
- 카드 hover 들림·그림자, 뒷면의 반짝임·떠다니는 장식, 위기 안내 패널의 등장 효과: 꾸밈뿐이거나 진지한 안내에 어울리지 않는다.
- 상담전화 링크·목록의 hover 전환, 등장 효과: 추가하지 않는다(2026-11-05 변경 범위에서 모션 없음). 이유: 위기 안내는 움직임 없이 바로 읽혀야 한다.

## 접근성

- 명도 대비 (종이 `#eef0e6`, 카드 `#f7f8f1`, muted `#e1e6d4` 기준 계산값)

  - `primary-foreground` on `menu-tarot`(주요 버튼) 약 8.0:1, `jar-foreground` on `jar` 약 10.9:1, `jar-muted` on `jar` 약 5.7:1, `jar` on `jar-foreground`(109 주 버튼 글자) 약 10.9:1

  - 카드 그림 보조선(opacity 0.35)은 장식이라 대비 기준 대상이 아니다. 주 선(opacity 1)은 비텍스트 기준 3:1을 넉넉히 넘는다

  - 3장 타로 idle: 역방향 스위치 → 분야 칩 4개(각각 Tab 정지, Space/Enter로 선택) → 질문 입력 → "세 장 뽑기"
  - 공개 후: 포커스를 결과 제목으로 옮긴다(오늘의 타로: 카드 이름 h2, 3장 타로: 결과 묶음 제목 h2 "세 장의 결과", 시각적으로 숨김 `sr-only`). 이어서 Tab 하면 "다시 뽑기"(3장) 또는 결과 하단 안내의 상담전화 링크(109 → 1577-0199 → 1588-9191 → 1388 → 1366)로 간다
  - 위기 상태: 포커스를 위기 패널 제목(`tabIndex=-1`)으로 옮긴다. Tab 순서는 "109 전화 연결" → "정신건강위기상담전화 1577-0199" → "한국생명의전화 1588-9191" → "계속 보기". Shift+Tab은 그 반대. "계속 보기" 후 포커스는 결과 제목
  - 위기 패널의 전화 링크를 눌러도 포커스는 그 링크에 남는다(패널이 바뀌지 않으므로 옮길 곳이 없다)
  - "다시 뽑기" 후 포커스는 "세 장 뽑기"
  - 포커스 표시는 모든 상호작용 요소에서 `ring-ring` 2px + offset 2px로 보인다. `jar` 패널 안 버튼·링크는 `ring-jar-foreground` + `ring-offset-jar`로 대비를 확보한다. 결과 하단 링크는 `ring-offset-background`
- 라벨·읽기
  - 카드 앞면: `role="img"` + `aria-label`(+ `<title>`) "바보 카드, 정방향" 형식(design.md 4.3). 뒷면: "타로 카드 뒷면". 내부 도형 `aria-hidden`
  - 공개 공지: 뽑기 영역에 `aria-live="polite"` 영역 하나를 두고 공개 시 한 번 읽는다. 오늘의 타로 "바보 (The Fool), 정방향 카드가 나왔습니다." / 3장 타로 "과거 바보 (The Fool) 정방향, 현재 …, 미래 … 카드가 나왔습니다." 재방문으로 바로 보여 줄 때는 "오늘 뽑은 카드는 바보 (The Fool), 정방향입니다."
  - 뒤집기 중 카드 컨테이너는 `aria-busy="true"`
  - 역방향 스위치: `<Label htmlFor>` 연결, 보조 문구는 `aria-describedby`
  - 질문 입력: `<Label htmlFor>` "질문 (선택)", 민감정보 안내와 글자 수를 `aria-describedby`로 연결
  - 분야 칩: `<button type="button" aria-pressed>`, 묶음에 `role="group" aria-labelledby`(보이는 라벨 "분야")
  - 위치 이름(과거·현재·미래)은 카드 위 보이는 글자이며 결과 블록에서는 h3다. 카드 그림의 `aria-label`에는 위치를 넣지 않는다(이름 규칙을 design.md 한 곳에서 유지)
  - 위기 패널: `role="region"`(지금처럼 `<section aria-labelledby>`) + 제목 연결. 모달이 아니므로 `alertdialog`를 쓰지 않는다. 이유: 화면을 가리지 않고 결과로 가는 길도 막지 않는다
  - 전화 링크의 접근성 이름은 모두 기관 이름을 포함한다. 보이는 글자가 이름 안에 그대로 들어가게 한다(WCAG 2.5.3 Label in Name)
    - 위기 패널 109 주 버튼: `aria-label="자살예방 상담전화 109 전화 연결"`. 보이는 "109 전화 연결"이 이어진 글자로 들어 있다. 기존 값 "자살예방 상담전화 109에 전화 연결"은 "에" 때문에 보이는 글자와 이어지지 않으므로 바꾼다
    - 위기 패널 다른 링크: `aria-label` 없이 보이는 글자가 이름이다. "정신건강위기상담전화 1577-0199", "한국생명의전화 1588-9191"
    - 결과 하단 링크: `aria-label` 없이 링크 안 두 줄 글자가 이름이다. 예: "자살예방 상담전화 109 자살 생각과 위기 상황 상담". 이유: 설명까지 한 번에 들려 어떤 곳인지 알 수 있고, 보이는 글자와 이름이 같다
  - 목록 의미 구조
    - 위기 패널: `<ul aria-labelledby="{묶음 이름 id}">`, 묶음 이름 "다른 상담전화". 109 버튼은 목록 밖에 둔다(주 행동이라 따로 둠)
    - 결과 하단: `<ul aria-labelledby="{안내 첫 줄 id}">`, 항목 5개 모두 `<li>`. 스크린리더가 "목록, 항목 5개"로 개수를 알려 준다
    - 순서가 의미 있는 목록이 아니라(우선순위는 있지만 단계가 아님) `<ol>`과 번호 표시는 쓰지 않는다
  - 아이콘은 모두 `aria-hidden`
- 터치 영역: 위기 패널 버튼 2개 `h-11`, 다른 상담전화 링크 `min-h-11`, 결과 하단 링크 블록 `min-h-11`(두 줄이라 자연 높이 약 48px). 링크 사이 세로 간격 `gap-1`(4px)로 인접 대상이 겹치지 않는다
- 확대: 200% 확대에서 3장 타로 카드 줄이 넘치지 않도록 폭을 비율(`calc`)로 둔다. 글은 고정 높이를 쓰지 않는다. 위기 패널 sm 2칸 그리드는 `minmax(0,1fr)`라 확대 시 링크 글자가 줄바꿈되며, 번호는 `whitespace-nowrap`이라 갈리지 않는다

| 장점 | 모양이 셋(채운 버튼 / 글자 링크 / 테두리 버튼)이라 "가장 먼저 할 일", "다른 선택", "결과 보기"가 한눈에 갈린다. 기관 이름이 보여 무엇에 전화하는지 알 수 있다. 패널 높이가 B안보다 낮다 | 세 번호의 누르는 모양이 같아 "전화할 수 있는 곳"임이 가장 분명하다 |
| 단점 | 1577-0199·1588-9191이 109보다 확실히 약하게 보인다(사용자 결정 "109 가장 강조"와는 맞는다) | 같은 크기 테두리 버튼 세 개가 쌓여 "계속 보기"가 목록 끝 하나처럼 묻힌다. 버튼에 기관 이름을 넣으면 너무 길고, 빼면 번호만 보여 어떤 곳인지 모른다. 데스크톱 오른쪽 열(약 500px)에 버튼 세 개가 한 줄에 안 들어간다 |

#### S6. 결과 하단 안내 바탕: 권장 A안

| | 권장: A안 종이 바탕 + 테두리 (`border border-border bg-background`) | B안 지금처럼 `bg-muted`, 보조 글자를 모두 `text-foreground`로 |
|---|---|---|
| 장점 | 보조 글자 약 5.0:1, 링크 약 5.6:1로 AA 충족. 무대 패널(`card`)보다 한 단계 낮은 면이라 결과보다 앞서 보이지 않는다. 면책·설명은 보조색, 번호는 링크색으로 세 단계 위계가 그대로 산다 | 승인된 기존 모양(옅은 녹색 면)을 유지한다. `foreground` 약 10.0:1 |
| 단점 | 승인된 모양이 바뀐다. 테두리 상자가 머리 영역 면책 상자와 비슷해 보일 수 있다(반경이 `rounded-panel`로 달라 구분됨) | 면책과 설명까지 진한 글자가 되어 위계가 사라지고 상자 전체가 진하게 보인다. 링크(`primary`) 약 4.8:1로 여유가 적다 |

- 참고: B안을 고르지 않더라도 지금 구현된 면책 단락(`text-muted-foreground` on `bg-muted`, 약 4.2:1)은 AA 미달이라 고쳐야 한다.
