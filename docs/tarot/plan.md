## 목표

로그인 없이 카드 한두 장을 뽑아 오늘의 흐름과 생각해 볼 점을 부드러운 문장으로 확인할 수 있고, 자체 제작 이미지와 자체 작성 문구로 제공되는 무료 타로 서비스를 만든다.

## 결정 기록

사용자가 확정한 내용이다. 이 문서의 본문은 아래 결정을 따른다.

| 번호 | 주제 | 결정 |
|---|---|---|
| 1 | 이미지 | 자체 제작 SVG 확정. 메이저 22장은 상징 SVG, 마이너 56장은 수트 아이콘 + 숫자, 뒷면도 자체 제작. 제작은 frontend-dev가 SVG 컴포넌트로 구현한다. AI 이미지 생성 도구로 만든 그림과 외부 덱 이미지는 쓰지 않는다. |

| 3 | 해석 문구 | 메인 AI(Claude)가 카드 의미 아이디어만 바탕으로 우리 구조(키워드 3개 + 정/역방향 1~2문장)로 처음부터 새로 작성하고, 사용자가 검수한다. 작성 중 타 사이트·책의 카드 해석 문장을 참조하지 않는다(웹 검색 포함). 사용자는 샘플(메이저 22장 등)을 검수해 톤을 고친다. 완성 후 문장 샘플을 웹 검색해 같은 문구가 있는지 확인한다. |
| 4 | 오늘의 카드 | "이 기기 기준" 하루 1장, 기준은 자정 KST, 재뽑기 없음. 다른 기기에서는 다른 카드가 나올 수 있다. |

| 8 | 광고 | AdFit은 사이트 승인이 끝났고 루트 레이아웃의 상단 슬롯이 타로 페이지에도 자동 노출된다(쿠키 동의 후). 수익은 AdFit 광고만이며 유료·크레딧은 없다. |
| 9 | 역방향 | 기본 켜짐, 뽑기 전에 선택. |
| 10 | 쓰리카드 메뉴 이름 | "3장 타로 (과거·현재·미래)" |
| 11 | 법률 확인 | 받지 않는다. 위험 수용으로 기록한다(아래 "위험과 수용 사항"). 이미지 자체 제작으로 최대 위험은 줄었다. |
| 12 | 질문 분야 | 권장안 그대로. 분야는 질문 예시를 채워 주는 용도뿐이고 해석 문구는 분야와 관계없이 같다. 금전은 "재물·생활"로 이름 붙이고 투자·도박 예시는 만들지 않는다. |
| 13 | 유료·크레딧 | 권장안 그대로. 전부 무료이고 "광고 보면 결과 공개" 방식은 쓰지 않는다. |
| 14 | 상시 면책 문구 | 사용자 지정 문구를 두 페이지 모두 "페이지 상단(h1 아래)"에 항상 표시하고, 결과 영역 하단에 짧은 문구를 한 번 더 둔다. 문구는 아래 "법적·정책 요구사항"의 "상시 면책 문구" 참고. |
| 16 | 문구 말투 통일 | 광고·법적 위험을 줄이기 위해 모든 사용자 노출 문구를 합니다체로 통일한다. 고지 문구 초안과 문구 안전 원칙은 "법적·정책 요구사항" 참고. |
| 15 | 과장·단정 표현 금지 | "100% 적중", "운명이 바뀐다" 같은 표현을 서비스 전체에서 쓰지 않는다. 금지 목록과 검사 방법은 "표현 규칙" 참고. |

기획자가 정한 부수 사항(사용자 확인 대상)
- 역방향 옵션 설정은 저장하지 않는다. 결정 5가 저장 항목을 날짜, 카드 번호, 방향으로 한정했기 때문이다. 페이지를 열 때마다 기본값(켜짐)으로 시작한다.
- 쓰리카드 결과와 질문은 어디에도 저장하지 않는다. 오늘의 카드만 저장한다.
- 기존 초안에 있던 "웨이트 원전과 대조해 검수"는 삭제했다. 결정 3의 "외부 해석 문장 참조 금지"와 충돌하기 때문이다.

## 범위

- 포함
  - 오늘의 타로: 원카드, 하루 1장 고정 (`/tarot/daily`)
  - 3장 타로(과거·현재·미래): 쓰리카드 1종 (`/tarot/three-card`)
  - 78장 카드 데이터: 카드별 정방향/역방향 키워드 3개, 요약 1~2문장
  - 자체 제작 SVG 카드 이미지 78장 + 뒷면 1종
  - 질문 입력(선택 사항), 저장 없음
  - 역방향 사용 옵션
  - 법적 고지 문구, 위기 상황 안내(상시 + 입력 감지)
  - 검색 노출 준비: 메타데이터, JSON-LD, 사이트맵, 서버 렌더링되는 설명 콘텐츠
- 제외 (후속 단계)
  - 켈틱 크로스
  - 분야별 해석 문장(연애, 직업, 재물·생활, 조언)
  - 카드 사전(78장 개별 페이지)
  - 지난 리딩 기록 목록, 공유(이미지/링크)
  - 로그인, 기기 간 동기화
  - 유료 결제, 크레딧(리워드 광고) 연동
  - 예/아니오 모드, 월간·신년 운세

## 기존 기능과의 충돌 확인

- `src/app/tarot/daily/page.tsx`: "준비 중"(ComingSoon) 상태이고 `robots: { index: false }`다. 실제 기능으로 바꾸면서 noindex를 제거한다. 기존에 노출된 URL이 아니므로 redirect는 필요 없다.
- `src/constants/menu.constant.ts`: 타로 그룹이 `comingSoon: true`이고 항목이 "오늘의 타로" 하나뿐이다. 출시 시 `comingSoon`을 풀고 "3장 타로 (과거·현재·미래)" 항목을 추가한다. `sitemap.ts`가 이 목록을 읽으므로 사이트맵 반영은 메뉴 등록으로 처리된다.
- `src/app/privacy/page.tsx`, `src/app/terms/page.tsx`가 이미 있다. 타로 항목(서버 저장 없음, 브라우저 저장 항목)을 추가한다. 기존 문구의 현재 내용은 이번에 확인하지 않았다.
- 광고: `src/app/layout.tsx` 113행의 `AdFitSlotComponent`(fixed, 헤더 아래 상단 고정)는 모든 페이지에 적용되므로 타로 페이지에도 자동 노출된다. 컴포넌트는 쿠키 동의 `accepted`일 때만 AdFit 스크립트를 불러오고, 동의 전에는 동의 안내(ConsentNudge)를 보여 준다. 따라서 타로 기능이 광고·동의 상태에 의존하면 안 된다(AC-24). layout.tsx의 "모바일 전용(md:hidden)" 주석은 실제 동작(데스크톱에서도 노출)과 달라서 사용자 결정으로 삭제했다(2026-11-04, 주석 한 줄만 제거).
- `COMPLIANCE.md` 11장(Disclaimers)에는 로또 관련 고지만 있다. 타로 고지 항목을 추가한다.
- 로또 페이지의 AgeGate는 `/lotto/*` 전용이므로 타로에는 영향이 없다. 타로는 나이 확인을 하지 않는다. 아동 대상 서비스로 오해되지 않도록 문구와 이미지를 정한다.
- `docs/conventions/data-storage.md`: "브라우저 저장소에는 민감한 개인정보를 넣지 않는다"와 "작고 기기에 남아야 하는 데이터는 localStorage"를 따른다. 질문은 저장하지 않고, 오늘의 카드(날짜, 카드 번호, 방향)만 localStorage에 둔다. 카드 의미 데이터는 코드 안 상수이므로 Supabase는 쓰지 않는다.
- `src/features/tarot/tarot-dev-guide.md`와 이 문서가 다른 부분(질문 입력 필수, 기록 저장, 시종/기사/왕비 표기 등)은 이 문서와 `docs/conventions/`를 따른다.

## 콘텐츠 제작 원칙

이미지 (결정 1)
- 메이저 22장: 카드 상징을 단순화한 SVG 아이콘 + 번호 + 한글 이름. 0번은 숫자 "0", 나머지는 로마 숫자를 쓴다.
- 마이너 56장: 수트 아이콘(완드, 컵, 소드, 펜타클) + 숫자. 에이스는 "A"로 통일한다. 코트 카드(페이지, 나이트, 퀸, 킹)는 수트 아이콘 + 직위를 나타내는 자체 도형 또는 이니셜.
- 뒷면 1종도 자체 제작한다. 유명 덱의 뒷면 도안(장미와 백합)을 쓰지 않는다.
- 제작은 frontend-dev가 SVG 컴포넌트로 구현한다. AI 이미지 생성 도구로 만든 그림, 외부 덱의 그림·도안·뒷면은 쓰지 않는다.
- 역방향은 카드를 상하 반전해 보여 주되 "역방향" 글자도 함께 표시한다.
- 각 이미지의 `alt`는 카드 이름 + 방향으로 새로 쓴다(예: "바보 카드, 정방향").
- 서비스명, 메타 태그, 설명 어디에도 "Rider-Waite", "라이더-웨이트" 등 상표성 명칭을 쓰지 않는다.
- 제작 이력(제작 주체, 제작일, 라이선스: 자체 제작)을 `THIRD_PARTY_NOTICES.md`에 기록한다. 외부 아이콘 라이브러리를 쓰면 라이선스도 기록한다.

해석 문구 (결정 3)
- 구조: 카드당 정방향 키워드 3개 + 역방향 키워드 3개, 정방향 요약 1~2문장 + 역방향 요약 1~2문장. 합계 요약 156문장, 키워드 468개.
- 쓰리카드의 위치(과거, 현재, 미래)는 위치 이름과 위치 안내 한 줄만 붙이고 카드 요약은 그대로 쓴다. 종합 요약은 만들지 않는다.
- 작성 방식: 메인 AI가 카드 의미 아이디어만 바탕으로 처음부터 새로 쓴다. 작성하는 동안 타 사이트·책·앱의 카드 해석 문장을 보지 않고, 웹에서 카드 해석 문장을 찾아 참조하지도 않는다.
- 진행 순서: (1) 메이저 22장 샘플 작성 → (2) 사용자 검수와 톤 수정 → (3) 수정된 톤으로 나머지 56장 작성 → (4) 완성 후 대표 문장 샘플을 웹 검색해 같은 문구가 있는지 확인(전수 검사가 아니라 샘플 확인).
- 카드마다 작성자(AI), 작성일, 검수자(사용자)를 기록한다. 기록 문서는 `docs/tarot/` 아래에 둔다.
- 톤: 합니다체, "~일 수 있습니다" 형태(서비스 전체 말투 통일, 법적 고지 항목 참고). 단정 표현("반드시", "100%", "보장", "헤어집니다", "합격합니다", "이 주식을 사세요")은 쓰지 않는다.
- 불안을 줄 수 있는 카드(초기 후보: 죽음, 탑, 악마, 소드 3, 소드 9, 소드 10)는 "끝, 전환, 돌아볼 신호"처럼 완화 문구와 함께 쓴다. 죽음 카드에는 "실제 죽음을 의미하지 않습니다" 설명을 붙인다.
- 역방향은 "정반대"가 아니라 "막힘, 지연, 내면, 과잉" 중 카드에 맞는 하나의 해석 렌즈로 쓴다.
- 오타·의미 오류 검수는 사용자가 한다. 외부 문서와 대조하는 검수는 하지 않는다.

명칭 (결정 7)
- 표기 형식은 "한글 이름 (영문 이름)"이다. 예: 바보 (The Fool), 컵 페이지 (Page of Cups), 컵 퀸 (Queen of Cups).
- 메이저 22장 한글 이름은 리서치 4.2의 "한글(기본)" 열을 쓴다(교황, 여황제, 마법사 등). 번호는 힘 8, 정의 11이다.
- 마이너 56장은 "수트 + 랭크" 순서(완드 에이스, 완드 2, 컵 페이지, 소드 퀸 등). 코트 카드는 페이지, 나이트, 퀸, 킹으로 통일한다.
- 다른 이름(대사제, 여제 등)은 검색 대응을 위해 설명 콘텐츠에서 "다른 이름"으로 언급할 수 있다.

## 유저 스토리

- US-1: 오늘 하루가 궁금한 방문자로서 로그인 없이 카드 한 장을 뽑고 싶다. 왜냐하면 출근 전에 가볍게 확인하고 싶기 때문이다.
- US-2: 같은 날 다시 방문한 사용자로서 같은 기기에서 아침에 뽑은 카드를 그대로 다시 보고 싶다. 왜냐하면 오늘의 카드가 바뀌면 의미가 없기 때문이다.
- US-3: 고민이 있는 사용자로서 과거-현재-미래 세 장을 뽑아 상황을 정리해 보고 싶다. 왜냐하면 한 장보다 흐름을 보는 데 도움이 되기 때문이다.
- US-4: 질문이 있는 사용자로서 질문을 적고 뽑을 수 있지만 적지 않아도 되길 바라며, 적은 내용이 어디에도 남지 않길 원한다. 왜냐하면 개인적인 내용을 남기고 싶지 않을 수 있기 때문이다.
- US-5: 처음 해보는 사용자로서 쉬운 한글 카드 이름(영문 병기), 정/역방향 뜻, 키워드, 쉬운 설명을 보고 싶다. 왜냐하면 타로 용어를 모르기 때문이다.
- US-6: 불안한 마음으로 들어온 사용자로서 죽음·탑 같은 카드가 나와도 겁먹지 않게 부드러운 설명을 보고 싶다. 왜냐하면 단정적인 표현이 상처가 될 수 있기 때문이다.
- US-7: 역방향이 낯선 사용자로서 뽑기 전에 역방향을 켜고 끌 수 있길 원한다. 왜냐하면 역방향을 쓰지 않는 방식도 많기 때문이다.
- US-8: 마음이 매우 힘든 사용자로서 필요할 때 상담 전화 정보를 보고 싶다. 질문에 힘든 마음을 적었다면 카드를 보기 전에 그 안내를 먼저 받고 싶다. 왜냐하면 타로로 해결할 수 없는 상황일 수 있기 때문이다.
- US-9: 검색으로 들어온 방문자로서 "오늘의 타로"를 검색해 바로 이 페이지에서 뽑고 싶다. 왜냐하면 가입 없이 쓰고 싶기 때문이다.
- US-10: 쿠키 동의를 거절한 방문자로서 동의하지 않아도 타로를 이용하고 싶다. 왜냐하면 광고와 분석에 동의하지 않을 뿐 기능은 쓰고 싶기 때문이다.
- US-11: 서비스 운영자로서 모든 이미지와 문구가 자체 제작이라는 기록을 남기고 싶다. 왜냐하면 저작권 분쟁을 피하고 광고 정책 점검에 대응해야 하기 때문이다.

## 예외·빈 상태

- 브라우저 저장소를 쓸 수 없는 환경(시크릿 모드, 저장소 비활성): 오류 화면 없이 뽑기는 동작한다. 새로고침하면 다른 카드가 나올 수 있다는 안내를 보여 준다.
- 저장된 오늘의 카드 값이 손상됐거나 알 수 없는 카드 번호인 경우: 오류 없이 저장값을 삭제하고 새로 뽑게 한다.
- 페이지를 연 채로 자정이 지난 경우: 다시 불러오면 새 카드를 뽑을 수 있다.
- 사용자 시간대가 KST가 아닌 경우: 날짜 기준은 항상 KST이고 안내 문구에 "한국 시간 기준"이라고 쓴다.
- 질문이 100자를 넘기거나 공백만 있는 경우: 100자까지만 입력되고, 공백만 있으면 질문이 없는 것으로 처리한다.
- 쓰리카드 도중 이탈: 저장하지 않으며 처음부터 다시 시작한다. 질문도 사라진다.
- 질문에 위기 표현이 있는 경우: 카드 결과 전에 상담 안내를 먼저 보여 주고, 사용자가 선택하면 계속 진행할 수 있다.
- 오늘의 카드 화면에 질문 입력이 있는 경우: 질문은 카드 선택에 영향을 주지 않고 저장도 하지 않으며, 같은 날 다시 열면 질문은 비어 있다.
- 이미지 로드 실패: 카드 이름과 방향이 텍스트로 나오고 해석은 정상 표시된다.
- JS 비활성: 설명 콘텐츠는 보이고 뽑기 영역에 "카드 뽑기에는 JavaScript가 필요합니다" 안내가 보인다.
- 역방향 옵션을 끄고 오늘의 카드를 이미 뽑은 경우: 이미 뽑은 카드는 바뀌지 않는다.
- 같은 질문 반복 뽑기(3장 타로): 막지 않고 안내 문구만 보여 준다.
- 쿠키 동의 전 또는 거절, 광고 차단, 광고 불러오기 실패: 타로 기능에는 영향이 없다.

  - 타로 원카드는 어떻게 읽나요?

- 페이지별 요건
  - 오늘의 타로 `/tarot/daily`: noindex 제거, 설명 콘텐츠(원카드 읽는 법, 정/역방향 설명, FAQ)를 서버 렌더링 HTML에 둔다. 권장 분량은 한국어 약 600자 이상(얇은 콘텐츠 방지).

- 사이트맵: `MENU_LIST`에 3장 타로 항목을 추가하고 `comingSoon`을 해제한다.
- 노출 대상이 아닌 것: 뽑은 결과(무작위). 결과를 별도 URL로 만들지 않는다.
- 78장 카드 사전: 이번 범위에서 제외한다. 카드당 분량이 짧으면 "얇은 콘텐츠"가 되어 광고 정책 점검에 불리할 수 있기 때문이다. 분야별 문장 등 카드당 콘텐츠가 충분해진 뒤 후속으로 재검토한다.
- 이미지 `alt`: 카드 이름 + 방향(예: "바보 카드, 정방향").

## 법적·정책 요구사항

- 개인정보 수집
  - 서버에 수집·저장하는 개인정보는 없다. 질문 텍스트는 서버로 전송하지 않는다.
  - 질문은 서버, localStorage, sessionStorage, 쿠키 어디에도 저장하지 않고 화면의 메모리(state)에만 둔다. 페이지를 벗어나거나 새로고침하면 사라진다.
  - 브라우저(localStorage)에는 오늘의 카드 고정에 필요한 날짜, 카드 번호, 방향만 저장한다. 개인을 식별할 수 없는 기능용 정보이며, 별도 수집 동의는 필요 없다고 본다. 이는 법률 전문가 확인을 받지 않은 판단이다(위험과 수용 사항 참고).
  - 쿠키 동의 거절과 관계없이 타로는 동작한다. 오늘의 카드 저장은 쿠키 동의 대상인 분석·광고와 별개의 기능용 저장이다.
  - 동의 후에 동작하는 분석·알림에 질문 텍스트와 위기 표현 감지 결과를 담지 않는다.
  - 위기 표현 감지는 브라우저 안에서만 처리하고, 서버·분석·텔레그램 이벤트로 절대 보내지 않는다.
  - 개인정보처리방침에 타로 항목(서버 저장 없음, 브라우저 저장 항목: 날짜·카드 번호·방향)을 추가한다. 이때 저장값이 다음 날 방문 시 자동 삭제되며 브라우저 설정에서도 삭제할 수 있다는 내용을 함께 적는다. 예: "저장된 값은 다음 날 방문 시 자동으로 삭제되며, 브라우저 설정에서도 삭제할 수 있습니다." 이용약관에도 서비스 성격(오락·참고용)을 추가한다.
  - 14세 미만 이용 제한은 법적으로 확인된 요구가 없다.
- 고지 문구 (초안, 최종 문구는 사용자 승인 후 확정)
  - 상시 면책 문구(사용자 지정, 페이지 상단 h1 아래에 항상 표시): "본 타로 서비스는 오락 및 엔터테인먼트 목적으로 제공되며, 전문적인 법률·의학·재정적 조언을 대신할 수 없습니다."
    - 한 줄~두 줄의 작은 글씨로 눈에 보이게 둔다. 접기·툴팁·스크롤 후 노출로 숨기지 않는다. 대비는 디자인 시스템의 보조 텍스트 색을 쓰되 읽을 수 있는 수준이어야 한다.
    - 위치 근거: 하단에만 두면 뽑기 화면에서 보이지 않아 광고 정책상 "오해 방지" 효과가 약하다. 상단에 두고, 결과를 본 시점에도 다시 보이도록 하단 짧은 문구를 병행한다.
  - 말투 통일 원칙(사용자 요청: 광고·법적 문제가 없도록 문구를 정하고 통일): 타로 서비스의 모든 사용자 노출 문구(면책, 고지, 안내, 카드 해석, FAQ, 버튼 안내)는 합니다체("~입니다", "~할 수 있습니다", "~바랍니다")로 통일한다. 이유: 면책·고지 문구는 공식적인 어조일수록 오해 여지가 적고, 사용자 지정 상시 면책 문구가 이미 합니다체이므로 한 어조로 맞추는 것이 일관된다. 버튼 라벨 같은 짧은 UI 텍스트는 명사형("카드 뽑기")으로 쓴다.
  - 문구 안전 원칙: ① 결과는 "미래를 예측하거나 보장하지 않는다"는 점을 밝힌다. ② 전문 분야(법률·의학·재정·심리) 조언을 대신하지 않는다고 밝힌다. ③ 단정·과장·공포 조장 표현을 쓰지 않는다. ④ 효과·적중률·"과학적으로 입증" 같은 주장을 하지 않는다. ⑤ 특정 덱 제작사와의 제휴·후원을 암시하지 않는다. ⑥ 상시 면책 문구를 제외한 고지 문구는 아래 초안을 기준으로 하고, 바꿀 때는 사용자 승인을 받는다.
  - 결과 화면 짧은 문구: "타로는 오락과 자기 성찰을 위한 콘텐츠이며, 결과는 미래를 예측하거나 보장하지 않습니다. 건강·법률·투자 등 중요한 결정은 전문가와 상담하시기 바랍니다."
  - 상세 안내(페이지 하단 또는 안내 영역)
    1. 본 서비스는 오락과 자기 성찰 목적으로 제공됩니다.
    2. 타로 결과는 과학적으로 입증된 것이 아니며, 미래나 결과를 예측하거나 보장하지 않습니다.
    3. 건강, 법률, 투자, 심리 위기와 관련된 문제는 해당 분야 전문가와 상담하시기 바랍니다.
    4. 타로 결과만으로 중요한 결정을 내리지 않으시기 바랍니다.
    5. 본 서비스는 특정 타로 덱 제작사나 출판사와 제휴·후원 관계가 없습니다.
    6. 카드는 무작위로 뽑히며 질문 내용과 관계가 없습니다. (F-12)
    7. 입력한 질문은 서버나 이 기기에 저장되지 않습니다. 상대방 이름·연락처 같은 개인정보나 민감한 내용은 입력하지 않으시기 바랍니다.
    8. 오늘의 카드는 날짜와 카드 정보만 이 기기에 저장됩니다. 다른 기기에서는 다른 카드가 나올 수 있습니다.
  - 위기 안내 문구(상시 표시): "마음이 많이 힘드시다면 혼자 견디지 마시고 자살예방 상담전화 109(24시간)에서 이야기를 나눠 보시기 바랍니다."
  - 전문가 상담 안내 문구: "건강, 법률, 투자와 관련된 고민은 전문가와 상담하시기 바랍니다. 타로 결과는 참고용입니다."
  - 죽음 카드 보충: "죽음 카드는 실제 죽음이 아니라 끝맺음과 전환을 의미하는 경우가 많습니다."
  - `COMPLIANCE.md` 11장에 타로 고지 항목(오락·참고용, 비제휴, 위기 안내, 서버 저장 없음, 브라우저 저장 항목)을 추가한다.
- 위기 안내 동작과 번호
  - 상시 안내: 결과 화면과 면책 영역에 위기 안내 문구를 항상 표시한다.
  - 입력 감지 안내: 질문에서 아래 목록의 표현이 감지되면 카드 결과를 보여 주기 전에 위기 안내 문구를 먼저 보여 준다. 사용자가 "계속 보기"를 고르면 결과를 보여 주고, 결과를 막지 않는다.
  - 번호: 자살예방상담전화는 2024년 1월부터 109로 통합 운영되며 24시간이다(2026-11-04 검색 확인. 출처: [보건복지부 129 사이트](https://www.129.go.kr/109), [한국생명존중희망재단](https://www.kfsp.or.kr/)). 출시 전에 번호와 운영 시간을 다시 확인해야 한다. 확인 전 상태로 표시한다.
  - 상담전화 확장(2026-11-05 사용자 결정): 109, 정신건강위기상담전화 1577-0199, 한국생명의전화 1588-9191(전국 대표번호), 청소년전화 1388, 여성긴급전화 1366 다섯 곳을 안내한다. 입력 감지 안내(위기 패널)에는 109, 1577-0199, 1588-9191 세 곳, 결과 하단 상시 안내에는 다섯 곳 전부를 보인다. 다섯 번호 모두 출시 전 재확인 대상이다. 문구와 배치는 `ui-ux-design.md` "상담전화 문구"를 따른다. 위 "위기 안내 문구(상시 표시)"의 109 단독 문장은 이 결정으로 대체된다.
  - 감지 방식: 입력 문자열에서 공백과 특수문자를 제거하고 영문은 소문자로 바꾼 뒤, 아래 표현이 포함되는지 본다. 감지에 실패할 수 있으므로(미탐) 상시 안내를 병행한다. 과하게 감지될 수 있으나(오탐) 안내만 보여 주고 결과는 막지 않으므로 허용한다.
- 위기 표현 감지 목록 (공백 제거 기준, 부분 일치, 초안)
  - 자살 계열: 자살, 자살하고, 자살할, 자살생각, 자살시도
  - 자해 계열: 자해, 자해하고, 스스로를해치, 나를해치, 몸을해치, 손목을긋, 손목긋, 손목을그어, 손목그어
  - 죽음 희망 계열: 죽고싶, 죽고파, 죽을까, 죽어버리, 죽어버릴, 죽을래, 죽는게낫, 죽는게나을, 죽어도좋, 차라리죽
  - 극단적 선택 계열: 극단적선택, 극단적인선택, 극단선택, 목숨을끊, 목숨끊, 스스로목숨, 삶을끝내, 삶을끝, 인생을끝내, 생을마감, 생을끝
  - 소멸·삶 거부 계열: 사라지고싶, 사라져버리고싶, 없어지고싶, 살기싫, 살고싶지않, 살아갈이유, 살이유가없, 더살자신, 살아있고싶지않
  - 수단 언급: 목을매, 목매, 투신, 뛰어내리고싶, 뛰어내릴까, 번개탄, 유서
  - 영문: suicide, suicidal, killmyself, selfharm, wanttodie
  - 오탐 방지: "죽음"(죽음 카드), "죽겠"("배고파 죽겠어요" 같은 관용 표현), "죽을 만큼"은 목록에 넣지 않는다. 단독 "죽"은 쓰지 않는다.
  - 이 목록은 초안이다. 이 계획서 승인 시 목록도 함께 승인되며, 추가·삭제는 사용자가 정한다.
- 전문가 상담 안내 감지 (예시, 최종 목록은 설계 담당이 정함): 건강(진단, 수술, 치료, 암, 우울증 등), 법률(소송, 고소, 재판, 변호사 등), 투자(주식, 코인, 비트코인, 투자, 대출, 부동산 등) 관련 표현. 질문 입력에서만 브라우저 안에서 감지한다.
- 상업적 이용 주의
  - 수익은 AdFit 광고만이다. 유료 결제, 크레딧 차감, "광고 보면 결과 공개" 구조는 쓰지 않는다. 광고는 결과를 보는 흐름을 막지 않는다.
  - 광고 노출: 루트 레이아웃의 AdFit 상단 슬롯이 타로 페이지에도 자동 노출된다(쿠키 동의 후). 타로 페이지가 광고 수 제한(AdFit 기준 페이지당 4개 이하)을 넘지 않게 한다.
  - 문구 금지: "연애운 100% 적중", "취업 합격 보장", "재물운 보장", "당신은 ~병에 걸립니다", "이 주식을 사세요", 반드시/확실히 같은 단정. 표시광고법·AdSense "허위 진술"·AdFit "부정확한 정보" 양쪽에서 위험하다.
- 표현 규칙 (과장·단정 표현 금지, 서비스 전체 적용: 화면, 카드 문구, FAQ, 메타데이터, OG, 메뉴 라벨, JSON-LD)
  - 금지 표현(부분 일치로 검사): "100%", "적중", "정확히 맞", "백발백중", "족집게", "무조건", "반드시", "확실히", "보장", "틀림없", "운명이 바뀐", "인생이 바뀐", "운명을 바꿔", "대박", "합격합니다", "헤어집니다", "성공합니다", "~하게 됩니다"처럼 미래를 확정하는 어미.
  - 허용 예외: "보장하지 않습니다" 같은 부정 고지 문장(면책 문구). 예외는 면책 영역의 문장에만 쓴다. 면책 문구에서도 "반드시" 대신 "~하시기 바랍니다"를 쓴다.
  - 권장 표현: "~일 수 있습니다", "~을 돌아보는 계기가 될 수 있습니다", "참고해 보시기 바랍니다", "오늘은 ~에 집중해 보는 것도 방법입니다".
  - 검사 방법: 문구 데이터와 페이지 소스를 금지 표현 목록으로 검색하는 점검을 QA와 검증 단계에 포함한다. 문구 검수 때 사용자도 이 목록을 기준으로 본다. 목록은 사용자가 추가·삭제할 수 있다.
  - 콘텐츠 금지: 투자 종목·매수 시점·복권·도박 번호를 묻거나 답하는 예시와 문구(AdFit "사행성"). 로또 서비스와 같은 도메인이므로 타로에서 로또 번호를 유도하지 않는다.
  - 이미지: 자체 제작이며 외부 덱의 그림, 도안, 카드 뒷면을 쓰지 않는다. 제작 이력은 `THIRD_PARTY_NOTICES.md`에 기록한다. 외부 폰트·아이콘을 추가하면 같이 갱신한다.
  - 문구: 메인 AI가 처음부터 작성하고 사용자가 검수한다. 작성 이력을 기록한다.
  - 아동 대상 서비스로 오해되지 않도록 문구·이미지를 정한다(Google Ads 아동 대상 정책의 점성술·오컬트 제한 참고).

## 위험과 수용 사항

사용자가 위험을 알고 수용한 항목이다. 출시 후에도 이 목록을 기준으로 점검한다.

| 위험 | 내용 | 대응 |
|---|---|---|
| 법률 확인 없음 | 법률 전문가 확인(표시광고법, 개인정보처리방침 개정, 14세 미만 이용 등)을 받지 않고 출시한다. 이미지를 자체 제작해 최대 위험은 줄었다. | 수용. 문구 금지 목록과 고지 문구로 위험을 낮춘다. |
| 저장 동의 판단 | 오늘의 카드(날짜, 카드 번호, 방향)를 localStorage에 저장하는 것이 개인정보가 아니며 별도 동의가 필요 없다는 판단은 법률 확인을 받지 않았다. | 수용. 저장 항목을 이 세 가지로 한정하고 처리방침에 공개한다. |
| AI 작성물의 저작권 귀속 | AI가 작성한 해석 문구는 한국에서 저작권 귀속이 불명확하다. 코드로 작성한 SVG 이미지도 AI가 구현하므로 같은 불명확성이 있다. | 수용. 작성자(AI)와 검수자(사용자)를 기록한다. 이미지 생성 도구는 쓰지 않는다. |
| 문구 우연 일치 | 외부 문장을 보지 않고 써도 흔한 표현이 타 사이트와 같을 수 있다. | 완성 후 대표 문장 샘플을 웹 검색해 확인한다. 전수 검사는 아니다. |
| 광고 정책 점검 | AdFit은 이미 승인됐지만 승인 후 추가된 신규 콘텐츠(타로)가 AdFit 정책 점검 대상이 될 수 있다. | 출시 후 AdFit 승인 상태를 확인한다. |
| 위기 감지 한계 | 키워드 감지는 오탐과 미탐이 있다. | 상시 안내를 병행하고 결과는 막지 않는다. 109 번호·운영 시간은 출시 전 재확인한다. |
| 이미지 몰입감 | 단순화한 상징 이미지라 익숙한 그림 카드보다 시각적 몰입감이 낮다. | 수용. 후속 일러스트 의뢰로 업그레이드할 수 있다. |
| 기기별 다른 카드 | 오늘의 카드는 기기 기준이라 저장소를 지우거나 다른 기기를 쓰면 같은 날 다른 카드가 나온다. | 수용. 화면에 안내한다. |
| 방문하지 않는 사용자의 저장값 잔존 | 저장값은 페이지를 열 때만 지연 삭제되므로, 앱을 다시 열지 않은 사용자의 마지막 저장값은 남을 수 있다. 개인정보가 아니며 약 50바이트다. | 허용. 타이머·서비스워커 자정 삭제와 삭제 버튼은 만들지 않는다. |
