## 결정 기록

- 2026-11-19: 방향 변경. 이전 B안(업태 룰렛 + 위치 기반 주변 가게 목록 + DB 적재 + 공공데이터 cron)을 폐기하고 메뉴 룰렛 + 지도 검색 링크로 바꿈. 사용자가 확정.
  - 뽑는 단위: 업태가 아니라 메뉴(예: 짜장면, 김치찌개, 돈카츠). 업태를 먼저 뽑는 2단계 구조를 쓰지 않음.
  - 결과 메뉴의 "근처에서 찾기"는 카카오맵·네이버지도 검색 링크. 자체 가게 DB, 주변 가게 목록, 위치 권한, 지오코딩, 공공데이터 적재는 하지 않음. 서버는 사용자 위치를 받지 않음.
  - 메뉴 데이터는 코드 상수. DB 없음. 이전 `0003_restaurants.sql`(스테이징)은 새 방향에서 사용하지 않음(처리 방식은 Q9).
  - 사이트 컨셉은 "운". 돌림판 연출과 "오늘의 점심운" 문구를 붙임. 돌림판은 "운빨 뽑기 도구"와 공유할 재사용 컴포넌트가 될 가능성이 크다. 상세는 설계 단계로 넘김(Q16).
- 2026-11-19: 이전 B안 결정 중 이번 방향에서 무효가 된 것: 반경 1km, 목록 10개, 위치 저장 금지 원칙의 구현(좌표 반올림, 로그 방지), 지역 선택, API 설계, RLS 정책, 0004 마이그레이션, 음식점 동기화 cron 분리 결정. 근거는 `docs/lunch/archive/plan-b-restaurants.md`와 `design-b-restaurants.md`에 있다.
- 2026-11-19: 재사용하기로 한 항목: 룰렛 연출 원칙(결과는 먼저 정하고 연출은 거기서 멈춤), 모션 줄이기 대응, 키보드·스크린 리더 접근성, 서버 렌더링 SEO 구조와 JSON-LD(BreadcrumbList, FAQPage), 금지 표현 목록, 오락 목적 고지 구조, 가게 상세·지역 landing 페이지 제외 방침.
- 2026-11-19: 법적 판단 방향(기획 판단, 사용자 확인 대기): 우리 서버가 위치를 받지 않으므로 위치 관련 법령 대상이 줄어든다. 개인정보처리방침은 변경 필요성이 낮다고 판단하고, 이용약관과 `COMPLIANCE.md` 11장은 점심 항목을 추가한다. 최종 판단은 사용자가 한다.
