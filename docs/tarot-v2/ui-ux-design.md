## 기존 명세 대비 변경점

| 기존 명세 | v2 변경 |
|---|---|
| 분야 칩 (3장만, 질문 예시 채움, 처음엔 선택 없음) | 1장·3장 공용 5칩(전체 포함, 기본 "전체"). 예시 채움 없음. 라벨을 칩 위 한 줄로 올림. 선택 표시 테두리를 진하게 |
| 질문 입력 | 입력칸 위에 용도 안내 한 줄 추가 |
| 결과 읽기 블록 | 요약 아래에 "분야 관점 문장" 한 줄 추가(분야가 "전체"가 아닐 때만) |
| 3장 결과 | 읽기 3열 아래에 "흐름 이야기" 블록 추가 |
| 3장 "다시 뽑기" 아래 문구 | 결과가 사라진다는 안내로 교체, 버튼 옆에 배치 |
| 오늘의 타로 데스크톱 오른쪽 열 | 뽑은 뒤에도 칩이 위에 남는다 |
| 문구 말투 정리 표의 "분야 안내(AC-11)" 행 | v2 문구(`TAROT_TOPIC_NOTICE`)로 대체됨 |

## 디자인 방향

한 줄 요약: 기존 "연구 노트에 끼워 둔 표본 카드"를 그대로 두고, 분야는 같은 표본을 다른 렌즈로 읽는 "메모 한 줄"로 얹는다. 새 장식은 넣지 않는다.

- 이유: v2의 변화는 화면의 개성이 아니라 "분야가 해석을 바꾼다"는 사실을 정직하게 보여 주는 일이다. 새 일러스트나 연출을 더하면 카드 그림 체계(이 기능의 개성 한 곳)와 경쟁한다.
- 문장 위계는 세 단계로 고정한다. 카드 자체의 요약(가장 크게) > 분야 관점 문장(한 단계 작게, 왼쪽 선) > 안내 문구(가장 작게, 보조색). 이유: "카드가 말하는 것"과 "분야 렌즈로 덧붙인 것"을 읽는 사람이 구분해야 "질문은 해석에 쓰이지 않는다"는 안내와 화면이 일치한다.
- 왼쪽 선 한 줄(`border-l-2 border-menu-tarot/40`)은 기존 죽음 카드 보충 문구에서 쓰던 "덧붙인 문장" 표시다. 분야 관점 문장이 같은 표시를 재사용한다. 이유: 새 표시 방식을 만들지 않고 이미 학습된 기호를 쓴다.
- 3장의 "흐름 이야기"는 상자나 장식 없이 제목 + 문단 + 구분선으로만 만든다. 이유: 이 문단이 3장의 핵심 가치이므로 글 자체가 주인공이어야 하고, 면(바탕색)을 입히면 결과 하단 안내(가장 낮은 면)와 위계가 섞인다.

## 색상

기존 명세 "색상" 표의 토큰을 그대로 쓴다. 추가되거나 바뀌는 용도만 적는다.

| 용도 | 토큰 | 이유 |
|---|---|---|
| 분야 칩 기본 | `border-border bg-card text-foreground`, hover `bg-muted` | 기존 칩과 같다 |
| 분야 칩 선택됨 | `border-menu-tarot bg-menu-tarot/10 text-menu-tarot` (테두리를 `/40`에서 전체 색으로 변경) | 메뉴 색의 "선택 상태" 용도. 선택과 비선택을 색상 차이만으로 구분하지 않도록(WCAG 1.4.1) 테두리 대비를 높인다. 테두리 `menu-tarot`은 카드 면 위 약 8.0:1, 글자는 옅은 면 위 약 6.9:1 |
| 분야 관점 문장 | 글자 `text-foreground`, 왼쪽 선 `border-menu-tarot/40` | 읽는 글이라 가장 높은 대비. 선은 장식이라 대비 기준 대상이 아니다 |
| 분야 표시줄(3장, 선택안 S2) | `text-muted-foreground` on `card` | 약 5.4:1, 기존 "질문:" 줄과 같은 용도 |
| 질문 용도 안내, 분야 안내 | `text-muted-foreground` on `card`, `text-xs` | 약 5.4:1. `bg-muted` 위에는 두지 않는다 |
| 흐름 이야기 제목·문단 | `text-foreground` | 약 11.8:1 |
| 흐름 이야기 구분선 | `border-border` | 기존 구획선과 같다 |
| 흐름 이야기 안내(`TAROT_STORY_NOTICE`) | `text-muted-foreground` | 약 5.4:1 |
| 재뽑기 결과 안내 | `text-muted-foreground` | 약 5.4:1 |

새 토큰: 없음.

## 타이포그래피

폰트는 Pretendard Variable 하나(변경 없음). 기존 명세 표의 값에서 추가되는 요소만 적는다. 모든 문장에 `break-keep`.

| 요소 | 크기 | 굵기 | 줄 간격 | 비고 |
|---|---|---|---|---|
| 분야 칩 그룹 라벨 "분야" | `text-sm` | 500 | 기본 | 칩 위 한 줄. 입력 라벨("질문 (선택)")과 같은 문법 |
| 분야 칩 | `text-sm` | 500 | 기본 | 선택 여부로 굵기를 바꾸지 않는다. 이유: 굵기가 바뀌면 칩 폭이 변해 줄바꿈이 흔들린다 |
| 분야 안내(칩 아래), 질문 용도 안내 | `text-xs` | 400 | `leading-5` | 줄 길이 `max-w-[68ch]` |
| 분야 관점 문장 | `text-sm` / `sm:text-base` | 400 | `leading-7` | 요약(`text-base` / `sm:text-lg`)보다 한 단계 작다. `max-w-[68ch]` |
| 분야 표시줄(3장) | `text-sm` | 400 | `leading-6` | 기존 daily "질문:" 줄과 같은 스타일 |
| 흐름 이야기 제목 h2 | `text-xl` / `sm:text-2xl` | 600 | `leading-tight` | 기존 h2(카드 이름)와 같다 |
| 흐름 이야기 문단 | `text-base` / `sm:text-lg` | 400 | `leading-8` / `sm:leading-9` | 한 문단 4문장이므로 요약(`leading-7/8`)보다 줄 간격을 한 단계 넓힌다. `max-w-[68ch]` |
| 흐름 이야기 안내 | `text-sm` | 400 | `leading-6` | 예측·보장 아님 고지라 xs보다 한 단계 키운다 |
| 재뽑기 결과 안내 | `text-sm` | 400 | `leading-6` | 결과가 사라진다는 안내라 기존 `text-xs`보다 키운다 |

## 간격·그리드

- 본문 폭, 섹션 사이, 무대 패널 규칙은 기존 명세와 같다(`max-w-4xl`, `space-y-10`, `rounded-panel p-5 sm:p-8`).
- 칩 줄: `flex flex-wrap gap-2`. 터치 영역은 모바일 `min-h-11`(44px), `sm` 이상 `sm:min-h-9`. 이유: 기존 칩(약 32px)은 모바일 손가락 기준에 못 미친다. 데스크톱은 포인터라 낮게 둔다.
- 칩 블록 안: 라벨 → 칩 줄 → 안내를 `space-y-2`.
- 카드 읽기 블록 안(`space-y-3` 유지): 키워드 → 요약 → 분야 관점 문장 → 죽음 카드 보충 문구 순. 요약과 분야 관점 문장은 같은 `space-y-3` 간격이다(한 묶음처럼 읽히되 선으로 구분).
- 1장 결과가 나온 뒤 칩 블록: 아래에 `border-b border-border pb-5`를 두어 "조작 영역"과 "읽기 영역"을 나눈다. idle에서는 이 선이 없다(바로 아래가 질문 입력이라 같은 폼이다).
- 3장 흐름 이야기 블록: `border-t border-border pt-6 space-y-3`. 데스크톱은 읽기 3열과 같은 안쪽 여백(`md:px-6`)을 주어 첫 열 왼쪽 끝과 정렬한다. 문단은 왼쪽 정렬이고 가운데 정렬하지 않는다.
- 3장 다시 뽑기 줄: 모바일 `flex flex-col gap-3`, `md` 이상 `md:flex-row md:items-start md:gap-4`. 안내는 버튼 옆, 윗선 정렬을 위해 `md:pt-2.5`.

## 화면별 레이아웃

### 오늘의 타로 (`/tarot/daily`)

변경은 오른쪽 열(모바일은 카드 무대 아래)뿐이다. 왼쪽 카드 무대와 2열 그리드(`md:grid-cols-[minmax(0,5fr)_minmax(0,7fr)]`)는 그대로다.

idle 모바일·데스크톱 오른쪽 열 순서 (D6: 질문 항상 펼침)

```
역방향 사용                    [스위치]
끄면 모든 카드가 정방향 …

분야
[전체][연애·인간관계][직업·학업]
[재물·생활][일상 조언]
분야를 고르면 같은 카드도 그 분야의 …

질문 (선택)
입력한 내용은 카드 선택과 해석에 쓰이지 …   ← 용도 안내 (입력칸 위)
[입력칸.........................]
민감정보 안내                      0/100
[         카드 뽑기          ]
```

revealed 오른쪽 열 순서 (칩이 idle과 같은 위치에 남는다)

```
(재방문) 오늘 뽑은 카드입니다. …
분야
[전체][연애·인간관계][직업·학업]
[재물·생활][일상 조언]
분야를 고르면 같은 카드도 그 분야의 …
────────────────────────────────  ← border-b
질문: …                             (방금 뽑았고 질문이 있을 때)
바보 (The Fool)                     ← h2, 공개 직후 포커스
정방향
[키워드][키워드][키워드]
요약 1~2문장
┃ 분야 관점 문장 1문장              ← 분야 "전체"이면 없음
(죽음 카드 보충 문구)
(전문가 안내) (저장 불가 안내)
```

- 칩을 결과 위에 두는 이유: 칩을 누르면 바뀌는 글(분야 관점 문장)이 칩 아래에 있어야 칩이 움직이지 않는다. 칩을 결과 아래로 보내면 분야 문장이 생기고 사라질 때(전체 ↔ 다른 분야) 칩이 세로로 밀려 연속해서 누르기 어렵다.
- 칩이 보이는 상태: idle, revealed. `checking`, `crisis`에서는 숨긴다(design.md). 위기 상태에서 숨겨도 선택값은 state에 남아, "계속 보기" 뒤 결과에 그대로 쓰인다.
- 재방문 복원 때는 항상 "전체"로 시작한다(design.md). 상태 줄은 칩 위에 둔다. 이유: 상태 줄은 이 화면 전체의 맥락 안내이고 칩은 그 아래 조작이다.
- 분야를 바꿔도 카드 무대, 이름, 방향, 키워드, 요약은 그대로이고 분야 관점 문장만 바뀐다(AC-4). 스크롤하지 않고 포커스는 누른 칩에 둔다.
- "오늘의 흐름" 한 문단(F-1)은 요약 + 분야 관점 문장이다. 소제목은 달지 않는다(선택 S1에서 추천). h1 아래 설명이 이미 "가볍게 보는 오늘의 흐름"을 말한다.
- 모바일 첫 화면이 길어지는 문제: idle에서 오른쪽 열이 칩 블록(약 150px)만큼 길어진다. 접힘(D6 대안)은 쓰지 않기로 확정됐으므로 간격을 줄이지 않고 칩 줄바꿈이 2줄로 끝나도록 칩 폭(`px-3`)만 맞춘다. 360px 폭 기준 첫 줄에 전체·연애·인간관계·직업·학업이 들어간다.

### 3장 타로 (`/tarot/three-card`)

idle (기존 구조: 무대 아래 `mx-auto max-w-xl space-y-5` 한 열)

```
역방향 사용                    [스위치]
분야
[전체][연애·인간관계][직업·학업][재물·생활][일상 조언]  (폭이 되는 만큼 한 줄, 아니면 줄바꿈)
분야를 고르면 같은 카드도 그 분야의 …
질문 (선택)
입력한 내용은 카드 선택과 해석에 쓰이지 …
[입력칸.........................]
민감정보 안내                      0/100
[         세 장 뽑기         ]
같은 질문으로 반복해서 …           ← 기존 TAROT_REDRAW_NOTICE 그대로
```

- `max-w-xl`(576px) 안에서 칩 5개 폭 합계가 약 460px라 데스크톱에서는 한 줄에 들어간다. 모바일은 두 줄.
- 칩이 질문 예시를 채우지 않는다(D5). 칩을 눌러도 입력칸은 바뀌지 않는다. 같은 칩을 다시 눌러도 아무 일도 없다(선택 유지).
- 3장은 칩이 idle에서만 보인다(design.md). 뽑은 뒤 분야를 바꾸려면 "다시 뽑기"로 돌아간다. 다시 뽑기 후 idle에는 이전 분야·질문·역방향 옵션이 남아 있다.

revealed 모바일

```
[ 카드 무대: 과거 / 현재 / 미래 3장 ]
분야: 연애·인간관계                  ← 분야 표시줄 (선택 S2, "전체"이면 없음)
과거                                  ← h3
지금 상황에 영향을 준 지난 흐름 …
컵 3 (Three of Cups) / 정방향 / [키워드] …
요약 1~2문장
┃ 분야 관점 문장
───────  (현재, 미래 같은 형식)
────────────────────────────────  ← border-t
흐름 이야기                           ← h2
과거 자리의 … 카드로 보면 … 수 있습니다. 현재 … 미래 … (마무리 문장)
이야기는 세 장의 카드 의미를 이어 쓴 참고용 문장입니다. …
(전문가 안내)
[ 다시 뽑기 ]
다시 뽑으면 지금 결과는 사라집니다. …
```

revealed 데스크톱

```
[ 카드 무대 3장 ]
분야: 연애·인간관계
[과거 읽기]      [현재 읽기]      [미래 읽기]       ← 3열, 각 열에 분야 관점 문장
┃ …              ┃ …              ┃ …
────────────────────────────────────────────────── border-t
흐름 이야기
과거 자리의 … (68ch 폭, 왼쪽 정렬, 첫 열 왼쪽 끝과 정렬)
이야기는 세 장의 카드 의미를 …
(전문가 안내)
[ 다시 뽑기 ]  다시 뽑으면 지금 결과는 사라집니다. 같은 고민을 …
```

- 흐름 이야기를 읽기 3열 아래, 전체 폭 한 블록으로 두는 이유: 이야기는 세 장을 잇는 글이라 특정 열에 속하지 않는다. 시간 순서(과거 → 현재 → 미래 읽기 → 종합)로 읽히는 위치다.
- 이야기 문단 안에서 위치 단어나 카드 이름을 굵게 하거나 색을 바꾸지 않는다. 이유: 문단은 한 문자열로 들어오고(`story: string`), 한 단어만 강조하는 처리는 가독만 해친다.
- 이야기 문단이 null이면 블록 전체(제목·문단·안내)를 그리지 않는다. 오류 문구나 빈 자리표시를 두지 않는다(plan 예외).
- 같은 수트 그룹·같은 방향 카드가 두 장 나오면 두 열에 같은 분야 관점 문장이 보인다(design.md 알려진 한계). 디자인으로 가리지 않는다.
- 분야 표시줄은 3장 결과가 칩을 숨기므로 "어느 분야로 읽은 결과인지"를 남기는 용도다(선택 S2).

### 공통 머리 영역

기존 명세와 같다. 바뀌는 것은 h1 아래 설명 문구(`headerDescription`)뿐이고 문구는 콘텐츠 단계(C-3)에서 확정한다. 레이아웃 변경 없음.

### 가이드·FAQ

레이아웃 변경 없음(기존 `max-w-[68ch]` 단락, 펼친 FAQ). 문구만 바뀐다(콘텐츠 단계). 새 그림은 넣지 않는다. 이유: 분야·이야기 설명은 글로 충분하고, 서버 HTML 본문이 목적이다(AC-26).

## 접근성

- 명도 대비 (종이 `#eef0e6`, 카드 `#f7f8f1` 기준, 기존 명세 계산값 재사용)
  - 칩 글자: 기본 `foreground` 약 11.8:1, 선택 `menu-tarot` on `menu-tarot/10` 약 6.9:1. 선택 칩 테두리 `menu-tarot` 약 8.0:1.
  - 비선택 칩의 `border-border`는 대비가 낮지만 칩은 글자가 식별 수단이라 기준 대상이 아니다. 선택 여부는 테두리 색 + `aria-pressed`로도 전달한다(색만으로 구분하지 않음).
  - 모든 `muted-foreground` 안내는 `card` 면 위에서만 쓴다(약 5.4:1). `bg-muted` 위에는 두지 않는다.
- 키보드 이동 (탭 순서는 시각 순서와 같다. CSS `order`로 바꾸지 않는다)
  - 1장 idle: 역방향 스위치 → 분야 칩 5개 → 질문 입력 → "카드 뽑기". Space/Enter로 칩 선택.
  - 1장 revealed: 칩 5개 → (결과 영역) → 전문가 안내 링크 등. 공개 직후 포커스는 기존대로 결과 h2에 간다. 칩은 h2보다 앞(DOM·시각 모두)이므로 분야를 바꾸려면 Shift+Tab으로 돌아간다. 이 순서를 택한 이유는 간격 장의 칩 위치 이유와 같고, 포커스를 칩으로 보내면 "결과가 나왔다"는 알림(h2 포커스 + aria-live)이 약해진다.
  - 3장 idle: 역방향 스위치 → 분야 칩 5개 → 질문 입력 → "세 장 뽑기". 기존 4개에서 5개로 늘 뿐이다.
  - 3장 revealed: 포커스는 sr-only h2 "세 장의 결과" → Tab 순서는 전문가 안내 → "다시 뽑기"(안내가 `aria-describedby`로 읽힘).
  - 칩을 눌러도 포커스는 그 칩에 남는다. 스크롤하지 않는다.
  - 포커스 링: 칩·버튼 모두 `ring-ring` 2px + offset 2px.
- 라벨·읽기
  - 칩 그룹: `fieldset aria-labelledby` + 보이는 라벨 "분야". 칩은 `<button type="button" aria-pressed>`.
  - 1장 분야 변경 알림(design.md가 ui에 위임한 항목): 결과가 나온 뒤 사용자가 칩을 바꿨을 때만 `aria-live="polite"` sr-only 영역에 분야 이름만 읽는다. 질문은 넣지 않는다. 첫 렌더나 공개 시에는 읽지 않는다(기존 공개 공지와 겹침 방지). 이유: 칩 버튼은 "눌림"만 알리고, 아래 문장이 바뀐 사실은 알리지 못한다. 새 문구는 아래 "새 문구" 표.
  - 용도 안내는 입력칸의 `aria-describedby`에 연결한다. 분야 안내는 칩 그룹 아래 일반 글자다(칩 `aria-describedby`로 묶지 않는다. 5개 버튼에서 같은 글이 반복되기 때문).
  - 분야 관점 문장은 일반 `p`. 왼쪽 선은 장식이라 접근성 이름이 없다.
  - 흐름 이야기: h2 + `p`. h1 개수는 늘지 않는다(AC-27). 제목 순서는 h1 → (sr-only h2 "세 장의 결과" → h3 위치 ×3) → h2 "흐름 이야기"로 이어진다.
  - 재뽑기 버튼: `aria-describedby`로 `TAROT_REDRAW_RESULT_NOTICE`를 연결.
- 터치 영역: 칩 모바일 `min-h-11`. 칩 줄 `gap-2`(8px)로 인접 대상이 겹치지 않는다.
- 확대: 200% 확대에서 칩 줄은 줄바꿈으로 흡수된다. 흐름 이야기는 고정 높이가 없고 `max-w-[68ch]`가 줄 길이를 지킨다. 칩 라벨 "연애·인간관계"는 `break-keep`이고 칩 안에서 줄바꿈되지 않도록 `whitespace-nowrap` 없이 칩 폭을 내용에 맞춘다(자연 줄바꿈 허용).

|---|---|---|
| 모양 | 칩을 바꿨을 때만 새 문장이 투명도 0 → 1로 나타난다. framer-motion(`motion.p`, `key`로 교체), 150ms, 이동·크기 변화 없음. 첫 공개 때나 "전체"로 바꿔 문장이 사라질 때는 효과 없음 | 즉시 교체 |
| 이유·모션 표 분류 | 칩은 그대로이고 문장 한 줄만 바뀌는 화면이라 바뀐 사실이 눈에 안 띌 수 있다. "무엇이 바뀌었는지 알려 준다" 기준에 해당. 표의 "기능의 핵심 연출"보다는 사용자 행동에 대한 반응(150~300ms)에 가깝다 | |
| 동작 줄이기 | 즉시 교체(`useReducedMotion`이면 duration 0). MotionConfig는 opacity를 줄이지 않으므로 직접 처리 | 해당 없음 |
| 장점 | US-2("분야를 고른 의미가 결과에 보여야 한다")를 눈으로 확인시킨다. 코드가 작다 | 구현이 가장 단순하다. 움직임이 하나도 늘지 않는다 |
| 단점 | 모션이 하나 늘고, 첫 공개와 칩 변경을 구분하는 처리(이전 분야 비교)가 필요하다 | 문장 길이가 비슷하면 변화를 놓칠 수 있다 |

### S4. 3장 흐름 이야기를 뒤집기가 끝난 뒤 보이기

| | 추천: 빼는 안 | 넣는 안 |
|---|---|---|
| 모양 | 이야기를 다른 읽기 블록과 같이 공개 시작 시 바로 그린다. 효과 없음 | 카드 3장이 다 뒤집힌 뒤(`isFlipping`이 false가 된 뒤) 이야기 블록이 투명도 0 → 1로 300ms 나타난다 |
| 장점 | 기존 규칙("글은 공개 시작과 함께 렌더링")과 같다. 기다림이 없고 레이아웃이 움직이지 않는다 | 카드 → 읽기 → 이야기 순서의 마지막 한 박자로 읽는 순서를 연출한다. 한 번만 일어나는 연출이라 과하지 않다 |
| 단점 | 이야기가 카드가 뒤집히는 0.7초 동안 먼저 보여 카드 이름이 조금 일찍 노출된다 | 이야기 블록이 나중에 생기면서 아래의 다시 뽑기 버튼이 밀려 내려간다. 결과를 보기까지 기다리는 시간이 늘고 동작 줄이기 처리가 필요하다 |

### 확정으로 처리한 항목 (선택 요청 아님)

- 1장 revealed 상태에서 칩 위치: 결과 위(idle과 같은 자리). 이유는 "오늘의 타로 > 화면별 레이아웃" 참고.
- 칩 라벨: 칩 줄 위 한 줄.
- 칩 컨트롤 방식: `aria-pressed` 버튼 묶음 유지.
- 1장 분야 변경 `aria-live` 알림: 넣는다(분야 이름만).
- 이야기 시각 처리: 면 없이 제목 + 문단 + 구분선.

### PM 전달 사항

- QA: `TAROT_TOPIC_NOTICE`, `TAROT_QUESTION_USAGE_NOTICE`, `TAROT_STORY_NOTICE`, `TAROT_REDRAW_RESULT_NOTICE`는 모두 위 위치에서 항상 보인다(AC-8, AC-14, AC-15). 분야 관점 문장은 `p`로 찾으며 분야 "전체"에서는 없어야 한다. 칩 선택 상태는 `aria-pressed`로 확인한다.
- 새 문구(분야 변경 알림 2개, 분야 표시줄 접두사)는 승인이 필요하다.
- 이 문서는 새 API, 데이터, 저장 항목을 추가하지 않는다. S2의 분야 표시줄은 root의 기존 선택 state와 `TAROT_TOPICS` 라벨만 쓴다.
