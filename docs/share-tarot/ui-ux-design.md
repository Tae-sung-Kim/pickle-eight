# share-tarot UI/UX 디자인 명세

입력: `docs/share-tarot/plan.md` (승인됨). design.md는 없다. 1·2차 공유 구조(`ShareCardFrameComponent`, `docs/archive/share/ui-ux-design.md` 공통 카드 규칙)를 재사용한다.
범위: 공유 카드 이미지 2종(오늘의 타로, 세 장 타로). 공유 패널·버튼은 위치만 적는다.

## 디자인 방향

한 줄 요약: 병 라벨 틀 안에 타로 카드를 "그대로 올려놓은" 조용한 카드. 개성은 카드 그림 한 곳에만 준다. 이유: 1·2차 카드와 같은 틀·글자·색 규칙을 지켜 이미지 묶음에서 기능만 이름표 색으로 구분되게 하고, 타로는 그림 자체가 가장 타로다운 요소이므로 그림을 키우고 나머지는 글자만 쓴다.

- 새 일러스트, 새 글꼴, 새 아이콘, 모션은 없다. 카드 그림은 기존 `TarotCardFaceComponent`(순수 SVG)를 그대로 쓴다.
- 역방향은 그림을 뒤집지 않고 "역방향" 글자 라벨로만 표시한다(plan 열린 질문 3, 확정). 정방향 카드에도 "정방향" 라벨을 붙여 두 상태가 글자로 같은 자리에서 구분된다.
- 참고 안(ui-ux-pro-max)은 없다. 채택 / 버림 항목 없음.

## 재사용 가능 여부 (조사 결과)

| 대상 | 결과 | 이유 |
|---|---|---|
| `TarotCardComponent` (`tarot-card.component.tsx`) | 카드에 쓰지 않는다 | framer-motion, `rotateY`, `perspective`, `backface-visibility`를 쓴다. 3D 변환은 html-to-image 캡처에서 앞면이 빈 칸이나 뒤집힌 채 찍힐 위험이 있고, 카드 규칙(모션 없음)과 충돌한다 |
| `TarotCardFaceComponent` (`card-face.component.tsx`) | 쓴다 | 훅·모션 없는 순수 SVG. 서버에서도 렌더된다. 크기는 부모 폭으로 정한다(비율 200:340) |
| `ShareCardFrameComponent` | 쓴다 | 머리·꼬리·테두리 그대로. 본문 440x410 영역만 새로 채운다 |
| `FortuneShareCardComponent` | 구조만 참고 | 본문 컴포넌트가 틀 안 children으로 들어가는 방식, `line-clamp`와 글자 길이 단계 규칙을 따른다 |

주의 두 가지(frontend-dev 전달):
1. `TarotCardFaceComponent`는 `isReversed`가 true면 SVG를 `rotate-180`으로 뒤집고 접근성 이름도 "역방향"이 된다. 공유 카드에서는 항상 `isReversed={false}`로 넘긴다(그림을 뒤집지 않는 결정). 화면의 결과 영역은 그림을 뒤집어 보여주므로 화면과 이미지의 그림 방향이 다르다. 이 차이는 plan에서 확정된 사항이다.
2. 카드 틀 SVG는 `fill="var(--card)"`를 쓴다. `--card`는 다크 모드에서 `#172a21`로 바뀌므로 카드 이미지가 다크 모드에서 어둡게 찍힌다(plan: 카드 배경 고정). 카드 그림을 감싸는 요소에 `--card`를 라이트 값(`#f7f8f1`)으로 고정해야 한다. 새 색은 만들지 않는다. 방법은 frontend-dev가 정한다(예: 감싸는 요소의 `--card` 덮어쓰기).

## 색상

| 용도 | 토큰 | 이유 |
|---|---|---|
| 카드 바탕, 본문 글자, 고지, 선 | `share-card-bg`, `share-card-fg`, `share-card-muted`, `share-card-border` (기존) | 1·2차와 같은 고정 토큰. 다크 모드에서도 이미지가 바뀌지 않는다 |
| 기능명 이름표 면, 카드 그림 선 색, 역방향 라벨, 세 장 위치 이름 | `share-card-accent-tarot` (신규) | 타로 메뉴 라벨 색. 이름표가 같은 묶음에서 기능을 구분하는 단서 |
| 정방향 라벨 | `share-card-border` 테두리 + `share-card-muted` 글자 | 역방향만 강조해 정/역 차이가 한눈에 보이게 한다 |

새 토큰 1개:

| 이름 | 값 | 이유 |
|---|---|---|
| `--share-card-accent-tarot` (`--color-share-card-accent-tarot`) | `#7a3358` | `menu-tarot`와 같은 값의 고정 복사본(1·2차 `accent-meal/lucky/fortune`과 같은 방식). 종이 `#eef0e6` 위 글자 대비 약 7.4:1 (계산값) |

- `globals.css`의 `:root`와 `@theme`에 등록한다. `.dark`에서는 덮어쓰지 않는다. `ShareCardAccentType`에 `'tarot'`, `ShareCardFrameComponent`의 `ACCENT_CLASS`에 `tarot: 'bg-share-card-accent-tarot'`를 더한다. 이는 공통 틀의 코드 수정이라 architect·PM 확인이 필요하다(아래 열린 질문 T-3).
- 강조색 글자는 맨 종이 위에서만 쓴다(1차 규칙). 이 카드에는 옅은 면(`accent/10`)을 쓰지 않는다.
- 카드에 `dark:`, hex 직접 값, Tailwind 기본 팔레트를 쓰지 않는다.

## 타이포그래피

폰트는 Pretendard 하나. 카드에는 `font-mono`를 쓰지 않는다. 모든 글자는 `keep-all`(틀에서 상속). 메신저 축소(약 0.55)를 고려해 가장 작은 글자도 16px 이상이다.

| 요소 | 크기 | 굵기 | 줄 간격 | 색 |
|---|---|---|---|---|
| 이름표(기능명), 사이트 이름, 주소, 고지 | 틀과 같음(20/700, 16/600, 16/600, 16/400) | | 틀과 같음 | 틀과 같음 |
| 오늘의 타로: 카드 한글 이름 | 32px | 700 | 1.2, 최대 2줄 | `fg` |
| 오늘의 타로: 영문 이름 | 18px | 400 | 1.35, 최대 2줄 | `muted` |
| 오늘의 타로: 한 줄 요약 | 20px | 400 | 1.55, 최대 6줄 | `fg` |
| 방향 라벨 (오늘의 타로) | 20px | 700 / 400 | 1 | 역: `accent-tarot` / 정: `muted` |
| 세 장: 위치 이름(과거·현재·미래) | 20px | 700 | 1 | `accent-tarot` |
| 세 장: 카드 한글 이름 | 22px | 700 | 1.2 | `fg` |
| 세 장: 방향 라벨 | 16px | 700 / 600 | 1 | 역: `accent-tarot` / 정: `muted` |
| 세 장: 한 줄 요약 | 18px | 400 | 1.5, 최대 3줄 | `fg` |

- 요약은 카드 데이터의 `summary` 첫 문장(plan 열린 질문 6). 새 문구를 만들지 않는다. 확인한 데이터 첫 문장은 약 24~40자라 위 줄 수 안에 들어간다.
- 영문 이름은 세 장 카드에는 쓰지 않는다. 이유: 폭과 높이가 부족하고, plan 표의 세 장 항목에 영문 병기가 요구되지 않는다.
- 대문자 라벨, 점으로 이은 메타 문장, 화살표 장식을 쓰지 않는다.

## 간격·그리드

- 틀 안쪽 본문 영역은 440 x 약 410px(틀 계산: 높이 675 - 여백 40 - 테두리 4 - 안쪽 패딩 56 - 머리 56 - 꼬리 약 105). 모든 배치는 이 영역을 기준으로 한다.
- 간격 단위는 4px 배수.
- 정렬: 오늘의 타로는 그림 왼쪽·글자 오른쪽 좌측 정렬, 세 장은 행마다 그림 왼쪽·글자 오른쪽 좌측 정렬. 이유: 한국어 문장 여러 줄은 좌측 정렬이 읽기 쉽고, 두 카드가 같은 "그림 왼쪽 + 글자 오른쪽" 문법을 쓰면 시리즈로 보인다.

- 방향 라벨(필): 높이 32, 가로 패딩 14, 반경 6(`rounded-md`).
  - 역방향: 테두리 2px `accent-tarot`, 글자 20/700 `accent-tarot`, 면 없음.
  - 정방향: 테두리 1px `border`, 글자 20/400 `muted`, 면 없음.

- 카드 그림: `TarotCardFaceComponent`에 `isReversed={false}`, `className`으로 폭 180, 선 색 `text-share-card-accent-tarot`. 그림 자체는 이미 틀·눈금자가 있어 별도 테두리·그림자를 더하지 않는다.
- 이름이 8자 이상이면 한글 이름은 2줄로 줄바꿈(32px 유지, `line-clamp-2`).

│ │ └──┘ ───────────────────────────────────── │ │ ← 행 구분선 1px

- 각 행: 왼쪽 그림 폭 73(높이 124, 비율 200:340), 간격 16, 오른쪽 글자 칸 351.
- 글자 칸 위에서 아래로: 줄1(위치 이름 20/700 `accent-tarot`, 간격 10, 한글 이름 22/700 `fg`, 간격 10, 방향 라벨), 간격 6, 요약.
  - 줄1은 한 줄 고정. 이름은 `nowrap`이고, 가장 긴 이름과 "역방향" 라벨이 351 안에 들어가야 한다(계산: 위치 약 40 + 10 + 이름 최대 8자 176 + 10 + 라벨 약 70 = 306 < 351). 실제 최장 이름은 구현 때 데이터로 확인한다.
  - 요약: 18/1.5, 3줄 x 27 = 81. 줄1 약 26 + 6 + 81 = 113 < 124. 한 줄 약 19자, 3줄 약 57자라 확인한 첫 문장(24~40자)이 잘리지 않는다. 57자를 넘는 문장이 있으면 `line-clamp-3`으로 말줄임(`…`).
- 방향 라벨(필): 높이 24, 가로 패딩 8, 반경 6. 역방향은 2px `accent-tarot` 테두리 + 16/700 `accent-tarot`, 정방향은 1px `border` 테두리 + 16/600 `muted`.
- 장점: 요약 글자가 18px로 읽히고 잘리지 않는다. 위치(과거·현재·미래)가 위에서 아래로 시간 순서로 읽힌다. 320px 화면에서 미리보기로 줄어도 행 단위라 안정적이다.
- 단점: 카드 그림이 73px로 작다. 카드 안의 번호·이름 글자(SVG 내부)는 이미지에서 읽기 어렵다(카드 이름은 오른쪽 글자로 다시 나오므로 정보 손실은 없다).

### 3. 공유 패널·버튼 위치 (1·2차와 같음)

- 위치: 결과 영역(카드 그림, 요약, 해석) 아래, 기존 고지(면책, 질문 주의) 위. `docs/archive/share/ui-ux-design.md` 1장(공유 영역)·2장(기능별 배치)의 "결과 아래 공유 영역" 규칙을 따른다. 모양, 문구, 상태는 변경 없음.
- 노출 조건(plan 예외 절): 뽑기 전, 뒤집기 중, 위기 신호 질문 결과, 3장 데이터 누락일 때는 숨긴다. 뒤집기가 끝난 뒤에만 보인다.
- 캡처용 카드는 화면 밖(또는 1·2차와 같은 방식의 숨김 영역)에 540x675로 그린다. 보이는 미리보기는 만들지 않는다(타로는 이름 가림이 필요 없다).

## 컴포넌트 상태

카드는 이미지 캡처 전용이라 hover, focus, 로딩, 에러가 없다. 상태는 데이터 조합뿐이다.

| 컴포넌트 | 기본 | hover | focus | disabled | 로딩 | 에러 | 빈 상태 |
|---|---|---|---|---|---|---|---|
| 오늘의 타로 카드 본문 | 그림 + 방향 라벨 + 이름 + 요약 | 없음 | 없음 | 없음 | 없음 | 없음 | 카드 데이터가 없으면 카드를 그리지 않고 공유 버튼을 숨긴다 |
| 세 장 카드 본문 | 3행 | 없음 | 없음 | 없음 | 없음 | 없음 | 3장 중 하나라도 데이터가 없으면 카드를 그리지 않고 공유 버튼을 숨긴다(빈 칸 금지) |
| 방향 라벨 | 정방향 또는 역방향 | 없음 | 없음 | 없음 | 없음 | 없음 | 없음 |

변형: 복원된 오늘의 카드(`TAROT_DAILY_RESTORED_NOTICE`)는 공유 버튼을 숨긴다(2026-11-26 사용자 승인, plan.md 74행). 전문가 상담 주제 감지 결과는 같은 카드를 쓴다. 전문가 주제는 고지 한 줄이 이미 카드에 있어 추가 요소가 없다.

## 인터랙션·애니메이션

없음. 카드는 이미지 캡처용이라 모션을 넣지 않는다. `TarotCardComponent`의 뒤집기 연출은 카드에 쓰지 않는다. 동작 줄이기 대체 동작도 필요 없다.

## 접근성

- 명도 대비(종이 `#eef0e6` 기준): 본문 `fg` 약 11:1, `accent-tarot` 약 7.4:1, `muted` 약 5.0:1. 가장 작은 글자 16px, 읽을 글자는 18px 이상. 이름표는 종이색 글자 on `accent-tarot` 면이라 같은 대비(약 7.4:1).
- 정/역 구분은 색만으로 하지 않는다: 글자(정방향/역방향), 테두리 두께(1px/2px), 굵기(400 또는 600/700)로도 구분된다.
- 키보드 이동: 카드는 이미지 캡처용이라 포커스를 받지 않는다. 공유 버튼의 키보드 동작은 1·2차와 같다.
- 라벨: 카드 DOM은 화면 밖 캡처용이므로 `aria-hidden`으로 두어 화면 읽기 프로그램이 중복 낭독하지 않게 한다(1·2차와 같은 방식). 그림 SVG의 `role="img"` 이름은 `isReversed={false}`라 "정방향"이 되는데, `aria-hidden` 안이라 낭독되지 않는다. 낭독해야 하는 방향 정보는 화면의 기존 결과 영역이 이미 가진다.

## 기존 디자인 시스템 변경 제안

- 새 토큰 `--share-card-accent-tarot`(`#7a3358`): 값은 기존 `menu-tarot`와 같고 1·2차와 같은 "고정 복사본" 방식이다. 시스템 변경이 아니라 확장이지만, 카드 토큰 목록에 한 줄이 늘어나므로 PM이 확인해 달라. 폰트, 메인 색, 반경 변경은 없다.
- `docs/conventions/design-system.md`를 바꾸는 제안은 없다(카드 토큰은 `docs/archive/share/ui-ux-design.md`에서 정의됨).

## 열린 질문 / 시안 선택 요청

- S-1 (PM 선택): 세 장 카드 레이아웃. 시안 A(세로 3행, 권장) / 시안 B(가로 3열). 판단 기준은 위 장단점. 시안 B를 고르면 요약이 약 32자 넘을 때 말줄임이 생긴다는 점을 받아들여야 한다.
- T-1 (확인): 오늘의 타로 카드를 "그림 왼쪽 + 글자 오른쪽" 가로 2칸으로 했다. 세로로 쌓는 안(그림 130x221 아래에 이름·라벨·요약 2줄)은 그림이 작아져 타로 카드의 존재감이 줄어 제외했다. 의견이 있으면 알려 달라.
- T-2 (확인): 화면의 결과는 역방향 그림을 뒤집어 보이고 공유 이미지는 뒤집지 않는다. 받는 사람이 이미지만 보고 "역방향" 글자를 놓치면 정방향으로 읽힐 수 있다. 정/역 라벨을 필 모양으로 키워 보완했다. plan에서 확정된 사항이라 변경은 요구하지 않는다.
- T-3 (architect/PM에게 되돌림): `ShareCardAccentType`과 `ShareCardFrameComponent`의 `ACCENT_CLASS`에 `'tarot'`를 추가해야 한다(공통 틀 코드 수정). design.md가 없으므로 dev-lead 또는 architect가 수정 범위를 확인해 달라.
- T-4 (확인): 카드 그림 감싸는 요소의 `--card` 고정은 구현 방법이 열려 있다(위 "주의 2"). 새 색은 쓰지 않는다.
