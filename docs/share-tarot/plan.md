## 목표

오늘의 타로와 세 장 타로 결과를 본 사용자가 카드 한 장 이미지나 기능 링크를 친구에게 보낼 수 있게 한다. 질문 입력 내용은 어떤 공유물에도 들어가지 않는다.

## 범위

- 포함:
  - `/tarot/daily`(오늘의 카드): 결과가 나온 뒤 공통 공유 버튼과 카드 이미지.
  - `/tarot/three-card`(3장 뽑기): 3장 결과가 나온 뒤 공통 공유 버튼과 카드 이미지.
  - 1차·2차 공통 규칙 재사용: 공유 경로 분기, 실패·취소·인앱 안내, 빈 이미지 차단, 캡처 제외 표시.
- 제외:
  - 질문 입력 내용(질문 문자열), 해석 전문, 3장 이야기 문장(`TAROT_STORY_NOTICE` 문장 포함), 날짜.
  - 카드 그림 재제작(이번 범위 밖. 재점검 결과가 "닮음"이면 별도 작업).
  - 사주, 꿈 해몽, 로또 기록·채점·분석·시뮬레이터, 나의 번호(1·2차 제외 유지).
  - 결과 전용 링크, 서버 저장, `/api/og-image` 결과 이미지, 공유 클릭 기록.
  - 새 페이지, 새 라우트, sitemap 변경.
  - 카드에 광고 요소 넣기.
  - 새 npm 라이브러리, 새 글꼴, 새 아이콘 세트.

### 공유 카드 내용 (타로)

| 기능 | 카드에 넣는 내용 | 넣지 않는 것 |
|---|---|---|
| 오늘의 타로 (`/tarot/daily`) | 카드 그림 1장, 카드 이름(한글 (영문)), 정/역 방향, 한 줄 요약, 고지 한 줄, 기능 주소 | 질문, 해석 전문, 키워드 목록, 날짜, 저장 시각 |
| 세 장 타로 (`/tarot/three-card`) | 3장 각각의 그림, 이름, 방향(과거·현재·미래 위치 이름), 각 한 줄 요약, 고지 한 줄, 기능 주소 | 질문, 이야기 문장, 해석 전문, 위치 안내 긴 문장 |

- 한 줄 요약은 카드 데이터의 기존 요약 첫 문장을 쓴다(열린 질문 6번). 새 문구를 만들지 않는다.
- 공유 이미지는 한 장이다(1차·2차와 같은 규칙).

## 유저 스토리

- US-1: 오늘의 카드를 뽑은 사용자로서 카드 그림과 뜻을 친구에게 보내고 싶다. 같이 보는 재미를 나누기 위해서다.
- US-2: 세 장을 뽑은 사용자로서 과거·현재·미래 세 장을 한 장 이미지로 저장하고 싶다. 흐름을 친구와 같이 보기 위해서다.
- US-3: 사이트 운영자로서 공유물에 질문 내용과 해석 전문이 실리지 않기를 원한다. 고민 내용이 퍼지지 않게 하기 위해서다.

## 완료 조건 (AC)

태그는 검증 층이다. `[E2E]`는 화면 흐름 단위로 묶었고, 자동 spec은 페이지당 대표 흐름만 만든다. 실기기 항목은 수동이며 `qa-report.md`에 따로 기록한다.

- AC-1 [E2E] (오늘의 타로, PC 저장 흐름. 열린 질문 1번의 방식): 카드를 뽑기 전에는 공유 버튼이 보이지 않는다. 뽑고 뒤집기가 끝나면 공유 버튼이 보이고, "이미지 저장"을 누르면 카드 PNG가 내려받아지며 파일 크기가 0이 아니다. 320px 너비에서 가로 스크롤이 생기지 않는다.
- AC-2 [E2E] (세 장 뽑기, PC 저장 흐름): 세 장을 뽑고 뒤집기가 끝나면 공유 버튼이 보이고, "이미지 저장"을 누르면 3장 카드 PNG가 내려받아지며 파일 크기가 0이 아니다. 320px 너비에서 가로 스크롤이 생기지 않는다.
- AC-3 [E2E] (위기 신호 질문, 오늘의 타로 대표 흐름. 열린 질문 5번 승인 뒤 확정): 위기 표현이 든 질문으로 뽑으면 안내 화면이 먼저 뜨고, "계속 보기" 뒤 결과 화면에 공유 버튼이 보이지 않는다.
- AC-4 [단위] (카드 문구 규칙): 카드 문구는 "공유 카드 내용" 표의 항목, 방향 라벨(`TAROT_ORIENTATION_LABELS`), 기능 주소, 고지 한 줄뿐이다. 질문 문자열, 해석 전문, 이야기 문장, 날짜는 카드에 들어가지 않는다. 카드 문구는 `tarot-copy-rule` 금지 표현 검사를 통과한다.
- AC-5 [정적] (공통 규칙 재사용): 공유 경로 분기, 실패·취소·인앱 안내, 빈 이미지 차단은 1차·2차 공통 모듈을 쓴다. 타로 전용 공유 분기를 새로 만들지 않는다.
- AC-6 [정적] (적용 범위): 공통 공유 버튼은 `/tarot/daily`와 `/tarot/three-card` 결과에만 붙는다. 타로 가이드·FAQ 영역, 다른 페이지(사주, 꿈 해몽, 로또 등)에는 붙지 않는다.
- AC-7 [정적] (검색·미리보기 값 유지): 두 페이지의 `title`, `description`, OG 제목이 바뀌지 않는다. 메타데이터는 `buildMetadata()`를 그대로 쓴다. 새 라우트와 sitemap 항목이 생기지 않는다.
- AC-8 [정적] (문구 모음과 캡처 제외): 타로 공유 고지 한 줄과 공유 문구는 타로 상수 파일에 모여 있고 copy-rule 검사 대상이다. 카드 DOM 안의 버튼, 입력란, 광고, 동의 배너에는 캡처 제외 표시가 붙어 있다.
- AC-9 [정적] (라이선스 문서): 새 라이브러리, 글꼴, 아이콘을 넣지 않았다면 `DEPENDENCY_LICENSES.md`, `THIRD_PARTY_NOTICES.md`는 바뀌지 않는다. 카드 그림을 바꾸면 `THIRD_PARTY_NOTICES.md` 41~46행과 `docs/tarot/` 저작 기록을 같이 갱신한다.
- AC-10 [E2E] (수동, 실기기 — 자동 spec 아님): iPhone Safari와 Android Chrome에서 타로 카드 이미지를 첫 시도부터 공유해 본다. 이미지가 빈 상태로 나오지 않고, 3장 결과의 글자가 잘리지 않는다. 대상 기기는 `docs/share/plan.md` 열린 질문 7번을 따른다.

## 예외·빈 상태

- 카드를 아직 뽑지 않은 상태, 뒤집기 애니메이션 중: 공유 버튼을 보이지 않게 한다. 뒤집기가 끝난 뒤에만 보인다.
- 오늘의 카드를 저장된 기록에서 복원한 경우(`TAROT_DAILY_RESTORED_NOTICE`): 공유 버튼을 숨긴다. 복원 결과에는 질문이 없어 위기 신호를 판정할 수 없기 때문이다(사용자 승인 2026-11-26, 새로 뽑은 결과에서만 공유).
- 위기 신호 질문 결과: 공유 버튼을 숨긴다(열린 질문 5번).
- 전문가 상담 주제 감지 결과(`TAROT_EXPERT_NOTICE_TEXT`): 공유 버튼은 보인다. 카드에 고지 한 줄이 이미 들어간다(열린 질문 5번).
- 3장 중 일부 카드 데이터 누락: 해당 카드 자리를 빈 칸으로 그리지 않는다. 데이터가 없으면 공유 버튼을 숨긴다.
- 이미지 만들기 실패, 공유창 취소, 인앱 브라우저: 1·2차 규칙과 같다.
- 긴 카드 이름(영문 병기 포함)과 긴 요약: 카드에서 잘리지 않게 줄인다. 줄임 기준은 설계.
- 3장 카드는 요약을 2줄까지 보여주고 넘치면 말줄임(`line-clamp-2`). 문구는 줄이거나 바꾸지 않는다. (변경 사유: 3행 높이 안에서 글자 크기를 유지하려고 사용자가 승인, 2026-11-26. 이전 기준 "요약 첫 문장이 말줄임 없이 들어가는 것"을 대체)
- 320px 너비: 공유 버튼과 안내 문구가 가로 스크롤을 만들지 않는다.
- 다크 모드: 카드 배경은 고정한다(1차 열린 질문 15번 기준).

## 검색 노출

- 키워드:
  - 기존 타로 검색어를 그대로 둔다(목록은 `docs/tarot/plan.md`의 검색 노출 절을 따른다). 공유 기능 자체를 검색어로 노리지 않는다.
- 페이지가 답할 질문:
  - 오늘의 타로: 오늘 카드 한 장을 어떻게 읽으면 되는지, 정/역방향은 무엇을 뜻하는지.
  - 세 장 타로: 과거·현재·미래 세 장을 어떻게 읽는지.
- 공유 버튼은 본문 설명과 제목을 바꾸지 않는다.
- 공유 링크 미리보기: 공유 주소는 각 페이지의 canonical 주소다. OG 제목·설명이 기능에 맞게 나오는지 확인한다(AC-7).

## 법적·정책 요구사항

- 개인정보 수집:
  - 타로 질문은 입력받을 수 있다. 공유 카드와 공유 주소에는 질문을 넣지 않으므로 공유 기능이 새로 수집하는 정보는 없다(AC-4).
  - 질문은 기존 기준대로 저장되거나 전송되지 않는다(`TAROT_SENSITIVE_INPUT_NOTICE`). 공유 기능은 이 기준을 바꾸지 않는다.
  - 공유는 브라우저 안에서 이미지와 주소를 만들고 서버로 결과를 보내지 않는다(1차 기준). 공유 기록은 만들지 않는다.
  - 위기 신호 판정은 화면 상태 계산으로만 쓰고, 저장하거나 기록하지 않는다(`docs/archive/tarot/design.md` 6.2).
- 고지 문구:
  - 카드 하단 고지 한 줄(초안): "오락과 자기 성찰을 위한 참고 결과입니다. 미래를 예측하지 않습니다." (열린 질문 4번. 법률 확인 필요.)
  - 타로 문구는 합니다체로 쓴다. "보장" 같은 금지 표현을 쓰지 않는다(`tarot-copy-rule` 7.1). 기존 면책 원문(`TAROT_RESULT_DISCLAIMER_TEXT`)은 길어서 한 줄에 넣지 않는다. 원문을 줄여 쓰지 않는다.
  - 공유 버튼이 보이는 화면의 기존 고지(상시 109 안내, 면책, 질문 주의)는 그대로 둔다.
- 상업적 이용 주의:
  - 카드에 광고 요소, 광고 링크, 상업 문구를 넣지 않는다.
  - 카드 문구는 자체 작성이다. 한 줄 요약은 기존 자체 문구를 쓰고, 새 문구를 만들지 않는다.
  - 새 글꼴, 로고, 이미지를 넣지 않는다.

### 그림 위험 재점검 (사용자 육안 확인, 수동)

- 배경: `THIRD_PARTY_NOTICES.md` 43행과 `docs/archive/tarot/design.md` 4.1·15장 기준으로 78장과 뒷면은 자체 제작 인라인 SVG다. 라이더-웨이트 도안을 따르지 않도록 설계됐다. 권리 귀속 불명확성은 기획 단계에서 수용된 위험이다.
- 공유로 그림이 외부에 퍼지면 노출 규모가 지금보다 커진다. 판단할 때 이 점을 포함한다.
- 확인 방법(수동, 사용자 육안): 개발 후 샘플 카드를 PNG로 뽑아 기존 타로 덱의 구도와 비교한다.
  - 샘플(권장): 메이저 0(바보), XIII(죽음), XV(악마), XVI(탑), XVII(별), XIX(태양), 마이너 에이스 4종(컵, 검, 막대, 동전).
  - 비교 기준: 인물 수와 자세, 배경 구성, 소품 배치, 색 조합이 기존 덱과 닮았는지. 판단 기준은 `docs/archive/tarot/ui-ux-design.md` "카드 SVG 시각 명세 > 공통 원칙"의 금지 도안 목록을 따른다.
- 결과 처리: 닮았다고 판단되면 별도 재제작 작업으로 분리한다(이번 범위 밖). 닮지 않았다고 판단되면 기록만 남기고 진행한다.
- 기록 위치: `docs/share-tarot/qa-report.md` 수동 항목.

## 열린 질문

사용자 확인이 필요한 것은 1~5번과 7번이다. 6번은 권장안으로 진행해도 되는지 확인한다.

1. (캡처 확인 방법) 인라인 SVG가 html-to-image 캡처에서 제대로 찍히는지 어떻게 확인할까. 권장: [E2E] AC-1·2는 PNG가 내려받아지고 파일 크기와 치수(540x675의 PNG 배율)만 확인한다. 픽셀 비교는 화면과 환경에 따라 흔들려서 쓰지 않는다. 글자·그림이 실제로 찍히는지는 개발 중 샘플 PNG 육안 확인 1회와 AC-10 실기기 확인으로 본다. 웹 글꼴(Pretendard)이 SVG의 `<text>`에 로드된 뒤 캡처해야 한다(1차 열린 질문 9번 기준). 사용자 확인 필요.
2. (3장 레이아웃) 1차 카드 레이아웃은 한 장짜리다. 3장을 540x675 한 장에 넣으려면 새 레이아웃이 필요하다. 권장: 3장을 한 장 이미지로 만들고(공유 1장 원칙), 새 레이아웃은 3단계 UI/UX 단계에서 그린다. 한 장 기준 크기는 유지한다. 3장 PNG 3개로 나누는 안은 권장하지 않는다. 사용자 확인 필요.
3. (역방향 표시) 권장: 그림을 뒤집지 않고 "역방향" 글자 라벨을 카드 이름 옆에 둔다(`TAROT_ORIENTATION_LABELS`). 그림을 돌리면 SVG를 방향별로 다시 그려야 하고, 공유 이미지에서 글자가 방향을 더 확실히 전달한다. 화면의 현재 표시 방식과 맞는지 UI/UX 단계에서 확인한다. 사용자 확인 필요.
4. (고지 문구) 타로 고지는 기존 면책 원문이 길어 한 줄에 들어가지 않는다. 권장: 짧은 새 한 줄을 `tarot-notice.constant.ts`에 추가하고 초안은 "오락과 자기 성찰을 위한 참고 결과입니다. 미래를 예측하지 않습니다."로 한다. 금지 표현과 합니다체 기준(`tarot-copy-rule`)을 통과해야 한다. 고지 문구는 사용자 승인 후 확정한다. 사용자 확인 필요.
5. (위기 신호와 공유 버튼) 타로 위기 감지는 두 가지다. 상시 109 안내는 모든 결과에 있어서 이를 근거로 버튼을 숨기면 공유가 사실상 막힌다. 권장: (a) 상시 안내는 공유 카드에 넣지 않고 버튼은 유지한다. (b) 질문 입력 감지(`hasTarotCrisisSignal`)가 참인 결과는 버튼을 숨긴다(AC-3). (c) 전문가 주제 감지 결과는 버튼을 유지하고 카드 고지 한 줄로 충분하다고 본다. 참고: 운세 쪽은 위기 감지 코드가 없어 `docs/TODO.md` 11번 기록대로 버튼 숨김이 없다. 2차와 기준이 다르므로 확인이 필요하다. 사용자 확인 필요.
6. (한 줄 요약 출처) 카드 데이터의 요약 1~2문장 중 첫 문장을 쓴다(`docs/tarot/plan.md` 카드 데이터 구조). 새 공유용 문구는 만들지 않는다. 길이가 길면 줄임 기준은 설계에서 정한다. 권장안대로 진행해도 되는지 확인한다.
7. (그림 재점검 시점과 기준) 샘플 카드의 육안 확인을 공유 출시 전에 1회 할지, 판단 기준을 사용자가 어떻게 정할지. 권장: 공유 출시 전 사용자가 샘플 PNG를 보고 "닮음 / 닮지 않음"을 기록한다. 닮음이면 재제작 작업을 별도 `docs/`로 분리한다. 사용자 확인 필요.
