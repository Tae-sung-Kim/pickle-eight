작성일: 2026-11-19
작성: researcher
용도: planner가 꿈 해몽 기획서(`docs/dream-interpretation/plan.md`)를 쓸 때 입력으로 쓴다.
범위: 도메인 지식, 해몽 방식과 용어, 서비스 형태 사례, 검색 수요와 SEO, 저작권, 법적·표현 주의점, 기존 서비스(로또·타로·운세)와의 연결, 데이터 규모 의견. 기술 구현 방식은 쓰지 않는다.

표시 규칙
- "관례"는 공식 규칙이 아니라 민간에서 통상 쓰는 방식이다. 꿈 해몽에는 공식 규칙이 없다.
- "추정"은 출처 없이 researcher가 판단한 내용이다.
- "확인 필요"는 이번 조사에서 근거를 확보하지 못한 항목이다.
- "법률 확인 필요"는 상업 서비스에 쓰기 전에 전문가 확인을 권하는 항목이다.
- "검색 요약 기준"은 원문 페이지를 열어 보지 못하고 검색 결과 요약만 본 항목이다.
- 상업 해몽 사이트의 숫자와 순위는 집계 기준이 공개되지 않은 경우가 많아 참고용으로만 적었다.
- 본 문서는 법률 자문이 아니다.

## 0. 조사 전 현황과 이 문서의 역할

기존 자산
- 이 저장소에 꿈 해몽 관련 기능, 메뉴, 문서는 없다. `src/` 전체 검색에서 "꿈" 또는 "dream" 문자열은 CSS 파일 한 곳에서만 나왔고 기능과 무관하다. 따라서 처음부터 새로 기획한다.
- 메뉴 구조는 `src/constants/menu.constant.ts`에 운세 그룹(`fortune`)과 로또, 타로가 있다. 꿈 해몽을 운세 그룹 아래에 둘지 독립 메뉴로 둘지는 기획 결정이다(11장 질문).
- 같은 사이트의 타로와 운세는 `COMPLIANCE.md` 11장에 면책 문구 위치, 금지 표현, 위기 상담 전화, 개인정보 처리 방식이 정리되어 있다. 꿈 해몽도 같은 틀을 따르는 것이 안전하다. 이 문서는 그 내용을 반복하지 않고 꿈에만 해당하는 쟁점을 추가한다.
- 저작물 절차는 `docs/tarot/copy-log.md`와 `docs/fortune/copy-log.md`에 있다. 4장에서 같은 절차를 제안한다.
- 타로 리서치 `docs/research/tarot.md`와 운세 리서치 `docs/research/fortune.md`의 법규 장은 꿈에도 대부분 해당한다. 중복 설명은 줄였다.

## 1. 한 줄 요약

꿈 해몽은 잠을 자는 동안 본 장면과 인물, 사물, 감정을 사전이나 민간 풀이에 따라 뜻으로 옮겨 보는 민속 풀이다. 과학적으로 꿈의 상징이 보편적 의미를 가진다는 근거는 찾지 못했다. 한국에서는 돼지꿈, 뱀꿈, 이빨 빠지는 꿈 같은 소재 검색이 많고, 무료 사전형 사이트와 AI 해몽 앱이 같이 쓰인다. 서비스는 "민간 풀이와 오락·자기 성찰용 참고"임을 밝히고, 예지나 보장 표현, 로또 번호 연결을 피해야 한다.

## 2. 핵심 개념과 용어

### 2.1 해몽의 기본 개념

- 해몽(解夢, 꿈풀이): 꿈의 장면이나 상징을 해석해 의미를 찾는 일. 위키백과는 내면 상태를 이해하거나 미래를 예측하는 데 쓰인다고 설명하고, 과학적 근거가 없는 미신이라고 적는다(검색 및 문서 발췌 기준, 2026-01-09 최종 편집).
- 꿈 해석 이론: 프로이트(1900년 『꿈의 해석』, 억압된 욕망의 표현), 융(집단 무의식과 연결된 상징), 현대 신경과학(뇌가 낮 동안의 정보를 정리하는 과정이라는 설명). 이는 학문적 설명이며 해몽 사전과 같은 뜻이 아니다.

### 2.2 한국 민간 해몽에서 쓰는 용어

| 용어 | 뜻 (처음 보는 사람 기준) | 출처 상태 |
|---|---|---|
| 길몽(吉夢) | 좋은 일이나 행운을 암시한다고 보는 꿈. 돼지, 금, 큰 물 등이 예로 든다 | 위키백과, 대구일보(검색 요약) |
| 흉몽(凶夢) | 나쁜 일을 암시한다고 보는 꿈. 죽음, 사고, 추락 등이 예로 든다. 전통적으로는 "조심하라"는 신호로 읽는 경우가 많다 | 위키백과, 나무위키(검색 요약) |
| 태몽(胎夢) | 아이를 가졌거나 출산 전후에 꾸는 꿈. 용, 호랑이, 나비, 꽃 등이 예로 든다. 아이의 성격이나 장래를 말하는 것으로 여긴다 | 위키백과 |
| 악몽(惡夢) | 불쾌하고 무서운 꿈. 의학에서는 수면 장애의 한 종류로 본다(5.3) | 정신의학 자료(검색 요약) |
| 예지몽 | 앞으로 일어날 일을 미리 보여 준다고 믿는 꿈. 과학적 근거 없음 | 위키백과 항목 목록 |
| 상징몽 | 사물이나 인물이 다른 뜻을 나타낸다고 보는 꿈 | 위키백과 항목 목록 |
| 일상몽 | 낮의 일을 그대로 재현한 꿈. 특별한 뜻이 없다고 본다 | 위키백과 항목 목록 |
| 개꿈 | 뜻이 없는 잡스러운 꿈이라는 뜻의 속된 말. 정의와 사용 범위는 확인 필요 | 위키백과에 항목 없음. 확인 필요 |
| 반몽(反夢) | 꿈 내용과 반대로 풀어야 한다는 민간 관념. 정확한 전통 근거 확인 필요 | 위키백과 항목 목록 |
| 용꿈 | 용이 나오는 꿈. 출세나 큰 행운의 상징으로 흔히 풀이된다 | 해몽 사이트 다수(확인 필요: 원전) |
| 돼지꿈 | 돼지가 나오는 꿈. 재물이나 길조로 풀이되는 것이 가장 흔하다 | 위키백과, 해몽 사이트 다수 |
| 조상 꿈 | 돌아가신 분이 꿈에 나오는 경우. 해석은 사전마다 다르다 | 해몽 사이트 다수. 확인 필요 |

### 2.3 해몽 방식의 기본 틀

민간 해몽은 크게 세 가지 방식이 섞여 있다.

- 소재 사전식: 꿈에 나온 대상(동물, 사람, 사물)을 찾아 뜻을 읽는다. 가장 흔하다.
- 상황 조합식: 대상과 행동, 장면(밝음·어둠, 올라감·떨어짐), 깨어난 뒤의 기분을 함께 본다. 같은 뱀 꿈도 어떻게 나왔는지에 따라 길흉이 갈린다고 설명하는 자료가 있다(대구일보, 검색 요약 기준).
- 길흉 이분법: 좋은 꿈과 나쁜 꿈으로 나눈다. 단순하지만 사용자가 가장 쉽게 이해한다. 다만 서구 심리학의 상징 해석이나 학문적 꿈 연구에서는 이 구분을 쓰지 않는다(관례의 차이).

### 2.4 학문적 꿈 연구의 현재 입장

- 현재 과학계에서 꿈의 상징에 보편적 의미 사전이 있다는 근거는 찾지 못했다. 대중 매체 글은 이 점을 자주 언급한다(검색 요약 기준, 2차 자료 위주).
- Hall과 Van de Castle가 1966년 펴낸 꿈 내용 분석 체계(`The Content Analysis of Dreams`)는 꿈 보고를 인물, 행동, 감정, 배경 등으로 코딩하는 방법으로 가장 많이 쓰인다고 소개된다. 이 체계는 빈도와 범주를 세는 것이지 상징의 뜻을 정하는 사전이 아니다(검색 요약 기준. 원문 확인 필요).
- 같은 자료들은 꿈 내용이 깨어 있을 때의 걱정과 이어진다는 연속성 연구를 소개한다(검색 요약 기준).
- 결론(추정): 서비스에서 "꿈이 무엇을 뜻한다"고 단정하면 근거가 없다. "민간에서 이렇게 풀이한다" 또는 "요즘 걱정과 이어서 생각해 볼 수 있다" 같은 틀이 맞다.

## 3. 규칙과 관례

### 3.1 공식 규칙이 있는가

- 꿈 해몽에는 법이나 학회가 정한 공식 규칙이 없다. 전통 해몽서와 상업 사이트가 각자 기준을 가진다.
- 따라서 "이 서비스의 풀이 기준"을 밝히는 것이 필요하다. 타로와 운세가 쓴 방식(해석 기준을 화면에 밝힘)과 같다.

### 3.2 길몽·흉몽 구분의 관례

- 관례 1: 소재 자체로 길흉을 정한다(예: 돼지는 길, 뱀은 흉). 사이트 대부분이 이 방식이다.
- 관례 2: 장면과 기분으로 바꾼다(밝은 물은 길, 탁한 물은 흉). 전통 자료에 있다는 설명이 있지만 원전 확인 필요.
- 관례 3: 죽음 꿈을 재생이나 전환의 길몽으로 보는 풀이가 있다. 나무위키 등은 이 관념을 소개한다(검색 요약 기준).
- 관례 4: 흉몽을 꾸면 몸을 사리고, 길몽을 꾸면 적극적으로 나서라는 해석. 상업 사이트 공통 문구(추정).

앱 시사점: 길흉 표시를 쓴다면 "민간에서 전하는 구분"이라고 밝히고, 흉몽을 공포나 위험 예고로 쓰지 않는다. 길흉 대신 "마음 점검", "주의", "좋은 신호" 같은 중립 표현을 쓰는 방식도 가능하다(기획 선택지).

### 3.3 태몽 관례

- 태몽은 출산 이야기와 함께 쓰이는 민속 관념이다. 의학적 근거는 없다.
- 임신 중이거나 임신을 준비하는 사람이 입력하면 성별이나 성격을 단정하는 문구가 나오기 쉽다. 이는 단정 표현 금지와 충돌한다(8장).
- 기획 권고(추정): 태몽은 "민간에서 이렇게 말해 왔다" 수준으로만 쓰고, 성별·건강·임신 여부를 판정하는 표현은 쓰지 않는다.

### 3.4 해몽 풀이의 출처 관례

- 많은 사이트는 "전통 해몽서를 참고했다"고 쓰지만 원전 제목과 판본을 밝히는 곳은 드물다. 이번 조사에서 확인한 것은 『주공해몽』(周公解夢, 중국 계열 해몽서로 한국에도 번역·편집본이 있음)이다. 해몽 사이트들이 이 책을 기준으로 삼는다고 설명하지만 원전 대조는 못 했다(확인 필요).
- 한국 고전 해몽서로 『해몽지남』이라는 이름이 기획 자료에 나올 수 있다. 이번 검색에서는 근거를 찾지 못했다. 확인 필요.
- 1984년 『꿈해몽법』(은광사)이 도서 목록에서 확인된다. 현대 저작이며 내용은 확인하지 않았다(4장 저작권 참조).
- 국립중앙도서관은 보존 가치가 있는 고서와 오래된 자료를 디지털화해 제공한다. 해몽 관련 고서가 공개되어 있는지는 검색 키워드(해몽, 몽점, 꿈 풀이)로 직접 확인이 필요하다(확인 필요).

출처: [국립중앙도서관 디지털화 자료](https://www.nl.go.kr/NL/contents/N10200000000.do), [Wikipedia Igong bon-puri (영문, 주공해몽 계열 소개)](https://en.wikipedia.org/wiki/Igong_bon-puri), [꿈 해몽 대백과 상품 페이지](https://www.yes24.com/product/goods/3238863) (상품 정보 기준).

## 4. 저작권

### 4.1 결론 요약

| 자산 | 상업 이용(광고 포함) | 근거와 주의 |
|---|---|---|
| 꿈의 상징에 대한 아이디어(예: "돼지가 나오면 재물이 생긴다는 생각") | 가능 (보호 대상이 아닐 가능성이 높음) | 저작권법은 사상·사실 자체를 보호하지 않고 표현을 보호한다(4.2). 단, 아이디어가 있다고 해서 그 아이디어를 설명하는 문장을 베껴도 된다는 뜻은 아니다 |
| 다른 해몽 사이트·책의 풀이 문장 | 복사, 번역, 어순 변경, 일부 단어 교체 금지 | 짧은 풀이 문장도 창작성이 있으면 보호될 수 있다는 해설이 있다. 풀이가 길수록 위험이 높다(타로·운세 리서치와 같은 결론, 검색 요약 기준) |
| 해몽 사이트의 소재 목록(예: 100개 꿈 이름 목록) | 목록 자체의 사실 나열은 가능성이 높다. 편집 저작물 가능성은 남음 | 특정 사이트의 선택과 배열을 그대로 가져오면 편집저작물 침해 판단이 가능하다. 법률 확인 필요 |
| 전통 해몽서(주공해몽 계열) 원문 | 원전 저작권 보호기간 확인 필요. 번역본·편집본·주석은 별도 저작물 | 오래된 원전은 보호기간이 지났을 가능성이 있으나, 현대 편집본과 번역은 별도 권리다. 법률 확인 필요 |
| 현대 해몽서(예: 『꿈해몽법』 1984년, 해몽 대백과류) | 쓰지 않는다 | 현대 저작물로 보고 문장과 구성 모두 보호 대상으로 본다 |
| 국립중앙도서관 디지털 고서 원문 | 기관 이용 조건 확인 필요 | 저작권 만료나 이용 허락이 있는 자료만 무료 열람이 가능하다고 안내된다(검색 요약 기준). 원문을 그대로 쓰는 것은 권장하지 않는다 |
| 공공누리 저작물(예: 한국민족문화대백과 항목) | 유형에 따라 다름 | 제1유형은 출처표시 조건에서 상업 이용과 변경이 가능하다. 해몽 항목이 있는지, 어떤 유형인지는 확인하지 못했다(확인 필요) |
| 꿈 관련 이미지(동물·꿈 장면 그림) | 자체 제작 권장 | 외부 그림 세트나 스톡 이미지는 라이선스 확인 필요. 타로처럼 인라인 SVG 자체 제작이 선례다(`COMPLIANCE.md` 11장) |
| 경쟁 사이트 화면·문구·목록 스크래핑 | 하지 않는다 | 표현 보호 위반과 약관 위반 위험. 검색 목적의 소재 이름 확인은 직접 검색 결과 열람으로 한다 |
| AI가 생성한 문구 | 법률 확인 필요 | 권리 귀속이 불명확하다. 기록 방식은 4.3 참고 |

### 4.2 저작물성의 기준 (법 조문 요약)

- 저작권법 제2조 제1호: 저작물은 사람의 사상이나 감정을 표현한 창작물이다. 창작성은 남의 것을 베끼지 않고 자기 생각을 표현했다는 뜻이며 높은 수준을 요구하지 않는다(생활법령 정보 기준).
- 저작권법은 표현을 보호하고, 그 속의 아이디어·사실·기능은 보호하지 않는다(생활법령 정보 기준).
- 저작권법 제7조는 법령, 고시, 판결, 사실 전달 수준의 시사보도 등을 보호받지 못하는 저작물로 든다(생활법령 정보 기준). 해몽 문구가 여기에 해당하지는 않는다.
- 해몽 문구의 창작성: 짧고 정형화된 한 줄 풀이("돼지꿈은 재물운을 뜻한다")는 누구나 쓸 수 있는 표현이라 창작성이 약하다고 볼 수 있다. 반대로 상황을 묘사하고 조언을 붙인 긴 문장은 창작성이 있을 가능성이 높다(추정, 법률 확인 필요).
- 판례 참고: 편집저작물 여부를 다룬 판결에서 이야기를 모으고 짧은 해설을 붙인 책에 대해 창작성 논쟁이 있었다. 판결 본문은 확인하지 못했고 검색 목록에서 쟁점만 확인했다(law.go.kr 판례 목록, 검색 요약 기준). 해몽 사전에 그대로 적용되는지는 확인 필요.

출처: [생활법령정보 저작권보호 개요](https://www.easylaw.go.kr/CSP/CnpClsMain.laf?csmSeq=695&ccfNo=1&cciNo=1&cnpClsNo=1), [CBLaw.Net 보호받지 못하는 저작물](https://cblaw.net/305), [law.go.kr 판례 목록(저작권침해 관련)](https://www.law.go.kr/LSW//precInfoP.do?precSeq=193856), [law.go.kr 판례 171365](https://www.law.go.kr/precInfoP.do?mode=0&precSeq=171365).

### 4.3 우리 방식: 독자 작성 + 작성 이력 기록 (copy-log 절차 제안)

타로와 운세에서 쓴 절차를 꿈 해몽에도 같은 순서로 쓰기를 제안한다. 파일 경로는 `docs/dream-interpretation/copy-log.md`(제안).

1. 작성 원칙: 민간 상징의 일반 아이디어만 바탕으로 처음부터 새로 쓴다. 작성 중에는 해몽 사이트, 책, 앱의 풀이 문장을 보지 않고 붙여 넣지 않는다. 번역과 어순 변경을 하지 않는다. (타로 copy-log, 운세 copy-log의 AI 생성 지침 2~3번과 같다.)
2. 소재 이름 목록: 검색 수요를 보기 위해 여러 사이트의 소재 이름을 참고할 수는 있으나, 목록을 통째로 옮기지 않는다. 소재 이름은 사실 나열이지만 편집은 자체로 한다. 법률 확인 필요.
3. 작성 이력: 묶음마다 작성 주체(AI, 사람), 작성일, 검수 상태를 기록한다.
4. 웹 검색 샘플 점검: 완성 후 대표 문장을 따옴표로 검색하고, 같은 문장이 있으면 새로 쓴다. 기록 표는 타로 copy-log 형식을 따른다. 샘플 규모는 묶음별 20문장 이상, 고지·FAQ 10문장 이상을 제안한다(운세 선례 기준, 추정).
5. 한계 기록: 검색 점검은 전수 검사가 아니며 "일치 없음"은 "없다"가 아니라 "찾지 못했다"라는 뜻이다(운세 copy-log 한계 절과 같다).
6. 검수: 오타와 의미 검수는 사용자(운영자)가 한다. 외부 문서와 대조하는 검수는 하지 않는다(타로 선례).

### 4.4 AI 생성 문구의 법적 위치

- 생성형 AI로 쓴 문구의 저작권 귀속은 이번 조사에서 확정하지 못했다. 법률 확인 필요.
- 선례: 타로와 운세는 AI 작성 이력을 `copy-log`에 남긴다. 꿈 해몽도 같은 방식을 권장한다.
- 입력으로 다른 사이트 문장을 넣으면 AI 생성물이라도 복제 문제가 생긴다. 이 점을 기록 원칙에 넣는다.

## 5. 법적·표현 주의점

### 5.1 오락 목적 고지

- 한국에서 꿈 해몽 서비스에 면책 문구를 의무화한 법령은 확인하지 못했다(확인 필요). 타로와 운세 리서치와 같은 결론이다.
- 법적 의무가 아니더라도 오인과 분쟁을 줄이기 위해 두는 것을 권한다. 타로 선례처럼 h1 바로 아래에 상시 노출하고 결과 아래에 짧은 안내를 반복하는 방식이 있다(`COMPLIANCE.md` 11장).
- 면책 문구에 담을 내용(새 문장으로 쓸 것. 아래는 목록이지 최종 문구가 아니다)
  1. 오락과 참고를 목적으로 한 민간 풀이 서비스라는 점
  2. 꿈과 현실 사건의 관계는 과학적으로 확인되지 않았고 미래를 보장하지 않는다는 점
  3. 건강, 수면, 정신건강, 법률, 재정 문제는 전문가 상담이 필요하다는 점
  4. 꿈 풀이로 중요한 결정을 하지 말라는 점
  5. 풀이 기준이 전통 해몽과 이 서비스의 기준임을 밝히는 점
  6. 특정 해몽서나 사이트와 제휴 관계가 없다는 점
  7. 로또 연결이 있다면 번호와 당첨은 무관하다는 점(9장)

### 5.2 단정, 예언, 보장 표현 금지

- 타로와 운세의 금지 표현 목록(보장, 적중, 100%, 반드시, 확실히, 운명이 바뀐 등)을 그대로 쓴다(`src/features/tarot/constants/tarot-copy-rule.constant.ts`, 운세의 `fortune-copy-rule.constant.ts` 참고).
- 꿈 특유의 금지 표현(추정):
  - "이 꿈은 곧 ~가 일어난다", "꿈이 ~를 예고한다" (예지 단정)
  - "꾸면 반드시 당첨된다", "꿈을 꾸면 돈이 들어온다" (재물 보장)
  - "태몽이므로 아들·딸이다" (성별 단정)
  - "이 꿈은 죽음을 뜻한다" (생명 관련 단정)
- 허용 방향(추정): "민간에서는 ~로 풀이해 왔다", "요즘 걱정과 이어서 생각해 볼 수 있다", "마음이 쓰이는 일을 돌아보는 계기로 삼아 보세요".

### 5.3 의료·정신건강 (악몽, 불안, 수면)

- 악몽이 반복되어 생활에 지장이 있으면 의학에서는 악몽장애(Nightmare disorder)로 본다. DSM-5(미국정신의학회 진단 기준) 기준으로는 반복적이고 길며 불쾌하게 기억되는 꿈이 있고, 생존이나 안전을 위협하는 내용이 많으며, 깨어난 뒤 빠르게 정신이 돌아오고, 수면 장애로 생활에 고통이 생겨야 한다. 공존하는 정신질환이나 의학적 상태로 설명되지 않아야 한다(검색 요약 기준, 정신의학 자료 기준).
- 악몽장애는 외상후 스트레스 장애 환자에서 흔하게 동반된다고 보고된다(검색 요약 기준). 한국에서도 대한수면연구학회 학술지에 악몽장애 임상 면담 연구가 실렸다(검색 요약 기준).
- 서비스 주의점(추정): 꿈 해몽 페이지에 악몽, 공포, 죽음, 추락 소재가 많이 들어오므로 "꿈 풀이로 해결되지 않을 때 전문가 상담"을 안내한다. 악몽을 진단하거나 수면 장애를 판단하는 표현은 쓰지 않는다.
- 위기 안내: 자살, 죽음, 살인 관련 소재를 풀이할 때는 타로·운세와 같은 상담 전화 안내를 둔다. 공유 상수 `src/constants/crisis-phone.constant.ts`를 재사용하는 방안을 제안한다(사용자가 설계에서 확정). 전화번호와 운영 시간은 출시 전 재확인이 필요하다(`COMPLIANCE.md`에 마지막 확인일 2026-11-05, 재확인 2026-11-16 기록). 이번 조사에서 확인한 현재 번호는 다음과 같다(검색 요약 기준): 자살예방 상담 109, 정신건강 상담 1577-0199, 생명의전화 1588-9191, 청소년 1388.
- 죽음 소재 완화(추정): 죽음 꿈을 "끝과 전환"으로 풀이하는 관례가 있다(2.2, 3.2). 이 관례를 쓰되, 자살과 관련된 장면은 전환 풀이로 넘기지 않고 상담 안내를 우선한다.

### 5.4 사행성·도박 조장 표현 (가장 큰 위험)

이 항목은 사이트의 로또 메뉴와 직접 연결되므로 기획 단계에서 명확히 정해야 한다.

- 꿈 해몽 사이트에는 "꿈 번호", "꿈에서 본 숫자로 로또 번호 뽑기", "돼지꿈 로또 번호" 같은 페이지가 많다. 이번 검색에서도 이런 사이트와 기사가 확인됐다(검색 요약 기준).
- 국내에서는 로또 예측 번호 서비스의 기만적 광고와 사행성 조장이 문제가 되어 왔다. 한국소비자원 피해구제 신청과 기사가 이어졌다(`docs/research/fortune.md` 8.2, 9장과 같은 근거).
- 2025년 10월 국회에서 복권 당첨 예상번호를 영리 목적으로 제공하거나 홍보하는 행위를 금지하는 복권 및 복권기금법 개정안이 발의됐다는 보도가 있다. 발의 주체는 13명, 처벌은 1년 이하 징역 또는 1,000만 원 이하 벌금으로 보도됐다. 통과 여부는 확인하지 못했다(확인 필요, 국회 의안정보시스템에서 확인해야 함).
- 2024년 뉴시스 보도에서 전문가와 소비자단체가 예측 번호 서비스를 규제해야 한다고 주장했다. 2021년 기획재정부 의뢰 연구도 영리 목적의 당첨번호 제공 제재를 제안했다(`docs/research/fortune.md` 9장, 검색 요약 기준).
- 2026년 3월 한국신문윤리위원회는 "예상번호" 광고를 낸 언론사 47곳에 주의 조치를 했다는 보도가 있다(검색 요약 기준, 원문 확인 필요).
- 동행복권은 당첨번호를 과학적으로 예측할 수 없다고 밝힌다(`docs/research/fortune.md` 9장 인용).

권고(추정, 법률 확인 필요):
1. 꿈 해몽 결과에서 로또 번호를 생성하거나 "꿈 번호", "행운 번호"를 로또 형식(1~45 범위, 6개)으로 보여 주지 않는다.
2. 꿈 해몽 페이지의 제목, 설명, 메타 키워드, 본문에 "로또 번호", "꿈번호", "당첨 번호" 같은 검색어를 넣지 않는다. 검색 수요가 있더라도 목표 키워드로 잡지 않는다.
3. 로또 메뉴로 가는 링크를 둘지는 기획 결정이다. 운세에서는 "행운의 숫자 1~10을 생성기로 연결"하는 방식이 승인되어 있다(`COMPLIANCE.md` 11장). 꿈에서 같은 링크를 두면 "꿈이 번호를 정한다"는 인상이 생긴다. 이 점을 기획서에 명시한다.
4. 광고 플랫폼의 사행성 항목(카카오 AdFit 등)에 로또 관련 광고가 붙지 않는지 확인이 필요하다(확인 필요).

### 5.5 과장·허위 광고

- 「표시·광고의 공정화에 관한 법률」 제3조의 거짓, 과장 광고 금지 조항은 `docs/research/fortune.md` 8.2에서 인용했다(조문 1차 확인 필요).
- 꿈 사이트 상당수가 "국내 1위", "15년 전통", "몇십만 명이 선택" 같은 문구를 쓴다. 이번 조사에서 확인한 앱 소개는 모두 자기 보고 수치였다(검색 요약 기준). 이런 수치를 쓰면 근거를 남겨야 한다.
- 권고(추정): 사용자 수, 순위, 전통 원전의 연도를 내세우지 않는다. 근거가 없으면 쓰지 않는다.

### 5.6 개인정보와 민감 입력

- 꿈 내용은 개인의 정신 상태, 가족 관계, 건강, 트라우마와 연결될 수 있다. 자유 서술로 받으면 민감정보가 들어올 수 있다.
- 개인정보보호법 제23조(민감정보)와 제2조의 정의는 `docs/research/fortune.md` 8.4에서 다뤘다. 꿈 입력은 건강·신념 등 민감정보가 섞일 가능성이 있으므로 법률 확인 필요.
- 권고(추정): 자유 서술 입력란을 두지 않고 선택형(소재, 상황, 기분 칩)으로 입력받는다. 타로처럼 질문 입력란을 두더라도 서버 전송과 저장을 하지 않는다. 입력은 화면 계산에만 쓴다. 이 방식이면 개인정보 부담이 가볍다(`COMPLIANCE.md` 1장 타로·운세 선례와 같은 방향).
- 생년월일이나 이름을 받지 않는다면 운세 같은 14세 미만 게이트 문제는 줄어든다. 다만 악몽과 가족 이야기를 다루므로 나이 안내를 둘지는 기획 결정이다.
- 제3자 정보: "엄마 꿈", "친구 꿈"처럼 타인이 등장하는 꿈은 이름을 입력받지 않는 것을 권장한다(추정).

### 5.7 광고 플랫폼 정책

- Google AdSense: 해몽·운세를 이름으로 제한하는 항목은 확인하지 못했다(`docs/research/fortune.md` 8.6, 타로 리서치와 같은 한계). 확인 필요.
- 대규모 콘텐츠 남용(scaled content abuse): Google은 AI 사용 자체가 아니라 가치 없이 많은 페이지를 대량 생성하는 것을 문제로 본다. 페이지 수 기준은 없다. 소재마다 한두 줄만 있는 페이지를 대량으로 만들면 위험하다(추정). 이 정책은 검색 노출 정책이며 AdSense 승인 기준과 별개다.
- 권고(추정): 소재 페이지는 소재마다 충분한 분량과 독자 작성 문구가 있을 때만 만든다. 얇은 페이지는 색인에서 빼거나 묶는다(기획 결정).

### 7.4 SEO 관점 메모 (`docs/conventions/seo.md` 기준)

- 새 페이지는 `buildMetadata()`로 메타데이터를 만든다. 직접 객체를 만들지 않는다. `pathname`은 `/`로 시작한다.
- 구조화 데이터: `jsonLdFaq`, `jsonLdBreadcrumb` 등을 쓴다. 소재 풀이에 FAQ가 많으므로 FAQ 구조화 데이터가 유용하다(추정).
- 사이트맵: `MENU_LIST`에 등록하고 준비 중이면 `comingSoon: true`. 소재 페이지는 별도 등록 방식을 설계에서 정한다.
- 콘텐츠는 서버 렌더링 HTML에 있어야 검색에 잡힌다. 타로와 운세는 일부 문구를 동의 후에만 불러오는 구조였다(`COMPLIANCE.md` 1장, 7장). 꿈 소재 풀이는 검색 노출 핵심이므로 동의 게이트에 걸면 검색에 잡히지 않는다. 공개 콘텐츠로 둘지 기획 결정이 필요하다(11장 질문).
- URL은 소문자, 하이픈을 쓴다(`/dream/pig` 같은 형태는 예시. 실제 경로는 설계에서 확정). 이미 노출된 URL을 바꾸면 301 redirect가 필요하다(`next.config.ts`).
- 한 페이지에 h1은 하나만 쓴다. 이미지에는 alt를 새로 쓴다.
- 얇은 콘텐츠 위험: 소재 이름만 바꾼 페이지를 대량으로 만들면 대규모 콘텐츠 남용으로 볼 수 있다(5.7). 소재 페이지마다 독자 풀이가 충분해야 한다.
- 경쟁 차별 포인트(추정): (1) 사행성 연결 없음, (2) 단정 없는 민속 풀이와 자기 성찰 문구, (3) 상황 선택형 풀이, (4) 12지 동물 소재를 띠 운세와 내부 링크로 묶기.

| 연결 대상 | 가능한 연결 | 평가 |
|---|---|---|
| 띠 운세 (`/fortune` 계열) | 12지 동물 소재(돼지, 뱀, 호랑이 등)에서 띠 운세 페이지로 링크 | 사용자 흐름이 자연스럽다. 띠 풀이와 동물 풀이를 같은 이름으로 쓰면 혼동 주의 |
| 오늘의 운세 | 오늘의 운세 하단에 "오늘 꿈을 찾아보기" 링크 | 가볍고 안전. 꿈 결과를 운세 점수와 섞지 않는다 |
| 타로 | 상징을 읽는 방식이 비슷하므로 "카드 상징 읽기"와 "꿈 상징 읽기"를 나란히 소개 | 타로의 정방향·역방향 구조와 비교하는 글은 가능하나 편집 중복 주의 |
| 로또 | 링크 없음이 권장. 링크를 둔다면 사행성 고지와 함께 `/lotto/generator`로 가는 링크만 | 5.4 참고. 기획과 법률 확인 필요 |
| 로또 메뉴 기록(나의 번호 등) | 연결하지 않는다 | 꿈에서 나온 번호를 저장하는 기능은 사행성 위험이 크다 |

### 8.2 차별점 후보

- 번호와 당첨 연결 없음. 해몽 사이트 다수와 가장 크게 다른 점이다.
- 단정 없는 표현. "꿈은 ~를 뜻한다"가 아니라 "민간에서는 ~로 풀이해 왔다"와 "요즘 생각을 돌아보는 계기"로 쓴다.
- 사람이 쓴 독자 문구와 작성 이력. 타로·운세 copy-log 방식을 그대로 보여 주는 것이 신뢰 요소가 된다.
- 상황 선택형 흐름. 소재 하나에 기분과 장면을 고르면 다른 문장이 나온다.
- 이 사이트의 기존 메뉴와 연결해 "상징을 읽는 세 가지 방식(꿈, 타로, 운세)"처럼 묶는 구조(추정).

## 9. 데이터 규모와 저장 방식 (의견)

### 9.1 규모 감

| 항목 | 경쟁 사이트 관찰 | 의견 (추정) |
|---|---|---|
| 소재 수 | 61(teck-tani), 100(mgunexcel), 146(검색 요약 사이트), 181(la-boom), 약 2만 건(신통, 세부 항목 수 불명) | MVP는 100~150개 소재면 검색 상위 소재를 대부분 덮는다. 상위 30개가 검색 수요의 대부분이라는 근거는 없음(확인 필요) |
| 소재별 풀이 | 한 줄 사전 풀이부터 상황별 여러 개까지 다양 | 소재당 기본 풀이 1개 + 상황별 2~3개가 적정. 전체 약 300~500개 문구 |
| 공통 문구 | 면책, 사용법, 길흉 설명, 상담 안내 | 10~20개 고정 문구. 면책 문구는 `COMPLIANCE.md` 식 고정 상수로 관리 |
| 동의어·별칭 | teck-tani는 이, 이빨, 치아 등 별칭 검색 | 소재당 별칭 2~5개. 별칭 목록은 자체 작성 |

### 9.2 정적 데이터로 충분한가

- 이번 범위(소재 100~150, 문구 수백 개, 정적 텍스트)는 정적 데이터로 충분하다는 것이 researcher의 의견이다(추정). 데이터가 자주 바뀌지 않고, 사용자 입력이 저장되지 않는다.
- 다만 소재 페이지를 수백 개 이상 만들고 검색 노출을 원하면 페이지 생성 방식과 목록 관리 규칙이 필요하다. 설계 담당이 정할 일이다.
- 사용자 기록(꿈 일기, 즐겨찾기)을 넣으면 저장소 정책이 필요하다. 저장 위치는 `docs/conventions/data-storage.md`에 따라 설계 단계에서 판단한다. 이번 리서치는 저장 방식을 권하지 않는다.
- DB가 필요해지는 경우(추정): 운영자가 웹에서 문구를 자주 고치거나, 다국어를 붙이거나, 사용자 저장과 통계를 한 곳에 모을 때.

### 9.3 데이터 출처별 상태 (요약)

| 데이터 | 상태 |
|---|---|
| 길흉 분류와 소재 이름 | 민간 관념. 자체 작성. 저작권 위험은 표현에만 있음 |
| 전통 해몽서 원문 | 원전 확인 필요. 원문 인용은 피한다 |
| 공공 데이터 (꿈 풀이 데이터) | 찾지 못함. 확인 필요 |
| 천문·절기 데이터 | 꿈 풀이에는 필요 없음 |

## 11. 기획자에게 넘길 열린 질문

범위와 메뉴
1. 범위: 소재 사전형만 할지, 상황 선택형까지 할지, AI 자유 서술 해몽까지 할지. 이 리서치는 AI 자유 서술을 1차 범위에서 뺄 것을 권한다(민감정보, 검수, 권리, 사행성 이유).
2. 소재 수: MVP를 100개 안팎으로 할지, 300개 이상으로 할지. 소재당 풀이 깊이는 어느 정도인지.
3. 메뉴 위치: 운세 그룹 하위(예: `/fortune/dream`)에 둘지, 독립 메뉴로 둘지. 메뉴 라벨과 색을 어떻게 할지(`design-system.md` 기준).
4. 공개 범위: 소재 풀이를 동의 없이 바로 보여 줄지(검색 노출에 유리), 운세처럼 동의 후 보여 줄지.

풀이 기준과 표현
5. 길흉 표시: 길몽·흉몽 태그를 쓸지, 중립 표현("좋은 신호", "주의할 신호", "마음 점검")으로 바꿀지.
6. 풀이 기준: 소재 이름 중심으로 할지, 상황 조합으로 할지. 전통 해몽 기준을 어디까지 반영하고 "이 사이트의 기준"을 어떻게 밝힐지.
7. 태몽: 범위에 넣을지. 넣는다면 성별·건강·임신 관련 단정 문구를 모두 뺄지.
8. 죽음·장례·자살 관련 소재: 풀이 방식(전환 관념 사용 여부)과 상담 안내 노출 기준.

로또와 사행성
9. 로또 연결을 0으로 둘지(리서치 권고), 로또 생성기 링크만 둘지. 링크를 둔다면 고지 문구는 어떻게 할지.
10. 꿈 결과에서 번호처럼 보이는 숫자(1~45, 6개)를 쓰지 않는다는 원칙을 기획서에 명시할지.
11. 로또 관련 개정안(2025-10 발의)의 현재 상태를 누가 확인할지. 법률 검토를 받을지, 운세·타로처럼 수용 위험으로 둘지.

입력과 개인정보
12. 입력 방식: 선택형(소재·상황·기분 칩)만 둘지, 자유 서술 입력란도 둘지. 리서치는 선택형을 권한다.
13. 타인 등장 꿈("엄마 꿈")처럼 제3자 정보를 입력받을지. 이름 입력은 받지 않는 것을 권한다.
14. 꿈 기록(일기, 즐겨찾기) 기능을 넣을지. 넣는다면 저장 위치와 동의 방식을 설계에서 정한다.
15. 나이 안내: 운세처럼 14세 게이트를 둘지, 안내 문구만 둘지.

문구와 저작권
16. 문구 작성 주체: AI 작성 + 사람 검수(운세 선례)로 할지, 사람이 직접 쓸지. 작성 이력(`docs/dream-interpretation/copy-log.md`)을 둘지.
17. 전통 해몽서 참조 범위: 원전을 참고만 하고 인용하지 않을지. 원전 판본을 특정할지.
18. 법률 검토: 꿈 해몽은 법률 검토 없이 수용 위험으로 갈지, 출시 전 검토를 받을지(타로·운세는 수용 위험으로 진행 중이다).

연결과 SEO
19. 오늘의 운세와 연결: 링크 수준으로 할지, 같은 화면에서 함께 보여 줄지.
20. 띠 운세와 12지 동물 소재를 내부 링크로 묶을지.
21. 소재 페이지 수: 소재 전부를 색인에 넣을지, 분량이 충분한 소재만 넣을지.
22. 검색 키워드 목표: 소재 검색 중심으로 할지, "꿈해몽" 같은 상위 키워드를 목표로 할지(경쟁이 큼).

운영
23. 면책 문구와 상담 전화 재확인 주기(`COMPLIANCE.md` 기준 출시 전 재확인). 담당자 지정.
24. 메뉴 출시 시점: 신년 시즌(연말~설)과 맞출지. 신년 시즌에 검색 수요가 몰리는지는 확인하지 못했다(확인 필요).
