# 날씨 반영 메뉴 추천 (meal-weather) 리서치

조사일: 2026-11-28. 기능 이름: `meal-weather`. 이 문서는 기획 입력용이며 코드 설계는 담당하지 않는다.

## 0. 한 줄 요약

"오늘 뭐 먹지" 추천에 현재 날씨(비·눈·더움·추움)를 반영하기 위해, 한국 기상청 동네예보 API(공공데이터포털 경유)를 1순위 데이터로 쓰는 것을 권장한다. 서버에서 시·도 대표 좌표로 호출하고 1시간 캐시한다. 상업적 이용이 허용되고 출처 표기만 하면 된다.

## 1. 전제 확인에서 나온 중요한 사실 (기획 전 확인 필요)

1. **시·도 17곳이 아닐 수 있다.** 전라남도와 광주광역시가 2026-07-01부로 "전남광주통합특별시"로 통합되었다는 보도가 있다. 이 경우 광역 단위는 16곳이 된다(추정). 대구·경북, 대전·충남 통합은 2026-11-27 기준 법 심의 중이거나 보류 상태로 보도됐다. 기획 전에 "17곳 기준을 유지할지, 현행 행정구역(16곳 또는 17곳)을 따를지"를 정해야 한다. (출처 4, 5, 6)
2. **Open-Meteo 무료 API는 이 사이트에 쓸 수 없다.** 무료 API 약관은 비상업 용도만 허용하며, 약관이 드는 상업 예시로 "구독이 있거나 광고를 게재하는 웹사이트나 앱"을 직접 든다. 이 사이트는 AdFit 광고를 게재하므로 해당된다. (출처 1, 2)
3. **DATA_GO_KR_API_KEY는 현재 개발 스크립트 전용이다.** `README.md` 55행 표는 "런타임 미사용"이라고 적고 있다. 런타임 호출로 바꾸면 README 표와 `COMPLIANCE.md`를 함께 고쳐야 한다. 키는 서버 전용으로만 쓰고 클라이언트 번들에 들어가면 안 된다. (저장소 `README.md`, `COMPLIANCE.md` 9장)
4. **사용자 위치를 받지 않는다는 기존 방침을 유지해야 한다.** `docs/meal-location/plan.md`는 위치 권한을 쓰지 않는 방향으로 정했다. 날씨 반영도 위치 권한 없이 "시·도 선택" 또는 "대표 좌표" 방식이어야 기존 방침과 맞는다. 이 결정은 기획자 몫이다.

## 2. 핵심 개념 (처음 보는 사람 기준)

- **동네예보**: 기상청이 전국을 약 5km 격자로 나눠 제공하는 예보다. 위도·경도가 아니라 격자 번호(nx, ny)로 지점을 지정한다.
- **초단기실황**: 격자별 "지금 관측된 값"이다. 매시 정시 기준으로 발표되고 약 40분 뒤부터 조회 가능하다는 정리가 있다(공식 확인 필요, 아래 3장 참고).
- **단기예보**: 3일 이내 시간별 예보다. 하루 여러 번 발표된다.
- **격자 변환**: 위도·경도를 nx, ny로 바꾸는 과정이다. 기상청 격자는 람베르트 정각원추 도법을 쓰고, 변환 상수(지구 반경, 투영 위도 30°·60°, 기준점 경도 126°, 기준점 위도 38°, 기준점 격자 X=43, Y=136)가 공개돼 있다(출처 7, 8). 공식 가이드 원문은 확인 필요.
- **공공누리**: 공공기관 저작물의 이용 조건 표시 체계다. 유형에 따라 출처표시, 상업적 이용, 변경 가능 여부가 달라진다(출처 9, 10).
- **규칙 구분**: 공식 규칙은 공공데이터 약관, 공공누리 유형 정의, Open-Meteo·Visual Crossing 약관처럼 제공처가 명시한 것이다. 관례는 "발표 후 40분" 같은 실무 타이밍처럼 공식 문서로 확인되지 않은 것이다.

## 3. 데이터 출처 조사

### 3.1 Open-Meteo (무료 API)

- 무료 API는 비상업 목적만 허용한다. 약관 원문: "You may only use the free API services for non-commercial purposes." (출처 1)
- 상업 예시: "Websites or apps that have subscriptions or display advertisements." (출처 1) → 이 사이트는 광고 게재이므로 상업 이용이다.
- 무료 한도: 분당 600, 시간당 5,000, 일 10,000, 월 300,000건. (출처 1, 2)
- 상업 이용은 유료 플랜(Standard 월 100만 건, Professional 월 500만 건, Enterprise 월 5,000만 건 이상)으로 해결한다. 요금은 페이지에 없고 확인 필요. (출처 2)
- 데이터 라이선스: CC BY 4.0. 출처 표시와 변경 사항 표시가 필요하다. (출처 1, 2)
- 키 필요 여부: 무료 티어는 키가 없다고 추정되나 명시되지 않았다. 확인 필요.

### 3.2 기상청 단기예보 조회서비스 (공공데이터포털)

- 제공처: 기상청 (공공데이터포털 `data.go.kr/data/15084084`). 동일 데이터를 "기상청 API허브 연계" 상품(`data.go.kr/data/15139470`)으로도 제공한다. (출처 11, 12)
- 이용허락범위: "저작권 표시, 공공저작물 : 출처표시 (제 1유형)". 공공누리 제1유형이다. (출처 11)
- 공공누리 제1유형: 출처표시 필요, 상업적 이용 가능, 2차 저작 가능. (출처 9, 10)
- 출처표시 방법: 작성연도, 기관명, 홈페이지 주소, 작성자명을 표시하고 온라인이면 링크를 건다. (출처 10)
- 심의: 15084084는 개발·운영 모두 자동승인으로 보도됐다. 15139470은 개발 자동승인, 운영 심의승인이다. (출처 11, 12)
- 트래픽: 개발계정 10,000건(출처 11). 일 기준인지 페이지에 없음, 확인 필요. 일반적으로 공공데이터포털 개발계정은 한국 시간 자정에 초기화된다는 정리가 있으나 이 API에 대해서는 확인 필요. 운영계정은 활용사례 등록 후 신청으로 늘릴 수 있다. (출처 13)
- 신청 절차(일반): 공공데이터포털 회원가입 → 해당 API 페이지에서 활용신청 → 자동승인 후 마이페이지에서 인증키 확인. 세부 화면은 확인 필요.
- 제공 항목: 초단기실황조회, 초단기예보조회, 단기예보조회, 예보버전조회. 요청 인자는 base_date, base_time, nx, ny, pageNo, numOfRows(필수), dataType(선택, 기본 XML). JSON은 dataType=JSON으로 받는다. (출처 11)
- 기본 numOfRows가 작으면 응답이 잘린다는 실측 기록이 있다. 단기예보는 응답이 수백 건이다. (출처 14)
- 오류: 잘못된 nx, ny는 resultCode "10"으로 온다는 기록이 있다. (출처 14)
- 이용 제한: 공공데이터 약관 제14조 5항에 따라 시스템 지장이 있으면 이용을 제한할 수 있다. (출처 13)

### 3.3 기상청 API허브 (직접 제공)

- `apihub.kma.go.kr`에서 같은 계열 API를 직접 제공한다. (출처 15)
- 공공데이터포털 15139470 페이지 기준 이용허락범위는 "제한 없음"이고 출처표시 제1유형이다. 트래픽은 "기관 정책에 따라 다를 수 있다"고만 적혀 있다. (출처 12)
- 운영 전환 시 심의가 필요할 수 있다. 확인 필요.

### 3.4 초단기실황·단기예보 발표 시각 (미확인 부분 많음)

- 초단기실황은 매 정시 base_time으로 발표된다. 실무 정리는 "매시 약 30분 생성, 40분 이후 조회 가능"이다. 블로그 2~3년 전 정리이며 공식 확인 필요. (출처 16)
- 초단기예보는 매시 30분에 발표한다(2021-06-29 이후 6시간 예보). (출처 16)
- 단기예보는 하루 8회(02, 05, 08, 11, 14, 17, 20, 23시), 3시간 간격 발표다. 2021-06-29부터 1시간 간격 항목으로 세분화됐다. (출처 16, 17)

### 3.5 그 밖의 대안

| 대안 | 상업 이용 | 키 | 한도 | 출처 표기 | 판단 |
|---|---|---|---|---|---|
| Visual Crossing 무료 | 무료 플랜도 상업 이용 "Yes" (가격표). 세부 약관은 영업팀 문의 권장 | 있음(계정). 키 없는 API는 IP 기준 공정 사용 | 무료 일 1,000 레코드(24시간 기준). 레코드 계산 방식은 확인 필요 | 무료 플랜에도 "Weather Data Provided by Visual Crossing" 표시 필요(눈에 띄게, 링크 포함) | 키 없이 상업 이용이 명시된 점은 좋다. 출처 표기 의무가 있다. 한국 격자 정확도는 기상청보다 낮을 수 있음(확인 필요) (출처 18, 19) |
| OpenWeatherMap 무료 | 페이지에 명시 없음 | 필요 | 분당 60, 월 100만 건. 일 한도 명시 없음 | 명시 없음, 확인 필요 | 상업 이용 조건 미확인으로 보류 (출처 20) |

Visual Crossing 무료 플랜의 레코드 한도(일 1,000 레코드)는 17곳 × 24시간 = 408건 정도로 맞출 수 있는지 계산 기준을 확인해야 한다(확인 필요).

## 4. 비교표와 권장안

| 항목 | 기상청 단기예보·초단기실황 (공공데이터) | Open-Meteo 무료 | Open-Meteo 유료 | Visual Crossing 무료 |
|---|---|---|---|---|
| 광고 사이트 상업 이용 | 가능(공공누리 1유형) | 불가 | 가능(플랜 구독) | 가능 |
| 출처 표기 | 필요(연도·기관·URL·작성자) | 필요(CC BY 4.0) | 필요 | 필요(문구 고정) |
| 호출 한도 | 개발 10,000건(일 기준 확인 필요), 운영은 신청 | 일 10,000 | 월 100만 건 이상 | 일 1,000 레코드 |
| 한국 격자 정확도 | 기상청 원본 | 모델 기반 | 모델 기반 | 기상 모델 기반 |
| 키 | 필요 | 확인 필요 | 필요 | 필요 |
| 격자 변환 | 필요 | 불필요(위경도) | 불필요 | 불필요 |
| 비용 | 무료 | 무료(비상업) | 유료(금액 확인 필요) | 무료 |

**권장안: 기상청 동네예보(초단기실황 + 단기예보)를 1순위로 쓴다.**

권장 사유:
- 상업 이용이 가능하고 조건이 "출처 표기"뿐이다.
- 한국 격자 기준 실측 값이라 시·도 대표 좌표 방식에 맞다.
- 17곳 × 시간당 1회 호출은 약 408건/일이라 개발 10,000건 안에 들어간다(단, 일 기준 확인 필요).

위험과 대응:
- **한도 초과**: 운영 전환 전에 활용사례를 등록하고 운영계정 트래픽을 신청한다. 캐시를 1시간 이상으로 두면 호출이 줄어든다.
- **약관 변경**: 공공데이터 약관과 공공누리 유형은 제공처가 바꿀 수 있다. 출시 전과 분기마다 확인한다.
- **장애 시 대체**: 기상청 API 실패 시 날씨 조건 없이 기존 추천으로 되돌린다(날씨 반영은 부가 기능으로 본다). 두 번째 공급자는 Visual Crossing 무료를 후보로 두되, 키 발급과 출처 표기 문구를 미리 준비한다.
- **발표 시각 미확인**: 초단기실황 조회 가능 시각이 공식으로 확인되지 않았다. 실패 시 직전 정시 값을 쓰는 방식이 필요할 수 있다(설계 담당 확인).
- **운영 심의**: 15139470 계열을 쓰면 운영 단계에서 심의 승인이 필요할 수 있다. 15084084 계열(자동승인)을 우선 확인한다.

## 5. 날씨 분류 기준을 위한 응답 필드와 시·도 대표 좌표

### 5.1 응답 필드 (기상청 동네예보 항목)

### 5.2 분류 기준 후보 (기획 결정 필요, 근거는 기상청 특보 기준)

| 분류 | 후보 조건 | 근거 |
|---|---|---|
| 눈 | PTY가 2, 3, 7 중 하나 또는 SNO 값 있음 | 항목 정의에서 도출 |
| 비 | PTY가 1, 4, 5, 6 중 하나 | 항목 정의에서 도출 |
| 더움 | 최고기온이 특정 값 이상(예: 30℃ 이상) | 기준값은 기획 결정. 기상청 폭염 특보는 체감온도 33℃ 이상(주의보)·35℃ 이상(경보) 기준이다(출처 21) |
| 추움 | 최저기온이 특정 값 이하(예: 5℃ 이하) | 기준값은 기획 결정. 한파주의보는 아침 최저 −12℃ 이하 2일 이상(출처 22, 2차 자료라 확인 필요) |

폭염 특보 기준은 체감온도로 바뀌어 있다. 앱 기준을 "특보 기준"처럼 쓰면 오해를 부를 수 있으니 문구를 주의해야 한다.

## 6. 날씨별 어울리는 음식 (일반 상식)

비 오는 날에는 파전·김치전 같은 전류와 칼국수, 수제비, 김치찌개, 얼큰한 찌개 같은 따뜻한 국물 요리가 흔히 떠오른다. 눈 오는 날과 추운 날에는 어묵, 붕어빵, 호떡, 군고구마처럼 간식이 먼저 떠오르고, 식사로는 설렁탕, 육개장, 부대찌개, 짬뽕, 삼계탕처럼 뜨끈한 국물 요리가 자주 꼽힌다. 더운 날에는 냉면, 콩국수, 막국수, 열무비빔국수, 오이냉국처럼 차갑거나 가벼운 음식이 떠오르고, 복날에는 오히려 삼계탕처럼 뜨거운 보양식을 먹는 이열치열 풍습도 있다. (출처 24, 25 참고. 일반 상식 수준이며 특정 문장을 옮기지 않았다.)

앱에 쓸 때는 "비 오는 날 전 생각"처럼 가벼운 문구로만 쓰고, 건강이나 효능을 단정하는 문장은 쓰지 않는다.

## 7. 비슷한 서비스 사례와 흔한 기능

확인된 사례 조사는 이번 범위에서 하지 않았다(미확인). 날씨 연동 음식 추천 서비스의 일반적 흔한 기능으로는 "날씨 기반 추천 문구", "날씨가 바뀌면 추천을 다시 보여주기", "날씨 정보 없을 때 기본 추천으로 되돌리기" 정도가 보인다(출처 24의 대략적 설명 기반, 일반 관찰 수준).

## 9. 관련 법규·정책

- **개인정보·위치정보**: 시·도 대표 좌표만 쓰고 사용자 위치를 받지 않으면 개인 위치정보를 다루지 않는다는 방향이다. 위치 권한을 요청하지 않는 기존 방침(`docs/meal-location/plan.md`)과 맞춘다. 위치정보법 해당 여부는 기존 기획과 같이 법률 확인이 필요하다(법률 확인 필요).
- **오락 목적 고지**: 운세·타로 기능과 같은 형식으로 "추천은 참고용이며 오락 목적"이라는 고지를 둘지 기획에서 정한다(`COMPLIANCE.md` 11장 형식 참고). 날씨 정보는 기상청 자료 기준이라는 출처 문구도 필요하다.
- **과장 광고·정확도 표현**: "날씨에 딱 맞는 메뉴", "반드시" 같은 단정 표현은 피한다. 특보 기준을 앱 기준처럼 쓰지 않는다.
- **광고 플랫폼(AdFit)**: 날씨 문구가 광고 클릭을 유도하거나 광고와 섞이면 안 된다. 광고 위치 정책은 `COMPLIANCE.md` 4장과 기존 AdFit 설정을 따른다(확인 필요: 날씨 영역에 광고가 어떻게 붙는지).
- **사행성**: 해당 없음(음식 추천 기능).
- **공공데이터 약관**: 제14조 5항에 따른 이용 제한 가능성이 있다(출처 13).

## 11. 기획자에게 넘길 열린 질문

1. **시·도 수**: 17곳을 유지할지, 2026-07-01 통합 이후 현행(16곳 또는 대구·경북, 대전·충남 확정 여부에 따라 달라짐)을 따를지 정한다.
2. **위치 방식**: 사용자 위치를 쓰지 않고 시·도 선택만 받을지, 아니면 기본값(예: 서울)으로 두고 선택을 생략할지 정한다. 기존 meal-location 방침과 맞춘다.
3. **런타임 키 사용**: `DATA_GO_KR_API_KEY`를 런타임에 쓰는 것을 승인하는가. 승인하면 `README.md` 표와 `COMPLIANCE.md`를 함께 고친다.
4. **더움·추움 기준값**: 기온 기준(예: 더움 30℃ 이상, 추움 5℃ 이하)을 정하고, 최고·최저 중 무엇으로 볼지 정한다.
5. **눈·비 우선순위**: 같은 시간에 비와 눈이 모두 있으면 어느 쪽을 우선할지 정한다.
6. **날씨 없을 때**: 호출 실패나 한도 초과 시 날씨 조건 없이 추천할지, 안내 문구를 띄울지 정한다.
7. **고지 문구**: "기상청 자료 기준", "추천은 참고용·오락 목적" 문구를 넣을지, 법률 확인을 받을지 정한다.
8. **Open-Meteo 유료 여부**: 기상청이 막힐 때 대체로 쓸 유료 플랜 예산이 있는가. 없으면 Visual Crossing 무료를 후보로 둔다.
9. **시·도 좌표 검증**: 위 17곳 좌표를 공신력 있는 자료로 검증할 담당을 정한다(미확인 상태).
10. **운영 트래픽**: 활용사례 등록과 운영계정 신청을 누가 하는가. 개발 한도 10,000건의 일/월 기준을 공공데이터포털 화면에서 확인할 필요가 있다.
11. **광고 배치**: 날씨 영역 주변 광고 배치를 `COMPLIANCE.md` 4장에 맞춰 확인할지 정한다.
