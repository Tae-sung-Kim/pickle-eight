# 손 없는 날 달력 UI/UX 디자인 명세

입력: `docs/no-son-days/plan.md`, `docs/no-son-days/design.md` (D-1=B 새 그룹, D-2=음력 표 공용 이동, D-3=광고 추천안 승인됨)
참고: `docs/conventions/design-system.md`, `docs/conventions/code-style.md` "먼저 재사용할 기존 코드", `src/components/common/title-wrapper.component.tsx`, `src/features/ad/components/adfit-slot.component.tsx`, `src/components/layout/pc-menu.component.tsx`
상태: 초안 (ui-ux-designer 작성, 사용자 승인 대기)

## 디자인 방향

한 줄 요약: 피클 병 속 연구실의 "관찰 일지" 한 페이지. 종이색 달력 위에 손 없는 날만 쪽빛 도장(작은 "손" 표식)이 찍힌다. 차분하고 정보 중심이며, 점술집 분위기는 내지 않는다.

이유:
- 이 기능의 일은 "날짜 하나를 빨리 찾는 것"이다(US-1~3). 장식보다 날짜 가독성이 먼저다.
- 사이트 전체 일관성을 지키기 위해 종이 배경, Pretendard, 기존 반경, 기존 `ContentWrapperComponent`/`TitleWrapperComponent`를 그대로 쓴다.
- 이 기능의 개성은 한 곳에만 둔다. 달력 칸의 도장 표식("손" 표식 + 쪽빛 옅은 면)이다. 나머지(고지, 연도 링크, 규칙 설명)는 조용하게 둔다.
- 면책 고지가 항상 보여야 하므로, 눈에 띄는 색 대신 중립 패널로 두고 글자 크기와 위치로 읽히게 한다.
- 빨강·파랑 요일 색은 쓰지 않는다. 달력의 관례(일요일 빨강, 토요일 파랑)를 따르면 쪽빛 도장과 헷갈리고, 빨강은 "공휴일"로 읽혀 plan이 뺀 공휴일 표시처럼 보인다.

## 색상

새 그룹 라벨 색 1개를 추가한다(D-1=B 승인에 따른 것이며, `design-system.md` 표 변경은 PM 승인 후 반영).

| 용도 | 토큰 | 이유 |
|---|---|---|
| 페이지 배경, 달력 빈칸 | `background` | 종이색. 달력 밖 여백과 같은 면이라 빈칸이 "비어 있다"고 읽힌다 |
| 달력 칸, 상태 카드, 연도 링크 | `card` | 종이보다 한 단계 밝아 칸이 떠 보이지만 그림자 없이 `border`로만 구분 |
| 선·구분 | `border` (칸 사이 1px) | 새 값 없음 |
| 본문, 날짜 숫자, 칸 안 음력 | `foreground` | 옅은 면 위에서도 대비가 높다 |
| 요일 머리글, 보조 설명, 범례, 탭 | `muted-foreground` | `background`·`card` 위에서만 쓴다. 옅은 면(`bg-menu-no-son-days/10`) 위에서는 쓰지 않는다(아래 대비 표) |
| 손 없는 날 칸 면 | `bg-menu-no-son-days/10` | 큰 면적에는 옅게 쓰라는 규칙(`design-system.md` 색 절)을 따른다 |
| 손 없는 날 표식 "손" | 면 `bg-menu-no-son-days`, 글자 `card` | 색이 아닌 글자 표식. 단색 인쇄·색각 이상에서도 구분된다 |
| 오늘 칸 | 안쪽 2px 링 `foreground` | 면 색이 손 없는 날과 겹치지 않도록 모양(링)으로 표시한다 |
| 아이콘, 배지, "다음 손 없는 날" 날짜 강조, 연도 링크 현재 표시 | `menu-no-son-days` | 메뉴 라벨 색의 정해진 쓰임(아이콘, 배지, 강조 요소 한두 개) |
| 이전·다음 달 버튼, 연도 링크, 포커스 링 | `primary` / `ring` | 기본 버튼·링크·포커스 링은 메뉴와 무관하게 `primary` 규칙 |
| 고지 패널 | `card` + `border`, 아이콘만 `menu-no-son-days` | 경고색(`warning`)을 쓰면 "위험"처럼 읽힌다. 안내 톤을 유지한다 |

### 새 토큰 (사용자 승인 필요)

- 이름: `--menu-no-son-days` (`--color-menu-no-son-days` 매핑도 같이 추가). 색 이름 "쪽"(쪽빛 염료, 민속 달력과 어울리는 이름이며 기존 이름 딜·당근·비트·강황·염수·가지처럼 재료 이름 규칙을 따른다)
- 값: `#2e5593`
- 이유: 기존 6색(초록, 주황, 자홍, 황토, 청록, 보라)과 겹치지 않는 푸른 계열이 비어 있다. 색상각은 염수 약 191도, 쪽 약 217도, 가지 약 245도로 이웃과 25도 이상 떨어진다. 빨강·주황은 당근·비트와 가깝고 공휴일을 연상시켜 피했다. 올리브는 강황과 비슷해 피했다.
- `.dark` 값은 넣지 않는다(다크 모드 미사용 규칙).
- `design-system.md` 메뉴 라벨 색 표에 추가할 행: `| 손 없는 날 | menu-no-son-days | #2e5593 | 쪽 |`
- `theme.constant.ts` 값 제안: `SECTION_BADGE_COLOR`는 `bg-menu-no-son-days/10 text-menu-no-son-days border-menu-no-son-days/20`, `BACKGROUND_COLORS`는 `bg-background`, `SECTION_ICON_COLOR`는 `text-menu-no-son-days`, 아이콘은 `CalendarDays`.

### 대비 계산 (WCAG 상대 휘도, 4.5:1 기준)

기준 휘도: `background` #eef0e6 = 0.862, `card` #f7f8f1 = 0.932, `foreground` #1b3328 = 0.028, `muted-foreground` #5a6a5f = 0.133.
쪽 #2e5593 휘도: R 46 -> 0.027, G 85 -> 0.091, B 147 -> 0.292. 0.2126 x 0.027 + 0.7152 x 0.091 + 0.0722 x 0.292 = 0.0918.
10% 옅은 면(`bg-menu-no-son-days/10`)을 `background` 위에 얹은 색은 약 #dbe1de, 휘도 약 0.742.

| 글자 / 배경 | 계산 | 비율 | 판정 |
|---|---|---|---|
| 쪽 글자 / `background` | (0.862+0.05) / (0.0918+0.05) | 6.43:1 | 통과 |
| 쪽 글자 / `card` | 0.982 / 0.1418 | 6.93:1 | 통과 |
| 쪽 글자 / 쪽 10% 면 (배지 글자) | 0.792 / 0.1418 | 5.59:1 | 통과 |
| `card` 글자 / 쪽 면 ("손" 표식) | 0.982 / 0.1418 | 6.93:1 | 통과 |
| `foreground` / 쪽 10% 면 (칸 안 숫자·음력) | 0.792 / 0.0775 | 10.2:1 | 통과 |
| `muted-foreground` / `background` | 0.912 / 0.183 | 4.98:1 | 통과 |
| `muted-foreground` / `card` | 0.982 / 0.183 | 5.37:1 | 통과 |
| `muted-foreground` / 쪽 10% 면 | 0.792 / 0.183 | 4.33:1 | 실패 |

- 마지막 행이 실패이므로 규칙을 정한다. 손 없는 날 칸과 월 목록의 손 없는 날 항목처럼 쪽 10% 면 위의 글자는 모두 `foreground`를 쓴다. `muted-foreground`나 `text-foreground/70` 같은 투명도 글자를 올리지 않는다.
- 비글자 요소(칸 링, 표식 면, 버튼 테두리)는 3:1 이상이면 된다. 쪽 면 / `background`는 6.43:1, `foreground` 링 / `card`는 약 12:1이다.
- 비활성 버튼은 대비 규정 대상이 아니지만 `opacity-40`으로 비활성임을 알아볼 수 있게 한다.

## 타이포그래피

폰트는 Pretendard Variable 하나. 숫자 칸(달력 날짜, 연도 링크)만 `font-mono`(Fira Mono)로 폭을 맞춘다. 이유: 7열 칸에서 숫자 폭이 같아야 줄이 맞고, `design-system.md`가 숫자에 `font-mono`를 허용한다.

| 요소 | 폰트 | 크기 | 줄 간격 |
|---|---|---|---|
| h1 (TitleWrapper 그대로) | Pretendard | 기존 TitleWrapper 값 | 기존 |
| 고지 본문 | Pretendard | `text-sm` (14px), 데스크톱 `text-base` | `leading-6` |
| 상태 카드 소제목 ("오늘", "다음 손 없는 날") | Pretendard `font-semibold` | `text-sm` | `leading-5` |
| 오늘 판정 문장 | Pretendard `font-bold` | `text-lg`, `sm:text-xl` | `leading-snug` |
| 다음 손 없는 날 날짜 | Pretendard `font-extrabold`, `tabular-nums` | `text-2xl`, `sm:text-3xl` | `leading-tight` |
| 다음 손 없는 날 보조(음력, 남은 날수) | Pretendard | `text-sm` | `leading-5` |
| 달력 월 제목 (h2) | Pretendard `font-bold` | `text-lg` | `leading-6` |
| 요일 머리글 | Pretendard `font-medium` | `text-xs` (12px) | `leading-4` |
| 달력 양력 날짜 | `font-mono` `font-semibold` | `text-sm` (14px), `sm:text-base` | `leading-5` |
| 달력 음력 날짜 | Pretendard `tabular-nums` | 11px(`text-[11px]`), 윤달 칸 10px(`text-[10px]`), `sm:text-xs` | `leading-4` |
| "손" 표식 | Pretendard `font-bold` | 10px(`text-[10px]`), `sm:text-[11px]` | `leading-none` |
| 범례, 이 달 목록 요약 | Pretendard | `text-xs`, 요약 `text-sm` | `leading-5` |
| 연도 링크 | `font-mono` | `text-sm` | `leading-5` |
| 연도 화면 월 제목 (h2) | Pretendard `font-bold` | `text-lg` | `leading-6` |
| 월 목록 항목 양력 / 음력 | Pretendard `font-semibold` / Pretendard | `text-sm` / `text-xs` | `leading-5` / `leading-4` |
| 규칙 설명 h2 / h3 | Pretendard `font-bold` / `font-semibold` | `text-xl` / `text-base` | `leading-snug` |
| 규칙 설명 본문 | Pretendard | `text-base` (모바일 `text-[15px]`는 쓰지 않는다) | `leading-7` (한글 본문은 줄 간격을 넉넉히) |
| 하단 고지, 출처 | Pretendard | `text-xs`, 데스크톱 `text-sm` | `leading-5` |

- 11px, 10px는 디자인 토큰에 없는 임의 크기다. 이유: 320px에서 칸 폭이 약 40px이라 `text-xs`(12px)면 "윤10.29" 같은 음력 표기가 넘친다. 칸 폭이 넓어지는 `sm`(640px) 이상에서는 `text-xs`로 올린다.
- 본문 한 줄 길이는 `max-w-2xl`(약 40자 안팎, 한글 기준)로 제한한다. 이유: 80자 미만 권장.
- 대문자 라벨, 가운뎃점으로 이은 메타 문자열, 화살표 붙은 링크 문구는 쓰지 않는다.

## 간격·그리드

- 폭: 레이아웃의 `max-w-7xl px-4 sm:px-6 lg:px-8` 안에서 본문은 `mx-auto max-w-5xl`(TitleWrapper와 같은 폭). 규칙 설명만 `max-w-2xl`로 좁힌다.
- 320px 기준 본문 폭은 288px(좌우 16px)다. 7열 달력은 칸 사이 선 1px 6개를 빼고 한 칸 약 40.3px이다.
- 달력은 `gap-px` + 바깥 `bg-border` 방식으로 선을 만든다. 칸 안쪽 좌우 여백은 0에서 2px 이내로 둔다. 이유: 40px 폭에 음력 표기가 들어가야 한다.
- 세로 간격: 섹션 사이 `space-y-8`, `lg`에서 `space-y-12`. 카드 안쪽 `p-4`, `sm:p-5`. 달력 머리(월 이동 줄)는 `px-2 py-2`.
- 반경: 상태 카드, 달력 바깥 틀, 고지 패널, 월 목록 카드는 `rounded-panel`(14px). 이전·다음 버튼, 연도 링크는 `rounded-lg`(8px). "손" 표식, 월 목록 항목은 `rounded-md`(6px). 달력 칸은 틀 안에서 각지게 둔다(바깥 틀에 `overflow-hidden`).
- 터치 영역: 이전·다음 버튼 44x44px(`size-11`), 연도 링크 높이 44px(`h-11`). 달력 칸과 월 목록 항목은 누르는 요소가 아니라 크기 제한이 없다.
- 달력 칸 최소 높이: 기본 56px, `sm` 이상 80px. 달력은 항상 6행 높이를 확보한다. 이유: 달에 따라 5행·6행으로 바뀌면 아래 내용이 튀어 달 이동 중 버튼 위치가 바뀐다.

## 화면별 레이아웃

### 허브 (`/no-son-days`)

위에서 아래 순서(DOM 순서와 같다. 읽기 순서와 키보드 순서가 일치해야 한다).

1. (레이아웃) 전역 AdFit 고정 배너 - 기존, 이 기능이 바꾸지 않음
2. breadcrumb: 홈 > 손 없는 날 달력. `text-xs text-muted-foreground`, `PageHeaderComponent`의 breadcrumb과 같은 모양
3. `TitleWrapperComponent`: h1 "손 없는 날 달력", 설명 한 줄(아래 문구)
4. 상단 고지 패널 (항상 보임, 접지 않음, h1 바로 아래)
5. 상태 카드 + 달력 (모바일은 세로, 데스크톱은 2열)
6. 연도별 링크
7. 규칙 설명
8. 광고 1개 (허브 하단, D-3)
9. 하단 고지 + 출처

모바일 (320px 우선) 와이어프레임:

```
 홈 > 손 없는 날 달력
        손 없는 날 달력
   (설명 한 줄, 가운데 정렬)
 ┌ ⓘ 고지 3문장 ───────────────┐
 └─────────────────────────────┘
 ┌ 상태 카드 ──────────────────┐
 │ 오늘                        │
 │ 11월 25일 수요일  음력 10월 16일 │
 │ 오늘은 손 없는 날이 아닙니다  │
 │ ─────────────────────────── │
 │ 다음 손 없는 날              │
 │ 11월 27일 금요일             │
 │ 음력 10월 19일      2일 뒤   │
 └─────────────────────────────┘
 ┌ 달력 ───────────────────────┐
 │ [‹]   2026년 11월      [›]  │
 │ 일  월  화  수  목  금  토   │
 │ ... 6행 ...                 │
 └─────────────────────────────┘
  범례: [손] 손 없는 날  [▢] 오늘 / 작은 숫자는 음력
  11월 손 없는 날 5일: 8일, 17일, 18일, 27일, 28일
 연도별 손 없는 날 (h2)
 [2026][2027][2028][2029]  (4열 x 6행)
 ...
 손 없는 날, 이렇게 계산합니다 (h2) ...
 [광고]
 하단 고지, 출처
```

- 상태 카드는 달력보다 먼저 둔다. 이유: US-1은 "오늘이 맞나"를 달력을 읽기 전에 알아야 한다.
- 상태 카드 안 구분은 가는 선(`border-t`) 하나. 이유: "오늘"과 "다음"은 서로 다른 질문이라 구조로 나눈다. 번호나 장식 라벨은 쓰지 않는다.
- 다음 손 없는 날 날짜(11월 27일 금요일)가 화면에서 가장 큰 글자다. 색은 `foreground`, 앞의 작은 `CalendarDays` 아이콘만 `menu-no-son-days`. 이유: 큰 숫자 + 그라데이션 같은 템플릿식 강조를 피하고, 크기 차이만으로 위계를 만든다.
- 오늘이 손 없는 날이면 "오늘" 영역에 쪽 10% 면과 "손 없는 날" 배지(아이콘 `Check` + 글자)가 붙는다. 아니면 평범한 `card` 면이다.
- 이 카드에 광고를 넣지 않는다(AC-12).

데스크톱 (`lg` 이상, 1024px) 와이어프레임:

```
 홈 > 손 없는 날 달력
              손 없는 날 달력 (가운데)
 ┌ ⓘ 고지 (max-w-5xl 전체 폭) ─────────────────────────┐
 ┌ 상태 카드 (5fr) ───────┐ ┌ 달력 (7fr) ─────────────────┐
 │ 오늘 ...               │ │ [‹]  2026년 11월  [›]       │
 │ ──────                 │ │ 일 월 화 수 목 금 토          │
 │ 다음 손 없는 날         │ │ ... (칸 높이 80px)           │
 │ ...                    │ │ 범례, 이 달 목록 요약         │
 └────────────────────────┘ └──────────────────────────────┘
 연도별 손 없는 날 (8열 x 3행)
 규칙 설명 (max-w-2xl, 왼쪽 정렬)
 [광고]
 하단 고지
```

- 2열: `lg:grid lg:grid-cols-[minmax(0,5fr)_minmax(0,7fr)] lg:gap-8`. 상태 카드는 위쪽에 붙고(`lg:self-start`) 고정(sticky)하지 않는다. 이유: 전역 광고 바가 이미 상단을 고정으로 덮고 있어 sticky가 더 가린다.
- `sm`~`lg` 사이(640~1023px)는 모바일과 같은 1열이고 달력 칸만 높이 80px로 커진다.
- 정렬: 제목·설명은 TitleWrapper 그대로 가운데. 고지, 카드, 달력, 규칙 설명 본문은 왼쪽 정렬. 이유: 가운데 정렬 긴 문장은 읽기 어렵다.

### 연도 화면 (`/no-son-days/[year]`)

순서: breadcrumb(홈 > 손 없는 날 달력 > 2027년), h1 "2027년 손 없는 날", 상단 고지, (모바일만) 월 바로가기, 12개월 목록, 달력, 연도 링크(현재 연도는 표시만), 허브로 가는 링크, 규칙 설명, 하단 고지와 출처. 광고는 전역 배너 1개뿐이고 이 화면에서 더 넣지 않는다(D-3).

```
 홈 > 손 없는 날 달력 > 2027년
        2027년 손 없는 날
 ┌ ⓘ 고지 ─┐
 [1월][2월][3월][4월][5월][6월]   (모바일만, 6열 x 2행)
 [7월]...
 ┌ 1월 ─────────── 손 없는 날 6일 ┐
 │ [7일 (목)    ] [8일 (금)    ]   │
 │ [음력 11월 29일] [음력 11월 30일] │
 │ ... 2열 x 3행                    │
 └──────────────────────────────────┘
 ... 12개월 (모바일 1열, md 2열, lg 3열)
 달력 (h2 "달력으로 보기")
 연도별 손 없는 날 링크
 규칙 설명, 하단 고지
```

- 월 목록: `grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4`. 월 카드는 `card` + `border` + `rounded-panel`, 머리줄에 "1월"(h2)과 오른쪽 "손 없는 날 6일"(`text-xs`, `muted-foreground`, 카드 면 위라 통과).
- 항목은 쪽 10% 면 `rounded-md` 작은 블록이고, 윗줄에 "7일 (목)", 아랫줄에 "음력 11월 29일"(윤달은 "음력 윤5월 9일")이 들어간다. 글자는 모두 `foreground`. 이유: 음력을 함께 보여야 하고(AC-3), 2열이면 가장 긴 "음력 윤10월 29일"도 한 줄에 들어간다.
- 월 바로가기는 `lg:hidden`. 모바일에서 목록이 길어(약 2500px) 월 점프가 필요하다. 링크는 `#month-1` 같은 앵커고 새 데이터가 아니다. 각 월 카드는 `scroll-mt-52`(약 208px)를 둔다. 이유: 전역 AdFit 바가 헤더(64px) 아래 고정이라 앵커 이동 시 제목이 가려진다.
- 목록을 달력보다 먼저 둔다. 이유: 이 화면의 핵심 질문은 "2027년 손 없는 날은 언제인가"(US-4, 검색 노출)이고, 달력은 1월 한 달만 보여 주는 보조 도구라서다. 반대 순서는 열린 질문 3번에 올렸다.
- 달력은 허브와 같은 컴포넌트다. 처음 달은 해당 연도 1월이다. 다음 달 버튼은 12월 다음에 다음 해 1월로 넘어가며, 월 제목이 "2028년 1월"로 연도를 보이므로 혼동이 없다.
- 데스크톱 달력은 `max-w-3xl mx-auto`. 목록 3열과 폭이 비슷하게 맞는다.

### 연도 링크 영역 (두 화면 공통)

- h2 "연도별 손 없는 날", 아래에 2026~2049 링크 24개.
- 열 수: 기본 4열(66px 폭, 높이 44px), `sm` 6열, `lg` 8열. 간격 `gap-2`.

## 달력 칸 표현

### 구조

- 마크업은 `table`(caption은 월 제목과 같은 문구, 시각적으로 숨김), 머리글 `th scope="col"` 7개, 6행(마지막 빈 행은 `aria-hidden`). 이유: 스크린 리더가 칸을 요일과 함께 읽는다.
- 시작 요일은 일요일(design.md의 `leadingBlankCount` 기준).
- 앞뒤 빈칸은 내용 없는 `td`, 면은 `background`. 날이 있는 칸은 `card`.
- 한 칸의 내용은 가운데 정렬 세로 쌓기 3줄이다. 이유: 40px 폭에서는 가로로 나란히 두면 숫자와 표식이 겹친다.
  1. 양력 날짜 (`font-mono font-semibold`)
  2. 음력 날짜 `월.일` (예: `10.19`), 윤달이면 앞에 "윤" (예: `윤5.9`)
  3. 손 없는 날이면 "손" 표식, 아니면 같은 높이의 빈 줄

### 칸 종류

| 종류 | 모양 | 비색(非色) 단서 |
|---|---|---|
| 평일 | `card` 면, `foreground` 숫자, 음력은 `muted-foreground` | 없음 |
| 손 없는 날 | 쪽 10% 면, 숫자 `font-bold`, 음력은 `foreground`, 3째 줄에 표식 | 표식 글자 "손" (`sm` 이상은 "손 없는 날"), 굵은 숫자 |
| 오늘 | 안쪽 2px `foreground` 링 | 링이라는 모양, 스크린 리더용 "오늘", `aria-current="date"`, 범례의 "오늘" |
| 오늘 + 손 없는 날 | 면과 표식은 손 없는 날과 같고 링이 더해진다 | 위 둘의 합 |
| 빈칸 | `background` 면, 내용 없음 | 없음 |
| 지난 날 | 평일·손 없는 날과 같은 모양 | 따로 흐리게 하지 않는다. 이유: design.md 3.3절이 정적 HTML 기준일 불일치 때문에 정했다 |

- "손" 표식: 기본 폭이 자기 글자 + 좌우 4px의 `rounded-md` 알약, 면 `menu-no-son-days`, 글자 `card`(대비 6.93:1), 크기 10px. `sm` 이상에서는 같은 자리에 "손 없는 날"을 쓴다(두 문자열을 `sm:hidden` / `hidden sm:inline`으로 나눈다).
- 스크린 리더: 칸 안의 보이는 텍스트(숫자, 음력, 표식)는 `aria-hidden`으로 두고, 한 번에 읽히는 문장을 시각적으로 숨긴 텍스트로 넣는다. 예: "11월 17일 화요일, 음력 10월 9일, 손 없는 날". 오늘이면 "오늘, "을 앞에 붙인다. 윤달은 "음력 윤5월 9일". 이유: "10.19" 같은 약식은 소리 내어 읽으면 뜻이 불분명하다.
- 320px 확인 지점(QA용): 윤달 손 없는 날 칸의 음력 `윤10.29`가 칸 폭 약 40px 안에서 줄바꿈 없이 들어가야 한다(`whitespace-nowrap`, 윤달 칸만 10px). 안 들어가면 "윤"을 첫 줄 숫자 오른쪽 위로 올리는 대안을 frontend가 PM에게 올린다.

### 월 제목 줄과 이동

```
 [‹]       2026년 11월       [›]
```

- 가운데 월 제목(h2, `text-lg font-bold`), 양쪽 `Button variant="outline"`에 아이콘 `ChevronLeft`/`ChevronRight`, `size-11`, `rounded-lg`.
- 이전·다음 버튼의 접근 가능한 이름: "이전 달", "다음 달". 월이 바뀌면 월 제목에 `aria-live="polite"`로 새 월을 알린다.
- 범위 끝(2026년 1월 이전, 2049년 12월 이후)에서는 해당 버튼을 비활성으로 표시한다: `opacity-40`, 커서 변화 없음, 눌러도 동작하지 않는다. 구현은 `disabled` 속성 대신 `aria-disabled="true"` + 클릭 무시를 권한다. 이유: 방금 누르던 버튼이 `disabled`로 바뀌면 포커스가 body로 튀어 키보드 사용자가 길을 잃는다. 이 방식으로 포커스가 그대로 남는다.
- 연도 화면의 달력도 같은 줄이다. 연도 이동은 달력 안에서 하지 않고 연도 링크 영역이 맡는다.

### 달력 아래 보조 정보

- 범례(한 줄, 좁으면 두 줄 줄바꿈): "손" 표식 샘플 + "손 없는 날", 링 샘플 + "오늘", 그리고 "작은 숫자는 음력, 윤은 윤달". 이유: 약식 음력 표기를 처음 보는 사람이 읽는 법을 알아야 한다.
- 이 달 요약 한 줄: "11월 손 없는 날 5일: 8일, 17일, 18일, 27일, 28일". 이유: 달력 칸을 하나씩 읽지 않고도 US-2의 답이 나오고, 스크린 리더와 자바스크립트가 꺼진 상태에서도 같은 정보가 남는다. 표시 데이터는 이미 있는 `NoSonMonthType`의 `days`에서 나오므로 새 데이터가 아니다.

## 접근성

- 명도 대비: 위 대비 표 참고. 모든 글자는 4.5:1 이상. 유일한 실패 조합(`muted-foreground` / 쪽 10% 면)은 쓰지 않는 규칙으로 막았다. 투명도로 옅게 만든 글자(`/70` 등)는 쓰지 않는다.
- 색만으로 구분하지 않기: 손 없는 날은 "손" 표식 글자 + 굵은 숫자 + 면, 오늘은 링 + 스크린 리더 문구, 윤달은 "윤" 글자다. 요일 색, 지난 날 흐림, 방위 같은 색 의존 정보가 없다.
- 키보드 이동: 순서는 breadcrumb 링크, (고지는 정지 없음), 이전 달, 다음 달, 연도 링크 24개, (연도 화면은 월 바로가기가 달력 앞), 허브 링크 순. 달력 칸에는 Tab 정지가 없다. 포커스 링은 `primary` 2px 이상(shadcn 기본 `focus-visible`). 범위 끝 버튼은 `aria-disabled`라 포커스를 유지한다.
- 라벨:
  - 달력 `table`에 caption(월 제목과 같음), 월 제목 영역 `aria-live="polite"`
  - 버튼 이름 "이전 달", "다음 달"(아이콘만 있으므로 `aria-label`)
  - 연도 링크 이름은 "2027년 손 없는 날"(`aria-label`), 화면에 보이는 글자는 "2027"
  - 현재 연도 `aria-current="page"`, 오늘 칸 `aria-current="date"`
  - 장식 아이콘은 `aria-hidden`
  - h1 하나, 월/규칙 제목 h2, 규칙 설명 하위는 h3
- 확대: 글자 200% 확대에서 가로 스크롤이 생기지 않도록 상태 카드와 고지는 줄바꿈 허용. 달력은 320px 기준 7열 유지가 필수이므로 칸 글자만 `sm` 이하에서 11px/10px로 고정한다.
- 동작 줄이기: 기본안에 CSS 애니메이션이 없다. 월 전환을 넣는 안을 고르면 위 표의 대체 동작을 적용한다.

## 광고 위치

D-3 승인안(레이아웃 배너를 상단 1개로 셈)을 따른다.

- 허브: 레이아웃 전역 배너(헤더 아래 고정) + 규칙 설명과 하단 고지 사이 1개 = 2개. 달력, 상태 카드, 연도 링크, 고지 패널 사이에는 넣지 않는다. 위아래 간격 `my-10`(40px)을 두어 실수로 누르는 일을 줄인다.
- 연도 화면: 전역 배너만 = 1개.
- 주의 1: 전역 배너는 `fixed`(헤더 64px 아래)라 스크롤해도 화면 위쪽을 계속 차지한다. 이 상태는 기존 동작이고 이 기능이 바꾸지 않는다. 다만 320x568 같은 낮은 화면에서는 헤더와 배너가 합쳐 약 200px을 가려 본문이 보이는 높이가 줄어든다. 앵커 이동 간격(`scroll-mt-52`)도 이 값을 기준으로 잡았다.
- 주의 2: 광고가 하나도 안 나올 때(`ADS_DISABLED`, 설정 없음) 허브 하단에는 빈 영역이 남지 않는다. 컴포넌트가 `null`을 돌려주므로 위아래 간격만 따로 두지 말고 광고 래퍼에 `my-10`을 같이 둔다.

## 면책 고지 위치

- 상단 고지: h1과 설명 바로 아래, 상태 카드와 달력보다 앞. 접지 않고 스크롤 없이 처음 화면에 들어오게 한다(모바일에서 고지 패널은 약 120px). 이유: 날짜 결과를 보기 전에 읽혀야 하고 AC-1이 h1 바로 아래를 요구한다.
- 하단 고지와 출처: 페이지 맨 아래(광고 다음), `text-xs sm:text-sm`, `muted-foreground`(배경 위라 통과), 위쪽에 `border-t`. 규칙 설명 안에 고지를 섞지 않는다.
- 연도 화면도 같은 두 위치에 같은 컴포넌트를 쓴다.
- 광고가 두 고지 사이에 끼는 구조가 아니라 광고는 하단 고지 위에 있다. 이유: 광고가 고지 문구를 덮거나 대신하지 않는다(AC-12).

## 헤더 (PC 메뉴 7개 그룹)

- 항목이 1개인 그룹은 드롭다운 없이 `h-10 px-4` 링크다(`pc-menu.component.tsx`). "손 없는 날"은 아이콘 + 5글자로 약 120px이다.
- 기존 6그룹 폭 약 600px에 120px이 더해지면 `lg`(1024px)에서 로고 영역과 합쳐 여유가 거의 없다. 이 기능에서 헤더 디자인은 바꾸지 않고, QA가 1024px과 1280px에서 줄바꿈·넘침이 없는지 확인한다. 넘치면 PM에게 올린다(헤더 변경은 사이트 전체 영역).
- 그룹 순서는 꿈 해몽 다음, 로또 앞(사용자 승인).
- 모바일 메뉴는 `mobile-menu.component.tsx`가 `MENU_LIST`를 쓰므로 추가 작업은 없다. 확인만 한다.

## 다크 모드

- 지금은 다크 모드를 쓰지 않는다. `dark:` 클래스를 쓰지 않고 토큰(`bg-card`, `text-foreground`, `bg-menu-no-son-days/10` 등)만 쓴다.
- `--menu-no-son-days`에 `.dark` 값은 넣지 않는다.
- 색은 hex를 컴포넌트에 직접 쓰지 않는다. 위 대비 계산의 hex는 문서용이다.

## 열린 질문 / 시안 선택 요청

1. 월 이동 전환 효과를 넣을지(넣는 안 / 빼는 안, 추천: 빼는 안). 인터랙션 절의 표 참고.
2. 새 라벨 색 쪽 `#2e5593` 승인. 마음에 안 들면 대안은 올리브 계열(강황과 비슷해 추천하지 않음)이다.
3. 연도 화면 순서: (가) 목록 -> 달력 (추천) / (나) 달력 -> 목록. (가)는 검색으로 들어온 사람이 연도 전체를 바로 보지만 달력이 아래로 밀린다. (나)는 허브와 같은 화면 감각이지만 첫 화면이 한 달뿐이라 "그해 전체"에 답이 늦다.
4. "이번 달로 돌아가기" 버튼 추가 여부(허브 달력 머리줄 오른쪽, 현재 달이 아닐 때만). 여러 번 이동한 뒤 처음 달로 돌아오기가 쉬워지지만, design.md에 없는 상태 동작(커서 초기화)이 하나 늘어난다. 추가하려면 architect에게 알려야 한다. 이 명세는 버튼 없이 작성했다.
5. 오늘 날짜가 표시 범위 밖일 때 허브 달력의 처음 달: 2026년 1월 이전이면 2026년 1월, 2049년 12월 이후면 2049년 12월로 보이게 하는 것을 추천한다. design.md에는 정의가 없어 architect 확인이 필요하다.
6. 전역 고정 광고 배너가 낮은 화면의 본문을 가린다는 점(광고 위치 절 주의 1)은 기존 동작이다. 이 기능에서는 건드리지 않는다. 바꾸고 싶다면 별도 작업이다.
