- 오락 고지 위치 충돌: ui-ux 본문은 결과 안에 오락 고지 한 줄을 두지만, 확정 답변은 "결과 하단 상자 한 곳에만 둔다"이다. 이 티켓은 확정 답변을 따른다. 하단 상자는 같은 페이지에 있으므로 AC-1의 "한 화면" 조건은 충족한다. QA-03이 같은 페이지에서 확인한다. 이 차이는 PM이 최종 확인한다.
- 78조합 문구 묶음 수: 78개 조합 키마다 문구 묶음 하나가 연결된다. 실제 작성 묶음은 34개다(띠 18, 별자리 16). 같은 조합 24개(띠 12, 별자리 12)만 전용 묶음이다.
- 기존 운세 파일 수정 범위: FE-01(운세 동의 공유 파일 7개, 한 티켓에서만 고친다), FE-08(운세 띠별·별자리 페이지 2개), FE-10(운세·홈 단위 테스트 기대값). 그 밖의 운세 파일은 수정하지 않는다.
- 설계 11장 누락: 운세 띠별·별자리 페이지 2개(FE-08)가 design 11장 충돌 목록에 없다. 이 티켓에서 추가로 관리한다.
- 담당 조정 2건: FE-10은 design 10장에서 QA였으나 frontend로 배정했다. FE-12는 design 10장 FE-8대로 PM이 담당자를 정한다.
- 문구 게이트: CP-1과 CP-2가 승인되기 전에는 화면 파일(FE-05~FE-08, FE-11)에 승인 문구를 연결하지 않는다. 초안 상태에서 상수 파일을 먼저 만들 수는 있다.
- 기존 의존성: M1 연출은 framer-motion을 쓴다. 새 라이브러리를 추가하지 않는다. 기존 의존성에 없다면 FE-04가 PM에게 보고한다.
- 홈 재구성: 현재 develop HEAD가 `5d39752 홈재구성`이다. G-0에서 실제 커밋 상태를 확인한 뒤 FE-09를 시작한다.
