## 디자인 방향

한 줄 요약: "병뚜껑을 돌려 보는 실험 다이얼". 종이색 칸에 먹물색 글자를 쓴 돌림판을 심록(`jar`) 테두리가 두르고, 당근색(`menu-lunch`) 바늘 하나가 가리킨다. 카지노의 금빛·무지개 룰렛이 아니다.

- 이유: 사이트 컨셉(피클 병 속 연구실, 화려한 카지노·점술집 분위기 금지)을 지키면서 "운을 차분하게 관찰한다"는 톤을 돌림판 한 곳에서 보여 준다. 사행성 오해를 줄이는 효과도 있다(번쩍이는 색, 금화, 폭죽이 없다).
- 개성은 **돌림판 비주얼 한 곳**에만 준다: `jar` 테두리, 종이색 두 톤 칸, 먹물 글자, `menu-lunch` 바늘, 가운데 병뚜껑(hub). 나머지(칩, 결과 카드, 고지, FAQ)는 dream·tarot에서 쓴 사이트 공통 어법(테두리 상자, 옅은 메뉴 면, 구분선)을 그대로 쓴다.
- 모션은 돌림판 회전 **하나**다(5장). 결과 카드의 등장 효과, 폭죽, 효과음은 넣지 않는다.

디자인 계획 점검 (기본값으로 흐르던 부분을 바꾼 기록)

| 처음 떠올린 안 | 왜 버렸나 | 바꾼 결정 |
|---|---|---|
| 칸마다 다른 원색(빨강, 노랑, 초록 무지개 돌림판) | 점심 메뉴 돌림판의 기본값이고 사이트 팔레트를 벗어난다. 번쩍이며 도는 색 대비는 깜박임 위험도 있다 | 종이색 두 톤(`card`, `background`)이 번갈아 놓이는 조용한 칸. 색은 바늘과 당첨 칸 하나에만 쓴다 |
| 결과에 폭죽, 반짝이, 효과음 | 사행성 오해를 키우고 design-system이 과하다고 본 "꾸밈만 하는 움직임"이다 | 돌림판이 멈추고 당첨 칸과 병뚜껑에 이름이 나타나는 것이 결과 연출의 전부다 |
| 메뉴 사진·이모지로 칸 장식 | 이번 기능은 사진 없음(plan), 이모지는 기기마다 모양이 다르다 | 글자만 쓴다 |
| 결과 카드를 큰 히어로 숫자·그라디언트로 | 기본값 처리다 | 메뉴 이름이 제목(h2)이고, 점심운은 옅은 세로 선이 붙은 한 줄 메모다 |
| 모든 고지를 한 상자에 합치기 | 상시 고지, 무작위·보상 없음 고지, 외부 링크 안내는 놓이는 자리와 읽히는 때가 다르다 | 자리별로 나눠 둔다(7장). 같은 상자 모양을 써서 "고지 자리"를 알아보게 한다 |

| 주요 버튼("룰렛 돌리기", "다시 뽑기") | `bg-menu-lunch text-primary-foreground`, hover `bg-menu-lunch/90` | 메뉴 색의 "주요 버튼 한두 개" 허용 범위. 종이색 글자 대비 약 5.5:1 |
| 칩·국물 선택의 선택 상태 | `border-menu-lunch bg-menu-lunch/10 text-foreground` + `Check` 아이콘 | 색만이 아니라 체크 아이콘으로도 선택을 알린다. 옅은 면 위 글자는 `foreground`(약 10:1) |
| 칩·국물 선택의 기본 상태 | `border-border bg-card text-foreground` | 안 눌린 칩도 글자가 또렷해야 "누를 수 있는 것"으로 읽힌다 |
| 결과 카드 | `border-border bg-card`, `rounded-panel` | 종이 위에서 한 단계 밝은 면 |
| 결과 카테고리 배지 | `border-menu-lunch/20 bg-menu-lunch/10 text-menu-lunch` | 기존 `SECTION_BADGE_COLOR.lunch`와 같은 값. **결과 카드(`card`) 안에서만 쓴다.** 종이 위에서는 약 4.46:1로 4.5에 못 미치고 카드 위에서는 약 4.8:1이다(계산값) |
| 점심운 메모 | 세로 선 `border-menu-lunch`, 라벨 "오늘의 점심운" `text-menu-lunch`, 문구 `text-foreground` | 메뉴 색의 "제목 장식" 용도. 문구가 메뉴 이름과 다른 층(가벼운 한마디)임을 선 하나로 알린다. 라벨 글자는 카드 위 약 5.5:1 |
| 안내 블록(후보 0개, 카테고리 0개) | `border-menu-lunch/30 bg-menu-lunch/10 text-foreground` | 경고색(`warning`, `destructive`) 없이 옅은 메뉴 면으로 차분히 알린다. dream 완화 블록과 같은 어법 |
| 고지 상자(상시, 무작위·보상 없음) | `border border-border bg-card text-muted-foreground` | dream·tarot 상시 면책과 같은 면 |
| 일반 링크, 포커스 링 | `primary`, `ring-ring` 2px + offset 2px | design-system: 기본 링크·포커스는 메뉴와 무관하게 `primary` |
| 사용 순서 번호 원 | 테두리 `border-menu-lunch`, 숫자 `text-foreground` | 옅은 면 위 메뉴색 글자는 4.5를 못 넘으므로 숫자는 `foreground` |

쓰지 않는 색: `warning`, `destructive`, `info`(글자), `success`, Tailwind 기본 팔레트, hex 값, `ball-*`/`chart-*`. 길흉이나 당첨을 연상시키는 색 구분은 쓰지 않는다.

새 토큰: **없음.**

### 메뉴 라벨 색 통일 (열린 질문 U6)

- 현재: `src/constants/menu.constant.ts` 점심 항목 `colorClass: 'text-orange-600'`. 다른 그룹(타로·운세·꿈)은 모두 `text-menu-<key>`이고, `theme.constant.ts`의 점심 항목(`text-menu-lunch`, `bg-menu-lunch/10 ...`)과 `globals.css`의 `--menu-lunch`(`#a5481f`, 당근)는 이미 토큰이다. 메뉴 항목만 어긋나 있다.
- 제안: `colorClass: 'text-menu-lunch'`. 이 파일은 개발 단계(F-8)에서 고친다.
- 이유 1: `orange-600`(`#ea580c`)은 종이 배경 위 약 3.1:1(계산값)로 글자색 AA 기준 4.5:1에 못 미친다. `menu-lunch`는 약 5.1:1이다. 이유 2: design-system은 Tailwind 기본 팔레트를 컴포넌트에 직접 쓰지 않는다고 정했고, 메뉴 라벨 색은 메뉴마다 하나다. 이유 3: 헤더 메뉴 아이콘 색이 h1·배지·버튼 색과 같아진다.
- `design-system.md` 표는 이미 `menu-lunch`가 `#a5481f`라고 적고 있어 **문서 변경이 필요 없다.** 승인 필요 항목은 이 상수 한 줄뿐이다.
- 아이콘은 지금의 `Utensils`를 그대로 둔다(변경 없음).

## 간격·그리드

- 4px 눈금. 새 간격 토큰 없음. 본문 폭: `mx-auto max-w-4xl px-4 pb-16`(레이아웃 `max-w-7xl` 안에서 좁힌다. 이유: dream 허브와 같은 폭이라 사이트 안에서 본문 폭이 일정하다).
- 섹션 사이 `space-y-10`, 섹션 안 `space-y-4`. 도구 영역(필터, 돌림판+결과)은 `space-y-6`.
- 반경: 칩·국물 선택 `rounded-md`, 버튼·지도 링크·고지 상자 `rounded-lg`, 결과 카드·안내 블록·자리 표시 상자 `rounded-panel`, 돌림판·병뚜껑 `rounded-full`(SVG 원).
- 그림자 없음. 면 구분은 `card`와 종이의 밝기 차이와 테두리로만 한다.
- 터치 영역: 칩, 국물 선택, 버튼, 지도 링크 모두 높이 44px 이상. 칩 사이 `gap-2`(8px).
- 데스크톱 2열: `md:grid md:grid-cols-[minmax(0,5fr)_minmax(0,6fr)] md:gap-8 md:items-start`. 돌림판 열(왼쪽)과 결과 열(오른쪽). 이유: 돌림판이 같은 자리에 있고 바뀌는 것은 오른쪽 결과뿐이라 무엇이 바뀌었는지 한눈에 보인다(tarot 카드 무대와 같은 구조).

## 화면별 레이아웃

### 공통 머리 영역

순서는 design.md 8.2 트리 그대로이며 모두 서버 HTML이다.

1. `ContentWrapperComponent type="lunch"` > `TitleWrapperComponent`: h1 "오늘 뭐 먹지", description "돌림판을 돌려 오늘의 점심 메뉴를 뽑아 봅니다."
2. `LunchTodayDisclaimerNoticeComponent`(상시 오락 고지, h1 바로 아래): `mx-auto max-w-2xl rounded-lg border border-border bg-card px-4 py-3 text-left text-sm leading-6 text-muted-foreground`. 아이콘 없음. 접기·툴팁 없음. 문구는 7장 표.
3. `LunchTodayIntroComponent`(서버): 소개 문단 + 사용 순서(아래).
4. `LunchTodayNoscriptNoticeComponent`(서버, `<noscript>`).

#### 소개와 사용 순서

- 소개 문단 하나(두세 줄). 아래에 h2 "이렇게 이용합니다"와 `ol` 세 항목. 사용 순서는 **실제 순서**라서 번호를 쓴다.
- 모바일: 세로 `space-y-3`, 항목은 [번호 원 24px] + 글. 데스크톱(md 이상): `grid grid-cols-3 gap-6`, 항목마다 번호 원이 글 위가 아니라 왼쪽.
- 번호 원: `size-6 rounded-full border border-menu-lunch text-sm font-semibold text-foreground`, 글은 `aria-hidden`이 아니라 `ol`의 자연 번호를 쓰고 원은 `aria-hidden`(스크린리더가 "1" 두 번 읽지 않게).
- 이유: 도구가 첫 화면에 최대한 가깝게 오도록 소개를 압축한다. 소개를 도구 아래로 옮기는 안은 열린 질문 U4.

- 무작위·보상 없음 고지(`LunchTodayRandomNoticeComponent`)는 root 바로 아래라서 **결과가 없을 때는 돌리기 버튼 바로 아래**, 결과가 나오면 결과 카드 아래로 내려간다. 데스크톱에서는 두 열 아래 전체 폭이라 결과 유무와 상관없이 돌림판 바로 아래에 있다. 이유: 결과를 보기 전에 "보상이 없는 오락"임을 읽을 수 있어야 한다(Q6).

#### 필터 패널 (`LunchTodayFilterPanelComponent`)

- 카테고리 그룹: `role="group" aria-label="카테고리"`, 보이는 제목 `p`("카테고리"). 칩은 `flex flex-wrap gap-2`. 칩 6개(한식, 중식, 일식, 양식, 분식, 세계·기타)는 `LUNCH_CATEGORIES` 순서.
  - 칩 모양: `inline-flex h-11 items-center gap-1.5 rounded-md border px-3 text-base font-medium`. 앞에 `Check` 16px 자리를 **항상 확보**하고(선택 안 됐을 땐 `invisible`) 선택될 때 나타나게 해 칩 폭이 눌러도 변하지 않게 한다. 이유: 폭이 변하면 줄바꿈이 흔들려 칩이 눈앞에서 움직인다.
  - 선택: `aria-pressed="true"`, 선택 색 위 표. 기본 상태는 모든 칩 선택(AC-3).
- 국물 그룹: `<fieldset>` + `<legend>`("국물", 보이는 제목). 세 선택지 "상관없음", "국물 있음", "국물 없음". 기본 "상관없음".
  - 마크업: 기본 `<input type="radio" class="peer sr-only">` + `<label>`. label 모양은 칩과 같고 `peer-checked:border-menu-lunch peer-checked:bg-menu-lunch/10`, 체크 자리 `peer-checked:visible`, 포커스는 `peer-focus-visible:ring-2 ring-ring ring-offset-2`. 이유: 새 라이브러리(RadioGroup, ToggleGroup)를 추가하지 않는다(design.md 8.4). 라디오는 방향키로 옮기고 탭 정지점이 하나다.
  - 세 선택지는 `flex flex-wrap gap-2`. 모바일 한 줄에 못 들어가면 줄바꿈.
- 카테고리와 국물 그룹 사이 `space-y-4`. 두 그룹을 한 상자로 감싸지 않는다(상자는 고지에만). 이유: 칩 자체가 이미 테두리를 가졌고 상자가 겹치면 테두리가 줄줄이 늘어선다.
- 후보 수: 필터 맨 아래(모바일) / 국물 그룹 오른쪽 끝(데스크톱 `md:justify-between`)에 "후보 메뉴 {n}개". n은 `candidates.length`다. `aria-live` 없음(design.md 4.2). 후보 0개일 때는 숫자 문장 대신 안내 블록이 대신한다.

##### 빈 상태 안내 (필터 패널 안, 항상 마운트된 `div role="status"` 안에서 내용만 조건부)

| 상태 | 문구 초안 | 보조 동작 |
|---|---|---|
| 카테고리 0개 | "카테고리를 하나 이상 고르세요." | 없음. 칩을 누르면 사라진다 |
| 카테고리 1개 이상, 후보 0개(예: 양식만 + 국물 있음) | "조건에 맞는 메뉴가 없습니다. 국물 조건을 바꾸거나 카테고리를 더 고르세요." | 안내 아래 버튼 "국물 조건 없애기"(`variant="outline"`, `h-11`). 누르면 기존 `SET_BROTH('all')`을 보낸다(새 상태 동작 없음) |

- 모양: `rounded-panel border border-menu-lunch/30 bg-menu-lunch/10 px-4 py-3 text-sm leading-7 text-foreground sm:text-base`. 위치는 후보 수 줄이 있던 자리(숫자 문장은 이때 그리지 않는다).
- 룰렛 버튼은 두 경우 모두 `disabled`이고 `aria-describedby`로 이 안내를 가리킨다. 돌림판은 빈 접시 상태(5장)로 바뀐다.
- 이유: 막다른 길을 두지 않고 원인(조건)과 다음 행동(조건 바꾸기)을 한곳에서 알린다. 국물 때문에 비는 경우에만 한 번에 해결하는 버튼을 준다.

#### 돌림판 패널 (`LunchTodaySpinPanelComponent`)

- 컨테이너: `mx-auto w-full max-w-80 md:max-w-sm space-y-4`(모바일 320px, 데스크톱 384px). 돌림판은 `aspect-square w-full`, 바깥 요소 `aria-hidden="true"`. 회전 중 컨테이너에 `aria-busy="true"`.
- 버튼: 돌림판과 같은 폭(`w-full`), `h-12 rounded-lg bg-menu-lunch text-base font-semibold text-primary-foreground`.
  - 라벨: 결과가 없을 때 "룰렛 돌리기". 결과가 있을 때(`done`) "다시 뽑기". 조건을 바꿔 결과가 지워지면 다시 "룰렛 돌리기". (열린 질문 U3 참고. 이유: 누른 버튼이 사라지지 않아 포커스가 유지된다.)
- 아이콘 없음. 이유: 글자 이름이 있으니 충분하고, 룰렛 모양 아이콘은 같은 화면 돌림판과 겹친다.

##### 돌림판 비주얼 (`RouletteComponent`, 공용)

SVG 하나, viewBox `0 0 400 400`, 중심 (200,200). 아래 숫자는 이 viewBox 단위다. 렌더 크기는 모바일 320px(배율 0.8), 데스크톱 384px(배율 0.96).

| 층 | 모양 | 토큰 | 회전 |
|---|---|---|---|
| 테두리 | 바깥 반지름 176, 안쪽 164의 고리 | `fill-jar` | 고정 |
| 칸 | 안쪽 반지름 164까지 부채꼴 `n`개, 칸 사이 선 1 | 짝수 `fill-card`, 홀수 `fill-background`, 선 `stroke-border`. `n`이 홀수면 마지막 칸은 `fill-muted`(첫 칸과 같은 톤이 이웃하지 않게) | **회전** |
| 칸 글자 | 반지름 방향, 테두리 쪽 정렬(끝 위치 반지름 150) | `fill-foreground` | **회전**(칸과 함께) |
| 당첨 칸 | 당첨 부채꼴 덧그림 | `fill-menu-lunch/20`, `stroke-menu-lunch` 3 | 칸과 함께. 멈춘 뒤에만 보임 |
| 바늘 | 오른쪽(3시 방향) 가장자리, 밑변 x=400(높이 32), 끝이 x=348에서 왼쪽을 가리키는 삼각 핀 | `fill-menu-lunch`, `stroke-background` 2 | 고정 |

- **바늘을 3시 방향에 둔다.** 이유: 멈췄을 때 당첨 칸이 수평이 되어 글자가 바르게 읽힌다(위쪽 바늘이면 당첨 칸 글자가 세로로 누워 읽기 어렵다). 칸 글자는 중심에서 테두리 쪽으로 읽는 방향이라 오른쪽 칸은 가로 정방향이다.
- 병뚜껑은 회전하지 않는 층이라 글자가 항상 바로 서 있다. 이름이 길면(5글자 초과) 글자 크기를 줄여 한 줄로 맞춘다(최소 렌더 12px 환산). 이유: 칸 글자가 작거나 없는 많은 칸 상태에서도 결과가 돌림판 위에서 읽혀야 한다.
- 칸은 후보 전체를 그린다(design.md 4.3). 직전 메뉴 칸도 똑같이 그린다. 이유: 숨기거나 흐리게 하면 칸 배치가 바뀌고 "직전 메뉴 제외"가 눈에 띄어 확률 오해를 부른다.
- 칸 순서는 `LUNCH_MENUS` 순서 그대로라서 같은 카테고리가 이어서 놓인다. 두 톤 번갈아 규칙이라 카테고리 경계는 보이지 않는다(칸 모양은 카테고리를 모른다. 공용 컴포넌트).

**후보가 많을 때: 칸 수에 따른 글자 3단계 (열린 질문 U2, 권장안)**

48칸 전체에 글자를 넣으면 읽을 수 없다. 칸 수를 줄이는 대신(후보가 줄어든다는 오해, design.md와 충돌) **칸은 후보 전체를 그리되 글자는 칸 수에 따라 단계적으로 줄이고 없앤다.**

| 칸 수 `n` | 칸 글자 | 크기 (viewBox 단위 → 모바일 렌더) | 이유 |
|---|---|---|---|
| 1~12 | 이름 전체 | 20 → 약 16px | 칸 하나의 폭이 55 단위(반지름 105 기준) 이상이라 여유 있다 |
| 13~28 | 이름 전체 | 15 → 약 12px | 안쪽 끝 폭이 15.7 단위 이상(반지름 70 기준)이라 이웃 글자와 겹치지 않는 한계 |
| 29~48 | **글자 없음**(칸 경계선만) | - | 29칸 이상은 칸 폭이 글자보다 좁아 읽을 수 없고, 억지로 넣으면 장식이 된다. 이름은 멈춘 뒤 병뚜껑과 결과 카드가 전한다 |

- 5글자 이상 이름은 글자 영역(반지름 70~150)에 맞춰 폭만 줄인다.
- 현재 데이터에서 칸 수의 범위(참고): 전체 선택 48, 국물 있음 15, 국물 없음 33, 카테고리 하나 6~10, 둘 14~18. 따라서 기본 상태(48)는 글자 없는 돌림판으로 시작한다. 카테고리를 좁히면 이름이 나타난다.
- 글자가 없는 상태가 허전하지 않도록 칸 경계선과 두 톤 칸, 테두리를 정돈해 "시계 문자판" 같은 모양으로 보이게 한다.
- 320px 폭 기기에서는 렌더 배율이 0.72라 13~28칸 글자가 약 10.8px로 줄어든다. 칸 글자는 장식(`aria-hidden`)이고 이름을 병뚜껑·결과 카드가 전하므로 그대로 둔다.

**칸 수 예외**

- `n = 0`: 칸 없이 점선 원(`stroke-border`, 선 2, 점선, `fill-muted/40`)과 흐린(`opacity-60`) 병뚜껑만 그린다. 바늘은 그리지 않는다. 회전하지 않는다.
- `n = 1`: 부채꼴이 아니라 전체 원 하나. 이름은 오른쪽 칸 자리에 그린다. 룰렛은 평소처럼 돌고 같은 칸에 멈춘다.
- `n = 2`: 반원 둘. 규칙은 같다.
- 조건이 바뀌어 `items`가 바뀌면 회전 각도를 0으로 되돌리고 당첨 칸·병뚜껑 이름을 지운 채로 즉시 새로 그린다(전환 효과 없음). 이유: 칸 구성이 바뀌는 것은 사용자가 방금 누른 결과이고 이전 각도는 새 칸에서 의미가 없다.

#### 결과 카드 (`LunchTodayResultComponent`, `done`일 때만)

- 바깥: `<section aria-labelledby={메뉴 이름 h2 id}>`, `rounded-panel border border-border bg-card p-5 space-y-5 sm:p-6`.
- 내용 순서(DOM 순서 = 화면 순서)
  1. 메뉴 이름 h2 + 카테고리 배지 한 줄(`flex flex-wrap items-center gap-3`). 이름 `text-3xl sm:text-4xl font-bold`. 배지 모양 `rounded-md border px-2 py-0.5 text-sm font-medium`, 색 위 표. 이유: 이름이 이 구역의 제목이라 위에 "오늘의 메뉴" 같은 머리 라벨을 따로 두지 않는다.
  2. 점심운 메모: `border-l-4 border-menu-lunch pl-4 space-y-1`. 라벨 `p` "오늘의 점심운"(`text-sm font-semibold text-menu-lunch`), 문구 `p`(`text-base sm:text-lg leading-8`). 문구는 한 문장, 가운데 정렬하지 않는다.
  3. 지도 링크 묶음(`LunchTodayMapLinksComponent`): 아래.
  4. 구분선 `border-t border-border pt-4` 아래 결과 하단 고지(`p`, `text-sm leading-6 text-muted-foreground`).
- 결과에 가격, 별점, 칼로리, 사진, 설명을 넣지 않는다(AC-12). 국물 여부 표시도 넣지 않는다(결과 정보가 아니라 필터 정보다).
- 등장: **효과 없이 바로 나타난다**(fade-up 없음). 돌림판이 멈추는 순간 병뚜껑 이름, 당첨 칸, 결과 카드가 한꺼번에 바뀐다. 이유: 움직임이 아니라 "한꺼번에 바뀜"이 결과 공개를 알린다.
- 결과 카드 자리 표시(데스크톱만, 결과 열이 비었을 때): `hidden md:flex min-h-40 items-center justify-center rounded-panel border border-dashed border-border px-6 text-center text-sm text-muted-foreground`, `aria-hidden="true"`. 문구는 결과가 없을 때 "룰렛을 돌리면 오늘의 메뉴가 이곳에 나옵니다.", 돌리는 중 "룰렛이 도는 중입니다." 모바일에서는 그리지 않는다. 이유: 데스크톱에서 오른쪽 열이 텅 비어 균형이 깨지고 결과가 갑자기 나타나 레이아웃이 튀는 것을 막는다. 모바일은 돌림판 아래에서 결과가 바로 이어지므로 자리 표시가 필요 없다.

#### 지도 링크 (`LunchTodayMapLinksComponent`, 결과 카드 안)

- 제목 h3 "지도에서 찾아보기". 아래 링크 둘: `flex flex-col gap-2 sm:flex-row`, 각 링크는 shadcn `Button asChild variant="outline"` 모양의 `<a>`(`h-11 w-full sm:flex-1`). 글자 "카카오맵에서 찾아보기", "네이버지도에서 찾아보기" + 뒤에 `ExternalLink` 16px(`aria-hidden`, `text-muted-foreground`). 접근성 이름 뒤에 sr-only "(새 탭에서 외부 사이트 열림)"(design.md 6.2).
- 링크 둘의 위계는 같다(어느 쪽도 주요 버튼이 아니다). 주요 버튼은 돌림판 버튼 하나다. 이유: 두 지도 서비스를 공평하게 보여 주고, 화면의 주된 행동(다시 뽑기)을 지도 링크가 가리지 않게 한다.
- 로고, 브랜드 색, 브랜드 아이콘을 쓰지 않는다(plan: 상표는 글자로만). 두 버튼에 같은 모양과 색을 쓴다.
- 링크 아래 외부 링크 안내(`p`, `text-sm leading-6 text-muted-foreground`). 문구는 7장 표.
- "새 탭" 표시는 아이콘 + 아래 안내 글 + 스크린리더 글자 세 곳에서 알린다(색에만 의존하지 않음).

### 자주 묻는 질문 (서버, `LunchTodayFaqComponent`)

dream의 FAQ와 같은 모양: h2 "자주 묻는 질문", 펼친 목록(아코디언 아님), 질문 h3, 답 `p`. 상자 없는 글. 이유: 답이 모두 서버 HTML과 화면에 보여야 하고 항목이 4~5개라 접을 이유가 없다. 질문·답 문구는 개발 단계 문구 작성(F-3)에서 `LUNCH_FAQ`로 쓰고 이 문서는 모양만 정한다.

### 점심운 문구의 위치와 톤 (문구 작성은 개발 단계)

- 위치: 결과 카드 안, 메뉴 이름 바로 아래의 한 줄 메모(세로 선 + "오늘의 점심운" 라벨). 지도 링크보다 위에 둬서 "메뉴 → 한마디 → 찾아보기" 순서로 읽힌다.
- 톤: 한 문장, 합니다체, 가벼운 가능성 표현("~일 수 있습니다", "~어떨까요"). 공백 포함 약 20~45자(모바일에서 두 줄 안). 메뉴 이름·국물·맛을 말하지 않는다(design.md 3.4).
- 카테고리별 분위기(문장이 아니라 방향만): 한식은 익숙함·편안함, 중식은 활기·왁자지껄함, 일식은 정돈된 기분, 양식은 여유·기분 전환, 분식은 가볍고 즉흥적인 기분, 세계·기타는 새로운 시도. 맛, 건강, 영양, 효능, 길흉 단정은 쓰지 않는다.

## 인터랙션·애니메이션

넣는 모션: **하나**(돌림판 회전). 회전 길이·감속은 사용자가 고른다(U1). 아래 표는 **A안**(규칙 안) 기준이고, B안으로 바뀌면 길이·회전 수·곡선만 바뀐다.

| 대상 | 이유 | design-system.md "모션" 표의 경우 | 도구 | 트리거 | 길이 | 동작 줄이기일 때 대체 |
|---|---|---|---|---|---|---|
| 돌림판 회전 | 부모가 이미 정한 결과로 멈추는 과정을 보여 주고, 바늘이 어느 칸을 가리키는지(결과 위치)를 알린다 | 기능의 핵심 연출 (타로 카드 뒤집기, 결과 공개와 같은 분류) | `framer-motion` (`animate={{ rotate }}` 누적 각도, `transformOrigin` 중심). CSS 애니메이션 쓰지 않음 | "룰렛 돌리기"/"다시 뽑기" 누름 (`spinId` 변경) | A안: 1.0초, 시계 방향 2바퀴 + 목표 각도, ease `[0.2, 0.7, 0.2, 1]` (tarot 카드 뒤집기와 같은 곡선, 빠르게 시작해 천천히 멈춘다) | 회전 없이 최종 각도로 바로 놓고, 당첨 칸·병뚜껑 이름·결과 카드를 같은 순간에 보인다. 완료 콜백은 다음 틱에서 직접 부른다(design.md 5.3). 결과 알림·결과 카드·지도 링크는 똑같이 나온다 |

공통 동작 규칙(A·B 모두)

- 시작 각도: 직전 각도에서 이어서 같은 방향으로 돈다(뒤로 되감기 없음). 조건 변경으로 칸이 바뀌면 0에서 시작.
- 멈추는 각도: 목표 칸의 **가운데**가 바늘 아래에 오게 한다. 칸 안에서 위치를 흔들지 않는다(design.md 5.2, 테스트가 결정적).
- 결과 표시 시점: 회전이 끝나는 순간(`onSpinEnd`). 회전 중에는 이전 결과가 이미 지워져 있다(`spinning`일 때 결과 카드를 그리지 않음). 병뚜껑 이름과 당첨 칸도 회전이 끝나야 나타난다.
- 도는 동안 버튼·칩·국물 선택은 `aria-disabled`(AC-7). 지도 링크는 이때 존재하지 않는다.
- 회전 중간에 새 `spinId`가 오면(발생하지 않아야 함) 새 목표로 다시 시작하고 이전 `onSpinEnd`는 부르지 않는다(design.md 5.2).

넣지 않는 모션과 이유

- 결과 카드 등장 효과(fade-up 등): 돌림판 멈춤과 경쟁하고 design-system이 과하다고 본 경우다. 결과는 바로 나타난다.
- 당첨 칸 깜박임, 폭죽, 효과음: 사행성 오해를 부르고 깜박임은 접근성 위험이다.
- 칩 선택·해제의 전환, 칸 구성 바뀔 때의 부채꼴 변환: 사용자가 누른 결과가 바로 보이면 충분하다.
- **마지막에 살짝 되돌아오는 안착(스프링 오버슈트): 넣지 않는다(확정 제안).** 이유: 바늘이 이웃 칸을 지나쳤다 돌아오면 "결과가 바뀐 것처럼" 보여 부모가 정한 결과와 연출이 어긋난다는 인상을 준다. 0.2초가 더 들기도 한다.
- 사용자 행동과 무관하게 계속 도는 대기 연출: 넣지 않는다(design-system).

| 장점 | 다시 뽑기를 반복해도 기다림이 짧다. 규칙 안이다. 곡선이 tarot과 같아 사이트 안에서 감속 느낌이 일정하다 | 멈추기 직전 느려지는 구간이 길어 룰렛다운 긴장감이 더 있다 |
| 단점 | 돌림판 특유의 "아슬아슬하게 멈추는" 느낌이 약하다. 결정이 빠르게 끝난다 | "연출 때문에 결과를 보기까지 기다린다"는 design-system의 과함 사례에 가깝다. 반복해서 돌리는 사용(US-4)에서 기다림이 쌓인다. 테스트 대기 시간이 길어진다 |

- 두 안 모두 값 세 개(길이, 회전 수, 곡선)만 다르다. 개발 단계에서 상수 하나로 만들어 바꾸면 되므로, 권장 A안으로 만든 뒤 화면을 보고 B안으로 바꾸는 것도 쉽다. 이 선택은 QA의 결과 대기 시간 기준(design.md 14.2)에도 영향이 있다.

## 접근성

- 명도 대비 (종이 `#eef0e6`, 카드 `#f7f8f1`, `menu-lunch` `#a5481f`. 모두 계산값이므로 구현 전에 한 번 더 재검산한다)
  - `foreground` 종이 위 약 11:1, `muted-foreground` 카드 위 약 5.4:1·종이 위 약 5.0:1(`bg-muted`, `bg-secondary` 위에는 쓰지 않는다).
  - `menu-lunch` 종이 위 약 5.1:1, 카드 위 약 5.5:1. 주요 버튼의 종이색 글자 on `menu-lunch` 약 5.5:1.
  - 옅은 메뉴 면(10%) 위: `foreground` 글자 약 10:1(칩 선택, 안내 블록). `menu-lunch` 글자는 종이 위 옅은 면에서 약 4.46:1로 4.5에 못 미치므로 **카드 위(약 4.8:1)에서만** 쓴다(결과 카테고리 배지). 사용 순서 번호 원의 숫자는 `foreground`.
  - 돌림판: 칸 글자 `foreground` on `card` 약 12:1, on `background` 약 11:1, 당첨 칸(`menu-lunch/20`) 위에서도 약 9:1. 병뚜껑 `jar-foreground` on `jar` 약 10.9:1. 바늘은 `background` 가장자리를 두르고 종이 위 `menu-lunch` 약 5.1:1(그래픽 3:1 이상).
  - 테두리·구분선·세로 선은 구조 표시이고 같은 정보를 글자가 전한다.
  - 선택 상태는 색에만 의존하지 않는다(`Check` 아이콘 + `aria-pressed` + 테두리 두께 색).
- 깜박임 (WCAG 2.3.1): 돌림판 두 톤 칸(`card` `#f7f8f1`, `background` `#eef0e6`)의 상대 휘도 차이는 약 7%로 일반 깜박임 기준인 10% 미만이다. 빠르게 돌 때 칸 경계가 번쩍이지 않고 흐려진다. 당첨 연출에 깜박임이 없다. 개발 중 재검산을 요청한다.
- 키보드 이동 (탭 순서)
  - 카테고리 칩 6개(Tab으로 하나씩, Space/Enter로 선택) → 국물 선택(탭 정지점 하나, 방향키로 이동) → 룰렛 버튼(Enter/Space) → (결과가 있으면) 카카오맵 링크 → 네이버지도 링크(Enter).
  - 후보 0개면 룰렛 버튼은 `disabled`라 건너뛴다. 이때 "국물 조건 없애기" 버튼은 국물 선택 뒤에 있다.
  - 도는 동안 `aria-disabled` 요소는 포커스를 유지하고 누르면 무시한다. 포커스가 사라지지 않는다.
  - 결과가 나와도 포커스를 옮기지 않는다. 결과는 `role="status"`가 읽어 주고, 돌림판 버튼은 같은 자리에 남아 있어(U3) 연속으로 "다시 뽑기"를 누를 수 있다.
  - 시각 순서와 DOM 순서를 같게 둔다. CSS `order`로 바꾸지 않는다(WCAG 2.4.3). 데스크톱 2열도 DOM 순서(필터 → 돌림판 열 → 결과 열)와 일치한다.
  - 모든 상호작용 요소에 포커스 표시가 보인다: `ring-ring` 2px + offset 2px(`ring-offset-background`). 라디오는 `sr-only` input이라 label에 `peer-focus-visible` 링을 준다.
- 라벨·스크린리더
  - h1 하나. h2: "이렇게 이용합니다", 결과 메뉴 이름(결과가 있을 때), "자주 묻는 질문". h3: "지도에서 찾아보기", FAQ 질문.
  - 돌림판 SVG와 병뚜껑 글자는 장식이라 바깥 요소 `aria-hidden="true"`. 칸 이름 48개를 읽지 않는다. 결과 이름은 `role="status"`가 전한다.
  - 결과 알림 `p`는 처음부터 마운트된 `role="status"` + `aria-atomic="true"`, 화면에 보이지 않게(`sr-only`) 둔다. 이유: 같은 이름을 결과 카드(h2)가 이미 보여 주므로 눈에 보이는 문장을 중복하지 않는다. 돌기 시작할 때 "도는 중" 알림은 넣지 않는다(결과 알림 하나만. 이유: A안 기준 1초라 시작 알림이 결과 알림과 겹쳐 읽히고 끊긴다. B안(1.8초)을 고르면 시작 알림을 다시 판단한다). 조건 변경 시 알림을 비운다.
  - 회전 중 컨테이너 `aria-busy="true"`.
  - 칩 그룹 `role="group" aria-label="카테고리"`, 국물은 `fieldset/legend`. 룰렛 버튼은 후보 0개일 때 `aria-describedby`로 안내 블록을 가리킨다.
  - 안내 블록: 항상 있는 `div role="status"` 안에 내용이 조건부로 들어온다(dream 위기 패널과 같은 방식). 후보 수 문장에는 `aria-live`를 두지 않는다(칩을 누를 때마다 읽히면 시끄럽다).
  - 지도 링크 이름: 보이는 글자("카카오맵에서 찾아보기")가 이름 앞부분에 그대로 들어가고 뒤에 "(새 탭에서 외부 사이트 열림)"이 붙는다(WCAG 2.5.3). 아이콘은 `aria-hidden`.
  - 아이콘만 있는 조작 요소가 없다(AC-32).
- 터치·확대: 모든 칩·버튼·링크 높이 44px 이상. 200% 확대에서 칩은 줄바꿈으로 흐르고 돌림판은 폭에 맞춰 줄어든다. 글은 고정 높이를 쓰지 않는다.
- 동작 줄이기: 위 모션 표의 대체 동작(회전 없이 최종 위치). `MotionConfig reducedMotion="user"`가 회전을 끄지만 완료 콜백은 부모가 직접 부른다. 결과 문장과 지도 링크는 똑같이 보인다(AC-6).
- 법적 고지는 접거나 숨기지 않는다. 상시 오락 고지는 h1 바로 아래 서버 HTML(AC-25), 무작위·보상 없음 고지는 결과 전에도 보인다(AC-26, AC-29), 외부 링크 안내는 지도 링크 바로 아래(AC-27), 결과 하단 고지는 결과 카드 맨 아래(AC-28).

## 다크 모드

쓰지 않는다(design-system). `dark:` 클래스를 쓰지 않는다. 돌림판 SVG를 포함한 모든 색이 토큰 클래스(`fill-*`, `stroke-*`, `bg-*`, `text-*`)라서 나중에 다크 모드를 도입하면 `.dark` 값만 정하면 된다. `fill-jar`와 `fill-jar-foreground`는 `.dark`에 이미 값이 있다. `menu-lunch`의 `.dark` 값은 지금 넣지 않는다.

- 승인이 필요한 변경은 코드 상수 한 줄이다: `menu.constant.ts` 점심 항목 `colorClass` `text-orange-600` → `text-menu-lunch`(U6). 문서의 표는 이미 이 값을 적고 있다.

## 열린 질문 / 시안 선택 요청

- **U1 돌림판 회전 길이·감속 (PM이 사용자에게 선택 요청).** A안 1.0초·2바퀴·`[0.2, 0.7, 0.2, 1]`(권장, 규칙 안) / B안 1.8초·4바퀴·`[0.12, 0.6, 0.18, 1]`(규칙 예외 승인 필요). 장단점은 "회전 길이·감속 선택" 표. 오버슈트 안착은 "넣지 않는 안"으로 이미 제안했으니 이의가 있을 때만 알려 주시기 바랍니다.
- **U2 후보가 많을 때 돌림판 표현 (선택 요청).**
  - A안(권장): 후보 전체를 그리고 칸 수에 따라 글자 3단계(1~12칸 큰 글자, 13~28칸 작은 글자, 29칸 이상 글자 없음). 이름은 멈춘 뒤 병뚜껑과 결과 카드가 전한다. 장점: 확률(모든 후보가 칸 하나)이 눈에 그대로 보이고 design.md와 충돌하지 않는다. 단점: 기본 상태(48칸)는 글자 없는 돌림판이라 돌아가는 동안 무엇이 걸리는지 알 수 없다.
  - B안: 항상 글자 없음(칸 수 무관). 장점: 가장 단순하고 화면이 일정하다. 단점: 6칸일 때도 이름이 없어 돌림판의 재미가 줄어든다.
  - C안(반려 제안): 후보 중 12개만 샘플로 그린다. 장점: 항상 글자가 읽힌다. 단점: 돌림판에 없는 메뉴가 뽑힐 수 있어 "후보 전체"(design.md 4.3)와 어긋나고 확률 오해를 부른다. 채택하려면 architect가 설계(`items`가 후보 전체가 아니게 됨)를 바꿔야 한다.
- **U3 돌리기 버튼 하나 vs 둘 (design.md 조정 요청).** design.md 8.2 트리는 "다시 뽑기" 버튼을 결과 카드 안에 둔다. 그런데 결과 카드는 돌리는 동안 그려지지 않으므로(`done`일 때만) 누른 "다시 뽑기" 버튼이 사라져 키보드·스크린리더 사용자의 포커스가 문서 처음으로 떨어진다(AC-31 위험).
  - A안(권장): 버튼은 돌림판 아래에 하나만 두고 라벨이 "룰렛 돌리기" ↔ "다시 뽑기"로 바뀐다. 결과 카드에는 버튼이 없다. 포커스가 유지되고 AC-18("다시 뽑기" 버튼이 보임)도 만족한다. 단점: design.md 트리에서 "다시 뽑기"의 위치가 결과 카드 안에서 돌림판 패널로 옮겨진다(architect 확인 필요. 상태·로직 변경 없음).
  - B안: 버튼 둘(돌림판 아래 "룰렛 돌리기" + 결과 카드 안 "다시 뽑기"), `SPIN_START` 때 포커스를 돌림판 버튼으로 옮긴다. 단점: 같은 동작 버튼이 한 화면에 둘이고 포커스 이동 코드가 필요하다.
- **U4 소개 문단·사용 순서의 위치 (선택 요청).** A안(권장): plan 순서 유지(h1 → 고지 → 소개 → 도구)이되 소개를 두세 줄로 압축한다. 단점: 모바일에서 돌림판이 첫 화면 아래에 놓인다. B안: 소개·사용 순서를 돌림판 아래(FAQ 앞)로 옮긴다. 장점: 모바일에서 도구가 더 빨리 보인다. 단점: plan 화면 순서와 design.md 트리를 바꾸고, 검색 노출용 소개가 도구 뒤에 놓인다(서버 HTML에는 그대로 있다).
- **U5 보상 없음 고지 문구 (선택 요청).** A안(제안): "룰렛 결과는 금전, 상품, 포인트, 경품 등 어떤 보상과도 무관한 오락입니다." B안: "돌림판 결과로 지급되거나 제공되는 보상은 없습니다. 금전, 상품, 포인트, 경품과 무관한 오락 목적의 기능입니다." A안은 한 문장이고 B안은 지급 여부를 직접 말한다. 문구는 법률 판단이 아니며 사행성 규제 해당 여부는 사용자 확인 사항(Q6)이다.
- **U6 메뉴 라벨 색 통일 (승인 요청).** `menu.constant.ts` 점심 항목 `colorClass`를 `text-orange-600` → `text-menu-lunch`로. `design-system.md`는 이미 `menu-lunch`를 정의하고 있어 문서 변경은 없다(이유는 "메뉴 라벨 색 통일" 절).
- **U7 필터 패널 작은 확장 (design.md 조정 요청, 선택).** 후보 0개일 때 안내 블록에 "국물 조건 없애기" 버튼을 둔다(기존 `SET_BROTH('all')` 사용, 새 상태 동작 없음). 이 버튼이 design.md 8.2 트리에 없는 요소라 architect·PM 확인이 필요하다. 한 카테고리만 고르려면 칩 5개를 꺼야 하는 불편은 있지만 전체 선택·해제 버튼은 상태 동작(`TOGGLE_CATEGORY`) 변경이 필요해 이번 명세에는 넣지 않았다. 필요하면 후속으로 올린다.

### 개발 담당 확인 사항 (선택 요청 아님)

- 공용 `roulette.component.tsx`의 `className`/CSS 변수로 색을 바꾸는 경로는 쓰지 않는다. 이 명세의 모든 색이 토큰 클래스라 부모가 색을 넘길 필요가 없다. 후속 "운빨 뽑기 도구"에서 다른 색이 필요해지면 그때 props를 확장한다.
- 칸 글자 단계(1~12 / 13~28 / 29~)와 크기는 공용 컴포넌트가 `items.length`로 정한다. 점심 지식(카테고리, 국물)은 없다.
- 렌더 확인 항목: 320, 360, 390px 폭과 데스크톱 1280px에서 칸 수 6, 12, 15, 28, 33, 48의 글자 겹침·잘림을 스크린샷으로 한 번 본다.
