변경 요약 (2026-11-23 개정)
- 돌림판: "결과 가리기"는 칸 글자와 강조 칸까지 숨긴다. 가리는 동안 바퀴가 비어 보이지 않게 하는 안내와 시각 처리를 정했다(돌림판 절, 문구).
- 제비뽑기: 이름 목록 섞기에서 "카드 한 장 뽑기"로 바꿨다. 뒷면 카드 격자, 카드 열기 모션, 열린 카드 구분, "남은 카드 모두 열기", 접근성을 새로 썼다. 공개 방식 3칸 스위치는 제비뽑기에서 없앴다(제비뽑기 절).
- 문구: 허브 도구 소개와 역할 비교, 제비뽑기 문구 전체, 돌림판의 가리기 문구와 FAQ를 다시 썼다.
- 바뀌지 않은 절: 사다리 타기 전체, 새 토큰 `menu-lucky` 값, 폰트, 고지 문구, 도구 전환 링크.

## 디자인 방향

한 줄 요약: 종이 위에 가지색 잉크 한 줄로 길을 그려 보는 조용한 실험대. 화면은 차분한 연구 노트로 두고, 개성은 "사다리 위에 그려지는 경로선" 한 곳에만 준다.

- 이유: 사이트 컨셉(피클 병 속 연구실)은 화려한 카지노·게임 분위기를 피한다. 이 기능은 사행성 오인을 줄여야 하므로(plan 법적·정책 요구사항) 더욱 반짝임, 확대, 불꽃, 사운드 같은 도박 연상 연출을 쓰지 않는다. 결과는 크고 읽기 쉬운 글자로 조용히 나온다.
- 개성의 한 곳: 사다리의 경로선. 이름을 고르면 `menu-lucky` 색의 굵은 선이 위에서 아래로 0.8초 동안 그려지고 도착 칸이 옅은 면으로 표시된다. 이 선이 이 기능에서 "무엇이 바뀌었는지, 어디를 보라는지" 알려 주는 가장 큰 움직임이다. 돌림판은 공용 컴포넌트의 기존 회전을 그대로 쓰고, 제비뽑기는 누른 카드 한 장이 0.2초 안에 열리는 것 외에는 움직임이 없다.
- 세 도구는 같은 틀을 쓴다: 도구 전환 링크, 입력 영역, (사다리·돌림판) 결과 공개 방식 스위치, 주요 버튼 하나, 결과 영역, 결과 하단 고지. 도구마다 다른 사이트처럼 보이지 않게 하려는 것이다. 제비뽑기만 공개 방식 스위치가 없다. 카드가 닫혀 있는 것 자체가 "가림"이고 카드를 여는 것이 "공개"라서 스위치가 겹치기 때문이다(plan 확인 18번).
- 제비뽑기 카드는 가지색으로 채운 뒷면과 옅은 면에 항목이 적힌 앞면 두 가지뿐이다. 카드 무늬, 별, 그림 같은 장식은 넣지 않는다. 이유: 도박(카드 게임) 연상을 피하고, 번호와 "열기" 글자만으로 "누르는 카드"임을 알 수 있다.

### 새 토큰: `menu-lucky` (S-1 A 확정, 값 제안)

- 이름: `menu-lucky`, 이름(한글) "가지". 가지 절임 색에서 따왔다. 다섯 메뉴 색(딜 녹색, 당근 주황, 비트 자홍, 강황 황토, 염수 청록)과 색상 각이 겹치지 않는 푸른 보라 계열은 비어 있었고, 로또(녹색)·음식(주황)·금전(황토)으로 읽히지 않는다.
- 값 제안: `#4b4690` = `oklch(0.44 0.12 284)`. `globals.css`는 기존 토큰이 모두 hex이므로 hex로 적고, oklch는 색 감각 확인용이다. 위치와 방식은 `--menu-meal` 등과 같다(`--menu-lucky`, `@theme`의 `--color-menu-lucky`). `.dark` 값은 넣지 않는다(design-system 다크 모드 규칙).
- oklch 환산: `#4b4690`을 sRGB → 선형 → OKLab으로 계산해 L 0.438, 채도 C 0.118, 색상 h 283.6도를 얻었다. 소수 둘째 자리로 반올림한 값이 위의 oklch다.
- 대비 계산 근거: WCAG 상대 휘도 `L = 0.2126R + 0.7152G + 0.0722B`(R, G, B는 sRGB를 선형으로 바꾼 값), 대비 = `(밝은 L + 0.05) / (어두운 L + 0.05)`. `#4b4690`의 L = 0.0789. 기존 토큰의 휘도는 `background` 0.862, `card` 0.933, `foreground` 0.0276이다. 같은 방법으로 `menu-meal`의 카드 위 대비를 계산하면 5.5:1로 design-system 문서의 "약 5.5:1"과 일치해 방법이 맞는지 확인했다.

| 글자(또는 선) | 바탕 | 대비 | 기준 |
|---|---|---|---|
| `menu-lucky` 글자 | `background` | 7.1:1 | 4.5:1 이상 통과 |
| `menu-lucky` 글자 | `card` | 7.6:1 | 통과 |
| `menu-lucky` 글자 | `menu-lucky/10` 면(종이 위) | 6.1:1 | 통과 |
| `menu-lucky` 글자 | `menu-lucky/10` 면(카드 위) | 6.5:1 | 통과 |
| `primary-foreground`(`#f7f8f1`) 글자 | `menu-lucky` 면 | 7.6:1 | 통과 |
| `primary-foreground` 글자 | `menu-lucky/90` 면(hover) | 약 6.8:1 | 통과 |
| `foreground` 글자 | `menu-lucky/10` 면 | 10.1:1 | 통과 |
| `foreground` 글자 | `menu-lucky/20` 면(강조 칸, 도착 칸) | 8.6:1 | 통과 |
| `menu-lucky` 선 | `menu-lucky/20` 면 | 5.2:1 | 선·테두리 3:1 이상 통과 |
| `stroke-muted-foreground` 선 | `background` | 5.0:1 | 3:1 이상 통과 |

- 위 수치는 손으로 계산한 값이다. 개발 단계에서 대비 도구로 한 번 더 확인하고 어긋나면 ui-ux-designer에게 알린다.

### 돌림판 칸 글자 대비 (roulette-common AC-9 기록)

칸 글자 `fill-foreground`(`#1b3328`, 휘도 0.0276) 기준. 공용 기본 면과 허용 목록의 모든 면이 4.5:1 이상이다.

| 칸 면 | 대비 | 결과 |
|---|---|---|
| `card` | 12.7:1 | 통과 |
| `background` | 11.8:1 | 통과 |
| `muted` | 10.6:1 | 통과 |
| `menu-lotto/10` | 10.2:1 | 통과 |
| `menu-meal/10` | 10.3:1 | 통과 |
| `menu-tarot/10` | 10.0:1 | 통과 |
| `menu-fortune/10` | 10.4:1 | 통과 |
| `menu-dream/10` | 10.2:1 | 통과 |
| `menu-lucky/10`(허용 목록에 없음, 참고) | 10.1:1 | 통과 |

- `/10` 면은 종이색에 옅은 색을 10% 섞은 값으로 계산했다. 칸 면이 이렇게 옅기 때문에 모든 허용 면의 대비가 10:1 이상이다.
- 결과 가리기 동안에는 칸 글자 자체가 없으므로 이 표의 대비 검사는 "결과 보기" 뒤와 일괄 공개 상태에만 해당한다.
- 개발 단계 전달: 강조색 `fill-menu-lucky/20 stroke-menu-lucky`는 AC-19의 허용 토큰 확인 목록에 추가해야 한다(칸 색 허용 목록 `fill-menu-<key>/10`과는 별개). 칸 색에 `fill-menu-lucky/10`을 쓰려면 roulette-common 허용 목록 갱신이 먼저인데, 이 명세는 칸 색을 쓰지 않으므로(U2 권장안) 필요 없다.
- 칸 패턴이 입력 순서를 드러내는가(plan 확인 21번): 칸 면은 `card`와 `background`가 번갈아 놓이고 홀수일 때만 마지막이 `muted`다. 이 규칙은 칸의 자리 번호에만 따르고 항목 글자나 입력 내용과 무관하다. 그래서 색 패턴이 항목 이름을 드러내지는 않는다. 다만 사용자가 입력 순서를 알고 있으면 바늘이 선 칸을 세어 짐작할 수 있다. 이 짐작은 막지 않는다(확인 21번 권장안). 칸마다 색을 섞는 규칙은 넣지 않는다. 이유: 섞어도 칸 수를 세는 짐작은 막지 못하고, 허용 토큰 밖 색이 필요해진다.

### 아이콘 (design.md 6장의 "ui-ux가 고른다")

기존 의존성 lucide-react(ISC)에서 설치된 패키지에 이름이 있는 것을 확인했다. 새 라이브러리와 이미지는 없다. 이번 개정에서 더한 `EyeOff`는 개발 단계에서 이름이 설치된 패키지에 있는지 한 번 더 확인한다.

| 위치 | 아이콘 | 이유 |
|---|---|---|
| 그룹(`SECTION_ICONS['lucky-draw']`) | `FerrisWheel` | 놀이공원의 관람차. 오락 느낌이고 주사위·동전·티켓처럼 사행·금전을 떠올리지 않는다 |
| 사다리 타기 | `Columns3` | 세로선 셋. 사다리의 세로선과 닮았다. lucide에 사다리 아이콘이 없다 |
| 돌림판 | `LoaderPinwheel` | 칸으로 나뉜 바퀴 모양 |
| 제비뽑기 | `Shuffle` | 섞기. 카드를 섞어 놓는다는 뜻이 그대로 맞는다 |
| 오류·초과 안내 | `CircleAlert` | 오류 문장 앞 |
| 확인함 표시, 열린 카드 | `Check` | 이름 고르기에서 경로를 본 이름, 제비뽑기에서 열린 카드 |
| 돌림판 결과 가림 안내 | `EyeOff` | 칸 글자가 일부러 가려졌다는 뜻. 문장 앞에 놓고 아이콘만으로 전하지 않는다 |

- `menu-icon.constant.ts`의 `MENU_ICONS`에 `Columns3`, `LoaderPinwheel`, `Shuffle`, `FerrisWheel`을 더한다. 문자열 이름은 아이콘 이름과 같게 쓴다. `Check`, `EyeOff`, `CircleAlert`는 화면 안 장식이라 `MENU_ICONS`에 넣지 않고 컴포넌트에서 직접 쓴다.

## 간격·그리드

- 4px 눈금. 페이지 본문 폭 `max-w-4xl`, 섹션 사이 `space-y-10`, 도구 패널 안 `space-y-5`, 입력 두 개 사이 `gap-4`. 모두 메뉴 룰렛 명세와 같다.
- 도구 패널: `rounded-panel border border-border bg-card`, 안쪽 여백 모바일 16px, 640px 이상 24px. 안쪽 입력 상자와 칸은 `rounded-lg`(입력, 버튼)와 `rounded-md`(스위치 칸, 배지 사각형)이다. 이유: 반경은 계층마다 다르게 쓴다.
- 모바일 좌우 여백 16px. 320px 화면에서 본문 폭은 288px이다.
- 터치 영역: 버튼, 스위치 칸, 이름 버튼, 카드는 높이 44px 이상(주요 버튼과 스위치 칸은 48px). 칸 사이 간격 8px 이상.
- 열 규칙
  - 허브 도구 링크: 모바일 1열, 768px 이상 3열.
  - 사다리 입력 두 개: 모바일 세로로 쌓고, 640px 이상 가로 2열.
  - 돌림판: 모바일 1열, 768px 이상 2열(왼쪽 입력과 옵션, 오른쪽 돌림판과 결과).
  - 제비뽑기 카드 격자(최대 30장): 320px를 기준으로 시작한다. 모바일(480px 미만) 3열, 480px 이상 4열, 768px 이상 5열, 1024px 이상 6열. 칸 사이 8px(`gap-2`).
    - 320px에서 카드 한 장은 폭 약 90px((288 − 8 × 2) ÷ 3), 높이 최소 96px다. 30장이면 10줄이고 격자 높이는 약 1,030px(96 × 10 + 8 × 9)다. 위쪽 도구 패널을 지나 아래로 스크롤하는 길이이며 가로 스크롤은 없다.
    - 이유: 2열이면 30장이 15줄(약 1,600px)로 길어져 한눈에 남은 카드를 가늠하기 어렵다. 4열이면 카드 폭이 약 66px라 열린 카드 안 항목 글자(15자까지)가 4줄 이상으로 늘어난다. 3열이 폭과 길이의 균형이다.
    - 카드 높이는 최소 96px이고, 글자가 길어 3줄을 넘으면 같은 줄의 카드가 같이 커진다(격자 기본 동작). 카드를 열 때 그 줄 높이가 바뀔 수 있다. 이유: 이 움직임이 카드 열기 반응과 함께 일어나며 짧다(0.2초 모션과 같은 시점).
- DOM 순서 = 시각 순서 = 탭 순서. CSS `order`로 바꾸지 않는다.
- 광고는 이 페이지 안에서 도구와 결과 영역 근처에 두지 않는다(레이아웃의 기존 고정 슬롯만). 화면 어디에도 새 광고 영역을 만들지 않는다.

위에서 아래 순서는 서버 렌더링이다.

1. h1 (허브 "운빨 뽑기", 도구는 "사다리 타기" / "돌림판" / "제비뽑기") 그리고 헤더 설명 한 줄.

4. 본문(허브는 도구 링크, 도구 페이지는 도구 패널).

6. 자주 묻는 질문(FAQ, 열고 닫는 방식 없이 모두 펼쳐 둔다. 이유: 서버 HTML과 화면 텍스트가 같아야 하고, 접으면 접근성·검색 노출이 약해진다).

이유: 방문자는 이 도구가 무엇인지(h1과 설명), 믿어도 되는지(고지), 바로 쓸 수 있는지(도구)를 이 순서로 확인한다.

- 모바일: 도구 링크 세 줄이 세로로 쌓인다.
- 데스크톱: 도구 링크 세 칸이 한 줄(`md:grid-cols-3`).

- 도구 링크 행: 왼쪽 48px 아이콘 타일(`bg-menu-lucky/10 text-menu-lucky`, `rounded-lg`), 오른쪽에 h3 이름(600, `text-lg`), 설명 한 줄, 예시, 인원 한계(`font-mono` 숫자). 행 전체가 링크이고 이름이 링크의 접근 가능한 이름이다.
- 설명 한 줄이 세 도구의 역할 차이를 먼저 말한다. 사다리는 "이름과 결과를 짝짓는다", 돌림판은 "항목 중 하나를 고른다", 제비뽑기는 "카드를 한 장씩 열어 항목을 뽑는다"(문구 장 참고). 이유: 사다리와 제비뽑기가 비슷해 보인다는 피드백을 해소하려면 허브에서 먼저 역할이 갈려야 한다.
- 도구 역할 비교 한 줄: 링크 행 세 개 아래, 한 줄 안내 위. `text-sm`, `foreground`, 한 문장. 이유: 링크 행 안의 문장은 짧아야 해서 비교 문장을 따로 둔다. 서버 HTML에 있어 검색 노출에도 쓰인다.
- 3열일 때는 아이콘이 위, 글이 아래로 쌓인다. 이유: 한 칸 폭이 약 280px라 가로 배치는 글이 좁아진다.
- 이유: 허브는 도구 세 개의 선택이 전부다. 그림과 장식 없이 설명과 한계 숫자만으로 "내가 찾던 도구인지"를 확인하게 한다. 카드 세 개가 같은 모양이라는 우려가 있지만 이 목록은 같은 위상의 세 선택이라 같은 모양이 맞다.
- 이 링크 외에 로또, 다른 메뉴, 외부 사이트로 가는 링크는 허브에 두지 않는다.

- 데스크톱(768px 이상): 입력 두 개는 640px부터 가로 2열. 사다리는 열 폭 최대 96px, 보드 폭 = 열 수 × 96px와 패널 폭 중 작은 값, 가운데 정렬. 높이 384px. 이름 버튼은 한 줄로 흐르는 칩(`flex-wrap`).
- 도구 패널과 결과 영역은 별도 박스다. 입력이 바뀌면 결과 영역이 사라진다(design.md 3.1). 결과 영역은 "시작" 전에는 DOM에 없고, 아래 결과 하단 고지만 항상 보인다(design.md 3.1).
- 이름 버튼: 앞에 번호 배지(`font-mono`)와 전체 이름. 이름은 줄바꿈된다. 번호는 위 번호 칸과 같은 번호라 버튼과 사다리 열이 짝지어진다. 번호는 입력 순서라 결과 정보가 아니다.
- 사다리 보드 구조(design.md 3.3의 세 층): 위 번호 칸 행(HTML, 장식), SVG, 아래 결과 칸 행(HTML, 장식). design.md 3.3의 "위 이름 칸"을 이 명세에서 "번호 칸"으로 바꾼다. 구조와 격자는 같고 칸 안 글자만 번호다. 이유: 열 폭 28px에서 이름은 읽히지 않고, 번호는 전체 이름을 가진 버튼과 짝이 된다.
- SVG: 세로선 2px, 가로선 2px, 모두 `stroke-muted-foreground`, `vector-effect="non-scaling-stroke"`. 경로선 4px `stroke-menu-lucky`, 끝과 꺾임을 둥글게. 높이는 모바일 288px, 768px 이상 384px. 이유: 세로 12칸 간격이 모바일에서 약 22px, 데스크톱에서 약 30px로 가로선이 서로 구분된다.
- 한 번에 하나의 경로만 그린다. 다른 이름을 고르면 이전 경로선은 지워지고 새 경로가 그려진다. 이유: 10개 경로가 겹치면 선이 읽히지 않는다. 확인한 결과는 아래 칸 표시와 "전체 결과" 목록에 남는다.
- 공개 방식별 모양

| 방식 | 아래 결과 칸 | 이름 고르기 | 전체 결과 목록 |
|---|---|---|---|
| 일괄 공개 | 시작 직후 모든 칸에 글자 | 언제든 가능 | 시작 직후 전부 |
| 결과 가리기 | "결과 보기" 전 모든 칸에 "?" | "결과 보기" 전에는 잠금과 안내 문장. 누르면 열린다 | 보기 전 비어 있고 안내 문장 |
| 한 명씩 열기 | 확인한 이름의 도착 칸만 글자, 나머지 "?" | 언제든 가능, 확인한 이름은 체크 표시 | 확인한 이름만 쌓임, 비었을 때 안내 문장 |

- "?"는 결과 정보가 아닌 자리 표시 글자다. 이유: 칸이 비어 있으면 로딩이나 오류로 오해한다.
- 도착 칸은 경로선이 끝나는 순간 `bg-menu-lucky/20 border-menu-lucky`가 된다. 같은 순간 도착한 결과 글자가 보인다.
- 시작 후 버튼 라벨은 "다시 시작"으로 바뀐다. 누르면 입력은 그대로 두고 새 사다리를 만든다. 이전 경로, 확인 기록, 공개 상태는 지운다(design.md `START`). 이유: 같은 행동이 다른 이름이 되지 않게 "시작"을 그대로 쓰되 두 번째부터는 "다시"를 붙여 새로 만든다는 뜻을 분명히 한다. QA는 "시작"과 "다시 시작"을 정확히 구분해 찾는다(예: 정확 일치).

### 돌림판 (`/lucky-draw/roulette`)

```
 돌림판 / 설명 / 상시 고지 / noscript
 도구 바꾸기: 사다리 타기 | 돌림판 | 제비뽑기
┌ 도구 패널 (모바일 1열, 768px 이상 2열) ─────────────┐
│ 항목                  4 / 28개   │      돌림판 (max-w-sm)  │
│ [ textarea 6줄 ]                │    ┌┄ 점선 고리(가림) ┄┐  │
│ (오류·안내)                      │    ┆   ◢ 바늘          ┆  │
│ 입력 안내                        │    ┆ (칸 면만, 글자 없음)┆  │
│ 결과 공개 방식                   │    └┄┄┄┄┄┄┄┄┄┄┄┄┘  │
│ [■일괄 공개][결과 가리기]        │  [        돌리기        ]│
│ 결과 가리기를 켜면 …(설명 한 줄) │  (잠금·막힘 사유 한 줄)  │
│ 뽑힌 항목 빼기      [스위치]     │  결과 영역 (돌림판 밖)   │
│ 켜면 뽑힌 항목을 빼고 …          │   [눈 가림] 결과가 정해졌어요 …│
└─────────────────────────────────┴──────────────────────────┘
남은 항목 3개                                [처음부터]    <- 빼기를 켰을 때만
[가] [나] [다]
결과 하단 고지
```

- 모바일은 순서대로: 입력, 입력 안내, 공개 방식, 공개 방식 설명, 옵션 스위치, 돌림판, 돌리기 버튼, 결과 영역, 남은 항목, 결과 하단 고지. 데스크톱은 왼쪽(입력, 안내, 공개 방식, 설명, 스위치)과 오른쪽(돌림판, 버튼, 결과 영역)으로 나뉜다. 이유: 오른쪽에 돌림판과 결과가 붙어 있어 돌린 뒤 시선이 한곳에 머문다.
- 돌림판: 폭 100%, 최대 384px, 가운데 정렬. 공용 컴포넌트를 그대로 쓰고(칸 글자 28개 이하만 보임), 아래 값만 넘긴다: 강조색 `fill-menu-lucky/20 stroke-menu-lucky`, 회전 시간 1.0초, 바퀴 2, 가리기일 때 `isResultHidden`. 칸 색은 넘기지 않는다.
- 320px에서 돌림판은 288px 폭이라 칸 글자가 약 11px(큰 글자 12개 이하일 때 14px)로 줄어든다. 공용 컴포넌트의 기존 동작이다. 이유: 칸 글자는 보조 표시이고 항목 전체는 입력란과 "남은 항목"에서 읽는다. 공용 컴포넌트는 이 명세에서 바꾸지 않는다.
- 공개 방식 설명 한 줄: 공개 방식 스위치 바로 아래, `text-sm muted-foreground`. 문구는 "결과 가리기를 켜면 결과 보기를 누를 때까지 칸 글자도 숨겨요."이고 두 칸 중 어느 쪽이 선택돼도 항상 보인다(레이아웃이 움직이지 않는다). 이유: 가리는 범위가 바늘 결과만이 아니라 칸 글자라는 점은 켜기 전에 알려야 한다.

결과 가리기 상태 (사용자 결정: 칸 글자도 숨김, 바늘은 그대로)

바퀴가 비어 보이는 문제를 세 가지로 푼다. 공용 컴포넌트는 바꾸지 않고, 돌림판 페이지 쪽에서만 처리한다.

| 상태 | 바퀴 | 결과 영역 | 이유 |
|---|---|---|---|
| 가리기 켬, 돌리기 전 | 칸 면과 칸 경계선과 바늘은 그대로. 칸 글자 없음, 강조 칸 없음. 바퀴 바깥에 점선 고리 | EyeOff 아이콘과 "결과 가리기를 켰어요. 칸 글자는 결과 보기를 누르면 나와요." | 칸 수와 경계선을 남겨 "돌림판"으로 읽히게 하고, 점선 고리와 안내 문장으로 "일부러 가렸다"를 알린다 |
| 가리기 켬, 돌리는 중 | 같은 모양으로 1.0초 회전. 회전 전체 동작은 공용 컴포넌트 그대로 | "돌리는 중이에요." | 회전은 보여 주고 어디에 섰는지만 가린다는 사용자 결정에 맞춘다 |
| 가리기 켬, 정지 후 결과 보기 전 | 바늘이 멈춘 자리만 보인다. 칸 글자·강조 칸 없음, 점선 고리 유지 | EyeOff 아이콘, "결과가 정해졌어요. 결과 보기를 누르면 칸 글자와 결과가 나와요." + [결과 보기] 보조 버튼. 결과 글자 없음 | 버튼 한 개로 다음 행동이 하나뿐이다. 결과 글자는 DOM에 없다(AC-31a) |
| 결과 보기를 누른 뒤 | 칸 글자와 강조 칸이 한꺼번에 나온다. 점선 고리는 투명 테두리로 돌아가 같은 자리를 유지 | 결과 글자(`text-menu-lucky`, 600)와 작은 라벨 "결과" | 한 번 누르면 칸 글자, 강조 칸, 결과 글자가 같은 순간에 보인다(AC-31) |

- 점선 고리: 바퀴 폭과 같은 크기의 `rounded-full` 박스에 안쪽 여백 8px, 테두리 2px. 가림이 아닐 때도 같은 두께의 투명 테두리라 켜고 끌 때 바퀴가 움직이지 않는다. 고리는 회전하지 않는다(바퀴 바깥 정적인 틀이다).
- 눈 가림 아이콘은 결과 영역 문장 앞에만 둔다. 바퀴 위에 글자나 아이콘을 얹지 않는다. 이유: 얹으면 바늘과 칸 경계가 가려지고 공용 컴포넌트 안으로 개입해야 한다.
- 바퀴가 비어 보이는 문제가 남는 한계: 칸 글자가 없는 바퀴는 처음엔 평범한 원판으로 보일 수 있다. 위 점선 고리, 공개 방식 설명 한 줄, 결과 영역 문장 세 곳이 같은 말을 해 준다.
- 공개 방식을 "결과 가리기"에서 "일괄 공개"로 바꾸면 가려진 칸 글자, 강조 칸, 결과 글자가 곧바로 나온다(이미 나온 결과를 지우지 않는다는 plan 공통 규칙). 그때 결과 알림은 한 번 읽힌다.
- 결과 영역(돌림판 밖): 카드 상자, 가운데 정렬, 최소 높이 96px로 결과가 나와도 위치가 흔들리지 않는다. 가림 상태 문장은 두 줄까지 들어가는 높이다.
  - 돌리기 전(일괄 공개): "돌리기를 누르면 결과가 여기에 나와요." (`muted-foreground`)
  - 돌리기 전(결과 가리기): EyeOff + "결과 가리기를 켰어요. 칸 글자는 결과 보기를 누르면 나와요." (`foreground`)
  - 돌리는 중: 이전 결과를 지우고 "돌리는 중이에요." 로 바꾼다(`muted-foreground`).
  - 결과 공개: 작은 라벨 "결과"(`text-sm muted-foreground`)와 큰 결과 글자(`text-menu-lucky`, 600).
  - 가리기, 정지 후 결과 보기 전: EyeOff + "결과가 정해졌어요. 결과 보기를 누르면 칸 글자와 결과가 나와요."와 [결과 보기] 보조 버튼. 결과 글자 없음.
- 돌리기 버튼 아래 한 줄 막힘 사유(항목이 2개 미만일 때, 가리기에서 결과 보기 전, 남은 항목이 1개 이하일 때). 사유가 없으면 이 줄은 비어 있지 않고 아예 렌더링하지 않아 레이아웃이 움직이지 않도록 최소 높이 24px을 둔다.
- 가리기에서는 결과 보기 전 "돌리기"를 막고(design.md 3.4, plan 확인 22번 권장안으로 확정), 막힘 사유로 "결과 보기를 누르면 다시 돌릴 수 있어요."를 보인다.
- "뽑힌 항목 빼기" 스위치: 기존 shadcn `Switch`, 왼쪽에 보이는 라벨, 아래에 설명 한 줄. 기본 꺼짐. 켜면 아래 "남은 항목" 목록이 생긴다. 이유: 끄면 입력란과 중복이라 목록이 필요 없다.
- "남은 항목": 작은 태그(`rounded-md border bg-card`, 글자 `text-sm`)가 줄바꿈되며 나열. 이 영역에 목록이 아닌 항목 수를 제목으로 둔다. 빠진 항목이 하나라도 있거나 남은 항목이 1개 이하이면 "처음부터" 보조 버튼이 보인다. 가리기 켠 상태에서도 남은 항목은 입력란과 같은 정보이므로 숨기지 않는다(결과 항목 자체는 바뀌지 않았으므로 새 정보가 아니다). 단, 결과 보기 전에는 방금 뽑힌 항목이 목록에서 빠진 것이 결과를 드러내므로, 가리기에서는 "결과 보기"를 누른 뒤에 목록을 갱신한다.

### 제비뽑기 (`/lucky-draw/lots`) (카드 한 장 뽑기, 전면 개정)

역할: 항목을 한 장씩 뽑는 도구다. 사다리는 이름과 결과를 짝짓는 도구이고 입력도 두 목록이라 모양이 다르다. 이름에 결과를 붙이지 않는다.

모바일 (320px 기준, 카드 3열)

```
 제비뽑기 / 설명 / 상시 고지 / noscript
 도구 바꾸기: 사다리 타기 | 돌림판 | 제비뽑기
┌ 도구 패널 ─────────────────────────────┐
│ 항목                      5 / 30개     │
│ [ textarea 8줄 ]                      │
│ (오류·안내) / 입력 안내                │
│ [        섞기        ]  (섞은 뒤 "다시 섞기") │
└────────────────────────────────────────┘
(섞기를 누른 뒤에만 아래가 생긴다)
결과                                        <- h2
열린 카드 0 / 5장          [남은 카드 모두 열기]
┌────┐┌────┐┌────┐
│ 1  ││ 2  ││ 3  │    <- 닫힌 카드: 큰 번호 + "열기", 가지색 면
│열기││열기││열기│
└────┘└────┘└────┘
┌────┐┌────┐
│ 4  ││ 5  │
└────┘└────┘
(카드를 열면)
┌────────┐
│(4)  ✓  │    <- 열린 카드: 옅은 면, 두꺼운 테두리, 번호 배지, 체크, 항목 글자
│ 발표 순서│
└────────┘
결과 하단 고지
```

- 도구 패널: 입력, 오류·안내, 입력 안내, 주요 버튼 하나. 공개 방식 스위치는 없다(plan 확인 18번). 주요 버튼은 "섞기"이고 섞은 뒤에는 "다시 섞기"다.
- 결과 영역은 "섞기" 전에는 DOM에 없다(AC-23). 결과 하단 고지만 항상 보인다. 입력이 바뀌면 카드와 결과 영역이 모두 사라진다(plan 공통 규칙).
- 결과 영역 위쪽 줄(도구 막대): 왼쪽 "열린 카드 {k} / {N}장"(`text-sm`, `font-mono` 숫자), 오른쪽 보조 버튼 "남은 카드 모두 열기"(`border-menu-lucky text-menu-lucky`, 높이 44px). 320px에서는 두 요소가 한 줄에 못 들어가므로 세로로 쌓고 버튼이 폭 전체를 쓴다. 640px 이상 가로 배치. 모두 열렸을 때: 버튼은 `aria-disabled`가 되고 개수 줄 아래에 "모든 카드를 열었어요."가 붙는다.
- 카드 격자: 모바일 3열, 480px 4열, 768px 5열, 1024px 6열(간격·그리드 장). `ol` 안에 `li`가 카드 수만큼 있고, 각 `li` 안에 카드 버튼 하나다.
- 닫힌 카드(뒷면): 높이 최소 96px, `rounded-lg`, `bg-menu-lucky`, 테두리 `border-menu-lucky`, 중앙에 큰 번호(`font-mono`, `text-2xl`), 번호 아래 "열기"(`text-sm`). 번호는 놓인 자리 순서(1~N)이고 항목과 무관하다(plan 확인 20번). 항목 글자는 DOM에 없다.
- 열린 카드(앞면): 같은 크기, `bg-menu-lucky/10`, `border-2 border-menu-lucky`, 왼쪽 위에 번호 배지, 오른쪽 위에 `Check` 아이콘, 아래에 항목 글자(가운데 정렬, `break-words`). 열린 카드는 다시 눌러도 아무 일이 없고 항목도 바뀌지 않는다(`aria-disabled`, 포인터가 기본 모양).
- 닫힌 카드와 열린 카드를 색만으로 구분하지 않는다. 구분 단서가 다섯 가지다: 채운 면 대 옅은 면, 큰 번호와 "열기" 대 항목 글자, 체크 아이콘 유무, 테두리 두께(1px 대 2px), 접근 가능한 이름("n번째 카드 열기" 대 "n번째 카드: 항목"). 이유: 색을 못 보는 사람도 어느 카드가 열렸는지 알아야 한다.
- 모두 열기: "남은 카드 모두 열기"는 열지 않은 카드를 한꺼번에 연다. 이미 열린 카드는 그대로다. 모션 없이 즉시 바뀐다(인터랙션 장 참고). 포커스는 버튼에 남고 버튼은 `aria-disabled`가 된다.
- 다시 섞기: 도구 패널의 주요 버튼 "다시 섞기"를 누르면 입력은 그대로 두고 열린 기록을 모두 지운 뒤 뒷면 카드 N장을 새로 섞어 놓는다. 한 번 연 카드도 모두 닫힌다. 확인 대화상자는 쓰지 않는다. 이유: 입력이 그대로이고 되돌릴 수 있는 일이다(다시 열면 된다). 위치가 격자 위쪽이라 아래까지 내려간 사용자가 올라와야 하는 불편은 U4에서 묻는다.
- 같은 이름이 여러 줄이면 카드 한 장씩 따로 만들어진다. 같은 글자가 두 카드에서 나올 수 있다.
- 오류: 이 브라우저에서 난수를 쓸 수 없으면 "섞기"를 막고 도구 패널 위에 오류 문장을 보인다. 카드 열기는 서버 요청이 없어 오류 상태가 없다.
- 빈 상태: 섞기 전에는 결과 영역 자체가 없다. 입력이 2개 미만이면 "섞기"는 비활성이고 이유 문장이 연결된다.
- 섞는 연출은 넣지 않는다(U1 확정). 섞기를 누르면 닫힌 카드 N장이 즉시 놓인다.

### 도구 전환 링크 (세 도구 페이지 공통)

- 입력 패널 바로 위 한 줄: "사다리 타기", "돌림판", "제비뽑기" 링크 세 개. 현재 도구는 `aria-current="page"`와 아래 줄 2px `menu-lucky`, 글자 600. 나머지는 `muted-foreground` 글자에 hover `foreground`.
- 이유: 도구 간 이동이 잦다. 허브까지 돌아가지 않게 한 줄로 둔다. 공개 방식 3칸 스위치(채운 면)와 모양이 달라 "페이지 이동"과 "선택"이 구분된다.
- 연출 중(경로 그리는 중, 돌림판 회전 중)에는 `aria-disabled="true"`와 `opacity-60`, 클릭 무시, 포커스 유지(design.md 3.1). 제비뽑기의 카드 열기 모션은 0.2초라 잠그지 않는다.

## 인터랙션·애니메이션

원칙: 사용자 행동에 대한 반응으로만 움직이고, 자동으로 움직이는 장식은 없다. 모든 움직임은 1초 이내이고 동작 줄이기를 지킨다. `framer-motion`은 `MotionConfig reducedMotion="user"`로 자동 줄고, 추가로 사다리 경로는 `useReducedMotion`으로 즉시 완성한다(design.md 3.3). 이 화면에서 CSS 애니메이션(`animate-*`)은 쓰지 않는다. 색 전환은 CSS transition이고, `transition-colors duration-150`에 `motion-reduce:transition-none`을 함께 둔다(design-guard 대응).

넣지 않는 것과 이유
- 결과 가리기에서 "결과 보기"를 누를 때의 공개 연출(사다리, 돌림판 칸 글자·강조 칸 포함): 없음(즉시 나타남). 이유: 이미 사용자가 누른 행동이고, 한꺼번에 나오는 글자를 차례로 보이면 결과를 보려고 기다려야 한다(design-system이 과하다고 본 경우).
- "남은 카드 모두 열기"의 연출(카드를 하나씩 차례로 열기, 물결): 없음(한꺼번에 즉시). 이유: 최대 29장이 차례로 열리면 총 길이가 길어지고, 이미 결과를 보겠다고 누른 행동이다. 한 장 열기(0.2초)만 모션이 있는 것과 대비되어 "한 장씩 주목해 열 때만 움직인다"는 규칙이 단순하다.
- 제비뽑기 섞는 연출, 카드 차례 등장(stagger), 카드 뒤집기 3차원 회전, 목록 항목 삭제·추가 효과(돌림판 남은 항목), 페이지·섹션 등장 효과, 카드 hover 확대·그림자: 없음. 이유: 이 화면의 움직임은 "결과 근거를 보여 주는" 경로선과 "누른 카드가 열리는" 변화에 모은다. 3차원 회전은 도박 카드 연상이 강하고 0.2초 안에서 글자가 거울상으로 보일 수 있다.
- 섞는 연출은 U1(빼는 안)로 이미 확정이다. 카드를 새로 섞어 놓는 순간에도 즉시 나타난다.
- 소리, 진동, 반짝임, 꽃가루, 글자 확대: 쓰지 않는다. 이유: 보상·사행 연상을 피한다.

## 접근성

- 명도 대비
  - 모든 글자는 4.5:1 이상. 메뉴 색 글자 7.1~7.6:1, 채운 버튼 글자 7.6:1, 닫힌 카드의 번호와 "열기" 글자 7.6:1, 열린 카드 항목 글자 10.1:1, 오류 글자 5.1~5.5:1, 보조 안내 5.0~5.4:1(수치는 색상 장 표). `muted-foreground`는 `muted` 면 위에 쓰지 않는다(약 4.5:1 미만).
  - 사다리 선(3:1 이상 필요)은 5.0:1, 경로선 약 7.1:1.
  - 색에만 의존하지 않는다: 선택 상태는 면 채움과 굵기와 라디오 상태, 확인한 이름은 체크 아이콘, 오류는 아이콘과 문장, 열린 카드는 글자 유무와 체크 아이콘과 테두리 두께와 접근 가능한 이름으로 알린다. 돌림판 가림은 점선 고리와 눈 가림 아이콘과 문장으로 알린다.
- 키보드 이동 (탭 순서는 DOM 순서와 같다)
  - 사다리: 도구 전환 링크, 참가자 입력, 결과 입력, 공개 방식(라디오는 방향키로 이동), 시작, 결과 보기(가리기일 때), 이름 버튼들(Enter, Space로 선택), 다시 시작.
  - 돌림판: 도구 전환, 항목 입력, 공개 방식, 뽑힌 항목 빼기 스위치(Space), 돌리기, 결과 보기(가리기일 때), 처음부터(보일 때).
  - 제비뽑기: 도구 전환, 항목 입력, 섞기·다시 섞기, 남은 카드 모두 열기, 카드 버튼들(왼쪽 위에서 오른쪽 아래 순서로 탭, Enter와 Space로 열기). 카드는 탭으로 이동하는 버튼이다. 격자 안 방향키 이동은 넣지 않는다. 이유: 30장이 한 번에 탭 순서에 들어가지만 건너뛰는 방법으로 "남은 카드 모두 열기"가 앞에 있어서 충분하고, 방향키 격자 이동은 역할(`grid`)을 새로 약속해야 해 구현이 복잡하다.
  - 카드를 열면 포커스는 그 카드에 남는다(열린 카드도 `aria-disabled` 버튼으로 남는다). 이유: 누르면 사라지는 요소는 키보드 사용자의 포커스를 잃게 한다.
  - "결과 보기"를 누르면 버튼이 사라지므로(사다리, 돌림판), 포커스를 결과 영역(사다리는 h2, 돌림판은 결과 영역, `tabIndex=-1`)으로 옮긴다. 이유: 포커스가 사라지면 키보드 사용자가 문서 맨 위로 되돌아간다.
  - "섞기"를 처음 눌러 카드가 생겨도 포커스는 "섞기" 버튼에 둔다(버튼이 그대로 있다). 알림이 카드가 놓였다고 알린다.
  - 연출 중 잠금 상태의 버튼과 링크는 포커스를 유지한다. 포커스 링은 모든 상호작용 요소에 보이고 `ring`(primary) 2px, 오프셋 2px.
  - 키보드 함정이 없다. Esc가 필요한 오버레이가 없다.
- 스크린리더와 라벨
  - 사다리 SVG와 번호 칸과 결과 칸은 `aria-hidden`. 전체 결과는 "전체 결과" 목록(`dl`, 이름과 결과 쌍)이 전달한다. 가리기와 한 명씩 열기에서는 공개된 쌍만 목록에 있다.
  - 돌림판 래퍼는 공용 컴포넌트에서 `aria-hidden`이다. 결과는 돌림판 밖의 결과 영역과 `role="status"` 알림이 전한다. 결과 가리기 동안 결과 영역의 가림 문장은 화면에서 읽을 수 있는 일반 글자이고, 알림에는 결과 글자가 없다.
  - 제비뽑기 카드:
    - 열기 전: 카드의 접근 가능한 이름은 "n번째 카드 열기"뿐이다. 항목 글자는 DOM, `aria-label`, `data-*`, `title` 어디에도 넣지 않는다(AC-26c). 번호 n은 놓인 자리 순서이고 항목과 무관하다.
    - 열린 뒤: 접근 가능한 이름은 "n번째 카드: 항목 글자"로 바뀌고, 같은 내용이 화면에도 있다(번호 배지는 장식이라 `aria-hidden`, `Check`는 `aria-hidden`). 이유: 스크린리더 사용자가 열린 카드를 다시 읽을 수 있게 한다.
    - 열린 카드는 `aria-disabled="true"`이므로 "사용할 수 없음"으로 읽히는 스크린리더가 있다. 이름에 "열기"가 없어 누를 수 있는 카드와 구분된다.
    - 알림(`role="status"`): 카드 한 장을 열면 "{n}번째 카드: {항목}"이 한 번 읽힌다. 열기 전에는 항목 글자가 알림에 없다(AC-26c). 남은 카드 모두 열기는 "남은 카드를 모두 열었어요. 열린 카드에서 항목을 읽을 수 있어요."만 한 번 읽는다(최대 29개 항목을 알림으로 줄줄이 읽지 않는다).
    - 열린 카드 수("열린 카드 {k} / {N}장")는 알림이 아니고 `aria-live` 없는 일반 글자다. 이유: 카드 열기마다 두 번 읽히지 않게 한다.
  - 알림(`role="status" aria-atomic="true"`, 화면에서 숨김)은 도구마다 하나이고, 결과 알림은 결과가 공개되는 순간 한 번만 바뀐다(AC-44). 보이는 결과 영역은 `aria-live`를 쓰지 않는다. 이유: 같은 글자를 두 번 읽지 않게 한다.
  - 결과가 가려진 동안 알림에 결과 글자를 넣지 않는다(문구 표).
  - 모든 입력에 보이는 라벨이 있다. 개수와 안내 문장은 `aria-describedby`로 연결한다. 사다리에서 입력 안내(미저장 안내)는 참가자와 결과 두 입력에 함께 연결한다.
  - 공개 방식은 `fieldset`과 `legend`("결과 공개 방식", 사다리와 돌림판만). 도구 전환은 `nav`(`aria-label="도구 바꾸기"`). 이름 고르기 묶음은 `role="group"`(`aria-label="이름 고르기"`). 제비뽑기 카드 격자는 `ol`이고 `aria-label`은 "카드 {N}장"으로 둔다(항목 정보 없음).
  - 확인한 이름의 체크 아이콘은 장식이고, 버튼에 숨은 글자 "결과 확인함"을 더한다(결과 글자는 넣지 않는다).
  - h1은 페이지당 하나, 섹션은 h2, 허브 도구 이름은 h3.
  - `data-*`와 `aria-label`에 항목 이름, 항목 id, 결과 인덱스를 넣지 않는다(AC-29, AC-26c). 사다리 이름 버튼의 접근 가능한 이름은 사용자가 입력한 이름(입력값이므로 결과 정보가 아님)이다.
- 터치와 확대: 모든 컨트롤 44px 이상. 글자 200% 확대에서도 가로 스크롤이 없고(AC-46), 칸 글자는 줄바꿈된다. 사다리 보드만 SVG가 폭에 맞춰 줄어든다. 제비뽑기 카드는 글자가 늘면 같은 줄의 카드 높이가 같이 늘어난다(고정 높이가 아니라 최소 높이).
- 동작 줄이기: 경로선, 돌림판 회전, 카드 열기, 색 전환 모두 즉시 바뀐다. 결과는 같은 시점에 나온다.

## 문구 (서비스 노출 문구, 최종 제안)

plan과 design.md에 이미 정한 문구는 그대로이고, 초안만 있던 것과 없던 것을 아래에서 확정 제안한다. 금지어(plan 법적·정책 요구사항)가 없는지 확인했다. "보장", "보상"은 S-4(A)로 확정된 정확한 문장 단위 예외(상시 고지, 결과 하단 고지, 네 페이지 meta description, 약관 10장)에서만 쓴다. 돌림판 페이지에는 "룰렛 돌리기"와 "메뉴"를 쓰지 않는다. 로또 단어와 링크는 없다. "뽑기", "뽑힌", "카드 뽑기"는 금지어가 아니지만 AdFit 심사 확인 대상이다(출시 전 체크).

| 제비뽑기 결과 영역 빈 상태 | 없음. 섞기 전에는 결과 영역 자체를 렌더링하지 않으므로(AC-23) 서버 HTML에는 이 문장이 없고, 도구 패널의 "섞기" 버튼 이유 문장으로만 안내한다 |
| 제비뽑기 카드 격자 aria-label | 카드 {N}장 |
| 제비뽑기 닫힌 카드(화면) | 큰 번호 {n}과 아래 "열기". 접근 가능한 이름 "{n}번째 카드 열기" |
| 제비뽑기 열린 카드(화면) | 번호 배지 {n}, 체크 아이콘, 항목 글자. 접근 가능한 이름 "{n}번째 카드: {항목}" |
| 제비뽑기 열린 카드 수 | 열린 카드 {k} / {N}장 |
| 제비뽑기 모두 열림 | 모든 카드를 열었어요. |
| 허브 한 줄 안내 | 입력한 이름은 서버로 보내거나 저장하지 않아요. |
| 허브 "도구 고르기" 인원 한계 | 사다리 타기 "2~10명", 돌림판 "항목 2~28개", 제비뽑기 "항목 2~30개" |
| noscript | JavaScript를 켜면 이 도구를 쓸 수 있어요. 설명과 자주 묻는 질문은 아래에서 그대로 읽을 수 있어요. |
| 사용 순서 제목 | 이렇게 이용합니다 |

- 결과 영역 빈 상태 문장은 결과 영역이 렌더링되는 도구(사다리 전체 결과, 돌림판)에만 있다. 제비뽑기는 섞기 전에 결과 영역이 DOM에 없어야 하므로(AC-23) 빈 상태 문장 없이 입력 안내와 "섞기" 이유 문장이 안내를 맡는다.
- 사다리는 시작 전 결과 영역이 DOM에 없다(AC-10). 입력 아래 버튼 이유 문장이 안내를 맡는다.

### 입력 오류와 막힘 이유 (버튼 위 또는 입력란 아래, `text-destructive` + `CircleAlert`, 같은 문장이 `aria-describedby`로 버튼과 연결)

| 상황 | 문구 |
|---|---|
| 돌림판·제비뽑기, 항목 1개 이하 | 두 개 이상 입력하세요. |
| 사다리, 참가자 1명 이하 | 참가자를 2명 이상 입력하세요. |
| 사다리, 참가자 11명 이상 | 참가자는 최대 10명까지 입력할 수 있어요. 시작하려면 10명 이하로 줄여 주세요. |
| 사다리, 결과 수가 다름 | 참가자 {a}명, 결과 {b}개예요. 같은 수로 맞춰 주세요. |
| 사다리, 결과가 11개 이상 | 결과는 최대 10개까지 입력할 수 있어요. 시작하려면 참가자 수에 맞춰 줄여 주세요. |
| 돌림판·제비뽑기, 상한 초과(S-3 A) | 최대 {N}개까지 입력할 수 있어요. 앞의 {N}개만 사용해요. |
| 한 줄이 15자 초과 | 한 줄은 15자까지 쓸 수 있어요. 긴 줄 {k}개는 사용하지 않아요. |
| 돌림판, 남은 항목 1개 | 항목이 한 개 남았어요. 처음부터를 눌러 목록을 되돌리세요. |
| 돌림판, 가리기에서 결과 보기 전 | 결과 보기를 누르면 다시 돌릴 수 있어요. |
| 제비뽑기, 남은 카드 0장에서 "남은 카드 모두 열기" | 열 카드가 없어요. 다시 섞기를 누르면 카드를 새로 섞어요. (버튼 이유 문장, 도구 막대의 "모든 카드를 열었어요."와 함께 쓰이지 않고 `aria-describedby`로만 연결) |
| 이 브라우저에서 난수 사용 불가 | 이 브라우저에서는 도구를 쓸 수 없어요. 다른 브라우저로 열어 보세요. |
| 사다리 생성 실패 | 사다리를 만들지 못했어요. 시작을 다시 눌러 주세요. |

- 사다리 입력 오류 우선순위(한 번에 한 문장만 보인다): 참가자 1명 이하, 참가자 11명 이상, 결과 11개 이상, 결과 수가 다름 순서. 이유: 가장 먼저 고칠 것부터 알린다.
- 오류 문장은 사과하지 않고, 무엇이 어긋났는지와 해결 방법을 한 문장으로 쓴다.
- 같은 문장은 입력란에 변경이 생길 때만 바뀐다. 입력 중 타이핑마다 알림(`role="status"`)이 반복해 읽히지 않도록 오류 문장은 `role="status"` 알림에 넣지 않고 `aria-describedby`로만 연결한다.

### 알림 (화면에서 숨김, `role="status"`, 결과 가려진 동안 결과 글자 없음)

| 시점 | 문구 |
|---|---|
| 사다리 시작, 일괄 공개 | 사다리가 만들어졌어요. 이름을 고르면 결과를 따라가 볼 수 있고, 전체 결과는 아래 목록에 있어요. |
| 사다리 시작, 결과 가리기 | 사다리가 만들어졌어요. 결과 보기를 누르면 볼 수 있어요. |
| 사다리 시작, 한 명씩 열기 | 사다리가 만들어졌어요. 이름을 고르면 그 이름의 결과가 나와요. |
| 사다리 경로 확인 끝(일괄·한 명씩) | {이름}의 결과: {결과} |
| 사다리 결과 보기 | 전체 결과가 나왔어요. 아래 목록에서 읽을 수 있어요. |
| 돌림판 회전 시작 | 돌리는 중이에요. |
| 돌림판 정지(일괄 공개) | 돌림판 결과: {항목} |
| 돌림판 정지(결과 가리기) | 결과가 정해졌어요. 결과 보기를 누르면 칸 글자와 결과를 볼 수 있어요. |
| 돌림판 결과 보기 | 돌림판 결과: {항목} |
| 제비뽑기 섞기 | 카드 {N}장을 섞어 놓았어요. 카드를 눌러 한 장씩 열어 보세요. |
| 제비뽑기 다시 섞기 | 카드 {N}장을 새로 섞었어요. 열린 카드는 모두 닫혔어요. |
| 제비뽑기 카드 열기 | {n}번째 카드: {항목} |
| 제비뽑기 남은 카드 모두 열기 | 남은 카드를 모두 열었어요. 열린 카드에서 항목을 읽을 수 있어요. |

- 조사(이/가, 은/는)가 받침에 따라 바뀌는 문장은 쓰지 않는다. 이유: 입력 글에 따라 조사를 맞추는 코드를 만들지 않으려는 것이다. 그래서 알림은 "{이름}의 결과: {결과}"처럼 고정 형태다.

### 사용 순서와 설명 문단 (서버 렌더링)

| 페이지 | 사용 순서(번호 단계) | 설명 문단 |
|---|---|---|
| 허브 | 1. 쓰고 싶은 도구를 고릅니다. 2. 이름이나 항목을 줄마다 하나씩 입력합니다. 3. 시작, 돌리기, 섞기를 눌러 결과를 확인합니다. | 세 도구 모두 로그인 없이 쓸 수 있고, 입력한 이름과 항목은 이 화면의 메모리에서만 쓰입니다. 서버로 보내거나 저장하지 않으며 새로고침하면 사라집니다. 이름과 결과를 짝지을 때는 사다리 타기, 항목 중 하나를 고를 때는 돌림판, 항목을 한 장씩 뽑을 때는 제비뽑기를 씁니다. 사다리 타기와 돌림판은 결과를 한꺼번에 보이거나 가렸다가 볼 수 있고, 사다리 타기는 한 명씩 열어 볼 수도 있습니다. 제비뽑기는 뒷면 카드를 한 장씩 열어 봅니다. |
| 사다리 타기 | 1. 참가자 이름을 줄마다 하나씩 입력합니다(2명부터 10명까지). 2. 같은 수의 결과를 입력하고 시작을 누릅니다. 3. 이름을 고르면 사다리를 따라 결과가 나옵니다. | 시작을 누르면 가로선이 무작위로 놓이고, 아래 결과 칸의 순서도 무작위로 섞입니다. 시작 전에는 사다리와 결과가 화면에 없습니다. 입력 순서와 결과 칸 순서는 관련이 없습니다. 이름과 결과를 짝지어 정할 때 쓰는 도구입니다. |
| 돌림판 | 1. 항목을 줄마다 하나씩 입력합니다(2개부터 28개까지). 2. 돌리기를 누릅니다. 3. 멈춘 칸의 항목이 결과로 나옵니다. | 모든 칸의 크기가 같아 각 항목이 뽑힐 확률은 같습니다. 결과 가리기를 켜면 결과 보기를 누를 때까지 칸 글자와 강조 칸도 숨깁니다. 뽑힌 항목 빼기를 켜면 뽑힌 항목을 빼고 남은 항목으로 다시 돌릴 수 있습니다. |
| 제비뽑기 | 1. 항목을 줄마다 하나씩 입력합니다(2개부터 30개까지). 2. 섞기를 누르면 뒷면 카드가 항목 수만큼 놓입니다. 3. 카드를 한 장씩 눌러 열어 항목을 확인합니다. 4. 남은 카드 모두 열기로 한꺼번에 열거나, 다시 섞기로 처음부터 다시 합니다. | 뒷면 카드를 섞어 두고 한 장씩 열어 항목을 정하는 도구입니다. 섞기를 누르면 항목이 카드 자리에 무작위로 나뉘고, 카드에는 번호만 보입니다. 카드를 열기 전에는 어떤 항목인지 화면 어디에도 없습니다. 한 번 연 카드는 다시 열 수 없습니다. 사다리 타기는 이름과 결과를 짝짓는 도구입니다. |

### FAQ 답 (화면과 FAQPage JSON-LD가 같은 문장, 페이지마다 3개 또는 4개)

질문 중 plan의 "결과가 보장되나?"는 S-4 예외 범위(고지 두 문장, meta description, 약관 10장)에 FAQ가 없어서 "결과로 상품이나 포인트를 받을 수 있나요?"로 바꿨다. 같은 뜻을 부정형으로 답한다.

| 페이지 | 질문 | 답 |
|---|---|---|
| 허브 | 운빨 뽑기에는 어떤 도구가 있나요? | 사다리 타기(2~10명), 돌림판(항목 2~28개), 제비뽑기(항목 2~30개)가 있습니다. 사다리 타기는 이름과 결과를 짝짓고, 돌림판은 항목 중 하나를 고르고, 제비뽑기는 뒷면 카드를 한 장씩 열어 항목을 뽑습니다. |
| 허브 | 입력한 이름은 저장되나요? | 아니요. 입력한 내용은 이 화면의 메모리에서만 쓰이고 서버로 보내지거나 저장되지 않습니다. 화면을 새로고침하면 사라집니다. |
| 허브 | 결과로 상품이나 포인트를 받을 수 있나요? | 아니요. 운빨 뽑기는 오락 목적의 도구이며, 결과는 금전, 상품, 포인트, 경품 등 어떤 보상과도 관련이 없습니다. |
| 사다리 타기 | 사다리 타기는 몇 명까지 할 수 있나요? | 2명부터 10명까지 할 수 있습니다. 참가자 수와 결과 수가 같아야 시작할 수 있습니다. |
| 사다리 타기 | 결과는 어떻게 정해지나요? | 시작을 누르면 가로선이 무작위로 놓이고, 아래 결과 칸의 순서도 무작위로 섞입니다. 그래서 어느 참가자가 어느 결과에 도착할지는 같은 확률로 정해집니다. |
| 사다리 타기 | 결과를 미리 볼 수 있나요? | 아니요. 시작을 누르기 전에는 사다리도 결과도 화면에 없습니다. 결과 가리기를 고르면 결과 보기를 누를 때까지 결과 글자를 숨깁니다. |
| 돌림판 | 항목마다 뽑힐 확률이 같은가요? | 네. 모든 칸의 크기가 같아서 각 항목이 뽑힐 확률은 같습니다. |
| 돌림판 | 뽑힌 항목을 빼고 다시 돌릴 수 있나요? | 네. 뽑힌 항목 빼기를 켜면 뽑힌 항목이 목록에서 빠지고 남은 항목만으로 돕니다. 항목이 한 개 남으면 돌릴 수 없고, 처음부터를 누르면 목록이 되돌아옵니다. |
| 돌림판 | 결과 가리기를 켜면 바늘만 보고 결과를 알 수 있나요? | 칸 글자와 강조 칸은 결과 보기를 누를 때까지 숨깁니다. 바늘이 어느 칸에 섰는지는 보이므로, 칸을 세어 입력한 순서와 맞춰 보면 짐작할 수 있습니다. |
| 돌림판 | 항목은 몇 개까지 넣을 수 있나요? | 2개부터 28개까지, 한 줄에 15자까지 넣을 수 있습니다. |
| 제비뽑기 | 카드는 어떻게 섞이나요? | 섞기를 누르면 입력한 항목이 카드 자리에 무작위로 나뉩니다. 카드에는 번호만 보이고, 열기 전에는 어떤 항목인지 화면 어디에도 없습니다. |
| 제비뽑기 | 한 번 연 카드를 다시 열 수 있나요? | 아니요. 한 번 연 카드는 다시 열 수 없고 항목도 바뀌지 않습니다. 처음부터 다시 하려면 다시 섞기를 누르세요. 입력한 항목은 그대로 두고 카드를 새로 섞습니다. |
| 제비뽑기 | 같은 이름을 여러 번 넣어도 되나요? | 네. 같은 이름이 여러 줄이면 줄마다 카드가 한 장씩 따로 만들어집니다. 항목은 30개까지, 한 줄에 15자까지 넣을 수 있습니다. |
| 제비뽑기 | 순서 정하기에도 쓸 수 있나요? | 네. 항목에 1번, 2번처럼 순서를 적어 넣고 카드를 한 장씩 열어 뽑으면 됩니다. 이름과 결과를 짝지어 정할 때는 사다리 타기가 맞습니다. |

- "같은 확률", "각 항목이 뽑힐 확률은 같다"는 design.md 2.3(균등 배정)과 plan 공정성 설명의 검증 가능한 문장 범위 안이다. "암호학적 난수" 같은 표현은 없다.
- 제비뽑기 "카드 순서는 섞기를 누른 뒤 무작위로 정합니다"(plan 공정성 설명 문장)는 위 사용 순서 설명 문단과 FAQ 첫 답에 같은 뜻으로 들어 있다.
- 위 문구는 plan 40번 금지어 정적 검사 기준으로 직접 확인했다(내기, 당첨, 추첨, 돈, 보장 등 없음. "보장", "보상"은 S-4 예외 문장에만 있다. 메뉴·룰렛 단어는 돌림판 페이지에 없다).
- "순서 정하기" 키워드는 제비뽑기 키워드에서 빼고 FAQ 질문 한 개로 답한다(plan 확인 19번). "당번 정하기"는 사다리 쪽 키워드이고, 사다리 FAQ에는 아래 한 문장을 사다리 "결과는 어떻게 정해지나요?" 답과 별도로 두지 않고 허브 예시 "4명이 청소 당번 정하기"와 사다리 설명 문단의 "이름과 결과를 짝지어 정할 때 쓰는 도구입니다."로 서버 HTML에 담는다. 이유: FAQ 문장을 늘리면 JSON-LD와 화면을 같이 늘려야 하고, 문장 하나가 설명 문단 안에서도 같은 역할을 한다. 추가 FAQ가 꼭 필요하면 PM이 알려 달라.

## 기존 디자인 시스템 변경 제안

없음 (규칙을 바꾸는 제안은 없다). 단, 승인된 S-1 A에 따른 아래 반영은 개발 단계에서 해야 한다.

- 새 토큰 `menu-lucky`(`#4b4690`, "가지")는 `globals.css`와 `docs/conventions/design-system.md`의 "메뉴 라벨 색" 표(운빨 뽑기 / `menu-lucky` / `#4b4690` / 가지 한 줄)와 `src/constants/theme.constant.ts`에 반영한다. 이 명세는 값만 제안한다. 규칙 문서는 사용자 승인 없이 agent가 고칠 수 없으므로 PM이 승인된 값으로 고친다.
- 참고: 규칙 문서는 `--menu-<key>`라고 적지만 이 기능의 그룹 키는 `lucky-draw`이고 토큰 이름은 `lucky`다. 승인 때 이 이름 차이를 같이 확인한다(design.md 6장과 같은 지적).
- 폰트, 메인 색, 반경 규칙, 모션 규칙은 바꾸지 않는다. 돌림판 가림 고리의 점선 테두리는 새 토큰이 아니라 기존 Tailwind 유틸리티와 `menu-lucky`의 투명도 값(`/50`)이다.

- 이 외에 이 명세가 정한 것(질문 없이 확정 제안): 사다리 위 칸을 이름 대신 번호로, 시작 후 버튼 라벨 "다시 시작", 사다리 경로 0.8초, 결과 보기 공개 연출 없음, 허브의 인원 한계 표시와 도구 역할 비교 한 줄, 제비뽑기 카드 격자(320px 3열, 480px 4열, 768px 5열, 1024px 6열), 카드 열기 0.2초(`opacity`와 가로 펴짐), "남은 카드 모두 열기"는 즉시, 돌림판 가림 시각 처리(점선 고리, 눈 가림 아이콘 문장, 공개 방식 설명 한 줄). 이견이 있으면 말해 달라.

- architect에게 되돌릴 것: 없음. 새 API와 데이터는 넣지 않았다. 카드 번호는 놓인 자리 순서이고 새 데이터가 아니다. 다만 design.md의 `lots` 상태 모델(열린 카드 위치 집합과 카드별 항목 하나만 내보내는 열기 함수, AC-26d), 돌림판 가리기에서 "남은 항목" 갱신 시점(결과 보기 뒤), 공용 `isResultHidden` 범위 확장은 design.md 재작업에서 이 명세와 맞춘다.

### plan 열린 질문 18~22 확정 (권장안으로 반영)

사용자가 지시한 대로 plan의 권장안으로 확정해 이 명세에 반영했다.

1. 18번 제비뽑기 공개 방식: 선택을 없애고 카드 열기("한 명씩")와 "남은 카드 모두 열기"("일괄")로 대신한다. 반영: 제비뽑기 절, 컴포넌트 상태 표(공개 방식 스위치는 제비뽑기에 없음), 문구.
2. 19번 키워드 이동: "순서 정하기", "발표 순서 정하기", "당번 정하기"를 제비뽑기 키워드에서 빼고, "당번 정하기"는 사다리 쪽으로 옮긴다. "순서 정하기"는 제비뽑기 FAQ 질문 한 개("순서 정하기에도 쓸 수 있나요?")로 답한다. 반영: FAQ 표, 허브 예시 문장.
3. 20번 카드 번호 표시: 카드에 놓인 자리 번호(1~N)를 보인다. 닫힌 카드는 큰 번호와 "열기", 열린 카드는 번호 배지. 번호는 항목과 무관하다. 반영: 제비뽑기 절, 색상 표, 타이포그래피.
4. 21번 칸 위치 추측 한계: 바늘이 선 칸을 세어 입력 순서와 맞추는 추측은 막지 않는다. 칸 색 패턴은 자리 번호에만 따르고 항목 글자를 드러내지 않는다는 점을 확인했다. 칸 색을 섞는 규칙은 넣지 않는다. FAQ에 이 한계를 사실대로 적었다. 반영: 색상 장 "칸 패턴" 항목, 돌림판 FAQ.
5. 22번 돌림판 "결과 보기" 전 다시 돌리기: 누르지 못하게 한다. "결과 보기"가 끝나야 다음 회전을 할 수 있다. 막힘 사유 "결과 보기를 누르면 다시 돌릴 수 있어요."를 쓴다. 반영: 돌림판 절, 입력 오류와 막힘 이유 표.
