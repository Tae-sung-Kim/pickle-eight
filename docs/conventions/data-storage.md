# 데이터 저장 위치

architect가 설계할 때 따른다.

새 데이터가 생기면 architect가 아래 기준으로 저장 위치를 판단하고, `design.md`에 데이터별 저장 위치와 이유를 적는다. 회원가입이 없는 기능은 Supabase를 기본값으로 쓰지 않는다.

- 코드 안 상수/JSON (`src/features/<기능>/constants`): 모두에게 같고 자주 안 바뀌는 데이터. 예: 타로 카드 의미, 점심 메뉴 목록
- sessionStorage: 탭을 닫으면 사라져도 되는 임시 상태. 예: 진행 중인 단계, 입력 중인 폼
- localStorage: 작고(수백 KB 이하) 기기에 남아야 하는 개인 데이터. 예: 저장한 로또 번호, 최근 기록, 설정
- IndexedDB: 크거나 많거나 검색이 필요한 개인 데이터, 오프라인 지원. 예: 수천 건 기록, 이미지·파일
- Supabase: 서버에서 갱신하거나 사용자끼리 공유하는 데이터, 기기 간 동기화(로그인 필요). 예: 로또 회차, 통계, 광고 설정
- 브라우저 저장소에는 비밀번호, 토큰, 민감한 개인정보를 넣지 않는다.
