# 홈 재구성 기획서

## 목표

홈(`/`)을 "로또 사이트" 첫 화면에서 "오늘의 운과 선택을 가볍게 즐기는 도구 모음" 첫 화면으로 바꿔, 방문자가 매일 쓰는 도구(운세, 뭐 먹지)를 먼저 찾게 하고 로또는 목록의 한 칸으로 둔다.

## 범위

- 포함:
  - 홈 제목(h1), 홈 메타 title·description, 히어로 문구를 도구 모음 톤으로 바꾼다. 제목에서 "로또" 단어를 뺀다.
  - 홈 서비스 목록 순서를 바꾼다. 운세·뭐 먹지를 위에 두고 로또는 목록의 한 칸으로 둔다. 목록의 메뉴 라벨은 바꾸지 않는다.
  - 최신 당첨 번호 배너(`LatestResultBannerComponent`)를 홈에서 뺀다. 배너를 어디에 둘지는 열린 질문 4번에서 정한다.
  - 루트 메타데이터의 `category`에서 "로또"를 뺀다. 현재 값은 `엔터테인먼트, 도구, 로또`이다.
  - 홈 로또 항목의 설명에 로또 검색 키워드를 남겨 검색 유입 손실을 줄인다(F-5).
- 제외:
  - `/lotto/*` 페이지의 SEO(메타데이터, OG, title, description, JSON-LD)는 그대로 둔다. 로또 검색 유입을 지키기 위해서다.
  - 로또 기능 자체(번호 생성, 회차 조회, 채점, 나의 번호, 분석, 시뮬레이터) 변경.
  - 메뉴 추가·삭제, 메뉴 라벨 변경. 기존 e2e가 "뭐 먹지", "꿈 해몽", "운빨 뽑기" 같은 정확한 이름에 의존한다. 라벨 변경 여부는 열린 질문 11·15번에서 정한다.
  - 사이트 이름(`NEXT_PUBLIC_SITE_NAME`) 변경. 열린 질문 1번으로 남긴다.
  - 루트 layout의 기본 title·description·OG·keywords 변경. 사용자 결정은 category까지다. 이 값도 로또 중심이라 열린 질문 8번으로 남긴다.
  - 404 화면, 헤더 디자인, 디자인 시스템 색·폰트 변경.
  - 실제 SEO 설정(sitemap 구조, robots) 변경. 순서 변경에 따른 재수집 요청은 배포 후 작업으로 둔다.

## 기능 목록

| ID | 기능 | 우선순위 (필수/선택) |
|---|---|---|
| F-1 | 홈 h1·설명·히어로 문구를 도구 모음 톤으로 바꾸고 제목에서 "로또"를 뺀다 | 필수 |
| F-2 | 홈 서비스 목록 순서 재배치. 운세·뭐 먹지를 위에, 로또는 한 칸 | 필수 |
| F-3 | 최신 당첨 번호 배너를 홈에서 빼고 새 위치(안 A 또는 안 B)로 옮긴다 | 필수 |
| F-4 | 루트 메타데이터 `category`에서 "로또"를 뺀다 | 필수 |
| F-5 | 홈 로또 항목 설명에 로또 검색 키워드를 남긴다 (유입 완화) | 선택 |
| F-6 | 홈에 "오락 목적" 고지 한 줄을 넣는다 (법적 검토 후 결정) | 선택 |
| F-7 | `/lotto/*` 페이지 SEO 변경 없음 (보호 조건) | 필수 |

F-3의 안 A는 배너를 로또 메뉴(`/lotto`) 안으로 옮기는 것이다. 안 B는 배너를 홈 목록 하단에 작은 카드로 내리는 것이다. 어느 안을 고를지는 열린 질문 4번에서 정한다.

## 유저 스토리

- US-1: 처음 들어온 방문자로서, 홈 제목만 보고 이 사이트가 어떤 도구를 모아 둔 곳인지 알고 싶다. 왜냐하면 로또 사이트로 오해하고 나가지 않도록 하고 싶어서다.
- US-2: 오늘의 운세나 메뉴를 고르러 온 방문자로서, 첫 화면에서 매일 쓰는 도구를 바로 찾고 싶다. 왜냐하면 매일 쓰는 도구가 목록 위에 있어야 한 번에 들어갈 수 있어서다.
- US-3: 로또 번호를 찾으러 온 방문자로서, 홈에서 로또 메뉴를 찾아 번호 생성이나 당첨 결과 조회로 가고 싶다. 왜냐하면 로또 기능은 그대로 쓸 수 있어야 해서다.
- US-4: 운영자로서, 홈 변경 뒤에도 로또 검색어 유입이 `/lotto/*` 페이지로 계속 들어오게 하고 싶다. 왜냐하면 로또 검색 트래픽이 가장 큰 유입원일 수 있어서다(수치는 열린 질문 2번).

## 완료 조건 (AC)

QA가 이 목록으로 테스트를 만든다. 화면에서 확인할 수 있는 문장으로 쓴다.

- AC-1: [E2E] 데스크톱과 모바일에서 홈을 열면 h1이 한 개만 보이고, h1과 히어로 문구 어디에도 "로또" 단어가 없다. 같은 화면의 서비스 목록에서 메뉴 그룹 이름이 한 번씩만 나오고, "로또"는 목록의 한 칸이다. 화면에 "준비 중" 문구가 없다.
- AC-2: [E2E] 홈에서 서비스 목록의 "운세"를 누르면 운세 허브로 가고, "로또"를 누르면 로또 메뉴(`/lotto`)로 간다. 데스크톱과 모바일에서 각각 확인한다.
- AC-3: [E2E] 홈에는 최신 당첨 번호 배너가 보이지 않는다. 같은 흐름에서 로또 메뉴로 들어가면 배너가 확정된 새 위치(안 A 또는 안 B)에 보인다.
- AC-4: [단위] 메뉴 그룹 순서와 그룹 안 하위 항목 순서가 확정안과 같다. 기준은 `MENU_LIST` 상수(또는 홈 전용 순서 상수)이며, 확정안이 나오면 이 AC의 기준 값을 채운다. 헤더·모바일·사이트맵도 같은 순서를 따르는지 같은 상수로 확인한다.
- AC-5: [단위] 홈 히어로 문구와 홈 title·description 문구 상수에 금지 표현(보장, 적중, 당첨 확률, 당첨을 보장, 반드시 맞다 류)이 없다. 문구 상수는 확정 문구로 채운다.
- AC-6: [정적] 루트 메타데이터의 `category` 값에 "로또"가 없다. 그 밖의 루트 메타 값은 열린 질문 8번 결정 전까지 바꾸지 않는다.
- AC-7: [정적] `/lotto/*` 페이지의 metadata 객체와 `generateMetadata`는 변경 diff가 없다. 홈의 JSON-LD(WebSite, ItemList)와 sitemap의 `/`, `/lotto` 등록은 기존 구조를 유지한다.
- AC-8: [E2E] 기존 홈 검사(`e2e/lotto.spec.ts`, `e2e/meal.spec.ts`, `e2e/dream.spec.ts`, `e2e/lucky-draw.spec.ts`의 홈 진입 부분)가 깨지지 않는다. 회귀로 한 번만 돌린다.

조건부 AC (해당 열린 질문 답이 나오면 추가한다)

- 모바일 접힘을 고르면 [E2E] 한 줄을 추가한다(데스크톱·모바일에서 접힘·펼침과 항목 이동). 열린 질문 14번.
- 홈 설명 문구를 그룹별 짧은 설명으로 바꾸면 [단위] 한 줄을 추가한다(그룹별 설명 문자열이 상수에 있고 로또 키워드를 포함하는지). 열린 질문 13번.

## 예외·빈 상태

- 로또 항목이 목록에 한 칸뿐이라, 로또 번호만 찾는 방문자는 한 번 더 누르게 된다. 로또 검색 유입은 `/lotto/*`에서 직접 받는 것이 기본이라 큰 문제는 아니지만, 검색 유입 데이터로 확인한다(열린 질문 2번).
- 배너 안 A(로또 메뉴 안)로 옮기면, 배너는 `/lotto/*`의 나이 확인(AgeGate) 뒤에 보인다. 배너 안 B(홈 하단)로 두면 나이 확인 전에 당첨 번호가 홈에 보인다. 이 차이를 열린 질문 4번에서 함께 본다.
- 배너 데이터가 없거나 불러오지 못하면 현재처럼 아무것도 보여 주지 않는다. 로딩 중에는 자리 표시만 보인다(안 B를 고르면 이 상태를 목록 하단에서도 확인).
- 나의 번호 저장 목록이 있으면 현재 배너 안에 "내 번호" 요약이 함께 나온다. 배너를 옮기면 이 요약도 같이 옮겨진다. 옮긴 뒤에도 저장된 번호가 있는 방문자가 요약을 찾을 수 있어야 한다.
- JS를 끈 상태에서도 h1과 서비스 목록은 서버 HTML에 있어야 한다(`seo.md`의 서버 렌더링 규칙). 배너는 클라이언트 조회라 서버 HTML에 없어도 된다.
- 좁은 모바일 화면에서 목록 항목 설명(예: "번호 생성기, 회차별 당첨 결과, ...")이 여러 줄로 바뀌어도 줄바꿈이 깨지지 않아야 한다.
- 메뉴 순서를 바꾸면 헤더(PC·모바일)와 사이트맵 순서도 같이 바뀔 수 있다(열린 질문 3번).
- 홈 URL `/`와 기존 링크는 그대로 둔다. 301 redirect는 필요 없다.
- `comingSoon` 그룹이 생기면 목록에 "준비 중" 배지가 붙는다. 현재 준비 중 그룹은 없다. 준비 중 항목이 홈 상단에 올라가는 일은 없어야 한다.

### 점검 항목과 제안

1. 그룹 순서 (열린 질문 3번과 연결). 현재는 로또가 맨 앞이다. 홈·헤더·모바일·사이트맵이 같은 순서를 따르므로, 순서를 바꾸면 네 곳이 함께 바뀐다. 권장은 열린 질문 3번의 순서다.
2. 그룹 이름 일관성. 라벨 길이와 톤이 섞여 있다.
   - 명사형: 로또, 타로, 운세, 꿈 해몽
   - 문장형·구어: 뭐 먹지(의문형), 운빨 뽑기(구어, "운빨" 표현)
   - 항목 라벨은 "오늘의 ~", "오늘 ~" 접두가 섞여 있다(오늘 뭐 먹지, 오늘의 타로, 오늘의 운세).
   - 로또 하위 "로또 시뮬레이터"는 그룹이 이미 로또라서 접두가 겹친다.
   - 제안: 그룹 이름은 현행 유지를 권장한다. "뭐 먹지"와 "꿈 해몽"은 검색 키워드이고 e2e가 정확한 이름으로 찾으므로 바꾸면 SEO·테스트 영향이 크다. 톤 차이는 허용하고, 하위 항목 라벨의 접두 중복만 정리하는 안을 열린 질문 15번으로 남긴다.
3. 하위 항목 순서.
   - 운빨 뽑기: 현행은 사다리 → 돌림판 → 제비뽑기. 사다리는 이름 여러 개를 넣어야 해서 입력이 가장 많고, 돌림판은 항목 하나만 고르면 된다. 권장은 현행 유지다(근거 데이터 없음, 사용자 판단).
   - 운세: 현행 오늘의 운세 → 띠별 → 별자리 → 사주는 입력 정보가 적은 순서다. 권장 유지.
   - 로또: 번호 생성기 → 회차별 당첨 결과 → 번호 채점기 → 나의 번호 → 통계 → 시뮬레이터. 권장 유지.
   - 하위 순서를 바꾸면 허브 페이지 목록 순서도 함께 바뀐다(열린 질문 16번).
4. 하위 항목 1개 그룹(뭐 먹지, 꿈 해몽) 표시. 헤더와 모바일은 그룹 자체가 바로 링크이고, 홈은 그룹 한 줄에 항목 라벨 한 개가 설명으로 붙는다. 그룹 라벨("뭐 먹지")과 항목 라벨("오늘 뭐 먹지")이 달라도 두 곳 모두 자연스럽다. 권장은 현행 표시 방식 유지다(열린 질문 12번).
5. 홈 목록 설명 문구. 라벨을 ", "로 이어 붙이는 방식은 로또처럼 6개가 한 줄에 들어가면 모바일에서 세 줄 이상으로 길어지고, 서비스 목록의 가독성이 떨어진다. 반면 로또 키워드(F-5)를 가장 많이 담고 있는 부분이라 줄이면 유입 완화 효과도 줄어든다. 권장은 그룹마다 짧은 설명 문구를 두는 안이다(열린 질문 13번).
6. 모바일 접힘. 현재는 전부 펼쳐져 있다. 전체 항목은 19개이고, 6개짜리 로또 그룹이 가장 길다. 접힘을 넣으면 그룹 제목 링크와 펼침 버튼을 나눠야 해서 동작 설계가 추가된다. 권장은 현행 펼침 유지 후 실제 모바일 화면을 본 뒤 재검토다(열린 질문 14번).
7. 사이트맵 주소 중복. 뭐 먹지와 꿈 해몽은 그룹 주소와 항목 주소가 같다. 현재 `sitemap.ts`는 그룹 주소와 항목 주소를 모두 넣으므로 같은 주소가 두 번 들어갈 수 있다. 설계 단계에서 중복 제거 여부를 확인한다. 기획상으로는 한 번만 나오면 된다.

### AC 영향

- AC-4를 그룹 순서와 하위 항목 순서까지 포함하도록 고쳤다.
- 모바일 접힘, 홈 설명 문구 방식은 답이 나온 뒤 조건부 AC로 추가한다(위 조건부 AC 참고).

## 법적·정책 요구사항

- 개인정보 수집: 홈 자체는 입력을 받지 않으며, 이번 변경으로 새로 수집하는 정보는 없다. 배너는 내부 API로 당첨 데이터를 읽고, 나의 번호는 기존처럼 브라우저에 저장한다. 배너 위치를 바꿔도 저장 방식은 바뀌지 않는다는 점만 확인한다.
- 고지 문구:
  - 로또: `COMPLIANCE.md` 2번(나이 확인은 `/lotto/*` 라우트에 적용), 3번(외부 API는 사용자 라우트에서 호출하지 않음)을 따른다. 홈 목록이나 배너에 로또 당첨 번호가 노출되는 한, `COMPLIANCE.md` 11번의 "로또 기관과 무관함(비제휴) 고지"가 어디에 있는지 확인하고 같은 수준으로 둔다. 현재 홈에 이 고지가 있는지는 확인하지 못했다(열린 질문 9번).
  - 운세·타로·뽑기: `COMPLIANCE.md` 11번의 "오락 목적 고지" 방식을 따른다. 홈은 운세·타로 결과를 보여 주지 않으므로 필수는 아니다. 홈 히어로 옆에 짧은 오락 목적 문구를 넣을지(F-6)는 열린 질문 9번으로 정한다.
  - 홈 히어로와 설명은 "보장", "적중", "당첨 확률" 같은 표현을 쓰지 않는다. 이 금지 표현은 AC-5로 확인한다.
  - 로또 관련 문구를 바꾸면 `COMPLIANCE.md` 항목(로또 응답 고지 등)과 어긋나지 않는지 확인한다.
- 상업적 이용 주의:
  - 광고 수익은 AdFit 디스플레이 광고만 쓴다(`COMPLIANCE.md` 4번, 타로·운세 항목과 같은 방침). 홈에는 `layout.tsx`의 고정 AdFit 슬롯(`fixed topOffsetPx={64}`)이 레이아웃 수준에서 나온다. 홈의 광고 노출 위치와 개수가 바뀌지 않는지 확인한다.
  - 홈 목록에 로또 항목이 있어도 로또 당첨 번호를 광고 옆에 두지 않는다. 배너를 안 B로 두면 이 규칙을 따로 확인한다.
  - 로또 번호 추천류 문구를 메타 키워드나 히어로에 쓰면 "당첨 보장"으로 읽힐 수 있다. 홈 문구에서는 "번호 생성" 대신 "번호 만들기" 같은 중립 표현을 검토한다(열린 질문 5번).
  - 사이트 이름과 상호(운빨연구소)를 바꾸면 AdFit 등록 정보와 사업자 표기도 함께 확인한다.
