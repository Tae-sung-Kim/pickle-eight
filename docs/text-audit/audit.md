# 화면별 텍스트 양 조사 (text-audit)

조사일: 2026-11-27. 읽기 전용 조사이며 코드는 바꾸지 않았다.

## 1. 측정 방법과 한계

- 로컬 dev 서버(localhost:3000)의 서버 HTML에서 `<head>`, 헤더, 내비, 푸터를 뺀 본문 텍스트를 공백 제외 글자 수로 센다. 아래 "총량"은 이 값이다.
- 상담전화 5곳은 DOM에 `tel:` 링크와 일반 텍스트가 둘 다 있고 CSS 미디어쿼리로 하나만 보인다. 총량에서는 한쪽(약 130자)만 남겼다. 이 DOM 중복은 화면에 보이지 않아 읽는 양이 아니다.
- JS 없을 때만 보이는 noscript 안내(47~81자)는 총량에서 뺐다. JS를 쓰는 이용자는 보지 못한다.
- 모든 페이지에 공통으로 붙는 푸터(브랜드 문구, 저작권, 광고 동의 배너, 쿠키 설정)는 약 110자이며 총량에 넣지 않았다.
- 운세·궁합·타로·꿈·뽑기·뭐 먹지는 안내문, 가이드, FAQ가 서버 HTML에 있어 실측했다. 결과 영역과 이용 동의 화면은 클라이언트에서만 그려져 실측하지 못했다. 운세 계열 이용 동의 화면은 상수 기준 약 390자(추정)다.
- 로또는 `AgeGateProvider`가 클라이언트에서 children을 그려서 서버 HTML이 제목 한 줄(42자)뿐이다. 로또 수치는 layout 컴포넌트와 상수의 한글 글자 수에서 낸 추정이며 버튼 라벨과 옵션명이 포함되어 있다.
- "첫 화면"은 스크롤 전에 보이는 양을 입력 컴포넌트 앞 블록 합계로 어림한 값이다. 기기 크기에 따라 달라진다.
- 접기(`details`/아코디언)는 현재 한 곳도 쓰지 않는다. 전 화면에서 `<details>` 수는 0이다.
- 방문한 화면: 홈, 운세 허브, 오늘, 띠, 별자리, 궁합 허브, 띠 궁합, 별자리 궁합, 사주, 뭐 먹지, 타로 2개, 운빨 뽑기 허브와 3개 도구, 꿈 허브, 꿈 상세(돼지), 손 없는 날 허브와 연도(2026), 로또 6개.

## 5. 접어도 되는 후보와 접으면 안 되는 블록

## 8. 핵심 발견

1. 운세 계열 화면은 서버 HTML만 2100~3000자이고, 결과 전에 이용 동의 화면 약 390자가 더 붙는다. 첫 화면에서 약 590자를 읽는다. 띠별 운세가 가장 많다.
2. 상시 면책, 입력 안내, 이용 동의, 결과 하단 면책, 이용 안내, FAQ에서 같은 뜻(오락·참고, 비전송, 만 14세)이 한 화면에 4~7번 반복된다. 법적으로 위치를 못 박은 곳은 h1 아래 상시 면책, 입력 근처 안내, 결과 하단 면책, 상담전화다. 이용 안내 목록 대부분은 위 문구와 중복이다.
3. 프로젝트 전체에 접기(`<details>`)가 한 개도 없다. FAQ를 아코디언 없이 펼친 것은 법이 아니라 fortune 디자인 결정이다.
