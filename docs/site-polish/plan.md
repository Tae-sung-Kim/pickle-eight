# site-polish 기획서

## 목표

사이트 공통 요소(모바일 헤더 이름, 사이트 아이콘, 푸터 소개 문구)를 다듬고, 개발 서버에서 보이는 CSP 콘솔 오류를 없애며, 개인정보처리방침과 이용약관의 낡은 부분을 수정 전 검토 목록으로 정리한다.

## 범위

- 포함:
  - 모바일 헤더 사이트 이름 노출 (360px 폭 기준)
  - 사이트 아이콘(`src/app/icon.svg`)을 헤더·푸터의 "8" 공 모양으로 교체
  - 푸터 소개 문구 변경
  - 개발 모드 CSP 오류(va.vercel-scripts.com) 해소
  - 개인정보처리방침·이용약관·쿠키/광고 동의 문구 검토 목록 작성 (수정 없음)
- 제외:
  - `og-image.svg` 교체 (별도 작업)
  - 개인정보처리방침·이용약관 본문 수정 (검토 목록만 작성, 수정은 사용자 승인 후 별도 작업)
  - 쿠키 배너·넛지 문구 수정 (검토 목록만 작성)
  - 운영 배포 CSP 변경
  - 사용하지 않는 CSP 허용 도메인 정리 (열린 질문으로 남김)
  - 다른 페이지 문구 수정

## 유저 스토리

- US-1: 모바일 방문자로서 좁은 화면에서도 사이트 이름을 보고 싶다. 왜냐하면 지금 어떤 사이트인지 바로 알아야 하기 때문이다.
- US-2: 방문자로서 탭과 헤더에서 사이트 아이콘을 보고 사이트를 알아보고 싶다. 왜냐하면 여러 탭 사이에서 구분해야 하기 때문이다.
- US-3: 방문자로서 푸터에서 이 사이트가 어떤 기능을 주는지 한 줄로 알고 싶다. 왜냐하면 처음 온 사람이 범위를 바로 파악해야 하기 때문이다.
- US-4: 개발자로서 개발 서버 콘솔에 CSP 오류가 없기를 원한다. 왜냐하면 진짜 오류를 가려서 보고 싶기 때문이다.
- US-5: 운영자로서 개인정보처리방침·이용약관의 문제점을 줄 번호와 함께 받고 싶다. 왜냐하면 법적 문구는 내가 승인한 뒤에만 고치고 싶기 때문이다.

## 완료 조건 (AC)

아래 E2E 세 항목은 홈 화면 한 번 열기 흐름으로 묶어 QA가 하나의 테스트로 만든다. 데스크톱 프로젝트에서 뷰포트를 360px로 지정해 확인한다 (열린 질문 4번 참고).

- AC-1: [E2E] 홈을 360px 폭으로 열면 헤더에 사이트 이름이 보이고, 우측 메뉴 버튼과 겹치지 않는다.
- AC-2: [E2E] 홈 푸터에 "운을 데이터로, 재미로."와 "운세, 궁합, 타로, 꿈 해몽, 로또, 메뉴 고르기, 뽑기까지 가볍게 즐겨보세요." 두 줄이 보인다.
- AC-3: [E2E] 홈을 개발 서버(`pnpm dev`)에서 열었을 때 콘솔에 Content Security Policy 위반 오류가 없다.
- AC-4: [정적] `src/components/layout/header.component.tsx`의 사이트 이름 `span`에서 `max-[560px]:hidden`이 제거되고, 기존 `truncate`와 `max-w-[110px] sm:max-w-[180px]`는 유지된다.
- AC-5: [정적] `src/app/icon.svg`는 git 원본(초록→보라 그라디언트 ∞)과 같고, 헤더·푸터 로고는 `/icon.svg` 이미지를 쓴다. `src/app/icon.png`와 `src/app/favicon.ico`가 있고, `public/og-image.svg`에도 ∞ 로고가 들어 있다. "8" 공은 남지 않는다.
- AC-6: [정적] `next.config.ts`의 `buildCsp()`에서 `va.vercel-scripts.com`이 개발 전용 분기(`!isProd`) 안에만 추가되고, 운영 허용 목록은 바뀌지 않는다.
- AC-7: [정적] `docs/site-polish/legal-review.md`가 있고, 항목마다 파일·줄 번호, 문제, 제안이 적혀 있다.
- AC-8: [정적] 이번 작업의 diff에 `src/app/privacy/page.tsx`, `src/app/terms/page.tsx`, `src/components/consent/` 파일이 들어 있지 않다.

## 예외·빈 상태

- 폭이 360px보다 좁은 기기(예: 320px)에서 사이트 이름이 잘리는 것은 허용한다. 메뉴 버튼과 겹치지 않는 것만 확인한다.
- `NEXT_PUBLIC_SITE_NAME` 값이 비어 있으면 헤더 이름이 빈 칸으로 보인다. 기존 동작이며 이번 범위 밖이다.
- 운영 빌드에서는 Vercel Analytics가 같은 출처(`/_vercel/insights/script.js`)를 쓰므로 CSP 변경의 영향을 받지 않아야 한다.
- 쿠키 동의 전후로 헤더·푸터·아이콘 표시가 달라지면 안 된다.
- 다크 모드에서 아이콘 색은 아래 열린 질문 2번이 정해질 때까지 확정하지 않는다.

## 검색 노출

- 키워드: 이번 작업은 새 검색 키워드를 추가하지 않는다. 푸터 문구는 모든 페이지 하단에 나오므로 검색 요약에 섞일 수 있음만 참고한다.
- 페이지가 답해야 할 질문: 해당 없음 (새 페이지 없음). 아이콘은 검색 결과와 탭의 사이트 식별에 쓰이므로 `/icon.svg` 경로와 metadata 설정은 그대로 둔다.

## 법적·정책 요구사항

- 개인정보 수집: 없음. 이번 작업은 새 입력·저장·전송을 추가하지 않는다. CSP 허용 도메인 추가는 개발 모드에만 적용된다.
- 고지 문구: 푸터 문구에 "로또"와 "운세"가 들어간다. 로또·운세 관련 고지(오락 목적, 당첨 보장 없음 등)는 기존 고지 위치를 그대로 쓰고, 소개 문구에 새 고지를 넣을지는 열린 질문 6번으로 남긴다. 법적 근거는 `COMPLIANCE.md`의 해당 장을 확인한다.
- 상업적 이용 주의: 헤더·푸터·아이콘은 광고 영역이 아니다. 광고 수익 관련 문구(쿠키 배너, 넛지)는 이번에 수정하지 않고 `docs/site-polish/legal-review.md`에 검토 항목으로만 적는다. 광고 사업자 허용 목록(CSP)과 개인정보처리방침 6번의 사업자 목록이 어긋나는 문제도 같은 문서에 적는다.
- 법적 문구(개인정보처리방침, 이용약관, 동의 문구) 수정은 사용자 승인 후에만 한다.

## 열린 질문

1. 아이콘의 "8" 글자를 폰트 텍스트로 둘지, 경로(path)로 바꿔 폰트 차이를 없앨지. 디자인 단계가 생략되어 사용자 결정이 필요하다.
2. 다크 모드 아이콘 색. 헤더 공은 다크 모드에서 `#0a1812`(`src/app/globals.css` 다크 변수)를 쓴다. 아이콘을 라이트 색 하나로 고정할지, 시스템 다크 모드에 맞춘 대응을 넣을지.
3. 16px 탭 아이콘에서 짙은 초록 공의 "8"이 읽히는지. 확인 방법(실제 탭 크기 캡처 등)을 정해 달라.
4. 기존 Playwright `mobile` 프로젝트는 Pixel 7(412px)이고 `@smoke`만 돈다. 360px 확인을 데스크톱 프로젝트에서 뷰포트를 360px로 지정해 할지, 360px 흐름에 `@smoke` 태그를 붙일지.
5. CSP 허용 목록 중 코드에서 로드하지 않는 도메인이 있다. 예: script 쪽 `pagead2.googlesyndication.com`, `securepubads.g.doubleclick.net`, `s0.2mdn.net`, `sdk.privacy-center.org`, style 쪽 `s3.us-east-1.amazonaws.com`. 광고 SDK가 런타임에 불러오는지 확인이 필요하다. 제거는 이번 범위 밖이며, 쓰는 사업자라면 개인정보처리방침 6번에도 적어야 한다.
6. 사용자가 브라우저에서 본 다른 오류가 더 있는지. 코드상 의심되는 CSP 위반 후보는 다음과 같다. (a) 카카오 AdFit `ba.min.js`가 광고 동의 후 추가로 불러오는 스크립트·프레임·이미지 도메인이 허용 목록에 있는지 동의 후 상태에서 확인 필요. (b) `ws://` 연결(Next dev HMR)이 `connect-src 'self'`로 허용되는지. (c) Vercel 디버그 스크립트가 개발 모드에서 추가 엔드포인트를 호출하는지 (`connect-src https:`로 대부분 허용). (d) 운영에서 `Content-Security-Policy`와 `Content-Security-Policy-Report-Only`가 같은 정책과 같은 보고 주소를 쓰는 것이 의도인지.
7. `va.vercel-scripts.com`을 `script-src-elem`에만 넣을지, `script-src`에도 넣을지. 오류 메시지가 `script-src-elem`이라 최소 범위는 elem이다. 실제 적용 위치는 설계 담당이 정한다.
8. 푸터 소개 문구에 로또 명칭을 계속 넣을지, 그리고 로또 관련 고지 문구가 `COMPLIANCE.md`에서 소개 문구에도 요구되는지.
9. 개인정보처리방침·이용약관·동의 문구 수정안을 언제, 어떤 순서로 승인받을지 (`docs/site-polish/legal-review.md` 기준).

### 처리 결과 (법적 문구 수정 시점)

- 4~7번: 법적 문구 수정 범위 밖. 이번 작업에서 다루지 않았고 열린 상태로 남긴다.
- 8번: 범위 밖. 푸터 문구는 이번에 바꾸지 않았다. `COMPLIANCE.md`에서 소개 문구에 고지를 요구하는 내용은 확인하지 못했다.
- 9번: 해소. 사용자가 "판단에 맡김"으로 승인했고, 변호사 없이 보수적 문구로 수정했다. 항목별 결과는 `legal-review.md`의 "처리 현황" 참고.
