# 뭐 먹지 메뉴 추가 기획서

## 목표

끼니별 메뉴 수를 늘려 돌림판 결과가 더 다양하게 나오게 한다. 점심 56개를 약 90개, 저녁 117개를 약 150개, 아침·브런치 44개를 약 65개로 늘린다.

## 범위

- 포함: 끼니별 메뉴 데이터 추가(이름, id, 카테고리, 국물 값), 개수 상수와 파일 주석 갱신, 개수에 묶인 단위 테스트 수정, `docs/menu-meals/copy-log.md` 기록.
- 제외: 화면, 계산 로직, DB, API, 카테고리 추가·삭제, 칩 기본 상태 변경, 운세·고지·FAQ·SEO 문구 변경, 메뉴 설명 문구 추가.
- 성격: 문구·상수만 바꾸는 소규모 변경. 설계와 UI/UX 단계는 생략한다(PM 승인 필요).

## 유저 스토리

- US-1: 점심 룰렛을 자주 돌리는 사용자로서, 돌릴 때마다 여러 종류의 메뉴가 나왔으면 좋겠다. 왜냐하면 목록이 적어 같은 메뉴가 자주 나온다고 느낄 수 있기 때문이다.
- US-2: 저녁 룰렛에서 야식을 켠 사용자로서, 야식 목록도 더 다양하면 좋겠다. 왜냐하면 야식 칩을 켰을 때 후보가 적다고 느낄 수 있기 때문이다.

## 완료 조건 (AC)

- AC-1 [단위]: 끼니별 메뉴 개수가 점심 90, 저녁 150, 아침·브런치 65이고 `MEAL_MENU_COUNTS`(`meal-menu.constant.ts`)와 같다.
- AC-2 [정적]: 카테고리별 개수가 위 "현재·목표 개수" 표와 같고, 카테고리마다 6개 이상이다.
- AC-3 [단위]: 끼니 안에서 id가 중복되지 않고, 이름이 중복되지 않는다(저녁은 카테고리와 이름 조합 기준). id는 소문자와 하이픈 형식이다.
- AC-4 [단위]: 새 메뉴 이름이 금지어 검사를 통과하고(메뉴 이름 예외 '해장' 포함), 아침·브런치 목록에 안주 연상 17개 이름이 없다.
- AC-5 [단위]: 야식 목록 테스트가 새 야식 메뉴 목록과 칸 순서로 통과하고, 야식 국물 목록 검사가 그대로 통과한다.
- AC-6 [E2E]: 데스크톱에서 점심, 저녁(야식 칩 켬), 아침·브런치 각 대표 흐름 1회로 룰렛을 돌리면 결과 이름이 해당 끼니(야식은 야식 칩) 목록에 있고, 기존 `e2e/meal.spec.ts`가 통과한다.
- AC-7 [정적]: 점심과 저녁에 같은 이름이 있으면 id와 국물 값이 같다. 야식 전용 이름은 저녁 안에서 id가 유일하다.
- AC-8 [정적]: 개수 주석(`meal-menu-lunch`, `meal-menu-dinner`, `meal-menu-breakfast` 헤더와 `meal-menu.constant.ts` 주석)이 새 값으로 바뀌었다. `docs/menu-meals/copy-log.md`에 추가 메뉴 표(작성자 AI 어시스턴트, 검수 PM 대기)가 있고, 점심 개수 표기(54 등 오래된 값)를 정정했다.
- AC-9 [정적]: 고지 문구, 운세, FAQ, SEO, 메뉴 그룹 설명 문구 파일의 diff가 없다.

## 개수에 묶인 테스트와 수정 대상

- `unit/meal/meal-menu.test.ts` 104~107행: 점심·아침 개수를 40~60개로 제한하는 검사가 있다. 점심 90, 아침 65는 이 범위를 넘어 실패한다. 권장: 이 범위 검사를 지운다. 103행의 `MEAL_MENU_COUNTS` 정확 개수 검사가 이미 있어서 대체된다.
- `unit/meal/meal-menu.test.ts` 43~92행 `LATE_NIGHT_NAMES`: 야식 메뉴가 추가되면 칸 순서대로 목록에 넣어야 한다. 권장: 새 야식 9개를 기존 `김치전` 뒤에 넣는다(저녁 파일에서도 같은 자리). 야식 국물 목록(196~209행)은 새 메뉴가 모두 dry라 바뀌지 않는다.
- `unit/meal/meal-menu.test.ts` 40행 `CATEGORY_COUNT`: 카테고리 수는 그대로라 바뀌지 않는다.
- `src/features/meal/constants/meal-menu.constant.ts` 22~26행: `MEAL_MENU_COUNTS`를 56/117/44에서 90/150/65로 바꾼다.
- `unit/meal/meal-pick.test.ts`: 개수를 상수나 배열 길이로 비교하므로 바뀌지 않는다.
- `e2e/meal.spec.ts`, `e2e/helpers/meal.util.ts`: 메뉴를 상수에서 읽고 개수를 하드코딩하지 않는 것으로 보인다. 야식 이름을 읽는 `e2e/meal.spec.ts` 176~180행 근처는 QA가 확인한다.
- `unit/meal/meal-copy.test.ts`의 76개 기준은 운세 문구 개수이므로 바뀌지 않는다.

## 예외·빈 상태

- 점심·아침은 끼니 안에서 이름이 유일해야 한다. 저녁은 카테고리와 이름 조합이 유일하면 되고, 야식 전용 이름은 `-late` id로 구분한다.
- 아침·브런치 목록에 안주 연상 메뉴 17개 이름(튀김, 치킨, 탕수육 등)과 같은 이름을 넣지 않는다.
- 야식 칩 기본 꺼짐 상태는 바뀌지 않는다. 야식 칩을 켜면 야식 57개가 후보가 된다.
- 메뉴 이름에 '술'이 들어가는 단어(예: 술빵)는 넣지 않는다.
- 후보 0개 안내 등 화면 상태 문구는 바뀌지 않는다.

## 검색 노출

- 키워드: 변경 없음. 기존 "오늘 뭐 먹지", "점심 메뉴 추천" 등 키워드를 그대로 쓴다.
- 페이지가 답해야 할 질문: 변경 없음. 새 페이지, 새 메타데이터, sitemap 변경은 없다.
- 권장: 메뉴 개수를 메타 설명이나 본문에 적지 않는다. 개수 숫자가 들어가면 문구 수정과 검수가 늘어난다.

## 법적·정책 요구사항

- 개인정보 수집: 없음.
- 고지 문구: 변경 없음. 기존 고지 5문장과 상시 고지를 그대로 둔다.
- 상업적 이용 주의: 상호명, 브랜드명, 특정 가게 메뉴명을 넣지 않는다. 후보는 일반 음식 이름만 쓴다. "로제떡볶이", "크로플" 등 일반 명칭으로 보지만, 사용자가 상표성을 우려하면 바꾼다(열린 질문 6번).

## 열린 질문

1. 저녁 +33 배분: 권장은 기본 후보(야식 제외)에 +24, 야식에 +9(기본 후보 93, 야식 57). 다르게 하려면 말해 달라.
2. 돌림판 칸 수: 권장은 이번 목표(90, 150, 65)를 상한으로 두는 것이다. 점심 90칸에서 칸 라벨이 읽히는지 구현 후 확인하고, 읽기 어려우면 점심 목표를 줄인다. 사용자 결정 필요.
3. 안주 연상 메뉴(튀김, 치킨 계열): 권장은 점심·아침에 넣지 않고 야식 카테고리에만 두는 것이다. 이번 후보는 이 기준을 지켰다. 점심에도 넣을지 확인 필요.
4. 점심·저녁 공유 메뉴: 권장은 같은 이름이면 같은 id와 국물 값으로 두는 것이다(현재 규칙 유지). 점심에만 넣고 싶은 이름이 있으면 알려 달라.
5. 아침 간편식 후보(과일도시락, 참치김밥 등)의 성격: 아침으로 적절한지 사용자 검토가 필요하다. 빼려면 같은 카테고리의 다른 이름으로 바꾼다.
6. 상표 판단: "로제떡볶이", "크로플", "시저 샐러드" 등을 일반 명칭으로 봐도 되는지 확인이 필요하다.
7. copy-log 정정 범위: 점심 개수 표기(54)와 저녁 개수 표기가 여러 줄에 오래된 값으로 남아 있다. 이번 작업에서 최신 값으로 함께 정정하는 것을 권장한다.
8. 후보 확정 절차: AI 작성 목록은 copy-log에 "AI 어시스턴트, 검수 대기"로 적고, 사용자가 검토한 뒤 PM이 검수 완료로 바꾼다. 이 절차로 진행해도 되는지 확인이 필요하다.
