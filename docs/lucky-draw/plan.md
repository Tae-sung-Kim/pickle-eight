## 목표

참가자 이름이나 항목을 넣고 사다리 타기, 돌림판, 제비뽑기로 짝, 순서, 결과를 무작위로 정하는 오락 도구를 한 곳에서 쓰게 한다. 입력한 내용은 서버로 보내거나 저장하지 않고, 결과는 보상과 무관한 오락이며 보장되지 않는다는 점을 화면에 분명히 한다.

## 현재 상태 확인 (기존 기능과 충돌 확인)

- 메뉴 그룹은 로또, 메뉴 룰렛(`/meal`), 타로, 운세, 꿈 해몽 다섯 개다. 운빨 뽑기 그룹은 없다. `MENU_LIST`에 새 그룹을 추가해야 한다.
- `/lucky-draw` 경로는 현재 쓰이지 않는다. 소스에서 "lucky"라는 단어는 운세의 행운 항목(`fortune-lucky.constant.ts` 등)에서만 쓰인다.
- 공용 돌림판(`src/components/common/roulette.component.tsx`)은 이미 확장되었다. 강조색(`accentClassName`), 회전 시간(`spinDurationSec`, 0.5~1.0초), 바퀴 수(`spinTurns`, 1~5), 칸별 색(`colorClassName`)을 쓸 수 있다. 칸 글자는 28개 이하일 때만 보인다. 이 기능은 이 API를 그대로 쓴다.
- 사다리 타기는 공용 돌림판으로 만들 수 없다. 세로선, 가로선, 경로를 그리는 별도 컴포넌트가 필요하다.
- 돌림판 기능은 메뉴 룰렛(`/meal`)과 검색 의도가 겹친다("룰렛 돌리기"). 역할 구분은 확인 항목 11번이다.
- 디자인 메뉴 색은 `menu-lotto`, `menu-meal`, `menu-tarot`, `menu-fortune`, `menu-dream` 다섯 개다. 운빨 뽑기 전용 색은 없다(확인 항목 12번).
- 제비뽑기 초안(이름 목록을 섞어 순서를 보여 줌)은 사다리와 모양이 거의 같아 역할이 겹쳤다. 2026-11-23 변경으로 뒷면 카드를 한 장씩 여는 방식으로 바꾼다(변경 기록 참고).
- 공용 돌림판의 `isResultHidden`(design S-2 A)은 가리는 동안 칸 글자와 강조 칸까지 그리지 않는다. 기본값이 false이므로 메뉴 룰렛은 바뀌지 않는다. `docs/roulette-common/plan.md`에는 아직 이 규칙이 없다(변경 기록의 영향 항목).

## 도구별 동작 (1차)

### 도구 역할 구분 (2026-11-23 변경)

- 사다리 타기: 이름과 결과를 짝짓는 도구다. 입력은 두 목록이다.
- 돌림판: 항목 하나를 고르는 도구다. 옵션으로 뽑힌 항목을 뺀다.
- 제비뽑기: 항목을 한 장씩 뽑는 도구다. 입력은 한 목록이고, 뒷면 카드를 한 장씩 열어 항목을 정한다. 이름에 결과를 짝짓지 않는다.

### 사다리 타기

- 입력: 참가자 이름을 줄 단위로 2~10줄, 결과 항목을 줄 단위로 입력한다. 두 목록의 줄 수가 같아야 "시작"이 켜진다. 빈 줄은 무시한다.
- "시작"을 누르면 결과 배정과 사다리 그림이 만들어진다. 시작 전에는 그림도 결과도 화면에 없다.
- 이름을 고르면 그 이름의 경로가 위에서 아래로 한 줄씩 그려지고, 도착한 결과를 보여 준다.
- 결과 공개 방식 세 가지를 모두 쓴다. "한 명씩 열기"에서는 고른 이름의 결과만 보인다.
- 사다리는 별도 컴포넌트로 만든다.
- 공정성: 참가자마다 서로 다른 결과가 하나씩 배정되고, 많은 횟수에서 모든 짝의 확률이 같아야 한다(AC-9~AC-12).

### 돌림판

- 입력: 항목을 줄 단위로 2~28줄 입력한다. 29줄째부터는 추가하지 않고 안내한다. 빈 줄은 무시한다.
- 모든 칸의 크기가 같으므로 각 항목이 뽑힐 확률은 같다.
- "돌리기"를 누르면 공용 돌림판이 기본값(1.0초, 2바퀴)으로 돈다. 멈춘 칸의 이름은 돌림판 밖의 결과 글자 영역에 보인다. 돌림판 래퍼는 `aria-hidden`이므로 결과 글자 영역이 따로 필요하다.
- 결과 가리기(돌림판 공개 방식): 회전 전과 회전 후 모두 칸 글자와 강조 칸을 그리지 않는다. 결과 글자 영역도 비워 둔다. "결과 보기"를 누르면 칸 글자, 강조 칸, 결과 글자가 함께 나온다. 이 옵션은 바늘이 멈춘 자리만 보고 결과를 알 수 없게 하려는 것이다(AC-31, AC-31a). 칸 글자 숨김은 공용 `isResultHidden`이 맡는다(변경 기록 참고).
- 칸 색은 공용 돌림판의 허용 토큰 안에서만 쓴다. 강조색은 운빨 뽑기 테마 색을 쓴다(확인 항목 12번).
- 옵션 "뽑힌 항목 빼기"(기본 꺼짐): 켜면 결과 칸을 목록에서 빼고, 다음 회전은 남은 칸만으로 돈다. 칸이 한 개 남으면 "돌리기"를 막는다. 모두 빠지면 "처음부터" 버튼으로 목록을 되돌린다.

### 제비뽑기 (카드 한 장 뽑기, 2026-11-23 변경)

- 입력: 항목을 줄 단위로 2~30줄 입력한다. 빈 줄은 무시한다. 같은 이름이 여러 줄이면 줄마다 따로 취급한다.
- "섞기"를 누르면 입력 줄 수만큼 뒷면 카드가 생기고, 항목을 카드 위치에 Fisher-Yates로 섞어 놓는다. 카드에는 번호(1부터 N, 놓인 자리 순서)만 보이고 항목 글자는 없다. 카드 위치와 항목의 대응은 열기 전에 화면과 DOM 어디에도 없다. "섞기"를 누르기 전에는 카드도 항목 글자도 없다.
- 사용자가 카드를 누르면 그 카드의 항목이 열려 카드 자리에 보인다. 한 번 연 카드는 다시 열 수 없다(누를 수 없는 상태).
- "남은 카드 모두 열기": 열지 않은 카드를 한꺼번에 연다. 전체 순서가 한 번에 보인다. 남은 카드가 없으면 비활성이다.
- "다시 섞기"(전체 초기화): 입력 목록은 그대로 두고, 열린 기록을 모두 지운 뒤 뒷면 카드 N장을 새로 섞는다.
- 공개 방식 선택은 없다. 카드를 여는 행위가 "한 명씩 열기"이고, "남은 카드 모두 열기"가 "일괄 공개"다. "결과 가리기"는 뒷면 카드가 이미 가리는 역할을 하므로 제비뽑기에서 뺀다(확인 항목 18번).

### 공통 규칙

- 입력 목록이 바뀌면 이전 결과를 지운다. 제비뽑기에서는 카드도 함께 지운다.
- 회전 중이나 연출 중에는 입력 변경, 도구 전환, 공개 방식 변경을 막는다(점심 메뉴 룰렛 AC-7과 같은 원칙).
- 공개 방식을 바꿔도 이미 나온 결과는 지우지 않는다. 사다리와 돌림판에서 "결과 가리기"로 바꾸면 결과 글자, 돌림판 칸 글자, 강조 칸은 "결과 보기"를 누르기 전까지 숨긴다.

## 유저 스토리

- US-1: 모임 총무로서, 사다리 타기로 당번과 담당을 빠르게 정하고 싶다. 참가자 이름을 한 번에 넣고 바로 그릴 수 있어야 하기 때문이다.
- US-2: 발표 순서를 정해야 하는 사람으로서, 제비뽑기에서 뒷면 카드를 한 장씩 열어 항목을 뽑고 싶다. 카드를 열기 전에는 어떤 항목이 나올지 알 수 없게 하기 위해서다. 이름과 결과를 짝짓는 일은 사다리 타기의 몫이다.
- US-3: 여러 항목 중 하나를 골라야 하는 사람으로서, 돌림판으로 항목을 고르고 뽑힌 항목을 빼고 다시 돌리고 싶다. 같은 항목이 계속 나오지 않게 하기 위해서다.
- US-4: "사다리타기"나 "제비뽑기"를 검색한 방문자로서, 첫 화면에서 이 도구가 무엇인지 알고 싶다. 찾던 도구인지 바로 확인하기 위해서다.
- US-5: 운영자로서, 입력한 이름이 서버에 남지 않고 결과가 보장되지 않는다는 점이 화면에 분명하길 바란다. 개인정보와 사행성 오해를 줄이기 위해서다.

## 완료 조건 (AC)

QA가 이 목록으로 테스트를 만든다. [E2E]는 Playwright, [단위]는 Vitest, [정적]은 문구나 파일 검사다. 2026-11-23 변경으로 바뀌거나 새로 붙은 번호는 AC-23~AC-26d, AC-29~AC-32, AC-31a, AC-35, AC-43이다. 기존 번호는 바꾸지 않고 뒤에 글자를 붙였다.

허브, 검색, 메뉴
- AC-1 [E2E]: `/lucky-draw`에 로그인 없이 들어가면 h1 "운빨 뽑기"(후보, 확정 필요), 세 도구 링크, 상시 오락 고지가 보인다.
- AC-2 [E2E]: 도구 페이지 세 곳(`/lucky-draw/ladder`, `/lucky-draw/roulette`, `/lucky-draw/lots`, 주소는 확인 2번)이 열리고, 각 페이지의 h1은 한 개다.
- AC-3 [단위]: 각 페이지의 title, description, canonical, og url, keywords가 `buildMetadata()` 결과와 같다. 직접 객체로 만들지 않는다.
- AC-4 [단위]: 서버가 보내는 HTML(클라이언트 렌더링 전)에 h1, 설명 문단, 사용 순서, FAQ 텍스트가 들어 있다.
- AC-5 [단위]: 페이지의 JSON-LD는 BreadcrumbList와 FAQPage뿐이다. 평점(aggregateRating, review)이 없다. FAQPage의 질문과 답은 화면 FAQ(접힌 답 포함)와 같다(text-slim 승인 2026-11-27).
- AC-6 [단위]: BreadcrumbList 이름은 도구 페이지마다 "홈 > 운빨 뽑기 > (도구 이름)"이다.
- AC-7 [정적]: `MENU_LIST`에 "운빨 뽑기" 그룹이 있고 항목은 세 개다. 출시 전에는 준비 중 상태이며, `/sitemap.xml`에 운빨 뽑기 주소가 없다. 출시 뒤에는 네 주소(허브와 도구 세 개)가 모두 있다.
- AC-8 [E2E]: 출시 상태에서 페이지 `robots`에 noindex가 없다.

사다리 타기
- AC-9 [E2E]: 참가자 1명이거나 11명 이상이거나 결과 줄 수가 참가자 줄 수와 다르면 "시작"이 비활성이고, 줄 수 차이를 알리는 안내가 보인다.
- AC-10 [E2E]: "시작"을 누르기 전에는 사다리 그림과 결과 글자가 화면과 DOM 어디에도 없다.
- AC-11 [단위]: 생성된 사다리의 모든 가로선은 이웃한 두 세로선만 잇는다. 같은 높이의 가로선끼리 겹치거나 옆 칸과 붙지 않는다.
- AC-12 [단위]: 생성된 결과는 참가자마다 서로 다른 결과 하나에 대응하는 일대일 배정이다.
- AC-13 [단위]: 10만 회 시뮬레이션에서 각 참가자가 각 결과에 도착하는 비율이 `1/n ± 4 × √(p(1−p)/N)` 안에 있다(허용 오차는 확인 6번).
- AC-14 [E2E]: 이름 하나를 고르면 경로가 한 줄씩 그려지고, 끝에 도착한 결과가 시작 전에 정한 배정과 같다.
- AC-15 [E2E]: 모든 이름의 경로를 확인하면 결과 전체가 참가자 줄 수만큼, 중복 없이 나온다.

돌림판
- AC-16 [E2E]: 항목이 1줄 이하이면 "돌리기"가 비활성이다. 2~28줄이면 "돌리기"가 켜진다. 29줄째는 추가되지 않고 안내가 보인다.
- AC-17 [E2E]: "돌리기"를 누르면 돌림판이 1.0초, 2바퀴로 돌고, 멈춘 뒤 결과 글자 영역에 멈춘 칸의 이름이 같은 시점에 나온다.
- AC-18 [E2E]: 회전 중에는 "돌리기"와 입력 변경이 막힌다.
- AC-19 [단위]: 칸 색과 강조색은 공용 돌림판 허용 토큰 목록 안에서만 나온다(칸 색 목록은 `docs/roulette-common/plan.md` 기준).
- AC-20 [E2E]: "뽑힌 항목 빼기"를 켜면 뽑힌 칸이 목록에서 빠지고, 다음 회전은 남은 칸만 대상으로 한다. 칸이 한 개 남으면 "돌리기"가 막히고, "처음부터"를 누르면 목록이 되돌아온다.
- AC-21 [E2E]: "뽑힌 항목 빼기"가 꺼져 있으면 뽑힌 항목이 목록에 그대로 남는다.

제비뽑기
- AC-22 [E2E]: 항목이 1줄 이하이면 "섞기"가 비활성이다. 2~30줄이면 켜진다. 31줄째는 추가되지 않고 안내가 보인다.
- AC-23 [E2E]: "섞기"를 누르기 전에는 카드와 항목 글자가 화면과 DOM에 없다. "섞기" 뒤 카드 수는 입력 줄 수와 같고, 모든 카드가 뒷면이며 항목 글자는 DOM에 없다.
- AC-24 [E2E]: "남은 카드 모두 열기"로 전부 열면 입력한 항목이 줄 수만큼 한 번씩 나온다(같은 이름은 여러 번 나올 수 있다).
- AC-25 [단위]: 카드 섞기 함수는 Fisher-Yates 방식이고, 카드 위치와 항목의 대응을 만든다. 항목 3개일 때 6가지 대응이 나오는 비율이 허용 오차(확인 6번) 안에서 같다.
- AC-26 [E2E]: "다시 섞기"는 입력 목록을 유지하고, 열린 카드 기록을 모두 지운 뒤 뒷면 카드 N장을 새로 섞는다. 입력 목록이 바뀌면 카드도 지워진다.
- AC-26a [E2E]: 열지 않은 카드를 누르면 그 카드의 항목 글자가 카드 자리에 나온다. 한 번 연 카드는 다시 누를 수 없고(비활성), 항목은 바뀌지 않는다.
- AC-26b [E2E]: "남은 카드 모두 열기"를 누르면 열지 않은 카드가 모두 열리고, 그 뒤 버튼이 비활성이다. 열린 카드 수는 0 이상 N 이하이며, 한 번 열린 카드는 줄지 않는다.
- AC-26c [E2E]: 카드를 열기 전에는 카드 위치와 항목의 대응이 화면과 DOM, `aria-label`, `data-*` 어디에도 없다. 열린 카드에는 그 카드의 항목 글자만 있고, 열지 않은 카드의 항목 글자는 DOM에 없다.
- AC-26d [단위]: 카드 한 장을 연 뒤에도 같은 세션에서 열지 않은 카드의 항목은 화면 상태에 없다. 상태 객체에 대응 목록 전체가 남지 않도록, 카드 열기 함수가 한 장의 항목만 내보낸다.

무작위와 예측 방지
- AC-27 [단위]: 사다리 생성, 돌림판 정지 칸, 카드 섞기의 모든 추첨은 `crypto.getRandomValues`로 얻은 값만 쓴다. 테스트에서 `Math.random` 호출이 0회다.
- AC-28 [단위]: 정수 뽑기는 거절 샘플링이다. 버려야 할 값을 주입하면 다시 뽑고, 버릴 범위의 경계 값(범위 바로 위 값 포함)에서도 치우침이 없다.
- AC-29 [E2E]: 사다리와 돌림판에서 결과가 정해지기 전("시작", "돌리기" 전)에는 강조, 결과 글자, `aria-label`, `data-*` 속성 어디에도 결과 정보가 없다. 제비뽑기는 AC-26c가 같은 원칙을 카드 기준으로 검사한다.

결과 공개 방식
- AC-30 [E2E]: 사다리의 기본 공개 방식은 "일괄 공개"다. 사다리는 "일괄 공개, 결과 가리기, 한 명씩 열기" 세 옵션이, 돌림판은 "일괄 공개, 결과 가리기" 두 옵션이 보인다. 제비뽑기에는 공개 방식 선택이 없고, "섞기" 뒤 카드 열기와 "남은 카드 모두 열기" 버튼만 보인다("결과 가리기" 옵션 없음).
- AC-31 [E2E]: 사다리에서 "결과 가리기"를 켜면 결과 글자가 DOM에 없고, "결과 보기"를 누르면 한꺼번에 보인다. 돌림판에서 "결과 가리기"를 켜면 회전 전과 회전 후 모두 칸 글자와 강조 칸이 DOM에 없고, "결과 보기"를 누르면 칸 글자, 강조 칸, 결과 글자가 함께 보인다.
- AC-31a [E2E]: 돌림판 "결과 가리기"로 회전을 끝낸 뒤 "결과 보기" 전에는, 화면과 DOM에 입력한 항목 글자가 하나도 없고 강조 칸도 없다. 그래서 멈춘 자리만 보고는 항목 이름을 알 수 없다. 이 AC는 두 조건(항목 글자 0개, 강조 속성 0개)만 검사한다. 바늘이 어느 칸에 서는지는 막지 않는다(확인 항목 21번).
- AC-32 [E2E]: 사다리의 "한 명씩 열기"에서는 누른 이름의 결과만 DOM에 있다. 나머지 결과는 DOM에 없다. 제비뽑기의 한 장씩 열기는 AC-26c가 검사한다.

저장과 개인정보
- AC-33 [E2E]: 입력 목록, 옵션, 결과는 localStorage, sessionStorage, 쿠키, 주소(URL)에 저장되지 않는다. 입력 후 세 도구를 모두 조작한 뒤 각 저장소와 주소를 검사한다.
- AC-34 [E2E]: 새로고침하면 입력 목록과 결과가 비어 있다.
- AC-35 [E2E]: 도구를 쓰는 동안 입력한 이름 문자열이 어떤 네트워크 요청의 주소나 본문에도 없다. 뽑기 이벤트, 카드 열기 이벤트, 공개 방식 변경 이벤트는 분석으로 보내지 않는다.
- AC-36 [E2E]: 쿠키 동의를 거절해도 세 도구가 모두 동작한다.
- AC-37 [E2E]: 위치 권한 요청이 뜨지 않는다.

고지와 문구
- AC-38 [E2E]: 각 도구 페이지 h1 바로 아래에 상시 오락 고지가 보인다(문구는 법적·정책 요구사항 장의 "고지 문구", 사용자 승인 뒤 확정).
- AC-39 [E2E]: 결과 영역 하단에 짧은 보상 무관 고지가 보인다.
- AC-40 [정적]: 화면, 메타, FAQ, 약관 신규 문장에 금지어가 없다. 금지어 목록은 법적·정책 요구사항 장에 있다. 부정형 "보장", "보상"(예: "보장하지 않습니다", "보상과 무관합니다")은 정확한 문장 목록 안에서만 허용한다. 목록은 상시 고지, 결과 하단 고지, 네 페이지 meta description, 약관 신규 장 문장이다(S-4 A). 목록 밖 문장의 "보장", "보상"은 금지한다.
- AC-41 [정적]: 결과 영역에 가격, 칼로리, 별점, 후기, 음식 평가가 없다.
- AC-42 [정적]: 입력 안내와 예시에 개인 연락처나 주소를 넣으라는 문구가 없고, 아동 이름 입력을 권하는 문구가 없다.

접근성과 모바일
- AC-43 [E2E]: 키보드만으로 입력, "시작", "돌리기", "섞기", "다시 섞기", 카드 열기, "남은 카드 모두 열기", 공개 방식 선택(사다리, 돌림판), "결과 보기", 사다리 이름 고르기를 할 수 있다.
- AC-44 [E2E]: 돌림판 결과 글자는 스크린리더가 읽는 영역(라이브 영역)에 한 번 나온다.
- AC-45 [E2E]: 동작 줄이기를 켜면 사다리 경로와 돌림판 회전이 없이 바로 결과가 보인다. `onSpinEnd`는 한 번만 불린다.
- AC-46 [E2E]: 320px 화면에서 가로 스크롤이 생기지 않고, 사다리 10명 입력 때도 결과가 보인다. 줄여 보이는 이름은 전체 이름을 읽을 수 있다.
- AC-47 [E2E]: 결과 버튼과 결과 영역 안에는 광고 영역이 없다. 광고가 로드되지 않아도 세 도구가 동작한다.

법적 문서
- AC-48 [정적]: `/terms`에 "운빨 뽑기" 장이 있고 오락 목적, 무작위 결과, 보장 없음, 보상 없음, 외부 링크가 없음(로또 연결 없음)을 말한다. 장 번호는 1부터 끝까지 연속이다. 제비뽑기 설명 문장은 카드 방식으로 쓴다.
- AC-49 [정적]: `/privacy`는 바꾸지 않는다. 입력은 화면 메모리에만 있다는 기존 문구와 맞는지 확인한다.
- AC-50 [정적]: `COMPLIANCE.md`에 운빨 뽑기 항목이 추가되었고, 법률 검토 상태가 "위험 수용"으로 적혀 있다(출시 전 반영).

## 예외·빈 상태

- 입력 줄이 없거나 공백만 있으면 "시작", "돌리기", "섞기"를 막고 "두 개 이상 입력하세요" 안내를 보인다.
- 앞뒤 공백은 지우고, 빈 줄은 무시한다.
- 상한을 넘는 줄은 추가하지 않고 "최대 N개까지 입력할 수 있어요" 안내를 보인다(N은 확인 5번).
- 한 줄의 글자 수가 상한(15자, 확인 5번)을 넘으면 추가하지 않고 안내한다.
- 같은 이름이 여러 줄이면 각각 따로 취급한다.
- 돌림판에서 "뽑힌 항목 빼기"를 켜고 칸이 한 개 남으면 "돌리기"를 막는다. 모두 빠지면 "처음부터"로 되돌린다.
- 사다리 참가자가 1명이면 사다리를 만들지 않고 안내한다.
- 제비뽑기: "섞기" 전에는 카드 자리 대신 안내 문장만 보인다. 카드를 모두 열면 "남은 카드 모두 열기"를 비활성하고 "모든 카드를 열었어요" 안내를 보인다.
- 연출 중에는 모든 조작을 막는다. 연출이 끝나면 다시 쓴다.
- 새로고침하면 입력과 결과가 모두 사라진다. 정상 동작이다.
- JavaScript가 꺼져 있으면 설명, 사용 순서, FAQ, 고지는 서버 HTML로 보이고, 도구 영역에는 안내 문구가 보인다.
- 광고 차단이나 광고 로드 실패는 도구 동작에 영향을 주지 않는다.
- 동작 줄이기: 회전과 경로 연출 없이 바로 결과를 보인다.

## 검색 노출

- 키워드(후보, 사용자 조회 후 확정. 검색량 수치는 아직 없다)
  - 허브: 운빨 뽑기, 랜덤 뽑기 도구
  - 사다리: 사다리타기, 사다리 게임, 사다리타기 온라인, 사다리 타기 당번, 당번 정하기(제안, 확인 항목 19번)
  - 돌림판: 돌림판, 돌림판 돌리기, 랜덤 돌림판(룰렛 돌리기는 확인 11번 전까지 제목에 쓰지 않는다)
  - 제비뽑기: 제비뽑기, 카드 뽑기, 랜덤 뽑기(후보). "순서 정하기", "발표 순서 정하기", "당번 정하기"는 제비뽑기 키워드에서 뺀다(제안, 확인 항목 19번)
- 제외 키워드: 사다리 내기, 내기 룰렛, 벌칙 내기(금전 내기 의도), 로또 번호(로또 페이지와 겹치고 사행 연상), 메뉴 추천, 오늘 뭐 먹지(`/meal`과 겹침), 룰렛 돌리기 단독(`/meal`과 경쟁).
- 페이지가 답할 질문
  - 허브: 운빨 뽑기에는 어떤 도구가 있나? 입력한 이름은 저장되나? 결과가 보장되나?
  - 사다리: 사다리 타기는 몇 명까지 되나? 결과는 어떻게 정해지나? 결과를 미리 볼 수 있나?
  - 돌림판: 항목마다 뽑힐 확률이 같은가? 뽑힌 항목을 빼고 다시 돌릴 수 있나? 결과 가리기를 켜면 바늘만 보고 결과를 알 수 있나?
  - 제비뽑기: 카드는 어떻게 섞이나? 카드를 열면 무엇이 나오나? 다시 섞으면 이전에 연 카드는 어떻게 되나? 순서 정하기에 쓸 수 있나?
- 제목과 설명: 초안은 만들지 않는다. 최종 문구는 사용자 승인 뒤 `buildMetadata()`로 넣는다. 설명에는 "오락 목적"과 "보장 없음"을 넣는다.
- FAQ(서버 렌더링, 화면에 있는 것(접힌 답 포함)만 JSON-LD에 넣는다): 도구마다 3~4개. 예: "입력한 이름은 저장되나요?", "결과는 어떻게 정해지나요?", "몇 명까지 할 수 있나요?". 제비뽑기 예: "카드는 어떻게 섞이나요?", "한 번 연 카드를 다시 열 수 있나요?"
- 구조: 허브와 도구별 페이지 세 개(확인 1번). 도구 페이지마다 h1은 하나이고, 도구 이름을 담는다.
- 주소는 소문자와 하이픈이다. 새 주소이므로 301은 필요 없다.
- 돌림판 페이지는 메뉴와 음식 단어를 쓰지 않는다. 항목 예시도 "A, B, C" 같은 일반 단어를 쓴다. `/meal`과 같은 검색 의도로 읽히지 않게 한다.
- 가게 정보, 평점, 리뷰를 담은 구조화 데이터는 쓰지 않는다.
- 이미지는 OG 이미지 하나만 둔다. 음식 사진, 외부 그림은 쓰지 않는다.
- 출시 전에는 준비 중 상태이므로 사이트맵에서 빼고, 출시 때 넣는다(`seo.md`).

## 법적·정책 요구사항

개인정보 수집
- 수집: 참가자 이름과 항목 텍스트를 입력받는다. 입력값은 화면 메모리에만 있고, 서버로 보내지 않고, 저장하지 않는다. localStorage, sessionStorage, 쿠키, URL에 넣지 않는다. 분석 이벤트(뽑기, 카드 열기, 입력, 공개 방식)도 보내지 않는다.
- 위치는 묻지 않는다. 기존 방침의 수집 항목과 저장 문구는 바꾸지 않는다(확정 3번).
- Vercel Web Analytics는 페이지 경로만 기록한다. 도구 경로에는 입력값이 없으므로 기존 방침으로 충분하다.
- 학생 명단이나 아동 이름은 대상으로 하지 않는다. 안내 문구로도 권하지 않는다(확인 10번).
- 14세 미만 연령 게이트는 두지 않는다. 입력이 화면 메모리에만 남고 사행 요소가 없다는 판단이다. 법률 검토는 위험 수용이다(아래).

고지 문구 (초안, 사용자 승인 뒤 확정. 이 문장들의 대략적 형식은 `COMPLIANCE.md` 11장 타로 항목을 따른다)
- 상시 고지(h1 바로 아래): "이 도구는 오락 목적으로 제공됩니다. 결과는 무작위로 정해지며, 추천이나 평가가 아니고 어떤 결과도 보장하지 않습니다."
- 결과 하단 고지: "결과는 금전, 상품, 포인트, 경품 등 어떤 보상과도 관련이 없습니다."
- 입력란 안내: "입력한 내용은 서버에 보내지거나 저장되지 않으며, 화면을 새로고침하면 사라집니다. 전화번호, 주소처럼 개인을 알아볼 수 있는 정보는 넣지 마세요."
- "보상", "보장"이 들어간 부정형 문장은 예외 목록(상시 고지, 결과 하단 고지, 네 페이지 meta description, 약관 신규 장 문장)에 있는 정확한 문장으로만 쓴다. 목록 밖에서는 쓰지 않는다(S-4 A).

금지어 (정적 검사, AC-40)
- 사행 연상: 내기, 배팅, 베팅, 판돈, 걸고, 복권, 로또, 사행, 상금, 당첨, 추첨(화면 문구에서는 "결과"를 쓴다. 확인 9번)
- 금전 연상: 돈(단어 단위로 검사하고, "돈까스" 같은 메뉴 이름은 예외), 밥값, 커피값, 쏘기
- 보장과 평가: 반드시, 무조건, 보장·보상(부정형은 예외 목록 안에서만, S-4 A), 확실, 100%, 최고, 대박, 인기, 베스트, 1위, 추천합니다, 추천 메뉴
- 광고: 광고
- 벌칙 문구(예: 설거지 담당)는 허용한다(확인 9번).

공정성 설명 (확인 8번)
- 화면에는 검증할 수 있는 문장만 쓴다. 예: "칸 크기가 같아 각 항목이 뽑힐 확률은 같습니다", "사다리는 시작을 누른 뒤, 카드 순서는 섞기를 누른 뒤 무작위로 정합니다".
- "암호학적 난수" 같은 표현은 쓰지 않는다. 난수는 내부 규칙(AC-27)으로만 보장한다.

사행성 오인 (법률 검토는 위험 수용, 확정 4번)
- 재물 모으기 요건(리서치 7-1절 (가))이 없다. 참가비, 상품, 포인트, 경품을 붙이지 않는다.
- 칸별 확률(가중치)을 1차에서 뺀다(확인 4번).
- 로또 페이지와 연결하는 링크를 두지 않는다(확인 15번).
- 벌칙 문구는 돈이나 음식 내기 표현 없이 쓴다.

광고 정책 (카카오 AdFit)
- 수익은 AdFit 광고만 쓴다. 제휴 링크, 쇼핑 링크, 음식점 광고, 외부 판매 연결을 넣지 않는다.
- AdFit 운영정책은 사행성 콘텐츠를 금지한다. 출시 전에 "뽑기", "추첨", "내기" 계열 단어로 심사에서 걸리지 않는지 확인한다(출시 전 체크). 제비뽑기와 카드 뽑기의 "뽑기"도 이 확인 대상에 든다.
- 광고는 결과 버튼과 결과 영역 주변에 두지 않는다(AC-47).

저작권과 상표
- 사다리 타기, 돌림판, 제비뽑기는 일반 규칙이다. 규칙 설명, 화면 구성, 칸 디자인, 문구는 직접 쓴다. 다른 사이트의 설명 문장과 구성을 옮기지 않는다(리서치 7-4절).
- 외부 아이콘, 이미지, 폰트를 쓰면 라이선스를 확인하고 `THIRD_PARTY_NOTICES.md`에 적는다. 새 라이브러리를 추가하지 않는 것을 목표로 한다.
- 항목 예시에 특정 상표나 프랜차이즈 이름을 쓰지 않는다.

약관과 방침
- `/terms`에 "운빨 뽑기" 장을 새로 쓴다. 오락 목적, 무작위 결과, 보장 없음, 보상 없음, 입력 미저장, 외부 링크 없음을 말한다(AC-48). 출시 전에 승인받는다.
- `/privacy`는 바꾸지 않는다(확정 3번). 기존 문구와 맞는지만 확인한다(AC-49).
- `COMPLIANCE.md` 11장에 항목을 추가한다(AC-50). 1장의 개인정보 항목은 입력 메모리 원칙을 따른다는 한 줄을 추가할지 출시 전에 정한다.

법률 검토
- 사행성 해석, 화면 구성 저작권, 약관·방침 문구는 위험 수용(2026-11-23 확정)으로 기록한다. 출시 후 확인할 일로 남긴다.

상업적 이용
- 수익은 AdFit 광고뿐이다. 입력값이나 결과로 광고 노출을 바꾸지 않는다. 광고가 도구를 가리지 않는다.

출시 전 체크(비법률)
- 고지 문구 최종 확인, 금지어 검사 통과, AdFit 심사 확인, 약관과 COMPLIANCE.md 반영, 사이트맵 등록, 준비 중 상태 해제.

## 사용자 확인 필요

확정 항목(확인 불필요, 이 문서에 반영함): 이름은 메모리에만 저장(확정 3번), 1차 공유 없음(확정 4번), 결과 공개 기본은 일괄 공개이고 가리기와 한 명씩 열기를 옵션으로 둠(확정 5번), 법률 검토는 위험 수용(확정 16번). 단, 확정 5번 중 제비뽑기 공개 옵션은 2026-11-23 변경으로 카드 열기로 바뀌었다(변경 기록). 돌림판 결과 가리기에서 칸 글자를 숨기는 것은 2026-11-23 사용자 결정으로 확정했다.

아래는 확인 전 13개 중 기획안이 있는 항목과 이번 기획에서 추가로 찾은 항목이다. 권장안이 기본으로 들어가 있다.

1. 페이지 구조 (확인 전 1번): 허브 + 도구별 페이지 세 개(B안). 권장: B. 근거: 도구마다 제목, 설명, FAQ를 따로 줄 수 있고, `/tarot/*`, `/fortune/*` 구조와 같다.

2. 주소 이름 (확인 전 2번): 허브 `/lucky-draw`, 도구 `/lucky-draw/ladder`, `/lucky-draw/roulette`, `/lucky-draw/lots`. 권장: 영문 짧은 말. 대안: 제비뽑기 주소를 `/lucky-draw/cards`로 바꾸면 로또 연상이 줄어든다. 확인 필요.

3. 재추첨 (확인 전 6번): 돌림판에 "뽑힌 항목 빼기" 옵션(기본 꺼짐), 제비뽑기에는 "다시 섞기". 근거: 순서 정하기에 맞추면서 리서치 3절의 "중복 없이 뽑기" 관례를 따른다. 제비뽑기 기본은 한 번 섞은 전체 순서이므로 중복이 없다. 기본값(돌림판 꺼짐)이 맞는지 확인 필요. (2026-11-23 변경: 제비뽑기는 카드 방식이므로 항목은 중복 없이 한 번씩 나온다. "다시 섞기"는 열린 기록을 지우는 전체 초기화다.)

4. 가중치 1차 제외 (확인 전 7번): 권장: 제외. 근거: 칸 크기별 확률을 화면에 밝혀야 하고, 돌림판 API 확장이 필요하며, 사행성 오인이 커진다. 1차 제외로 확정할지 확인 필요.

5. 인원·항목 한계 (확인 전 8번, 숫자 제안)
   - 사다리 참가자 2~10명. 근거: 경쟁 서비스 상한은 2~10명(mangul, moamoang), 2~20명(teck-tani), 2~30명(cora), 2~100명(playcloud8)으로 흩어져 있다. 10명을 넘으면 320px 화면에서 열 폭이 약 29px 이하로 줄어 이름을 읽기 어렵다(320 − 좌우 여백 32 = 288, 288 ÷ 10). 320px 실측은 설계 단계에서 확인한다.
   - 돌림판 항목 2~28개. 근거: 공용 돌림판은 28개 이하에서만 칸 글자를 보여 준다. 29개부터 글자가 숨는다(`docs/roulette-common/plan.md`).
   - 제비뽑기 항목 2~30개. 근거: 카드 수가 화면 한 줄에 넣기 어려운 수준이 되지 않게 잡았다. 경쟁 서비스 근거는 찾지 못했다(확인 필요). 카드 방식으로 바뀌어도 상한은 그대로 둔다.
   - 항목 한 줄 최대 15자(제안). 근거: 사다리 열 폭과 돌림판 칸에서 한 줄로 읽히는 길이. 설계와 화면 확인 뒤 조정할 수 있다.

6. 분포 검증 허용 오차 (확인 전 17번, 숫자 제안): 시행 10만 회, 각 결과 비율이 `1/n`에서 4 표준편차 안이면 통과. 허용 오차는 n=2 ±0.63%p, n=4 ±0.55%p, n=6 ±0.47%p, n=10 ±0.38%p다. 근거: 표준편차는 √(p(1−p)/N)이다. 4 표준편차면 한 번 검사가 우연히 실패할 확률이 칸마다 약 0.006%로 작다(정규 근사). 난수가 암호용이라 시드를 고정할 수 없으므로 허용 오차가 필요하다. 3개 항목 순열 검사(AC-25)도 같은 기준을 쓴다. 확인 필요.

7. 결과 예측 방지 (확인 전 11번): 기획 AC에 넣었다(AC-10, AC-23, AC-26c, AC-29, AC-31, AC-31a, AC-32). 사다리 그림은 "시작" 뒤에 만들고, 카드는 "섞기" 뒤에만 보이며 항목은 카드를 열어야 보인다. 한계: 사다리 그림을 따라가면 결과가 보이는 것은 사다리 방식 자체라 막지 않는다. 확인 필요.

8. 공정성 설명 문장 (확인 전 12번): 검증 가능한 문장만 화면에 쓴다. "암호학적 난수" 표현은 쓰지 않는다. 확인 필요.

9. 벌칙 문구와 금지어 (확인 전 9번): 벌칙(예: 설거지 담당) 허용. 돈, 밥값, 쏘기, 내기 표현 금지. 추가 제안: 화면에서 "당첨", "추첨"을 쓰지 않고 "결과"를 쓴다(사행 연상 회피). "돈"은 단어 단위 검사로 메뉴 이름 예외를 둔다. 확인 필요.

## 변경 기록 (2026-11-23, 구현 후 사용자 피드백)

결정 1. 돌림판 "결과 가리기": 칸 글자까지 숨긴다(design S-2 A 확정 유지, 범위 확장)
- 바뀐 점: 결과 가리기를 켜면 회전 전과 회전 후 모두 칸 글자와 강조 칸을 그리지 않는다. "결과 보기"를 누르면 칸 글자, 강조 칸, 결과 글자가 함께 나온다. 이전에는 강조 칸과 병뚜껑 글자만 숨겼다.
- 이유: 바늘이 당첨 칸에 서고 칸 글자가 그대로 보이면 멈춘 자리만 봐도 결과를 알 수 있었다.
- AC 변경: AC-31(돌림판 칸 글자와 강조 칸 조건 추가), AC-31a 신설(멈춘 자리로 결과를 알 수 없음, DOM 항목 글자 0개와 강조 속성 0개로 검증), AC-29(사다리와 돌림판 기준으로 범위 정리), AC-30(돌림판 옵션 두 개 유지).
- 공용 영향(`docs/roulette-common/`): `isResultHidden`(기본값 false)이 칸 글자와 강조 칸까지 숨기도록 규칙이 넓어진다. 기본값이 false이므로 메뉴 룰렛(`/meal`)은 prop을 넘기지 않아 화면이 그대로다. 단 `docs/roulette-common/plan.md`에는 이 규칙이 아직 없다. 규칙 한 절을 추가해야 하며, 이 기획에서는 그 문서를 고치지 않는다. 회귀는 `unit/shared/roulette.test.ts`(`isResultHidden` 경우 추가)와 `e2e/meal.spec.ts`로 확인한다.
- 한계: 바늘 위치로 칸 번호를 세는 추측은 막지 않는다(확인 21번).

결정 2. 제비뽑기: 이름 목록 섞기에서 카드 한 장 뽑기로 바꾼다
- 바뀐 점: 입력 항목 수만큼 뒷면 카드를 섞어 놓고, 사용자가 카드를 한 장씩 연다. 한 번 연 카드는 다시 열 수 없다. "남은 카드 모두 열기"와 "다시 섞기"(전체 초기화) 버튼을 둔다. 공개 방식 선택은 없앤다.
- 이유: 이름 목록을 섞어 순서를 보여 주는 방식은 사다리와 거의 같았다. 사다리는 이름에 결과를 짝짓는 도구, 제비뽑기는 항목을 한 장씩 뽑는 도구로 역할을 나눈다.
- AC 변경: AC-23, AC-24, AC-25, AC-26 수정. AC-26a, AC-26b, AC-26c, AC-26d 신설. AC-29 범위 정리. AC-30(제비뽑기 옵션 제외), AC-32(사다리 전용으로 한정), AC-35(카드 열기 이벤트 추가), AC-43(카드 조작 추가).
- 검색과 문구: 제비뽑기 키워드에서 "순서 정하기", "발표 순서 정하기", "당번 정하기"를 뺀다(확인 19번). 사다리 쪽으로 옮길 후보는 "당번 정하기"다. 문구 영향은 "문구 영향 목록" 절에 적었다.
- 다시 작업할 하위 문서(승인 뒤 PM이 지시): `design.md`의 제비뽑기 절과 `lots` 상태 모델, `ui-ux-design.md`의 제비뽑기 화면 전체(카드 배치, 열린 카드, 버튼)와 돌림판 가리기 상태(칸 글자 숨김 반영), `dev-tasks.md`의 제비뽑기 티켓, `qa-report.md`. 구현 쪽은 `src/features/lucky-draw/lots/`, `src/app/lucky-draw/`, `unit/lucky-draw/`, `e2e/lucky-draw.spec.ts`를 고친다. 이미 구현된 제비뽑기 코드는 이 변경과 맞지 않으므로 다시 만든다.

결정 3. 나머지는 바꾸지 않음
- 사다리 공개 방식 세 가지, 돌림판 "뽑힌 항목 빼기", 한계(사다리 2~10명, 돌림판 2~28개, 제비뽑기 2~30개, 한 줄 15자), 분포 허용 오차, 법적 고지와 금지어, 메뉴 등록과 준비 중 상태는 그대로다.
