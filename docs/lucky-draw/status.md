## 결정 기록 (리서치 11절 질문 번호 기준)

사용자가 확정한 것:

- 질문 3 이름 저장: 브라우저 메모리에만 둔다. 새로고침하면 사라진다. 방침 수정 없음.
- 질문 4 공유: 1차에는 공유 기능을 넣지 않는다. 나중에 결과 이미지 저장을 추가할 수 있다.
- 질문 5 결과 연출: 기본은 일괄 공개, 옵션으로 결과 가리기와 한 명씩 열기. (2026-11-23 변경: 제비뽑기 옵션은 카드 열기로 대체. 아래 참고)
- 질문 16 법률 검토: 위험 수용. 사행성 해석, 화면 저작권, 아동 개인정보는 출시 후 확인할 일로 기록한다.
- 2026-11-23: plan.md "사용자 확인 필요" 17개를 모두 권장안대로 승인. 새 색 토큰 `menu-lucky`(`design-system.md`, `globals.css` 변경)는 설계 단계에서 S-1 A로 승인. 값은 ui-ux-design에서 제안하고 개발 단계에서 반영한다.
- 2026-11-23: design.md S-1~S-6을 모두 권장안(A)으로 확정하고 설계 승인.
- 2026-11-23: ui-ux-design.md U1~U3을 모두 권장안으로 확정하고 UI/UX 승인. U1 섞기 연출 없음, U2 종이색 번갈이 + 강조만 `menu-lucky`, U3 `#4b4690`.
- 2026-11-23 (구현 후 사용자 피드백 1): 돌림판 "결과 가리기"는 칸 글자와 강조 칸까지 숨긴다. 회전 전과 회전 후 모두 적용하고, "결과 보기"를 누르면 함께 나온다. 이유: 바늘이 당첨 칸에 서고 칸 글자가 보이면 멈춘 자리만 봐도 결과를 알 수 있었다. 설계 S-2 A의 `isResultHidden`을 이 범위로 넓힌다. 공용 기본값은 false이므로 메뉴 룰렛은 바뀌지 않는다. `docs/roulette-common/plan.md`에 규칙 추가가 필요하다.
- 2026-11-23 (구현 후 사용자 피드백 2): 제비뽑기를 "카드 한 장 뽑기"로 바꾼다. 항목 2~30개를 입력하면 뒷면 카드 N장을 Fisher-Yates로 섞어 놓고(카드에는 번호만), 사용자가 카드를 한 장씩 열어 항목을 뽑는다. 한 번 연 카드는 다시 못 연다. "남은 카드 모두 열기"와 "다시 섞기"(전체 초기화) 버튼을 둔다. 공개 방식 선택(결과 가리기, 한 명씩 열기)은 제비뽑기에서 없앤다. 역할 구분: 사다리는 이름에 결과를 짝짓는 도구, 제비뽑기는 항목을 한 장씩 뽑는 도구. 제비뽑기 키워드 "순서 정하기", "발표 순서 정하기", "당번 정하기"는 사다리 쪽이나 FAQ로 옮길지 열린 질문 19번으로 올렸다.
- 2026-11-23 (피드백 2 후속): plan.md 열린 질문 18~22번 신설(제비뽑기 공개 방식 정리, 키워드 이동, 카드 번호 표시, 칸 위치 추측 한계, 결과 보기 전 다시 돌리기). 사용자 승인 전이다.
- 2026-11-23 (UI/UX 변경 반영): 열린 질문 18~22번을 plan 권장안으로 `docs/archive/lucky-draw/ui-ux-design.md`에 반영했다(사용자 승인 전). 돌림판 가림 시각 처리는 점선 고리, 눈 가림 아이콘 문장, 공개 방식 설명 한 줄. 제비뽑기 카드 격자는 320px 3열, 열기 모션 0.2초, "남은 카드 모두 열기"는 즉시. 신규 선택지 U4(다시 섞기 버튼 위치).
- 2026-11-23 (설계 변경 반영): `docs/archive/lucky-draw/design.md`를 개정했다(사용자 승인 전). S-2 B 확정 반영, 제비뽑기 카드 방식 상태·리듀서·컴포넌트·테스트 구조, 확인 18~22번 권장안 확정. 확인 21번 관련: 칸 수가 홀수면 마지막 `fill-muted` 칸이 기준점이 되어 칸 수 세기 추측이 가능하다는 점을 ui-ux 확인 항목으로 넘겼다(3.4).
