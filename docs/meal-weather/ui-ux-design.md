입력: `docs/meal-weather/plan.md`(승인), `docs/meal-weather/design.md`(승인. DQ1~DQ4 권장안 A로 확정: 서버 메모리 캐시, 02시 발표 기준, 가중치 3, 보통 날씨에도 날씨 자료를 썼으면 출처·정확도 문구 표시)
기준 화면: `docs/archive/meal-location/ui-ux-design.md`, 현재 코드 `src/features/meal/roulette/components/` (`root`, `filter-panel`, `area-input`, `result`, `map-links`)

이 문서는 기존 `/meal` 화면에 "날씨 패널 한 곳"과 "결과 카드 안 날씨 안내 한 곳"을 더하는 변경만 정한다. 돌림판, 끼니 선택, 필터, 동네 입력, 지도 링크, 공유 영역의 모양은 바꾸지 않는다. 새 토큰, 새 폰트, 새 shadcn 컴포넌트, 새 아이콘 묶음은 없다. 아이콘은 이미 쓰는 `lucide-react`에서만 가져온다.

## 디자인 방향

한 줄 요약: 연구 노트의 "관측 조건" 칸. 오늘 날씨를 장식 없이 한 줄로 적고, 그 자료가 어디서 왔고 틀릴 수 있다는 점을 같은 자리에서 읽히게 한다.

- 이유: 이 기능은 룰렛의 확률을 조금 기울일 뿐이고 결과는 여전히 무작위다. 화면이 날씨 기능을 크게 말하면 "날씨에 맞는 메뉴를 알려 준다"로 읽혀 plan Q1(추천 표현 금지)과 부딪힌다. 그래서 조용하게 두고, 정보의 정직함(출처, 정확도, 켜고 끄기)에만 힘을 쓴다.
- 기억에 남는 한 곳: **결과 카드의 날씨 한 줄 앞에 붙는 작은 날씨 아이콘(눈·비·더움·추움 4종).** 줄 문장이 말하는 날씨를 한눈에 알려 주고, 날씨가 없거나 보통일 때는 아예 없어서 "오늘은 날씨가 반영됐다"는 신호 역할을 한다. 나머지는 기존 종이색과 먹물 글자다.
- 날씨 패널은 `menu-meal` 색을 쓰지 않는다. 이유: 메뉴 색은 선택 상태와 강조에만 쓰고, 조작 컨트롤은 기본 컨트롤 색을 따른다는 규칙(동네 입력과 같은 판단).

디자인 계획 점검 (기본값으로 흐르던 부분을 바꾼 기록)

| 처음 떠올린 안 | 왜 버렸나 | 바꾼 결정 |
|---|---|---|
| 날씨 위젯 카드(큰 아이콘, 온도 크게, 그라데이션) | 숫자 표시는 범위 밖이고, 큰 날씨 카드는 결과보다 날씨가 주인공처럼 보인다 | 아이콘 20px 하나와 문장 한 줄만 쓴다 |
| 지역 칩 17개를 한 줄로 나열 | 시·도가 많아 모바일에서 세로로 길어지고 끼니·카테고리 칩과 같은 모양이라 섞인다 | 선택 상자(Select) 하나. 칩은 "여러 개 고르는 필터", 선택 상자는 "하나 고르는 값"으로 모양을 나눈다 |
| 위치 핀 아이콘, "내 지역 찾기" | 위치 기능으로 읽힌다(plan 범위 밖) | 아이콘 없이 글자 라벨 "날씨 지역"만 쓴다 |
| 날씨 고지 전체를 접는 "더 보기" | 날씨 지역이 서버로 간다는 사실(안내 1)은 접으면 안 되는 고지다(방침 변경 사유) | 안내 1은 항상 보인다. 안내 2(스위치 설명)만 기존 `CollapsibleComponent`로 접는다(UW-2 확정) |
| 날씨 줄에 눈·비 애니메이션(내리는 입자) | 사용자 행동과 상관없는 장식 모션이고 결과 확인을 방해한다 | 정지 아이콘만 쓴다 |
| 켜짐/꺼짐을 스위치 모양에만 의존 | 꺼짐 상태의 스위치 바탕(`input`)은 카드 위 대비가 약 1.5:1이다 | 스위치 옆에 "켜짐/꺼짐" 글자를 같이 쓰고, 꺼짐 상태 테두리를 `muted-foreground`로 올린다 |

## 간격·그리드

- 4px 눈금. 날씨 패널은 필터 묶음의 세 번째 항목으로 들어가고 기존 묶음의 `space-y-4`(16px)를 그대로 쓴다. 이유: 끼니 → 카테고리·국물 → 날씨가 모두 "뽑기 전 조건"이라 한 흐름으로 읽혀야 하고, 간격이 같아야 다른 사이트처럼 보이지 않는다.
- 패널 안: 라벨과 컨트롤 사이 8px(`mb-2`), 컨트롤과 안내 문장 사이 8px. 접는 안내는 스위치 행 아래 8px에서 시작한다.
- 컨트롤 높이 44px(`h-11`), 반경 `rounded-lg`(버튼·입력 규칙), 안쪽 좌우 여백 12px. 이유: 동네 입력란과 칩이 모두 44px이고 터치 영역 기준이 같다.
- 폭
  - 모바일(640px 미만): 선택 상자와 스위치 행 모두 폭 전체.
  - 640px 이상: "내 지역" 제목 하나 아래 입력 두 개(왼쪽 시·도 선택 "날씨 지역", 오른쪽 동네 이름 입력)를 2열(`grid sm:grid-cols-2 sm:gap-6`, 위쪽 맞춤)로 나란히 둔다. 그 아래 줄에 한 줄 안내, 다음 줄에 스위치 행(`sm:max-w-sm`)과 접는 안내 2. 이유: 두 입력이 모두 "내 지역"을 묻는 짧은 입력이라 한 묶음으로 읽히고, 동네 이름을 돌림판 아래에서 위로 올려 세로 길이를 줄인다. 모바일은 세로 한 열. 입력은 둘로 유지한다(시·도는 서버로 가고 동네 이름은 안 가는 약속이 달라서 합치지 않는다).
- 결과 카드 안: 기존 카드의 `space-y-5`를 따른다. 날씨 블록 안 줄 간격은 8px(`space-y-2`).

## 화면별 레이아웃

### 오늘 뭐 먹지 (`/meal`)

머리 영역, 끼니 스위치, 카테고리·국물, 돌림판, 동네 입력, 결과 카드, 지도 링크, 공유 영역의 순서와 모양은 그대로다. 달라지는 곳은 두 곳이다.

1. 필터 묶음(root의 첫 `space-y-4` 묶음) 맨 아래, 돌림판 위에 "내 지역" 묶음(`<fieldset>` + `<legend>` "내 지역")이 들어간다. 동네 이름 입력은 돌림판 아래에서 이 묶음 안으로 옮겼다(기능·지도 검색어 동작은 그대로).
2. 결과 카드 안, 운세 인용 블록 아래·지도 묶음 위에 "날씨 안내"가 들어간다.

스위치 행은 라벨이 행 안에 있고 행 위에 별도 제목이 없다.

- DOM 순서 = 시각 순서 = 탭 순서. 끼니 → 카테고리 칩 → 국물 → (후보 0개일 때) 국물 조건 없애기 → 날씨 지역 선택 상자 → 날씨 반영 스위치 → **날씨 반영 안내 트리거(접는 안내)** → 룰렛 돌리기 → 동네 입력란 → 동네 입력 안내 트리거 → (값이 있을 때) 지우기 → 지도 링크 3개. CSS `order`로 바꾸지 않는다.
- AC-6은 "날씨 지역 → 날씨 스위치 → 룰렛 돌리기 → 지도 링크" 순서로 닿을 수 있어야 한다는 조건이라 그 순서는 지켜진다. 다만 스위치와 룰렛 돌리기 사이에 탭 정지점이 하나 늘어난다. Tab 횟수를 세는 테스트는 깨지므로 QA는 포커스 대상 확인으로 작성한다(해당 검사에 닿는 순서만 확인).
- 스위치 행은 `Label`이 행 전체를 감싸고 `htmlFor`로 스위치와 연결한다. 이유: 스위치 본체는 작아(32x18px) 눌러야 할 영역이 좁으므로 행 전체를 눌러도 켜지게 한다.
- 날씨 패널 위에 구분선·제목·상자를 만들지 않는다. 이유: 필터 묶음과 같은 열이라 구분선이 있으면 "다른 기능"처럼 보이고, 별도 제목은 라벨과 중복이다.

#### 날씨 지역 선택 상자

- 라벨 "날씨 지역". 이유: 동네 입력("동네 이름 (선택)")과 이름 자체가 달라야 헷갈리지 않는다. "지역" 한 단어로 두지 않고 "날씨"를 붙여 용도를 라벨에 담았다.
- 처음에는 값이 없다(기본 지역 금지). 상자에는 placeholder "시·도 선택"이 보인다.
- 목록 첫 항목은 "선택 안 함". 고르면 값이 비고 placeholder로 돌아간다. 이유: 한 번 고른 뒤 날씨 없이 되돌릴 방법이 필요하다(design.md의 "선택 안 함으로 되돌릴 수 있어야 한다"). 구현 메모: Radix Select는 빈 문자열 항목 값을 허용하지 않으므로 "선택 안 함"에는 비어 있지 않은 대체 값을 쓰고, 상태로 올릴 때 null로 바꾼다.
- 목록 항목: `MEAL_WEATHER_REGIONS`의 `label` 순서 그대로. 화면에는 짧은 이름만 쓴다.
  - 서울, 부산, 대구, 인천, 광주, 대전, 울산, 세종, 경기, 강원, 충북, 충남, 전북, 경북, 경남, 제주, 전남
  - 전남·광주 통합 여부와 최종 개수는 개발 시점 현행 행정구역으로 정해진다(design.md). 통합되면 해당 항목 하나로 바꾼다. 이 문서는 짧은 표기 규칙("특별시·광역시·도 같은 접미사를 뺀다, 충북·충남·전북·전남·경북·경남처럼 두 글자로 줄인다")을 정한다.
  - 이유: 모바일 목록에서 한 줄에 들어가고, 이용자는 같은 줄임말을 일상에서 쓴다. 정식 이름은 입력이 아니라 선택이라 줄여도 혼동이 없다.
- 목록은 기본 Select 패널(`SelectContent`)을 쓴다. 높이가 길면 패널 안에서 스크롤된다(기본 동작).

#### 날씨 반영 스위치

- 기본 켜짐. 지역을 고르지 않았을 때도 켜진 채다(지역이 없으면 영향이 없다). 비활성(disabled)으로 만들지 않는다. 이유: 비활성은 탭 순서에서 빠져 AC-6(날씨 지역 → 날씨 스위치 → 룰렛 돌리기)을 깬다.
- 행 안: 왼쪽 라벨 "날씨 반영", 오른쪽에 상태 글자("켜짐" 또는 "꺼짐")와 스위치. 상태 글자는 `aria-hidden`이다(스위치 자체가 켜짐/꺼짐을 읽어 준다).
- 끄면 날씨 조회와 날씨 줄이 모두 없다(plan).

#### 패널 안내 문장 (UW-2 확정: 안내 1은 항상 보이고, 안내 2만 접는다)

- 안내 1, 선택 상자 아래, **항상 보임**: "날씨 지역은 오늘 날씨 정보를 가져오는 데만 쓰입니다. 위치 권한을 요청하지 않습니다." (plan 고지 1 그대로.) 이유: 날씨 지역 값이 서버로 가고 위치 권한은 쓰지 않는다는 사실은 방침을 바꾼 이유라 접지 않는다.
- 안내 2, 스위치 행 아래, **접힘이 기본**: 기존 `CollapsibleComponent`(`src/components/common/collapsible.component.tsx`, 동네 입력이 쓰는 것과 같다)를 `heading` 한 개만 주고 쓴다. 새 컴포넌트는 만들지 않는다.
  - 트리거 글자(`heading`): "날씨 반영, 확률이 어떻게 달라지나요?" 이유: 접혀 있어도 이 줄만 읽으면 "스위치가 확률에 관한 것"이라는 걸 알 수 있고, 질문 형태라 눌러 볼 동기가 생긴다. "더 보기" 같은 내용 없는 이름은 쓰지 않는다.
  - 본문: "날씨 반영을 켜면 날씨에 어울리는 메뉴가 뽑힐 확률이 조금 높아집니다. 결과는 여전히 무작위입니다." (plan 고지 2 그대로. "추천" 표현이 없다.) 본문은 `<details>` 안이라 서버가 그린 HTML에도 들어 있고 JS 없이 열린다(`CollapsibleComponent` 기본 동작).
  - `note`(접혀도 보이는 한 줄)는 쓰지 않는다. 이유: 트리거 글자가 이미 내용을 짐작하게 하고, 한 줄을 더하면 접은 효과가 줄어든다.
- 안내 1은 문단, 안내 2는 접는 요소다. 둘은 서로 다른 컨트롤의 설명이라 한 목록으로 묶지 않고, 번호·점·상자 없이 쓴다.
- 접어도 안내 2의 뜻을 놓치지 않게 하는 장치(UW-2 조건):
  1. 결과 카드의 날씨 한 줄이 "조금 더 잘 뽑히게"(확률이 오른다)와 "결과는 여전히 무작위예요"(무작위)를 함께 말한다(아래 문구표, 확정 안 1에 "결과는 여전히 무작위예요."를 보강했다). 이유: 원래 안 1은 확률이 오른다는 뜻만 있고 무작위라는 말이 없었다. 접힌 안내 2를 안 읽은 이용자도 결과를 볼 때 두 뜻을 같은 자리에서 본다.
  2. 출처·정확도 문장은 날씨 자료에 대한 것이라 이 뜻을 담지 않는다. 대신 위 날씨 한 줄이 맡는다.
  3. 보통 날씨·날씨 없음·꺼짐은 뽑기가 균등이라 "확률이 달라졌다"는 말이 필요 없다.
  4. 트리거 글자에 "확률"이 들어 있어 접힌 상태에서도 주제가 보인다.

#### 결과 카드 안 날씨 안내 (`MealRouletteWeatherNoteComponent`)

위치: 결과 카드에서 운세 인용 블록(`border-l-4`) 바로 아래, 지도 묶음 위. 이유: 날씨 줄은 이 결과가 만들어진 방식에 대한 설명이라 메뉴·운세와 가까워야 하고, 지도 링크(외부로 나가는 행동) 앞에 있어야 한다. 광고 슬롯은 이 영역에 없다.

구성 (스냅샷 상태별)

| 스냅샷 | 보이는 것 |
|---|---|
| `ready` + 눈·비·더움·추움 | 날씨 아이콘 + 날씨 한 줄, 그 아래 출처, 그 아래 정확도 문구 |
| `ready` + 보통 | 출처, 정확도 문구 (한 줄 없음, 아이콘 없음. UW-5 확정) |
| `unavailable` | 실패 안내 한 줄 (muted, 아이콘 없음) |
| `off` | 아무것도 그리지 않는다. 빈 여백도 만들지 않는다 |

- 날씨 한 줄: 아이콘(20px)과 문장을 가로로(`flex items-start gap-2`) 놓는다. 아이콘은 문장 첫 줄 가운데에 맞춘다(`mt-1`, `shrink-0`). 문장은 줄바꿈된다.
- 아이콘 4종(`lucide-react`, 모두 `aria-hidden`): 눈 `Snowflake`, 비 `CloudRain`, 더움 `Sun`, 추움 `Thermometer`. 아이콘 이름은 개발 시 설치된 `lucide-react` 버전에 있는지 확인하고, 없으면 같은 뜻의 가까운 아이콘으로 바꾼다.
- 출처 문장: 상수 `MEAL_WEATHER_SOURCE_TEXT`의 글자 중 기상청 홈페이지 주소 부분을 링크로 건다. 링크는 `target="_blank"` `rel="noopener noreferrer"`이고, 링크 안에 `<span className="sr-only">(새 탭에서 외부 사이트 열림)</span>`을 둔다(지도 링크와 같은 어법). 링크 스타일은 `text-primary underline underline-offset-2`. 줄바꿈이 어색한 주소는 `break-all`로 칸 밖으로 나가지 않게 한다.
- 정확도 문구: "날씨는 실제와 다를 수 있습니다." 독립된 한 줄.
- 날씨 안내 블록과 지도 묶음 사이는 카드 기본 간격(20px)이고 구분선은 넣지 않는다. 이유: 카드에 이미 `border-t` 고지가 아래에 있어 선을 더하면 시끄럽다.

#### 날씨 한 줄 문구 (UW-1 확정: 안 1. 단, 무작위 뜻을 보강했다)

제약: 뽑힌 메뉴가 그 날씨에 어울린다고 말하지 않는다. "추천"을 쓰지 않는다. `{menu}` 바로 뒤에 받침 조사를 붙이지 않는다. 금지어("날씨에 딱", "보양", "몸에 좋", "건강", "폭염", "한파", "특보", "반드시")를 쓰지 않는다. 결과 카드 제목이 이미 메뉴 이름을 크게 보여 주므로 **한 줄에 메뉴 이름을 넣지 않는다.** 이유: 같은 메뉴 이름이 카드 안에서 두 번 나오면 군더더기이고, 조사 문제와 "어울린다는 뜻으로 읽히는" 위험이 둘 다 사라진다. 이 경우 `MEAL_WEATHER_LINE_TEMPLATES`에 `{menu}` 자리표시가 없고 `getMealWeatherLine`의 `menuName` 인자는 쓰이지 않는다(design.md 상수 설명과 달라지는 점이라 architect 확인 필요).

| 날씨 | 확정 문구 |

| 비 | 오늘은 비가 와요. 비 오는 날 메뉴가 조금 더 잘 뽑히게 돌렸어요. 결과는 여전히 무작위예요. |

- 보강 이유: 안내 2가 접히므로 결과 카드의 한 줄이 "확률이 조금 달라지는 무작위"라는 뜻을 직접 지녀야 한다. 사용자가 고른 안 1의 앞 두 문장은 그대로이고, 뒤에 안 2에서 쓰던 "결과는 여전히 무작위예요." 한 문장만 붙였다.

- plan의 AC-1은 "오늘은 비가 와요. ○○ 어때요?"로 적혀 있다. Q1 확정으로 이 문장은 쓸 수 없으므로 위 비 문구로 PM이 AC-1을 고쳐야 한다(E2E는 "오늘은 비가 와요." 포함 여부로 확인하면 된다).

#### 실패 안내

"날씨 정보를 가져오지 못해 날씨 없이 뽑았어요." (plan 고지 5 그대로.) 조회 중에 룰렛을 누르면 최대 3초 기다렸다가 날씨를 반영해 뽑는다. 3초가 지나도 응답이 없거나 실패하면 날씨 없이 뽑고 같은 문장을 쓴다(둘 다 `unavailable`). 오류 색(`destructive`)·아이콘·굵기를 쓰지 않는다. 이유: 날씨는 덤이고 뽑기가 본 기능이라 이용자에게 문제처럼 보이면 안 된다. 패널에는 조회 중 표시를 두지 않는다(UW-4 확정).

#### 세로 길이 (모바일 320px, 안내 문장 기준 계산값)

기준: 안내 문장 `text-sm`(14px) `leading-6`(24px), 폭 288px에 한 줄 약 20자.

| 구성 | 안내 1 | 안내 2 | 합계(패널 안내 영역) |
|---|---|---|---|
| 처음 안(둘 다 항상 보임, 이전 명세) | 약 3줄 72px + 간격 8px = 80px | 약 4줄 96px + 간격 8px = 104px | 약 184px |
| 지금 안, 접힘(기본) | 80px | 트리거 제목 2줄(`text-lg leading-snug` 약 50px) + 위아래 여백 16px + 간격 8px = 약 74px | 약 154px |
| 지금 안, 펼침 | 80px | 74px + 본문 4줄 96px + 여백 약 16px = 약 186px | 약 266px |

- 접어도 모바일에서 줄어드는 높이는 약 30px뿐이다(트리거 제목이 두 줄이고 44px 이상 눌림 영역이 필요하기 때문). 이전 명세에 적은 "약 150~170px 늘어난다"는 이 계산의 "처음 안 184px"로 바로잡는다.
- 640px 이상: 안내 2의 트리거가 오른쪽 열 폭(약 350px)에서 한 줄이라 약 52px. 왼쪽 열(라벨+선택 상자+안내 1 약 160px)이 더 길어 패널 높이를 정하고, 접힘·펼침이 패널 높이를 키우지 않는다(펼침은 오른쪽 열이 약 150px까지 늘어 왼쪽 열과 비슷하다).

## 인터랙션·애니메이션

**새 모션은 없다(UW-3 확정: 모션 없음).** 날씨 패널과 날씨 안내는 즉시 나타나고 사라진다. 기존 돌림판 회전 하나만 움직인다.

- 이유: 날씨는 덤 정보라 연출이 결과(메뉴)를 가리면 안 된다. 돌림판 연출이 이미 한 곳에 있고, 연출이 서로 경쟁하지 않게 한다. 결과가 나오는 순간 날씨 안내도 같이 즉시 보인다.
- 이미 컴포넌트에 들어 있는 기본 동작은 그대로 쓴다. 새로 붙이는 것이 아니다: 선택 목록 열림·닫힘(`tw-animate-css`, shadcn `SelectContent`), 스위치 손잡이 이동(`transition-transform`), 포커스 링 색 변화, 접는 안내의 화살표 방향 전환(`CollapsibleComponent`의 `group-open:rotate-180`, 순간 전환이며 새로 붙이는 효과가 아님). `<details>`의 열고 닫기에는 애니메이션이 없다.
- 동작 줄이기: 새 모션이 없으므로 새 대체 동작은 없다. 기본 Select의 열림 효과는 shadcn 기본 구현을 따른다(`src/components/ui/`는 건드리지 않는다).

- 명도 대비 (종이 `#eef0e6`, 카드 `#f7f8f1`, `foreground` `#1b3328`, `muted-foreground` `#5a6a5f`, `primary` `#2d6a3e`, `menu-meal` `#a5481f` 기준 계산값. 구현 전에 한 번 더 재검산한다)
  - 라벨·날씨 한 줄·접는 안내 트리거 `foreground` on 종이·카드 약 11:1.
  - 안내 문장·출처·정확도·실패 안내·켜짐/꺼짐 글자·접는 안내 본문 `muted-foreground` on 종이·카드 약 4.9~5.3:1.
  - 출처 링크 `primary` on 카드 약 6:1.
  - 날씨 아이콘 `menu-meal` on 카드 4.5:1 이상(색 토큰 규칙 값).
  - 선택 상자·스위치 행 테두리와 스위치 꺼짐 테두리 `muted-foreground` on 카드 약 5.3:1(비텍스트 3:1 이상). 켜짐 스위치 `primary` on 카드 약 6:1.
- 키보드 이동
  - Tab 순서: 날씨 지역(시·도) → 동네 이름(값이 있으면 지우기 버튼) → 날씨 스위치 → 안내 2 트리거 → 룰렛 돌리기 → 지도 링크. 동네 입력의 "동네 입력 안내 더 보기" 접힘은 없앴다.
  - 선택 상자: Enter/Space/방향키로 열고, 방향키·타입어헤드로 항목 이동, Enter로 선택, Esc로 닫는다(Radix Select 기본). 선택하면 포커스는 선택 상자로 돌아온다(기본).
  - 스위치: Space로 켜고 끈다. Enter는 쓰지 않는다(스위치 기본 동작).
  - 접는 안내 트리거: `<summary>`라서 Enter 또는 Space로 열고 닫는다(브라우저 기본). 포커스는 트리거에 그대로 있고 본문으로 옮기지 않는다. 본문은 글자뿐이라 펼쳐도 탭 정지점이 늘지 않는다. 포커스 링은 `CollapsibleComponent`의 `focus-visible` 값을 그대로 쓴다. 눌림 영역은 컴포넌트의 `min-h-11`(44px) 이상.
  - 날씨 패널에서 Enter를 눌러도 룰렛이 돌지 않는다. `<form>`을 쓰지 않는다.
  - 결과 카드의 출처 링크는 지도 링크보다 앞의 탭 순서에 있다(DOM 순서).
- 라벨·스크린리더
  - 선택 상자: 보이는 `Label` "날씨 지역"을 `htmlFor`/`id`(Radix에서는 트리거 `id`)로 연결한다. 접근성 이름이 보이는 글자와 같다(WCAG 2.5.3). `aria-describedby`로 한 줄 안내의 id를 연결한다. 동네 이름 입력도 같은 id를 연결한다(오류 문장이 있으면 오류 id가 앞). 한 줄 안내는 항상 보이므로 연결해도 안전하다.
  - 스위치: 행 안의 `Label` "날씨 반영"과 스위치를 `htmlFor`로 연결해 이름은 "날씨 반영", 상태는 켜짐/꺼짐으로 읽힌다. 행 안 "켜짐/꺼짐" 글자는 `aria-hidden`이다(중복 낭독 방지). **스위치에는 `aria-describedby`로 안내 2를 연결하지 않는다.** 이유: 안내 2 본문은 접힌 `<details>` 안이라 접힌 동안 숨겨져 있어 스크린리더가 읽는다는 보장이 없고, 스위치 바로 다음 탭 정지점이 안내 2 트리거여서 다음에 닿는 요소가 곧 설명이다.
  - 접는 안내: `CollapsibleComponent`가 만드는 `<details><summary>` 구조 그대로 쓴다. 스크린리더는 트리거를 "날씨 반영, 확률이 어떻게 달라지나요?, 제목 수준 3, 접힘/펼침 상태 버튼"으로 읽고 펼침 상태를 알려 준다. 별도 `aria-*`를 덧붙이지 않는다. 같은 컴포넌트를 쓰는 동네 입력 안내와 같은 동작이다.
  - 제목 수준: 트리거가 `h3`라서 필터 영역에 `h3`이 하나 생긴다. 앞쪽 제목 수준(`h1` 머리, `h2` 구역 제목)과 건너뜀이 없는지 구현 때 문서 개요를 한 번 확인한다. 어긋나면 이 한 곳만 `level`을 맞춘다(컴포넌트 변경 없이 prop).
  - 지역 값이 빈 상태: 트리거가 "날씨 지역, 시·도 선택"으로 읽히도록 placeholder를 유지한다.
  - 선택 후 날씨 조회 결과는 따로 알리지 않는다(`aria-live` 없음). 이유: 조회는 백그라운드이고 결과가 날씨 줄로 나오는 때가 알림 시점이다.
  - 결과 알림(`MealRouletteStatusComponent`, `role="status"`)의 문장에 날씨를 넣지 않는다(design.md "프론트 구조"). 날씨 안내는 결과 카드 안에서 읽는다.
  - 날씨 안내 블록은 일반 문단 묶음이다. 별도 `role`·`aria-live`를 붙이지 않는다. 아이콘은 `aria-hidden`이라 문장만 읽힌다.
  - 출처 링크: 링크 글자가 이름이다. "(새 탭에서 외부 사이트 열림)"을 `sr-only`로 붙인다.
- 터치·확대
  - 선택 상자·스위치 행·접는 안내 트리거 모두 높이 44px 이상, 스위치 행은 행 전체가 눌림 영역. 글자 16px 이상(트리거는 18px)이라 모바일 자동 확대가 없다.

## 다크 모드·동작 줄이기

- 다크 모드: 쓰지 않는다. 모든 색이 토큰 클래스(`bg-card`, `border-muted-foreground`, `text-foreground`, `text-muted-foreground`, `text-primary`, `text-menu-meal`)다. `dark:` 클래스를 새로 쓰지 않는다. 기본 Switch·Select 파일 안에 들어 있는 `dark:`는 `src/components/ui/`라 검사 대상이 아니고 그대로 둔다.
- 동작 줄이기: 이 문서가 추가하는 모션이 없다.

## 기존 디자인 시스템 변경 제안

없음.

- 선택 상자·스위치 행·스위치 꺼짐 테두리에 `border-muted-foreground`를 쓰는 것은 동네 입력란이 이미 내린 같은 결정(기존 토큰 사용)이고 새 토큰이나 시스템 값 변경이 아니다. 같은 문제(3:1 미달)가 카테고리 칩 등 다른 컨트롤에 있는지는 이 문서 범위 밖이라 PM이 알고 있도록 적어 둔다.

## 결과 영역 좌우 균형(2026-11-28)

입력: 사용자 요청 "돌림판 영역 아래가 너무 비어 있어. 잘 분리해줘." 스크린샷 파일이 없어 사용자가 전한 설명과 현재 코드(`root.component.tsx`, `result.component.tsx`, `weather-note.component.tsx`, `map-links.component.tsx`)로 판단했다. 높이 숫자는 클래스에서 계산한 추정치이며 구현 후 실측으로 확인한다. 이 절은 위 절을 바꾸지 않고 "결과 영역(돌림판 + 결과 카드 + 지도·공유)의 배치"만 정한다.

### 문제 진단

- 데스크톱(`md`, 768px 이상)은 `md:grid-cols-[minmax(0,5fr)_minmax(0,6fr)] md:items-start`의 2열이다. 동네 이름 입력이 위쪽 "내 지역" 묶음으로 올라가면서 왼쪽 열에는 돌림판과 "룰렛 돌리기" 버튼뿐이다. 오른쪽 열에는 결과 카드 하나에 메뉴 이름, 운세 인용, 기온 줄, 날씨 한 줄, 출처, 정확도, 지도 링크 묶음(제목, 버튼 3개, 외부 링크 고지), 공유 영역, 하단 고지가 모두 들어 있고 그 아래에 `ResultNextLinksComponent`가 붙는다.
- 추정 높이(1024px 폭, 날씨 있음): 왼쪽 열 약 480~520px. 오른쪽 결과 카드 약 900~1,000px(메뉴·운세 약 190px, 날씨 묶음 약 190px, 지도 묶음 약 330px, 공유 영역 약 200px, 하단 고지 약 70px, 안쪽 여백과 간격). 차이가 약 400px 이상이라 왼쪽 열 아래가 비어 보인다.
- 원인은 왼쪽이 모자란 것이 아니라 오른쪽 한 카드에 "무엇이 뽑혔나(결과와 이유)"와 "다음에 할 일(지도·공유)"이 섞여 길어진 것이다. 그래서 왼쪽을 채우기보다 오른쪽을 둘로 나누는 쪽이 원인에 맞다.

### 대안

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A | 날씨 정보(기온·문장·출처·정확도)를 결과 카드에서 빼서 왼쪽 열 돌림판 아래 별도 "오늘의 날씨" 카드로 | 왼쪽이 채워진다 | DOM 순서가 돌림판 → 날씨 → 결과가 되어 모바일에서 날씨가 메뉴보다 먼저 나온다. CSS `order`로 고치면 탭·읽기 순서와 시각 순서가 어긋난다. 날씨 문장은 "이 결과가 이렇게 뽑혔다"는 뽑은 순간의 스냅샷이라 메뉴와 떨어지면 연결이 끊긴다. 결과가 없을 때 왼쪽 카드가 비거나 숨어 뽑기 전후 레이아웃이 흔들린다. 날씨 off·unavailable에서 카드가 사라지면 균형이 다시 깨진다 |
| B | 왼쪽 열을 `sticky`로 두어 스크롤해도 돌림판이 따라옴 | DOM·탭 순서 변경 없음. 코드 한두 줄 | 빈 공간 자체는 그대로다(첫 화면 왼쪽 아래가 비어 보임). 뷰포트 높이가 돌림판 열보다 작은 노트북에서는 위가 잘리고 고정 머리 영역과의 간격을 따로 맞춰야 한다. 원인(오른쪽이 너무 김)을 고치지 않는다 |
| C | 지도 링크와 복사·저장 묶음을 왼쪽 열 돌림판 아래로 | 높이가 맞는다 | DOM 순서가 돌림판 → 지도 → 결과가 되어 모바일에서 메뉴를 보기 전에 지도 링크가 나온다(A와 같은 문제). 결과가 나오기 전에는 왼쪽 아래가 비거나 자리가 흔들린다. 지도 링크는 결과 메뉴에 의존하는데 떨어져 의미가 약해진다 |
| D | 결과 카드를 둘로 나눈다. 카드는 "뽑힌 결과와 이유"(메뉴, 운세, 기온·날씨 한 줄·출처·정확도, 하단 고지)만 갖고, "다음에 할 일"(지도 링크, 공유)은 데스크톱에서 카드 아래 2행으로 내려 돌림판 열과 같은 격자에 놓는다. DOM은 돌림판 → 결과 카드 → 지도 → 공유 → 다음 링크 | 1행에서 돌림판 열(약 500px)과 결과 카드(약 520~600px)의 높이가 비슷해진다. DOM 순서가 지금과 같고 시각 순서가 DOM을 그대로 따른다. 날씨 스냅샷이 메뉴와 같은 카드에 남는다. 모바일에서 결과 → 날씨 → 지도 → 공유로 자연스럽다. 새 컴포넌트·토큰 없이 root의 격자 배치와 결과 카드의 자식 이동만 바뀐다 | 지도·공유가 카드 밖으로 나와 "한 카드 안의 묶음"이라는 시각적 결속이 약해진다(같은 격자·같은 열 폭으로 보완). 날씨 off·보통일 때 카드가 짧아져 1행에서 오른쪽이 왼쪽보다 100px쯤 짧을 수 있다 |

### 권장안: D

1. 결과와 날씨의 연결. 날씨 한 줄·출처·정확도가 메뉴·운세와 같은 카드에 남아 "이 메뉴가 뽑혔고 이 날씨 때문에 가중치가 조금 달랐다"가 한 카드 안에서 위에서 아래로 읽힌다. 날씨 안내는 뽑은 순간의 스냅샷이라 결과와 같은 카드여야 의미가 맞는데, A는 이것을 깬다.
2. 모바일 순서. 한 열이면 돌림판 → 결과 카드(메뉴, 운세, 날씨) → 지도 링크 → 공유 → 다음 링크다. 요청한 "메뉴 결과 → 날씨 → 지도 링크" 순서가 그대로다. A와 C는 이 순서가 깨진다.
3. 탭 순서·읽기 순서. 현재 DOM 순서(돌림판 → 결과 카드 안: 출처 링크 → 지도 링크 → 공유 → 다음 링크)와 같다. 변경은 카드의 `</section>`이 지도 앞에서 닫히는 것뿐이고 포커스가 닿는 요소의 순서는 그대로다. AC-6("날씨 지역 → 날씨 스위치 → 룰렛 돌리기 → 지도 링크")과 "출처 링크는 지도 링크보다 앞" 규칙이 유지된다. CSS `order`·`grid-area` 재배치를 쓰지 않는다.
4. 뽑기 전. 결과가 없으면 지도·공유·다음 링크 행은 그리지 않고 기존 점선 자리 표시만 남는다. 자리 표시는 데스크톱에서 돌림판 열 높이까지 늘어나게 해서 오른쪽이 휑하지 않게 한다(아래 상태 표). 모바일은 기존대로 자리 표시를 그리지 않는다.
5. B는 보조책으로만 남긴다. D 적용 후에도 실측에서 1행 높이 차이가 크면 그때 B를 더한다(개발 확인 사항 5).

### 간격·정렬 규칙 (기존 토큰만)

- 격자: `md:grid md:grid-cols-[minmax(0,5fr)_minmax(0,6fr)] md:items-start md:gap-x-8`(기존 값). 행 간격은 `md:gap-y-6`(24px). 모바일은 `space-y-6`을 유지하고 `md`에서 `space-y-0`으로 바꾼다(기존 방식).
- 1행 왼쪽: 돌림판 열. 지금과 같다.
- 1행 오른쪽: 결과 카드. 안쪽 `space-y-5`, 반경 `rounded-panel`, 테두리 `border-border`, 면 `bg-card`는 그대로. 카드 마지막 요소는 하단 고지(`border-t pt-4`)다.
- 2행 왼쪽: 지도 링크 묶음. 카드 면(`bg-card`·테두리)을 씌우지 않는다. 이유: 이미 `h3` 제목과 `outline` 버튼 3개가 있어 상자까지 만들면 카드 안의 카드가 되고, 카드 면이 한 화면에 여러 개 생겨 시끄럽다. 묶음 안 간격은 기존 `space-y-3`, 버튼은 기존 `h-11 w-full`.
- 2행 오른쪽: 공유 영역(`SharePanelComponent`). 공유 영역의 모양은 바꾸지 않는다. 지도 묶음과 같은 위쪽 선에 맞춘다(`items-start`).
- 정렬은 모두 왼쪽 정렬이다(가운데 정렬 없음). 이유: 카드·묶음 모두 읽는 단위이고 기존 `/meal` 화면의 정렬이 왼쪽이다.
- 새 토큰·새 색·`dark:`·새 애니메이션은 없다. 지도 묶음 제목과 공유 영역이 카드 밖으로 나가 배경이 카드색에서 종이색(`background`)으로 바뀌므로 글자 대비가 약간 낮아진다(종이 위 `muted-foreground` 약 4.9:1, 위 접근성 절의 계산값 범위. AA 통과).

### 상태별 모습

| 상태 | 데스크톱 | 모바일 |
|---|---|---|
| 결과 없음(뽑기 전) | 1행만 있다. 왼쪽 돌림판, 오른쪽 점선 자리 표시(기존 문구). 자리 표시 칸은 1행 높이까지 늘어난다(칸 `md:self-stretch`, 자리 표시 상자 `h-full`). 지도·공유·다음 링크는 그리지 않는다 | 자리 표시를 그리지 않는다(기존과 같다). 돌림판 아래에 아무것도 없다 |
| 결과 있음 + 날씨 있음(눈·비·더움·추움) | 1행 오른쪽 카드가 가장 길다. 2행에 지도·공유 | 위 와이어프레임 |
| 결과 있음 + 날씨 보통 | 카드에 기온 줄, 출처, 정확도만 있다(한 줄·아이콘 없음). 카드가 약 120px 짧아진다. 돌림판 열이 더 길 수 있고 2행은 1행에서 더 긴 칸 아래에서 시작한다 | 위 와이어프레임에서 날씨 한 줄만 빠진다 |
| 결과 있음 + 날씨 off(지역 없음 또는 스위치 꺼짐) | 날씨 묶음이 없다(빈 여백도 없음). 카드는 메뉴·운세·하단 고지만 있어 가장 짧다(약 330px). 1행은 왼쪽이 더 길고 2행이 그 아래에서 시작한다 | 날씨 줄 없이 카드 → 지도 |
| 결과 있음 + 날씨 unavailable | 카드에 실패 안내 한 줄(약 48px)만 추가 | 같음 |
| 회전 중(spinning) | 지도·공유는 기존 카드가 그려지는 조건에서만 그린다. 다음 링크는 `resultMenu && !spinning`일 때만 그린다(기존 규칙 유지). 회전 중 카드 처리는 기존 동작(`menu`가 null이면 자리 표시)을 따른다 | 같음 |

- 날씨 off·보통에서 1행의 좌우 높이 차이가 생기는 것은 정상이다. 이유: 날씨 정보가 없는 결과를 늘려 맞추면 의미 없는 여백이 생긴다. 2행이 두 열 중 더 긴 쪽 아래에서 시작하므로 어느 상태에서도 아래쪽은 가지런하다.

### 접근성

- 랜드마크: 새 랜드마크를 만들지 않는다. 결과 카드는 지금처럼 `section[aria-labelledby=메뉴 이름 h2]`이다. 지도 묶음·공유 영역·다음 링크는 `section`·`aside`로 감싸지 않고 일반 `div`다. 이유: 이름 붙은 영역이 늘면 스크린리더 영역 목록이 길어지고, 이 묶음들은 결과의 부속 행동이라 독립 영역이 아니다.
- 제목 수준: `h1`(머리) → `h2`(결과 카드의 메뉴 이름) → `h3`("지도에서 찾아보기", 기존 `MealRouletteMapLinksComponent`의 `h3`). 카드 밖으로 나가도 `h2` 다음에 `h3`이 오므로 수준 건너뜀이 없다. 필터 영역의 접는 안내 `h3`가 `h2`보다 앞에 오는 건 위 접근성 절의 기존 확인 항목 그대로다.
- DOM 순서 = 시각 순서(모바일 한 열, 데스크톱 행 단위로 왼쪽→오른쪽·위→아래) = 탭 순서. 룰렛 돌리기 → (결과 카드) 날씨 출처 링크 → 지도 링크 3개 → 공유 영역 버튼 → 다음 링크. 격자는 DOM 순서대로 2열을 채우는 기본 흐름만 쓰고 `order`·`grid-area`·`row-start`로 재배치하지 않는다. 2행의 두 칸이 DOM상 지도 → 공유 순이라 왼쪽 → 오른쪽 순서가 일치한다.
- 스크린리더 읽기 순서 변화: 결과 카드 안 순서가 날씨 → 지도 → 공유 → 하단 고지에서 날씨 → 하단 고지, 그다음 카드 밖에서 지도 → 공유로 바뀐다. 하단 고지(`MEAL_RESULT_NOTICE_TEXT`)는 결과 전체에 대한 안내라 지도·공유 앞에서 읽혀도 의미가 맞고, 고지가 더 빨리 읽히는 이점이 있다.
- 결과 알림(`role="status"`)은 건드리지 않는다. 카드가 나뉘어도 알림 문장은 그대로고 새 `aria-live` 영역이 없다.
- 공유 영역의 미리보기 이미지·상태 문구(`SharePanelComponent`)의 접근성 동작은 그대로다. 카드 밖으로 나와도 `role`·`aria-*` 변경이 없다.
- 확대: 200% 확대에서 `md`보다 좁아지면 한 열로 돌아가 위 모바일 와이어프레임대로 읽는다(가로 스크롤 없음).

### 개발 담당 확인 사항

바꿔야 할 컴포넌트와 파일

| 파일 | 변경 |
|---|---|

| `src/features/meal/roulette/components/result.component.tsx` | 카드 안에서 `MealRouletteMapLinksComponent`와 `shareSlot`을 뺀다. root가 쓰지 않게 되는 `shareSlot`, `area` prop은 제거한다. 카드 구성은 메뉴 이름·카테고리 → 운세 인용 → 날씨 안내 → 하단 고지. 자리 표시(`menu`가 null)는 데스크톱에서 1행 높이까지 늘어나도록 `h-full`을 주고 칸에 `self-stretch`를 준다. 기존 `min-h-40`은 그대로 둔다 |

| `src/features/meal/roulette/components/weather-note.component.tsx` | 변경 없음. 날씨 스냅샷은 카드 안에 그대로 남는다 |
| `e2e/meal*.spec.ts`, `e2e/meal-weather.spec.ts` | 지도 링크·공유 버튼을 결과 카드 `section` 안에서 찾는 선택자가 있으면 페이지 기준으로 바꾼다. 날씨 문장과 출처 링크는 카드 안에서 계속 찾는다. QA가 확인한다 |
| 단위 테스트 | 해당 없음(레이아웃만 바뀐다) |

구현 확인 사항

1. 하단 고지(`border-t pt-4`)가 카드 마지막이 되는데, 지도·공유가 빠진 카드에서 `border-t`가 어색하지 않은지 본다(위 날씨 안내와의 구분선으로 읽힌다). 어색하면 선을 없애는 것은 디자이너 확인이 필요하다.
2. 지도 묶음의 `h3`가 종이색(`background`) 위에 놓인다. 색 토큰은 그대로이며 대비는 위 계산값 범위다.
3. 모바일에서 카드와 지도 묶음 사이 24px이 단절되어 보이는지 360·390px에서 본다.
4. 확인 폭: 320, 390, 768, 1024, 1280px. 상태는 결과 없음, 날씨 눈·비·더움·추움, 보통, off, unavailable, 공유 영역 있음·없음.
5. 1024px 이상에서 1행의 좌우 높이 차이가 200px를 넘는 상태(날씨 off 등)가 흔하면 PM에게 알린다. 그때 왼쪽 열에 `md:sticky md:top-<머리 높이 + 16px>`를 보조로 더할지 정한다. 지금은 넣지 않는다.
6. 새 CSS 애니메이션, `dark:`, 새 색·토큰은 없다. `motion-reduce:` 처리는 필요 없다.

### 사용자가 고를 것

- 지도·공유를 카드 밖으로 빼는 것에 동의하는가.
  - 권장: 빼는 안(D). 일체감 약화는 같은 격자·같은 열 폭·같은 정렬로 보완하고, 날씨 스냅샷을 결과와 같은 카드에 두는 원칙은 지킨다.
  - 대안: 카드 안에 그대로 두고 B(sticky)만 적용한다. 코드는 가장 적지만 빈 공간이 남고 노트북 화면에서 돌림판이 잘릴 수 있다.
- 그 밖에 승인 문서(문구·고지·탭 순서·모션 없음)가 바뀌는 선택 항목은 없다.
