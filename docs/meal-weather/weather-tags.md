# 날씨 태그 기준표 (meal-weather, H-1)

- 작성일: 2026-11-28
- 상태: 초안. 사용자 승인 대기. 승인 전에는 FE-5가 메뉴 데이터와 `meal-weather-tag.constant.ts`를 채우지 않는다.
- 출처: `docs/meal-weather/design.md` "메뉴 날씨 태그 데이터 구조", "가중 뽑기 알고리즘"; `docs/meal-weather/plan.md` F-3~F-5; `docs/research/meal-weather.md` 6장(날씨별 어울리는 음식, 일반 상식).
- 대상 메뉴: `meal-menu-breakfast.constant.ts`(80개), `meal-menu-lunch.constant.ts`(120개), `meal-menu-dinner.constant.ts`(야식 제외 123개). 태그는 이 목록 안의 id만 쓴다.

## 0. 요약

- 날씨는 눈·비·더움·추움 4종. 보통에는 태그가 없다.
- 기존 메뉴 중 태그 12칸 모두 5개 이상이 되도록 골랐다. 보충이 필요한 칸은 아침 비 칸 하나뿐이고, 메뉴 2개(칼국수, 김치전)를 목록 끝에 추가하는 안을 제안한다.
- 가중치 3일 때 날씨 칸의 태그 메뉴가 뽑힐 확률은 점심·저녁 11~17%, 아침 16~22%다. 가중치 1(균등)일 때는 4~9%다.
- 아침 목록은 80개에서 82개가 된다. 점심·저녁 목록 개수는 바뀌지 않는다.

## 1. 적용 기준

| 항목 | 기준 |
|---|---|
| 날씨 4종 | 눈, 비, 더움, 추움. 분류 순서는 plan F-3을 따른다 (눈 → 비 → 더움 → 추움). |
| 보통 | 태그를 달지 않는다. 키도 두지 않는다. |
| 야식 메뉴 | 저녁 목록의 야식 57개(`lateNight`)에는 태그를 달지 않는다. 야식 칩은 단독 선택이고 기본 꺼짐이라, 기본 후보 123개를 기준으로 표를 만든다. (사용자 결정 3번) |
| 가중치 | 3으로 계산했다. 값은 DQ3에서 아직 확정되지 않았다. |
| 확률 식 | 칸 안 태그 메뉴가 뽑힐 확률 = `w·n / (N + (w-1)·n)`. n은 태그 수, N은 후보 수, w는 가중치. 직전 메뉴 제외와 필터 적용 전 기준의 근사값이다. |
| 근거 | 리서치 6장 수준의 일반 상식만 쓴다. 건강·효능 주장은 쓰지 않는다. 아침 항목은 리서치에 직접 근거가 없어 상식 추정이다. |
| 중복 | 같은 메뉴가 여러 날씨에 들어가는 것은 허용한다. 표에서 ※로 표시한다. |
| 이름 | 일반 음식 이름만 쓴다. 브랜드명, 식당명은 쓰지 않는다. |

## 5. 가중치 3일 때 확률

| 끼니 | 날씨 | 태그 n / 전체 N | 가중치 1 (균등) | 가중치 3 |
|---|---|---|---|---|
| 아침 | 눈 | 6 / 82 | 7.3% | 19.1% |
| 아침 | 비 | 5 / 82 | 6.1% | 16.3% |
| 아침 | 더움 | 6 / 82 | 7.3% | 19.1% |
| 아침 | 추움 | 7 / 82 | 8.5% | 21.9% |
| 점심 | 눈 | 6 / 120 | 5.0% | 13.6% |
| 점심 | 비 | 5 / 120 | 4.2% | 11.5% |
| 점심 | 더움 | 7 / 120 | 5.8% | 15.7% |
| 점심 | 추움 | 7 / 120 | 5.8% | 15.7% |
| 저녁 | 눈 | 7 / 123 | 5.7% | 15.3% |
| 저녁 | 비 | 5 / 123 | 4.1% | 11.3% |
| 저녁 | 더움 | 7 / 123 | 5.7% | 15.3% |
| 저녁 | 추움 | 8 / 123 | 6.5% | 17.3% |

- 계산: 가중치 3일 때 확률 = 3n / (N + 2n). 예: 점심 비 5/120이면 15 / 130 = 11.5%.
- 확률은 칸 안 태그 메뉴 전체가 뽑힐 확률이다. 메뉴 하나당 확률은 3 / (N + 2n)이다.
- 가중치 3이 DQ3의 예시(8/120에서 17.6%)와 같은 식을 따른다.

## 6. 사용자가 정할 것

각 항목에 권장안을 적었다. 이 중 1번과 2번은 승인 전에 정해야 FE-5를 시작할 수 있다.

1. 보충 메뉴 개수와 후보
   - 권장: 아침 비 칸에 2개 (칼국수, 김치전). 기준 5개를 맞추는 최소 개수다.
   - 대안 후보: 수제비 (korean, soup) 또는 호떡 (quick, dry). 전 계열을 빼고 싶으면 호떡을 쓴다.
   - 보충 0개는 아침 비 칸이 3개로 남아 기준 5개에 미달하므로 권장하지 않는다.
2. 보충 기준 단위 (칸 기준 또는 끼니 기준)
   - 문제: plan F-5 문장은 "태그 메뉴가 5개 미만인 끼니에만"이라고 쓰고, design은 "5개 미만이던 날씨 목록에만"이라고 쓴다.
   - 권장: 칸 기준. design의 단위 테스트 조건과 맞고, 이 표도 칸 기준으로 만들었다. plan F-5 문장은 칸 기준으로 고친다.
   - 대안: 끼니 기준. 아침은 보충 대상이 되지만 보충을 모든 칸에 붙일지 정해야 해서 권장하지 않는다.
3. 야식 메뉴 태그 여부
   - 권장: 태그를 달지 않는다. 야식 칩은 단독 선택이고 기본 꺼짐이라 기본 후보에 영향이 없다. 칩을 켜면 균등 뽑기가 된다.
   - 대안: 야식 57개에도 태그를 단다. 칩을 켠 상태에서도 날씨가 반영되지만 야식 태그 기준을 따로 정해야 한다.
4. 점심·저녁 비 칸에 전 계열 넣기
   - 문제: 리서치의 "비 오는 날 전" 상식이 점심·저녁 목록에는 없다 (저녁의 파전·김치전은 야식 칩에만 있다).
   - 권장: 현행 유지. 두 칸 모두 5개라 보충 규칙상 추가가 필요 없다.
   - 대안: 점심·저녁에 전 1개를 목록 끝에 보충한다 (6개가 된다). 저녁에 쓰면 야식 칩의 같은 이름과 헷갈릴 수 있어 id를 따로 정해야 한다.
5. 가중치 값 (DQ3)
   - 권장: 3. 표가 이 값으로 계산됐다.
   - 대안: 2는 칸별 확률이 이보다 낮다. 값은 DQ3에서 따로 확정한다.
6. 아침 근거
   - 문제: 리서치 6장은 점심·저녁 중심이라 아침 태그 근거는 상식 추정이다.
   - 권장: 상식 수준으로 두고 PM이 검수한다. 메뉴 추가 전 copy-log에 기록한다.
   - 대안: 아침 날씨 태그를 빼고 점심·저녁만 가중한다. 그러면 아침 날씨 한 줄만 나온다.

## 7. FE-5 대조용 확인 항목

- 모든 태그 id가 해당 끼니 메뉴 목록(보충 포함)에 있다.
- 한 칸 안에 같은 id가 두 번 들어가지 않는다.
- 눈·비·더움·추움 각 칸이 5개 이상이다 (보충 뒤).
- 보충 메뉴는 아침 목록 끝 2개뿐이고, 기존 메뉴의 순서와 내용은 바뀌지 않는다.
- 보통에 해당하는 키가 없다.
- 위 개수가 `MEAL_MENU_COUNTS`(아침 82, 점심 120, 저녁 180)와 맞는다.

## 8. 표현 주의

- 날씨와 메뉴의 관계는 "뽑힐 확률이 조금 달라짐"으로만 설명한다. 특정 음식이 건강에 좋다거나 몸에 효과가 있다는 문장은 쓰지 않는다.
- 이 표는 오락용 무작위 뽑기의 가중치 기준이다. 추천 기준으로 쓰지 않는다 (plan Q1).
