# 결과 화면 다음 기능 링크 기획서

## 목표

결과를 본 사용자가 같은 사이트의 다른 기능으로 자연스럽게 넘어가도록, 결과 화면 끝에 다른 기능 이동 링크 2개를 둔다.

이 기능의 실제 목적은 페이지 수와 체류 시간을 늘리는 것(광고 노출 증가)이다. 그래도 링크 문구와 배치는 사용자의 이동을 돕는 수준으로만 정하고, 광고 클릭을 유도하지 않는다. 승인 사항: 광고 클릭 유도 문구, 광고 강조, 광고 근처 배치는 하지 않는다(카카오 애드핏 정책 위험).

## 범위

- 포함:
  - 결과가 나온 화면 18곳(운세 4, 궁합 결과 2, 타로 2, 꿈 상세 1, 뭐 먹지 1, 운빨 뽑기 3, 로또 5. 아래 표 참고)에 이동 링크 블록 추가 또는 기존 블록 유지
  - 추천 대상 정의를 한 곳에서 관리
- 제외:
  - 새 페이지, 새 메뉴, 새 라이브러리, 새 폰트
  - 광고 슬롯 자체의 변경 (`src/app/layout.tsx`, `src/features/ad/`는 이 기획에서 건드리지 않는다)
  - `/lotto/[draw]`(회차 상세), `/lotto/my-numbers`(저장 목록), `/fortune/compatibility`(허브), `/tarot`·`/dream` 허브 목록 화면: 결과 화면이 아니므로 제외. `/lotto/[draw]`는 열린 질문 Q7 참고
  - 손 없는 날 달력(`/no-son-days`, `/no-son-days/[year]`): 결과 화면이 아니라 달력이라 기본 제외. 포함 여부는 열린 질문 Q3
  - 클릭 추적 이벤트 추가(기본안 제외. 열린 질문 Q5)
  - 자동 이동, 타이머 이동, 결과 전 강제 이동

| ID | 기능 | 우선순위 (필수/선택) |
|---|---|---|

## 유저 스토리

- US-1: 운세 결과를 본 사용자로서, 같은 주제의 다른 운세를 바로 볼 수 있으면 좋겠다. 왜냐하면 결과가 하나만 있으면 다음에 할 일이 없기 때문이다.
- US-2: 타로나 로또 결과를 본 사용자로서, 결과 아래에서 관련 기능을 한 번에 찾고 싶다. 왜냐하면 메뉴로 돌아가지 않아도 되면 편하기 때문이다.
- US-3: 결과 내용과 고지 문구를 읽고 싶은 사용자로서, 추천 링크 때문에 고지나 결과가 가려지지 않았으면 좋겠다.

## 완료 조건 (AC)

QA가 이 목록으로 테스트를 만든다. 검증 층 태그를 붙인다.

### 화면 흐름 (E2E, 기능 종류당 대표 흐름 1개)

- AC-1: [E2E] 오늘의 운세 결과 화면에서 결과 아래 블록 제목 "다른 기능도 볼 수 있어요"와 추천 링크 2개가 보이고, 링크 하나를 누르면 해당 페이지로 이동한다. 이 흐름에는 기존 동의 절차를 거친다.
- AC-2: [E2E] 타로 오늘의 카드 뽑기 후, 결과 영역의 면책 문구와 위기 상담 전화 목록이 그대로 보이고, 추천 링크 블록은 그 아래에 있다. 링크 블록이 고지를 가리지 않는다.
- AC-3: [E2E] 뭐 먹지 룰렛 결과가 나온 뒤 추천 링크 2개가 보이고, 키보드 Tab으로 링크에 포커스가 가면 포커스 표시가 보이며 Enter로 이동한다.
- AC-4: [E2E] 로또 번호 생성기에서 번호를 생성한 뒤, 추천 링크 2개가 모두 `/lotto/` 아래 페이지를 가리키고, 로또 고지(참고용, 당첨 보장 없음)가 화면에 그대로 보이며 링크 블록과 겹치지 않는다.

### 규칙 (단위)

- AC-5: [단위] 추천 대상 정의는 화면마다 정확히 2개이고, 자기 자신을 가리키지 않으며, 쿼리나 해시가 없고, 실제 존재하는 경로만 쓴다.
- AC-6: [단위] 로또 링크 금지 규칙: 로또 외 화면의 추천 대상에는 `/lotto` 경로가 없다. 로또 화면의 추천 대상은 모두 `/lotto` 경로다.
- AC-7: [단위] 링크 문구와 블록 제목은 기존 금지 표현 검사(타로·운세·메뉴 copy-rule 상수)를 통과하고, 클릭을 재촉하는 말(예: "지금 바로", "꼭", "놓치지 마세요", "광고")을 포함하지 않는다.

### 코드·문서 확인 (정적)

- AC-8: [정적] 링크 블록 컴포넌트에 광고 컴포넌트 import가 없고, 블록은 `use client` 없이 서버 HTML에 그대로 들어간다(검색 크롤링 대상).
- AC-9: [정적] 링크 블록 바로 위나 아래에 광고 슬롯을 두지 않는다. 블록 아래에는 본문 블록(가이드, FAQ, 상세 고지 중 하나)이 최소 1개 있다. 블록이 페이지 맨 아래에 오지 않는다.
- AC-10: [정적] 링크 블록은 결과 영역(결과 카드, 공유 버튼) 뒤에 두고, 공유 버튼 사이에 끼우지 않는다.
- AC-11: [정적] 링크에 생년월일, 질문, 입력값, 동의 상태, 선택값을 넣지 않는다. 링크는 `/` 경로만 쓴다(기존 AC-81 규칙과 같음).
- AC-12: [정적] 색은 토큰만 쓴다. 링크는 `primary`, 설명은 `muted-foreground`. 메뉴 색은 쓰지 않는다. 새 패키지, 새 폰트, 새 이미지 파일을 추가하지 않는다(`package.json` 변경 없음).
- AC-13: [정적] 법적 고지 상수 파일(운세·타로·꿈·뭐 먹지·운빨 뽑기·손 없는 날·로또 고지)은 이 작업에서 수정하지 않는다.
- AC-14: [정적] 승인된 대상 화면에만 블록이 들어가고, 이미 이동 링크가 있는 궁합·운세 화면은 Q2 결정 전까지 바꾸지 않는다.

## 예외·빈 상태

- 결과가 아직 없는 상태(타로 뽑기 전, 룰렛 전, 번호 생성 전)에는 추천 블록을 보이지 않는다. 기본안이다. 기존 면책 문구와 위기 상담 전화는 원래대로 보인다(Q4).
- 결과를 다시 뽑거나 다시 생성해도 추천 블록은 그대로 있고, 추천 2개는 바뀌지 않는다.
- 동의 거부 또는 연령 차단 상태(운세, 궁합)에서는 결과가 없으므로 블록을 보이지 않는다.
- 로또 화면에서 연령 확인(age gate)이 떠 있으면 추천 블록은 확인 뒤에만 보인다.
- 운세 블록으로 가는 링크는 동의 절차를 거친다. 링크 문구가 결과를 바로 약속하면 안 된다.
- 모바일 화면에서 링크가 한 줄에 여러 개 붙으면 줄바꿈으로 읽기 쉽게 한다. 링크 높이는 기존 터치 기준(44px)을 따른다. 레이아웃 세부는 디자인 단계를 생략했으므로 기존 `FortuneCompatibilityLinkComponent`의 모양을 참고 기준으로 쓴다.
- 링크 대상 페이지가 준비 중(`comingSoon`)이면 추천 대상에서 뺀다.

## 검색 노출

- 키워드: 새 검색 키워드 없음. 새 페이지를 만들지 않으므로 기존 페이지의 검색 키워드를 그대로 쓴다.
- 페이지가 답해야 할 질문: 해당 없음 (기존 페이지가 답한다).
- 부수 효과: 내부 링크가 늘어 크롤링 경로가 생긴다. 링크 문구는 기존 메뉴 라벨("오늘의 운세", "띠별 운세", "3장 타로 (과거·현재·미래)" 등)을 그대로 써서 제목과 맞춘다. 사이트맵과 메타데이터는 바꾸지 않는다.
- 링크가 결과 전 상태에서도 서버 HTML에 들어가야 하는지는 열린 질문 Q4에서 정한다.

## 법적·정책 요구사항

- 개인정보 수집: 없음. 링크는 고정 경로 이동만 한다. 생년월일, 질문, 선택값, 동의 상태를 URL이나 저장소에 싣지 않는다. 새 저장소 키를 만들지 않는다. 기존 사이트 전체 Analytics(경로 기록)는 그대로 둔다. 클릭 이벤트 추가는 기본안에서 빼며, 추가하려면 Q5에서 승인받는다.
- 고지 문구: 이 기능이 새로 붙이는 고지 문구는 없다. 대신 아래 기존 고지를 가리지 않아야 한다.
  - 타로(`/tarot/daily`, `/tarot/three-card`): 오락·자기 성찰 목적 고지, 결과 아래 위기 상담 전화 5곳
  - 운세(`/fortune/*`): 오락·참고 목적 면책, 결과 아래 위기 상담 전화 5곳
  - 궁합: 과학적으로 검증되지 않음 고지(결과 고지 1개, 전화 목록 없음)
  - 꿈 해몽: 오락·자기 성찰 목적 고지, 하단 위기 상담 전화
  - 뭐 먹지: 결과는 무작위이며 추천이나 평가가 아니라는 고지, 보상과 무관한 오락 고지
  - 운빨 뽑기: 보상과 무관한 오락 고지
  - 손 없는 날: 민간 풍습 고지, 결과 보장 없음
  - 로또: 참고용 통계이며 당첨을 보장하지 않는다는 고지, 로또 푸터 고지
- 법적 연결 제약 (COMPLIANCE.md 11장 기준, 장 위치만 적음):
  - 꿈 해몽, 운빨 뽑기, 궁합 화면에서 로또 링크를 만들지 않는다.
  - 운세에서 로또 링크는 기존 "행운 숫자 1~10" 링크 하나뿐이다. 이 기능으로 새 로또 링크를 추가하지 않는다.
  - 로또 화면 안에서만 로또 링크를 쓴다. 로또 외 화면이 로또로 가면 연령 확인이 뜨므로 추천 대상에서 뺀다.
- 상업적 이용 주의:
  - 목적이 광고 노출 증가라는 점은 정책 판단에서 불리하게 작용할 수 있다. 카카오 애드핏 운영정책은 광고 자리를 가리거나, 오클릭을 유도하거나, 노출·클릭을 비정상적으로 늘리는 것을 제한한다(`docs/research/adfit-fixed-banner.md` 1장, 2장). 도입 전에 정책 원문을 직접 대조하고 담당 채널에 문의한다(Q1).
  - 금지: 광고 클릭 유도 문구, 광고와 같은 색 면 또는 같은 박스, 광고 바로 옆 배치, 광고를 가리는 배치, 자동 이동, 타이머 이동, 결과 전 강제 이동, 광고 링크처럼 보이는 아이콘.
  - 콘텐츠 자체에 문제될 데이터는 없다. 추천 대상은 기존 메뉴 경로뿐이고, 외부 링크와 외부 데이터는 추가하지 않는다.

## 열린 질문

- Q1 (광고 정책): 애드핏 담당 채널에 "결과 화면 내부 메뉴 링크가 광고 노출 증가 목적의 설계로 보이는지"를 문의해 서면 답을 받을까? 상단 고정 광고 확정 전에 이 기능을 시작할지도 정해야 한다. 현재 `src/app/layout.tsx`와 `src/features/ad/components/adfit-slot.component.tsx`에 미커밋 수정이 있다.
- Q2 (기존 링크 처리): 운세·궁합 결과 화면에 이미 있는 링크는 (a) 그대로 두고 추가하지 않을지, (b) 공통 블록으로 바꿀지(기존 문구와 위치가 바뀜)? 기본안은 (a)다.
- Q3 (손 없는 날): 달력 화면을 결과 화면으로 볼지. 넣는다면 추천 2개(오늘의 운세, 오늘의 타로)를 승인받는다.
- Q4 (표시 조건): 결과 전 상태에서도 블록을 보일지, 결과가 나온 뒤에만 보일지? 결과 뒤에만 보이면 서버 HTML에는 들어가지 않아 크롤링 경로에서 빠진다. 기본안은 "결과 뒤에만 표시"다.
- Q5 (측정): 링크 클릭 수를 세려면 이벤트를 추가해야 하는데, 이는 새 추적이다. 기본안은 추가하지 않는다. 체류 시간과 페이지 수는 기존 Analytics로 본다. 추가할지 결정이 필요하다.
- Q6 (문구와 제목): 블록 제목 "다른 기능도 볼 수 있어요"와 링크 문구 예시 "오늘의 운세도 볼까요?" 톤을 승인받는다. "추천"이라는 단어는 뭐 먹지 화면의 "추천이 아니다" 고지와 충돌할 수 있어 제목에서 뺐다. 링크 문구 전체를 타로·운세·뭐 먹지 copy-rule 검사에 넣을지도 정해야 한다.
- Q7 (로또 범위): `/lotto/[draw]` 회차 상세도 결과 화면으로 볼지. 이 기획서에는 넣지 않았다.
- Q8 (추천 쌍): 위 표의 추천 쌍을 승인받는다. 특히 운빨 뽑기 3곳끼리 잇는 안, 뭐 먹지 → 운빨 뽑기 안을 확인한다.
- Q9 (디자인 생략): 디자인 단계를 생략한다는 조건에 따라 블록 모양은 기존 `FortuneCompatibilityLinkComponent`와 같은 안으로 정한다. 다른 모양이 필요하면 다시 묻는다.
