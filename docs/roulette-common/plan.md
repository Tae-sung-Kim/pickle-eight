# 공용 돌림판 컴포넌트 리팩터링 기획서

## 목표

점심 화면에만 묶여 있던 돌림판(`RouletteComponent`)을 강조색, 회전 시간, 바퀴 수, 칸별 색을 호출하는 쪽에서 정할 수 있게 바꿔, 다음 기능(운빨 뽑기 돌림판)이 점심 색과 점심 설정을 물려받지 않고 같은 컴포넌트를 쓸 수 있게 한다. 점심 화면의 동작과 외형은 바꾸지 않는다.

## 범위

- 포함:
  - `src/components/common/roulette.component.tsx`에 선택 prop 추가: 강조색(`accentClassName`), 회전 시간(초), 바퀴 수.
  - `src/types/roulette.type.ts`의 `RouletteItemType`에 칸별 색 선택 필드(`colorClassName`) 추가.
  - 점심 사용처(`src/features/meal/roulette/components/spin-panel.component.tsx`)가 기본값으로 지금과 같이 동작하는지 확인.
- 제외:
  - 운빨 뽑기 기능 자체(돌림판 화면, 제비뽑기, 사다리). 사다리는 이번 범위에서 다루지 않는다.
  - 점심 화면의 UI 문구·레이아웃 변경.
  - 새 디자인 토큰 추가, 다크 모드 도입.
  - 테두리·병뚜껑(`jar` 토큰) 색 변경. 고정 유지한다.

## 기능 목록

| ID | 기능 | 우선순위 (필수/선택) |
|---|---|---|
| F-1 | 강조색 선택 prop (`accentClassName`). 빈 값이나 생략이면 지금의 점심 색 | 필수 |
| F-2 | 회전 시간(초)·바퀴 수 선택 prop. 기본값은 1.0초, 2바퀴 | 필수 |
| F-3 | 칸별 색 (`RouletteItemType.colorClassName`). 없으면 기존처럼 번갈아 칠함 | 필수 |
| F-4 | 점심 화면 회귀 유지 (hydration 좌표 고정, 동작 줄이기 처리 포함) | 필수 |

## 유저 스토리

- US-1: 운빨 뽑기 담당 개발자로서, 점심과 다른 강조색·회전 시간·칸 색으로 돌림판을 쓰고 싶다. 왜냐하면 같은 컴포넌트를 기능마다 복사하지 않기 위해서다.
- US-2: 점심 메뉴를 고르는 사용자로서, 리팩터링 후에도 지금과 똑같이 돌아가고 결과가 나오는 돌림판을 쓰고 싶다. 왜냐하면 화면이 바뀌면 안 되기 때문이다.

## 완료 조건 (AC)

QA가 이 목록으로 테스트를 만든다.

- AC-1: 점심 화면에서 새 prop을 하나도 넘기지 않아도, 당첨 칸 면·테두리와 바늘 색이 리팩터링 전과 같은 클래스(칸 `fill-menu-meal/20 stroke-menu-meal`, 바늘 `fill-menu-meal`)로 나온다.
- AC-2: 점심 화면에서 회전 시간은 1.0초, 바퀴 수는 2바퀴로 돌고, 멈춘 뒤 병뚜껑에 결과 이름이 기존과 같은 시점에 나온다.
- AC-3: `accentClassName`을 넘기면 당첨 칸 면·테두리가 넘긴 클래스 색으로 바뀌고, 점심 기본 색 클래스는 남지 않는다. 바늘은 같은 값에서 `fill-` 클래스의 투명도를 뺀 색으로 바뀐다(`fill-menu-x/20` → `fill-menu-x`).
- AC-4: 회전 시간(`spinDurationSec`)은 0.5 이상 1.0 이하의 값이면 그 값으로 회전한다. 범위 밖, NaN, 무한대면 1.0초로 회전한다. 생략하면 AC-2와 같다.
- AC-5: 바퀴 수(`spinTurns`)는 1 이상 5 이하의 정수면 그 바퀴 수만큼 돈 뒤 목표 칸에서 멈춘다. 0, 음수, 소수, 6 이상, NaN, 무한대면 2바퀴로 돈다. 생략하면 AC-2와 같다.
- AC-6: `colorClassName`이 있는 칸은 그 색으로 칠해지고, 홀수 칸 마지막 칸(`fill-muted`) 규칙보다 우선한다. `colorClassName`이 없거나 빈 문자열이거나 공백만 있으면 색이 없는 것으로 보고 기존처럼 `fill-card`와 `fill-background`를 번갈아 쓴다. 전부 없으면 화면이 지금과 같다.
- AC-7: 칸 수가 1개일 때도 `colorClassName`이 있으면 단일 원에 그 색이 적용된다.
- AC-8: 칸 수가 0개, 1개, 홀수(예: 3개), 28개 초과(글자 숨김)인 경우 모두 기존과 같이 그려진다.
- AC-9: 칸 색은 아래 허용 토큰 목록 중에서만 쓴다. 허용 토큰을 쓴 칸은 칸 글자(`fill-foreground`)와 명도 대비 4.5:1 이상이다. 대비 수치는 ui-ux-design 단계에서 확인해 기록한다.
- AC-10: 동작 줄이기(reduced motion)를 켜면 회전 없이 바로 결과가 표시되고, `onSpinEnd`가 정확히 한 번 호출된다.
- AC-11: 점심 페이지에서 hydration 불일치 경고가 콘솔에 나오지 않는다. 좌표는 기존처럼 소수 셋째 자리로 고정된다.
- AC-12: 단위 테스트(`react-dom/server` 렌더 문자열 검사, 추가 의존성 없음)가 아래를 검증하고 통과한다.
  - `accentClassName` 생략, 값 지정, 빈 문자열(기본 점심 색 사용)
  - `spinDurationSec`, `spinTurns`의 범위 안·밖 값(기본값 대체)
  - `colorClassName` 적용, 빈 문자열 처리, 칸 1개
  - 테스트 위치: `unit/shared/roulette.test.tsx` (제안). vitest 설정이 `.tsx` 테스트를 읽는지 설계 단계에서 확인한다.
- AC-13: `pnpm typecheck`와 `pnpm lint`가 통과한다. 새 prop과 필드는 모두 선택값이라 기존 호출부에서 타입 오류가 나지 않는다.
- AC-14: 회귀 범위는 `unit/meal`과 `e2e/meal.spec.ts`다. 스크린샷 비교는 하지 않는다.

## 칸 색 허용 토큰 (제안, 디자인 단계에서 확정)

칸 글자는 `fill-foreground`(짙은 녹색 `#1b3328`)다. 아래처럼 연한 면 토큰만 허용한다. 진한 토큰(`jar`, 메뉴 라벨 색 100%)은 허용하지 않는다.

- 기존 종이 계열: `fill-card`, `fill-background`, `fill-muted`
- 메뉴 면 (옅게, `design-system.md`의 `bg-menu-<key>/10` 규칙): `fill-menu-lotto/10`, `fill-menu-meal/10`, `fill-menu-tarot/10`, `fill-menu-fortune/10`, `fill-menu-dream/10`

`/10` 면 위 글자 대비는 ui-ux-design 단계에서 실제 값으로 확인하고 AC-9 기록에 남긴다.

## 예외·빈 상태

- 칸 수 0개: 빈 원만 보이고 회전하지 않는다. 버튼은 호출부(spin-panel)가 막는다.
- `colorClassName`이 빈 문자열이거나 공백만 있으면 색이 없는 것으로 본다.
- `accentClassName`이 빈 문자열이면 기본 점심 색을 쓴다.
- `spinDurationSec`가 범위 밖, NaN, 무한대면 1.0초. `spinTurns`가 범위 밖, 소수, NaN, 무한대면 2바퀴.
- 칸 구성이 바뀌면(칸 key 목록 변경) 당첨 칸 표시를 지우고 바늘 각도를 0으로 되돌린다. 기존 동작을 유지한다.
- 동작 줄이기 사용자는 회전 없이 바로 결과를 본다. 연출 때문에 결과를 늦게 보이게 하지 않는다.

## 검색 노출

- 키워드: 없음 (내부 컴포넌트 리팩터링이며 새 페이지나 URL이 없다.)
- 페이지가 답할 질문: 없음. 점심 페이지의 기존 메타데이터, JSON-LD, sitemap은 바꾸지 않는다.

## 법적·정책 요구사항

- 개인정보 수집: 없음. 새 입력이나 저장 항목이 없다.
- 고지 문구: 없음. 이번 변경은 화면 문구를 바꾸지 않는다. 운빨 뽑기 기능을 만들 때 "오락 목적", "당첨 보장 없음" 등 고지가 필요한지는 그 기능의 기획서에서 따로 정한다.
- 상업적 이용 주의: 없음. 새 라이브러리, 폰트, 이미지를 추가하지 않는다. 테스트도 `react-dom/server`를 쓰므로 의존성을 추가하지 않는다.

## 결정 사항

1. 회전 시간: 0.5~1.0초만 허용. 범위 밖, NaN, 무한대는 기본값 1.0초. (AC-4)
2. 바퀴 수: 1 이상 5 이하의 정수만 허용. 잘못된 값은 기본값 2. 상한 5는 짧은 제한으로 둔 값이다. (AC-5)
3. 테스트: `react-dom/server` 렌더 문자열 검사. 의존성 추가 없음. 스크린샷 비교 안 함. 단위 테스트 위치는 `unit/shared/` 제안. (AC-12, AC-14)
4. `jar` 테두리·병뚜껑: 고정 유지, 이번 범위 밖. 문제 정의 정정: `jar`는 병 속 심록(`#173a2b`)이라 점심 색(`menu-meal`)이 아니다. 점심 색이 새어 나오는 곳은 칸 강조(면·테두리)와 바늘이다.
5. 칸 색: 라이트 기준만 보장한다. 다크 모드는 지금 쓰지 않으므로 다크 대응은 이번 범위 밖이다. 허용 토큰은 위 목록의 연한 토큰만, 글자 대비 4.5:1 이상. (AC-9)
6. 칸 색 우선순위: 홀수 마지막 칸 `fill-muted`보다 칸 색이 우선. 칸 1개 원에도 칸 색 적용. 빈 문자열 `colorClassName`은 색 없음. (AC-6, AC-7)
7. `accentClassName` 빈 문자열: 기본 점심 색 사용. (예외 절)
8. 칸 색 기능: 이번 범위에 포함. (승인됨)

## 확인 사항

- A. (확정) `accentClassName` 하나로 칸 면·테두리와 바늘을 함께 바꾼다. 바늘은 값 안의 `fill-` 클래스에서 투명도(`/20`)를 뺀 색을 쓴다.
